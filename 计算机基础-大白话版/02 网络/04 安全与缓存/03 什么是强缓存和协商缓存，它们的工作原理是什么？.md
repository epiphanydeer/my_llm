# 03 什么是强缓存和协商缓存，它们的工作原理是什么？

## 1. 🎯 一句话听懂 + 生活大白话例子

- **一句话听懂**：**强缓存**是“保质期内直接吃，连店都不用去问”（0 网络请求）；**协商缓存**是“过期了先打电话问老板‘这东西改配方了吗？’，没改就继续吃旧的（304），改了才重新买（200）”。
- **生活大白话例子**：
    - 就像你冰箱里放着一盒牛奶（网页里的图片/CSS）：
        - **强缓存（看保质期）**：盒子上印着“有效期 7 天”（`Cache-Control: max-age=604800`）。只要今天才第 3 天，你直接从冰箱拿出来喝，**根本不用给超市打电话**（浏览器状态码显示 `200 OK (from memory/disk cache)`）。
        - **协商缓存（问老板改没改）**：到了第 8 天保质期过了（强缓存失效），你不确定厂家有没有出新包装，于是给超市老板打了个电话（发请求带上 `If-None-Match` 或 `If-Modified-Since`）。老板查了一下说：“配方包装一点没变，你手里那盒还能喝！”（返回 `304 Not Modified`，不传正文，极省流量）；如果老板说“换新包装了”，才给你送一盒新的（返回 `200 OK` + 新资源）。

## 2. 🧠 底层机制与核心对比

### 核心子概念（大白话版）

- **强缓存的两个指令（**`Cache-Control` **vs** `Expires`**）**：
    - `Expires`（HTTP/1.0）：写死一个绝对过期日期（如 2026 年 12 月 1 日），缺点是**全靠用户电脑本地时间准不准**，用户把系统时间往回改一年就乱套了。
    - `Cache-Control`（HTTP/1.1，**优先级更高**）：用相对倒计时（如 `max-age=3600`，代表从收到起管 1 小时），完全不受用户本地时钟错乱影响。常见还有 `no-store`（彻底不许缓存）和 `no-cache`（注意！它不是不缓存，而是“跳过强缓存，每次都必须去问服务器协商一下”）。
- **协商缓存的两对暗号（**`ETag` **vs** `Last-Modified`**）**：
    - `Last-Modified` / `If-Modified-Since`：靠**文件最后修改时间**（精确到秒）比对。缺点是如果文件在 1 秒内改了两次，或者打开文件改了一行又改回去（内容其实没变，但修改时间变了），就会误判。
    - `ETag` / `If-None-Match`（**优先级更高**）：靠**文件内容的哈希指纹**比对。只要内容变一个字节指纹就变，内容没变指纹就绝对不变，精准度 100%，但服务器计算指纹会多花一点点 CPU。

### 强缓存与协商缓存对比表

| **对比维度** | **强缓存（Strong Caching）** | **协商缓存（Conditional Caching）** |
| --- | --- | --- |
| **是否发请求给服务器** | **完全不发请求**，直接读本地内存/硬盘 | **必须发请求**去服务器核对一下 |
| **命中后的状态码** | `200 OK (from memory/disk cache)` | `304 Not Modified`（只回头部，不传正文） |
| **控制字段** | `Cache-Control`（优先） / `Expires` | `ETag + If-None-Match`（优先） / `Last-Modified + If-Modified-Since` |
| **未命中会怎样** | 走协商缓存（如果有验证头）或重新下载 | 服务器返回 `200 OK` + 最新完整资源 |
| **最适合的资源** | 长期不变的静态资源（带版本号的 JS/CSS/图片） | 经常可能更新的 HTML 主页、接口数据 |

## 3. 🗣️ 面试官视角：怎么串成体系回答

面试时按 **“先强后协的完整流程 -> 各自核心字段及优先级 -> 工程最佳实践”** 回答：

“浏览器缓存分为**强缓存**和**协商缓存**两级，加载资源时**先走强缓存，过期了再走协商缓存**：

1. **强缓存**：由响应头 `Cache-Control`（如 `max-age=3600` 相对时间，优先级最高）和 `Expires`（绝对时间）控制。只要没过期，浏览器**不发任何网络请求**，直接从本地读取。
2. **协商缓存**：强缓存过期后，浏览器会向服务器发请求做校验，靠两对头字段——`Last-Modified / If-Modified-Since`（秒级修改时间）和 `ETag / If-None-Match`（内容哈希指纹，优先级更高，能解决 1 秒内多次修改或内容未变时间戳变了的误判）。如果服务端比对发现资源没变，就返回 `304 Not Modified` 让浏览器继续用本地缓存；变了才返回 `200` 和新资源。 在实际前端工程里，通常是 `index.html` **用协商缓存（或** `no-cache`**）保证每次能拿到最新入口**，而带了哈希文件名的 JS/CSS/图片开启超长强缓存。”

## 4. ❓ 高频面试追问与参考答法

- **Q1：请求头/响应头里的** `Cache-Control: no-cache` **和** `no-store` **有什么区别？**
    - **参考答法**：千万别被字面意思骗了！`no-cache` **不是“不缓存”**，它的意思是“你可以存本地，但每次用之前必须跳过强缓存，找服务器协商确认（走 304）”；而 `no-store` **才是真正的“绝对不准缓存”**，连硬盘和内存都不许留底，每次必须重新下载（常用于银行余额、极度敏感的隐私数据）。
- **Q2：如果强缓存设了 1 年，但中途我紧急修复了一个 JS Bug 想让用户立刻生效，怎么办？**
    - **参考答法**：强缓存未过期前浏览器根本不会发请求，所以不能靠服务器通知。工程上的标准做法是**构建时给文件名加上内容哈希（如** `app.a1b2c3.js`**）**。一旦代码改了，HTML 里引用的文件名就变了，浏览器发现是一个全新的 URL，就会直接跳过旧缓存去下载新文件。

## 5. 🤖 和大模型/AI 开发有什么关系

- **RAG 知识库抓取与网页去重**：在做全网爬虫或企业文档定时同步进向量数据库时，如果每次都把几万个网页重新下载一遍再切片算 Embedding，既浪费带宽又烧钱。聪明的爬虫会记录每个网页的 `ETag` 和 `Last-Modified`，下次同步时带上 `If-None-Match`——如果对方返回 `304`，直接跳过，省下大量网络抓取和向量化算力！
- **模型权重与静态评测集的本地缓存**：Hugging Face Hub（`transformers`）和 CDN 分发大文件时，也重度依赖 `ETag` 来校验本地缓存的模型权重文件是不是最新版本，没变就直接复用本地缓存，变了才重新拉取。

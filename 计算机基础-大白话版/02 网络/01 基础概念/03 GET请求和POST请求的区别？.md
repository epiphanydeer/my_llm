# 03 GET请求和POST请求的区别？

## 1. 🎯 一句话听懂 + 生活大白话例子

- **一句话听懂**：GET 是“把条件写在明信片正面去取东西”，大家都能看见且字数有限；POST 是“把资料装进密封信封里寄过去办事”，能装很多东西且地址栏看不见。
- **生活大白话例子**：
    - **GET 就像去档案室查资料**：你在单子正面写着“我要看 2026 年 3 月的天气表”（参数直接挂在 URL 后面），管理员按单子拿给你看。别人路过一眼就能看到你在查什么，单子背面没地方写长篇大论，但你可以把这张单子收藏起来下次直接用（可收藏、可缓存）。
    - **POST 就像去银行柜台办开户**：你填了一整叠身份证复印件、住址、签名装进文件袋（请求体 Body）递进去，窗口外的人看不到你袋子里写了啥，袋子能装很厚一沓（理论上无大小限制），但办完一次不能随便刷新重交，不然就开两个户了。

## 2. 🧠 底层机制与核心对比

### 核心子概念（大白话版）

- **参数位置（URL vs 请求体）**：GET 把参数拼在网址 `?` 后面（如 `?name=tom&age=18`）；POST 把数据藏在 HTTP 报文的“肚子”（请求体 Body）里。
- **数据大小限制**：因为浏览器和服务器对网址长度有限制（一般几 KB），GET 传不了太长的数据；POST 放请求体里，只要服务器允许，传几百 MB 的文件都行。
- **安全性（暴露面 vs 传输加密）**：POST 只是不在地址栏明晃晃展示，但抓包依然能看到明文，**两者在 HTTP 下都不防窃听**，真正防窃听必须靠 HTTPS 加密。
- **缓存与书签**：GET 的完整信息都在 URL 里，天然适合被浏览器记住（收藏夹、历史记录）和缓存；POST 每次都带新数据去改状态，通常不缓存。
- **编码限制**：URL 里只能放标准的 ASCII 字符，中文等字符必须转成 `%E4%B8%AD...` 这种乱码格式；POST 的请求体可以直接传 JSON、二进制图片、文件等任意格式。

### 核心对比表

| **对比维度** | **GET 请求** | **POST 请求** |
| --- | --- | --- |
| **核心用途** | 向服务器获取/查询资源 | 向服务器提交数据/触发业务处理 |
| **数据放哪** | 拼在 URL 末尾（`?k=v`） | 放在 HTTP 请求体（Body）中 |
| **数据大小** | 受 URL 长度限制（通常约 2KB~8KB） | 理论上无限制（取决于服务器配置） |
| **数据可见性** | URL 直接可见，会留在历史记录/日志中 | 地址栏不可见，但仍需 HTTPS 才加密 |
| **幂等性** | 幂等（查 1 次和查 10 次一样） | 非幂等（提交 2 次可能建 2 条记录） |
| **缓存支持** | 默认可被浏览器和代理缓存 | 通常不被缓存 |
| **支持格式** | 仅限 ASCII 字符（非 ASCII 需 URL 编码） | 支持文本、JSON、XML、二进制文件等 |

## 3. 🗣️ 面试官视角：怎么串成体系回答

面试官问这题，最看重你能不能分清**“语义规范”**和**“底层传输”**，不要把“POST 绝对安全”当成真理：

“GET 和 POST 本质上都是基于 TCP 的 HTTP 请求，它们的区别主要体现在**设计语义**和**参数载体**上： 第一，**语义与幂等性**：在 RESTful 规范里，GET 用于‘查询’，要求安全且幂等，可被缓存和收藏；POST 用于‘提交或创建’，会改变服务器状态，是非幂等的。 第二，**参数位置与大小**：GET 参数拼在 URL 后面，只能用 ASCII 字符，受浏览器 URL 长度限制（一般 2K~8K）；POST 数据放在请求体（Body）里，支持 JSON、二进制文件等多种格式，理论上没有长度限制。 第三，**安全性误区**：很多人以为 POST 比 GET 安全，其实只是 POST 参数不直接暴露在地址栏和浏览器历史记录里，**如果走明文 HTTP，抓包一样能看到**，真正的数据安全必须依赖 HTTPS 加密。”

## 4. ❓ 高频面试追问与参考答法

- **Q1：为什么常听人说“GET 发 1 个 TCP 数据包，POST 发 2 个 TCP 数据包”？这是真的吗？**
    - **参考答法**：这是一个常见误区！HTTP 协议规范里**并没有规定** POST 必须分两次发。实际上，在现代浏览器中，绝大多数情况下 GET 和 POST 都是把请求头和请求体打包在一次发送；只有在极少数旧浏览器或服务端启用了 `Expect: 100-continue`（先发请求头问服务器收不收大文件，服务器回 100 再发请求体）时，POST 才会分两次发。
- **Q2：既然 POST 也能用来查询，为什么不所有接口都用 POST？**
    - **参考答法**：因为会丢掉浏览器和网络基建的很多红利——比如 GET 可以直接把链接发给朋友打开、可以存书签、可以被 CDN 和浏览器缓存直接加速，而 POST 都不行。不过在真实项目里，如果查询条件极其复杂（比如几百个筛选 ID，URL 放不下），工程上也确实会妥协用 POST 来做复杂查询。

## 5. 🤖 和大模型/AI 开发有什么关系

- **Prompt 传输为什么只能用 POST**：大模型对话时，System Prompt 加上十几轮历史对话、RAG 召回的几万字参考资料，体积动辄几十 KB 甚至上 MB，URL 根本装不下，且包含大量中文和特殊符号，所以大模型推理接口（Chat Completions）必须使用 **POST + JSON 请求体**。
- **RAG 检索与流式接口**：在 Dify、LangChain 等 AI 应用框架中，简单的状态查询（如“查询知识库列表”）用 `GET` 方便缓存；而向量检索、文档切片上传（二进制文件 `multipart/form-data`）、对话生成全用 `POST`。
- **注意敏感信息别放 GET**：开发 AI 应用时，千万不要把用户的 API Key（如 `sk-...`）作为 GET 参数拼在 URL 里，否则它会被明文记录在网关日志、代理服务器和浏览器历史中，造成严重泄露。

# 04 HTTP中常见的状态码有哪些？分别是什么含义？

## 1. 🎯 一句话听懂 + 生活大白话例子

- **一句话听懂**：HTTP 状态码就是服务器回给浏览器的“三位数字暗号”，一眼就能看出这次请求是“办成了、搬家了、你自己填错了，还是服务器罢工了”。
- **生活大白话例子**：
    - 把访问网站比作**去餐厅点菜**：
        - **2xx（200）**：“菜做好了，请慢用！”（一切正常）。
        - **3xx（301/302/304）**：301 是“本店永久搬去新街口了，以后别来这儿”；302 是“今天店里装修，临时去隔壁分店吃”；304 是“今天菜单和昨天一模一样，看你手机里存的旧菜单就行”（省得重印）。
        - **4xx（400/401/403/404）**：客人的问题——400 是“你点的菜名我听不懂（格式错）”；401 是“请先出示会员卡（没登录）”；403 是“会员卡看了，但这是 VIP 包厢你进不去（没权限）”；404 是“菜单上根本没这道菜（路径错）”。
        - **5xx（500/502/503）**：后厨的问题——500 是“厨师炒菜把锅烧糊了（代码报错）”；502 是“传菜员问后厨，后厨回了一句乱码（网关上游挂了）”；503 是“今天客人太多坐不下了，请等会儿再来（限流/维护）”。

## 2. 🧠 底层机制与核心对比

### 核心子概念（大白话版）

- **五大分类一眼识别**：
    - `1xx`：信息提示（“收到一部分了，你接着说”，如 `101` 切换成 WebSocket 协议）。
    - `2xx`：成功（“搞定了”，如 `200` 正常返回、`201` 创建成功、`204` 删完了啥也不用回）。
    - `3xx`：重定向/缓存（“别找我，去那儿”或“用你本地的”）。
    - `4xx`：客户端锅（“你的请求有问题：参数错、没登录、没权限、找错门”）。
    - `5xx`：服务端锅（“我这边出故障了：代码崩了、上游挂了、太忙了”）。
- **高频易混点区分**：
    - **301 vs 302**：301 是永久搬家，浏览器会死记住新地址，下次直接去新地址；302 是临时借用，下次还得先问老地址。
    - **401 vs 403**：401 是“你是谁？先登录”（未认证）；403 是“我知道你是谁，但你级别不够”（无权限）。
    - **500 vs 502 vs 503**：500 是自己代码炸了；502 是网关/代理（如 Nginx）后面的真实服务挂了；503 是服务还活着但主动拒绝服务（维护中或限流熔断）。

### 高频十大状态码速查表

| **状态码** | **英文全称** | **大白话含义** | **典型触发场景** |
| --- | --- | --- | --- |
| **200** | OK | 一切正常，数据给你 | 网页正常打开、API 成功返回 JSON |
| **301** | Moved Permanently | 永久搬家（浏览器会缓存新址） | 网站换新域名、HTTP 强制跳 HTTPS |
| **302** | Found | 临时改道（下次还走原路） | 未登录跳登录页、OAuth 授权回调 |
| **304** | Not Modified | 东西没变，直接用你本地旧的 | 浏览器协商缓存命中，省流量 |
| **400** | Bad Request | 你发的格式/参数不对 | JSON 少个括号、必填参数没传 |
| **401** | Unauthorized | 没登录或凭证过期，先验证身份 | 没带 Token 或 Token 过期访问接口 |
| **403** | Forbidden | 身份知道，但你没权限进 | 普通用户点管理员后台、IP 被拉黑 |
| **404** | Not Found | 找不到你要的东西 | 网址拼错了、商品已下架删除 |
| **500** | Internal Server Error | 服务器内部代码报错崩溃 | 后端空指针异常、数据库连接断开 |
| **503** | Service Unavailable | 服务器太忙或维护中，暂不接客 | 秒杀流量打满熔断、系统停机维护 |

### 常见扩展状态码补充表

| **分类** | **状态码** | **英文名称** | **简明含义与场景** |
| --- | --- | --- | --- |
| **1xx** | `100` / `101` | Continue / Switching Protocols | 100 继续发请求体；101 升级协议（如切到 WebSocket） |
| **2xx** | `201` / `202` / `204` / `206` | Created / Accepted / No Content / Partial Content | 201 新建成功；202 异步受理；204 成功无返回体（如 DELETE）；206 断点续传部分内容 |
| **3xx** | `303` / `307` | See Other / Temporary Redirect | 303 强制用 GET 重定向；307 保持原方法（如 POST）临时重定向 |
| **4xx** | `405` / `409` / `413` / `429` | Method Not Allowed / Conflict / Payload Too Large / Too Many Requests | 405 方法不对；409 状态冲突；413 文件太大；429 请求太频繁被限流 |
| **5xx** | `502` / `504` | Bad Gateway / Gateway Time-out | 502 网关收到上游无效响应；504 网关等上游响应超时 |

## 3. 🗣️ 面试官视角：怎么串成体系回答

千万别按数字大小背流水账，按 **“五大分类总纲 -> 每类挑 2~3 个最核心的对比解释”** 来答：

“HTTP 状态码用三位数字区分请求结果，**1xx 表示信息提示，2xx 表示成功，3xx 表示重定向或缓存，4xx 表示客户端出错，5xx 表示服务端出错**。 面试和排错中最核心的有这几个：

- **2xx** 最常用 **200**（成功）、**204**（成功但无内容返回）和 **206**（断点续传）；
- **3xx** 重点区分 **301 永久重定向**（浏览器缓存新址，利好 SEO 权重转移）和 **302 临时重定向**，以及协商缓存命中的 **304**；
- **4xx** 重点区分 **400**（参数语法错）、**401**（未登录/认证失败）和 **403**（已登录但无权限），以及 **404**（资源不存在）；
- **5xx** 重点区分 **500**（后端代码异常）、**502**（网关后端挂了）、**503**（过载熔断/维护）和 **504**（网关等后端超时）。”

## 4. ❓ 高频面试追问与参考答法

- **Q1：401 和 403 英文里都有“未授权/禁止”的意思，开发时怎么严格区分？**
    - **参考答法**：**401 看“身份”（Authentication），403 看“权限”（Authorization）**。没登录、Token 传错了或过期了，服务器不知道你是谁，就返回 **401**，前端收到后通常跳去登录页；你已经登录了，服务器认识你是普通用户张三，但你非要删管理员的数据，服务器明确拒绝你，这就返回 **403**。
- **Q2：线上突然报大量 502 和 504，它们有什么区别？怎么排查？**
    - **参考答法**：这两个都是**网关（比如 Nginx）**报的错。**502（Bad Gateway）** 说明后端服务根本没正常回话（比如进程崩溃、端口没启动、被 OOM 杀掉了）；**504（Gateway Time-out）** 说明后端服务活着，但干活太慢了（比如慢 SQL 或死循环），超过了网关的等待超时时间。

## 5. 🤖 和大模型/AI 开发有什么关系

- **429 Too Many Requests（限流噩梦）**：调大模型 API（OpenAI / Anthropic / 火山 / 阿里云）时，最常遇到的就是 **429**——每秒请求数（RPM）或每分钟 Token 数（TPM）超标了。写 AI Agent 或批量跑评测脚本时，必须针对 429 做**指数退避重试（Exponential Backoff）**。
- **502 / 504 与大模型慢响应**：大模型推理（尤其长文本或思考模型）动辄耗时十几秒到一两分钟。如果前端和模型之间隔着 Nginx 或 API 网关，网关默认 60 秒超时就会直接给用户甩一个 **504 Gateway Time-out**！所以 AI 应用必须在网关层调大超时时间，或者改用 **SSE 流式返回**（不断往外吐字，保持连接活跃不超时）。
- **400 / 401 排查**：传给模型的上下文超过了最大窗口（如超出 128K tokens）或 JSON Schema 写错，API 会返回 **400**；API Key 填错、欠费或过期则会返回 **401**。

# 03 有哪些页面置换算法？

## 1. 🎯 一句话听懂 + 生活大白话例子

- **一句话听懂**：当物理内存装满了、又必须把硬盘里的新页面搬进来时，**页面置换算法**就是决定“该把内存里哪一页老数据踢出去腾地方”的淘汰规则，目标是让下次找数据时尽量还在内存里（降低缺页率）。
- **生活大白话例子**：把你的**手机桌面/小书包（物理内存）**想象成只能放 3 本书的格子，现在要放第 4 本书进来，必须淘汰 1 本：
    - **OPT（最佳置换）**：你开了“未来预知外挂”，知道未来一个月最晚才用到《线性代数》，那就先把它踢出去——理论最省事，但现实中没人能预知未来！
    - **FIFO（先进先出）**：谁最早放进书包就先踢谁，不管它是不是你每天都在翻的《字典》——最傻瓜，容易把常用书踢掉。
    - **LRU（最近最久未使用）**：看每本书**上一次翻阅的时间**，谁最久没被翻过了就踢谁——非常符合“刚用过的书等会还要用”的习惯。
    - **LFU（最少使用）**：给每本书贴个“累计翻阅次数”贴纸，谁被翻的次数最少就踢谁。
    - **Clock（时钟置换）**：把书摆成一圈，每本书贴个“最近用过吗（0/1）”小标签，指针转圈巡逻：看到贴 `1` 的就撕掉改 `0` 放过它一次机会，看到贴 `0` 的直接踢掉！
    - **改进 Clock**：在上面基础上再看一眼“这本书有没有被你涂改写笔记（修改位）”，优先踢掉“既没被翻过、又没被涂改（不用抄回书柜）”的书，省去写回硬盘的力气。

## 2. 🧠 底层机制与核心对比

### 六大页面置换算法（大白话拆解）

1. **OPT（最佳置换）**：淘汰未来最长时间不会被访问的页面。缺页率最低，但需要预知未来访问序列，无法在现实中实现，只用来当理论“天花板标尺”。
2. **FIFO（先进先出）**：用队列记录进入顺序，谁先进来谁先滚。实现极简，但违背局部性原理，还会出现奇葩的 **Belady 异常**（给的物理页框越多，缺页率反而越高）。
3. **LRU（最近最久未使用）**：利用**局部性原理**，淘汰最长时间没被访问的页。性能最接近 OPT，但每次访存都要更新时间戳或调整双向链表，纯软件/硬件开销都比较大。
4. **LFU（最少使用）**：淘汰最近一段时间里访问**次数**最少的页。适合访问频率冷热分明的场景，但对突发热点不友好（以前爆火过的老页面计数太高，可能赖着不走）。
5. **Clock（时钟置换 / 二次机会算法）**：LRU 的低成本近似版！所有内存页连成环形队列，每页 1 个**访问位（P）**。淘汰时指针顺时针扫：遇到 `P=1` 就置 `0` 饶它一命继续走；遇到 `P=0` 就立刻淘汰。最多转两圈必能找到淘汰页。
6. **改进 Clock 算法**：再加 1 个**修改位（M）**，因为没修改过的页直接丢弃就行，修改过的页踢出去前必须写回硬盘（I/O 很慢！）。淘汰优先级从高到低分 4 档：
    - 第一优先：`(P=0, M=0)` 没用过也没改过（直接扔，零 I/O）；
    - 第二优先：`(P=0, M=1)` 没用过但改过；
    - 第三优先：`(P=1, M=0)` 用过但没改过；
    - 第四优先：`(P=1, M=1)` 既用过又改过。

### 六种页面置换算法核心对比表

| **算法** | **核心淘汰依据** | **优点** | **缺点 / 风险** | **典型适用场景** |
| --- | --- | --- | --- | --- |
| **OPT（最佳）** | 未来最久不用 | 理论最优，缺页率最低 | **无法实现**（不能预知未来） | 仅作性能评估的理论上限 |
| **FIFO（先进先出）** | 最早进入内存 | 实现最简单（队列） | 性能差，存在 **Belady 异常** | 极简单的低要求系统 |
| **LRU（最近最久未用）** | 距上次访问时间最长 | 基于局部性原理，性能接近 OPT | 维护链表/时间戳开销大 | Redis 等缓存系统、高性能场景 |
| **LFU（最少使用）** | 历史访问频率最低 | 适合冷热数据固定且差异大的场景 | 旧热点难淘汰，突发新热点易被踢 | 访问模式稳定的静态缓存 |
| **Clock（时钟）** | 访问位 `P=0`（给一次机会） | 成本低、性能近似 LRU | 对访问时间先后判断不够精确 | **通用操作系统折中首选** |
| **改进 Clock** | 综合访问位 `P` 和修改位 `M` | 优先踢未修改页，**大幅减少磁盘 I/O** | 最多需扫描 4 轮，逻辑略复杂 | 对磁盘 I/O 敏感的操作系统 |

## 3. 🗣️ 面试官视角：怎么串成体系回答

面试官问“有哪些页面置换算法”，按**“理论上限 -> 简单基线 -> 局部性主力 -> 工程折中”**的脉络讲，逻辑极其顺滑：

1. **理论标尺**：**OPT** 淘汰未来最久不用的页，最优但不可实现。
2. **最简基线**：**FIFO** 淘汰最早进来的，简单但性能差且有 **Belady 异常**。
3. **基于局部性原理的经典算法**：**LRU** 看“上一次访问时间”，**LFU** 看“累计访问次数”。其中 LRU 性能逼近 OPT 且无 Belady 异常，但精确实现每次访存都要改链表，OS 内核开销太大。
4. **操作系统实际工程折中**：因此操作系统实际常用 **Clock（时钟算法）** 及其**改进版**，只用 1~2 个硬件标志位（访问位、修改位）做近似 LRU，既省开销又能减少脏页写回磁盘的 I/O 次数。

## 4. ❓ 高频面试追问与参考答法

- **追问 1：什么是 Belady 异常？为什么 FIFO 会出现而 LRU 不会？**
    - **参考答法**：Belady 异常是指“增加分配给进程的物理页框数量，缺页率反而上升”的反常现象。FIFO 会出现是因为它只看进入时间、不看访问局部性，多给一个页框反而打乱了淘汰节奏把刚要用的页踢出去了；而 **LRU、OPT 等属于“栈式算法”**（页框数为 $N$ 时内存里的页面集合一定是页框数为 $N+1$ 时的子集），因此绝对不会出现 Belady 异常。
- **追问 2：LRU 和 LFU 在实际缓存淘汰中有什么区别？**
    - **参考答法**：**LRU 看重“时间新鲜度”**（最近一次访问距今多久），适合热点随时间漂移的场景；**LFU 看重“访问频次”**（一共被访问过多少次），适合长期稳定的高频数据。但 LFU 如果一个老数据以前被刷过一万次，哪怕现在彻底过时了也很难被踢掉，通常需要配合“频率衰减机制”使用。

## 5. 🤖 和大模型/AI 开发有什么关系

- **大模型 KV Cache 与 Prefix Caching 淘汰策略**：在多轮对话或长文档问答（如 Kimi、Claude Prompt Caching）中，显存和内存空间有限，推理引擎（如 SGLang、vLLM）会把历史对话的 KV Cache 缓存在内存里。当显存满了需要踢掉一部分旧用户的对话缓存时，使用的正是 **LRU（最近最久未使用）** 或 **改进型前缀树 LRU**，保证正在高频聊天的用户缓存不被踢掉。

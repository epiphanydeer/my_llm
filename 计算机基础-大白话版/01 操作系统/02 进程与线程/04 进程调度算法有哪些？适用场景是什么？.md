# 04 进程调度算法有哪些？适用场景是什么？

## 1. 🎯 一句话听懂 + 生活大白话例子

- **一句话听懂**：不同场景对电脑的要求不一样（有的要**总产量高**，有的要**反应快**，有的要**绝对准时**），所以没有“万能调度算法”，必须根据场景选对算法。
- **生活大白话例子**：同样是交通调度，不同路况规则完全不同：
    - **货运码头（批处理系统）**：不关心单个集装箱等了几秒，只关心一天能装卸多少吨货（**高吞吐量**） -> 用 FCFS、SJF、HRRN。
    - **客服热线（交互式系统）**：顾客打进来如果 5 秒没人理就会挂电话，必须人人都能快速得到回应（**低响应时间**） -> 用时间片轮转（RR）、多级反馈队列（MLFQ）。
    - **医院急诊室（实时系统）**：心梗病人必须插队立刻抢救，晚一分钟就出事（**严格截止时间**） -> 用优先级调度、EDF（最早截止时间优先）。

## 2. 🧠 底层机制与核心对比

### 调度核心指标与算法分类（大白话拆解）

评价一个调度算法好不好，主要看 5 个指标：

- **周转时间**：从任务提交到彻底干完一共花了多久（越短越好）。
- **响应时间**：从你点鼠标到屏幕首次有反应等了多久（交互系统最看重）。
- **吞吐量**：单位时间内一共完成了多少个任务（批处理最看重）。
- **公平性**：大家分到的 CPU 时间均不均衡，有没有人被饿死。
- **CPU 利用率**：CPU 真正干活的时间占比（越少摸鱼越好）。

### 常见调度算法与适用场景对比表

| **调度算法** | **抢占性** | **公平性** | **响应时间** | **吞吐量** | **适用场景** |
| --- | --- | --- | --- | --- | --- |
| **FCFS（先来先服务）** | 非抢占 | 高 | 差 | 中 | 简单的批处理系统、嵌入式演示环境、轻负载后台 |
| **SJF / SRTF（短作业/最短剩余时间）** | SJF非抢占 / SRTF抢占 | 低 | 好 | **高** | 已知任务长度的批处理、科学计算、编译服务器 |
| **RR（时间片轮转）** | 抢占 | **高** | 好 | 中 | 分时系统、多用户交互式环境、普通桌面系统 |
| **优先级调度（PSA）** | 可选 | 低 | 好 | 高 | 实时系统、工业控制、操作系统内核关键任务 |
| **MLFQ（多级反馈队列）** | 抢占 | 中 | **很好** | **高** | 现代通用桌面系统（混合交互式 + 后台批处理） |
| **CFS（完全公平调度）** | 抢占 | **很高** | **很好** | **高** | Linux 桌面与服务器、多核系统、云计算虚拟化 |

补充两个实时调度算法：**EDF（最早截止时间优先）**动态挑离死线最近的先做；**RMS（速率单调调度）**按任务周期固定优先级，周期越短优先级越高。

## 3. 🗣️ 面试官视角：怎么串成体系回答

面试官问“调度算法有哪些、分别适合什么场景”时，建议用**“四大系统场景 -> 对应指标 -> 匹配算法”**的矩阵式答法：

1. **批处理场景（追求吞吐量与周转时间）**：用 **FCFS、SJF、HRRN**，不需要频繁人机交互，重点是把成批算力跑满。
2. **交互式/分时场景（追求响应速度与公平）**：用 **时间片轮转（RR）**，保证每个用户和窗口都能及时响应，不会卡死。
3. **实时系统场景（追求严格的时间约束）**：比如自动驾驶或工控，用 **抢占式优先级调度** 或 **EDF / RMS**，确保高危任务绝不超时。
4. **通用复杂系统（混合负载）**：既要看视频不卡顿，又要后台下载文件，所以 Windows 用 **MLFQ（多级反馈队列）** 自适应调节，而 Linux 服务器广泛使用 **CFS（完全公平调度器）**，用红黑树按虚拟运行时间（`vruntime`）精准分配 CPU。

## 4. ❓ 高频面试追问与参考答法

- **追问 1：什么是“护航效应（Convoy Effect）”？怎么避免？**
    - **参考答法**：护航效应是指在非抢占的 FCFS 调度中，一个非常耗时的 CPU 密集型长进程堵在最前面，导致后面一大堆本来只需要几毫秒的短进程被迫排长队，系统平均等待时间飙升（就像高速公路上一辆慢吞吞的大货车压住了一排小轿车）。避免方法就是改用**抢占式调度**（如 RR 时间片轮转、SRTF）或限制单次最大执行时间。
- **追问 2：Linux 的 CFS（完全公平调度器）是怎么做到“完全公平”的？**
    - **参考答法**：CFS 抛弃了传统固定时间片的概念，而是给每个进程记录一个**虚拟运行时间（**`vruntime`**）**。谁的 `vruntime` 最小（说明之前享受到的 CPU 时间最少），谁就排在红黑树最左边，下次优先调度谁；权重越高的进程，`vruntime` 涨得越慢，从而自然分到更多 CPU 时间。

## 5. 🤖 和大模型/AI 开发有什么关系

- **训练集群 vs 推理集群的调度差异**：
    - **大模型离线训练（Training）就像批处理系统**，动辄跑几天几周，追求的是 GPU 利用率和吞吐量（类似 FCFS/队列配额 + 优先级抢占）；
    - **在线 AI 对话（Inference）就像交互式系统**，用户盯着屏幕等首字输出（TTFT），如果响应超过 2 秒就会流失，需要结合时间片/流式调度与优先级队列来保障用户体验。

## 6.1 云 API、托管推理与自部署怎么选【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 对工业安全图片问答，先确认图片和制度能否发送到目标环境，再用相同负载比较模型质量、请求成本、P95、可用性及运维代价；保密限制由实际业务规则决定。

### 概念与数据流

| 五要素 | 部署方案对比 |
| --- | --- |
| 输入 | 同一任务集和请求负载下的质量、成本、延迟、资源和数据授权条件。 |
| 做什么 | 对齐模型版本、输入输出长度与负载，核算固定与变动成本并检查硬约束。 |
| 输出 | 各方案的可比指标、限制和待验证项，由项目方作决策。 |
| 哪里出错 | 不同请求长度比较、漏算人力/空闲资源、拿报价当账单、忽略失败和数据权限。 |
| 参数影响 | 并发、流量波动、token 数、硬件利用率及 SLA 影响单次成本和延迟。 |

云 API 减少自建推理服务的工作量，但受外部服务、数据边界和计费方式影响；托管服务与自部署提供不同程度的运行控制，也带来不同的运维责任。不能仅凭单价判断最便宜。真实选型还需比较模型质量、数据处理约定、故障恢复和合同条件。

### 面试追问

【🔥 必会】如何选择 API 还是自部署？ 结论：先确认约束，再做同负载对比。看质量、数据授权、吞吐、P95、总成本与运维能力；流量、设备和模型版本变化后应重新评估。

【🔥 必会】自部署单次调用便宜但总成本高，怎么定位？ 结论：核对固定成本和利用率。按实际请求数分摊设备、运维、空闲与失败重试成本，再对齐 API 的 token 和网络费用。

【⭐ 理解】本地部署是否自动安全？ 结论：不自动安全。仍要管理访问、日志、数据存储与模型供应链；具体措施取决于实际系统。

### 故障模式与排障

- 方案成本比较失真：检查请求量、平均 token 数、计费单位及闲置成本；按同一负载重新计量并纳入运维。

- 测试延迟远低于线上：核对并发、输入输出长度、预热和排队；在接近真实负载下记录请求级数据与失败。

- 质量不一致：核对模型和 tokenizer 版本、推理参数、提示与数据；用同一任务集分析差异。

### 工程 trick 与坑

- 下例月成本是固定费用加请求数乘单次成本；它无法自动覆盖阶梯价格、token 波动、机器折旧、出网和人力，需将这些纳入实际输入或另行建模。

- approved 是外部审查状态的演示输入，代码不执行任何认证或数据授权。

- 生产自部署可评估 vLLM 或 NVIDIA TensorRT-LLM。以官方示例为入口：在兼容环境中，vLLM 用 vllm serve Qwen/Qwen2.5-1.5B-Instruct 启动模型服务；TensorRT-LLM 的快速入门在其容器内使用 trtllm-serve "TinyLlama/TinyLlama-1.1B-Chat-v1.0"。两者均提供兼容接口，实际模型、GPU、驱动、版本及 API 能力须按目标环境核对。参见 [vLLM 快速入门](https://docs.vllm.ai/en/latest/getting_started/quickstart/)和 [TensorRT-LLM 快速入门](https://nvidia.github.io/TensorRT-LLM/quick-start-guide.html)。

- **待补充：**当前机器未实际启动或压测上述两种服务；不能从命令推断吞吐、延迟、量化质量或模型兼容性。实际部署先用本地受控数据检查模型、端口与接口，再按第 6.4 节测负载。服务暴露前须配置网络与身份边界；vLLM 官方指出其 API key 并不覆盖所有端点，不能只靠它保护整个服务。

### Toy code：同负载下估算部署成本

运行前提：Python 3.10+，标准库。数字和授权标记均为虚构，不是任何供应商报价。

```python
"""按统一月请求量比较虚构部署方案；不自动选择供应商。"""
from dataclasses import dataclass
from math import isfinite


@dataclass(frozen=True)
class Deployment:
    """同一负载下的价格、运维成本、P95 和授权审查状态。"""
    name: str
    cost_per_request: float
    monthly_fixed_cost: float
    p95_seconds: float
    approved: bool


def compare(options: list[Deployment], monthly_requests: int) -> list[dict[str, object]]:
    """检查指标后估算月成本；隐性费用必须计入输入。"""
    if not options or isinstance(monthly_requests, bool) or not isinstance(monthly_requests, int) or monthly_requests < 0:
        raise ValueError('方案不能为空，请求量应为非负整数')
    seen: set[str] = set()
    result: list[dict[str, object]] = []
    for option in options:
        if not option.name.strip() or option.name in seen:
            raise ValueError('方案名称必须唯一且非空')
        seen.add(option.name)
        values = (option.cost_per_request, option.monthly_fixed_cost, option.p95_seconds)
        if not all(isfinite(value) and value >= 0 for value in values):
            raise ValueError('成本和延迟必须为非负有限数')
        if not isinstance(option.approved, bool):
            raise ValueError('授权审查状态必须是布尔值')
        total = option.monthly_fixed_cost + monthly_requests * option.cost_per_request
        result.append({'name': option.name, 'monthly_cost': total,
                       'p95_seconds': option.p95_seconds, 'approved': option.approved})
    assert len(result) == len(options)
    return result


def main() -> None:
    """覆盖有效方案、零请求和非法数值。"""
    options = [Deployment('托管示例', 0.02, 0.0, 1.3, True),
               Deployment('自部署示例', 0.001, 300.0, 0.9, False)]
    rows = compare(options, 10000)
    assert rows[0]['monthly_cost'] == 200.0 and rows[1]['monthly_cost'] == 310.0
    assert compare(options, 0)[1]['monthly_cost'] == 300.0
    bad_options = [Deployment('错误', float('nan'), 0, 1, True)]
    for candidates, count in (([], 1), (bad_options, 1), (options, -1)):
        try:
            compare(candidates, count)
        except ValueError:
            pass
        else:
            raise AssertionError('非法评估数据必须拒绝')
    print('虚构成本对比:', rows)
    print('价格、延迟和审查状态必须以实际合同和测量为准。')


if __name__ == '__main__':
    main()

```

逐段理解。 Deployment 记录方案输入；compare 校验负载和数值，再汇总固定及变动成本；自检覆盖零请求、无方案和非有限数。

### 这段代码怎么在面试里讲

- 不变量：请求数为非负整数，成本与 P95 是非负有限数，每个方案名称唯一。

- 关键过程：同一月请求量下按相同公式计算，再同时列出延迟和外部审查状态。

- 边界与坑：这是线性成本示例，真实账单、质量与授权不能由它自动推断；P95 必须来自同负载测量。

### 本节收尾：费曼自述与闪卡

费曼自述： 部署先看数据和业务约束，再按相同负载比较质量、总成本、延迟及运维；单价低不等于总成本低。

- 问：自部署成本只有 GPU 费用吗？答：不是，还要考虑闲置、运维、存储与其他开销。

- 问：对比 P95 时要固定什么？答：负载、并发、请求长度、模型和测量口径。

- 问：这个示例测了 vLLM 吗？答：没有，只给出官方文档入口。

- 问：代码里的授权状态从哪里来？答：只是外部传入的虚构标记，不是自动审查。

## 6.2 KV Cache：prefill、decode 与分页【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 同一序列先处理前缀，再逐 token 生成时复用历史 K/V；用全量因果注意力对照缓存结果，并解释它节省什么、占用什么、何时不能复用。

### 概念与数据流

| 五要素 | 单次自回归请求的 KV Cache |
| --- | --- |
| 输入 | 当前 token 的隐藏状态、当前层历史 K/V、位置与注意力掩码；prefill 输入完整前缀。 |
| 做什么 | prefill 批量计算前缀并保存 K/V；decode 计算新 token 的 Q/K/V，把新 K/V 追加后对历史做注意力。 |
| 输出 | 当前注意力输出和更新后的每层 K/V，供下一次 decode 使用。 |
| 哪里出错 | 缓存混用不同请求、位置或掩码错误、重复输入前缀、缓存超限、模型或适配器变化后错误复用。 |
| 参数影响 | 层数、并发、序列长度、KV 头数、头维度和 dtype 决定缓存占用；缓存策略影响读写和碎片。 |

对于各层形状相同的全上下文模型，粗略字节数为 2 * L * B * T * H_kv * D_head * 每元素字节数；2 对应 K 和 V。GQA/MQA 应使用 KV 头数而非查询头数。此式不含权重、激活、分配对齐、元数据和碎片；滑动窗口、不同层配置、并行切分和前缀共享会改变实际占用。

Prefill 常一次处理较长输入，decode 通常每步处理新 token；缓存避免反复计算历史 K/V，但仍需读取历史缓存并计算当前查询的注意力，因此不能保证延迟与上下文长度无关。PagedAttention 把 KV 按块管理并通过映射使用，可改善分配利用与共享；它不是把缓存占用变为零，也不是量化。Prefix Cache 可复用满足同一模型、适配器、token 前缀、位置与掩码等条件的前缀；具体共享边界按推理引擎实现验证。

### 面试追问

【🔥 必会】KV Cache 为什么能加速？ 结论：复用历史 token 已算出的 K/V。每个 decode 步只需计算新增 token 的投影，但当前查询仍要读取历史 K/V；小张量拼接和内存带宽可能成为瓶颈。

【🔥 必会】缓存解码与全量前向结果不一致怎么查？ 结论：先对齐位置、掩码和缓存归属。使用相同模型和 eval 模式，逐 token 比较 logits、缓存长度与输入，再检查 dtype、容差和库版本。

【🔥 必会】什么时候旧缓存不能继续使用？ 结论：依赖它的前缀计算发生变化时。更换模型权重或适配器、前缀 token、位置编码或相关掩码，都要按引擎规则重新计算；不同用户请求不能随意混用。

【⭐ 理解】分页和量化有什么区别？ 结论：分页管理块，量化改变数值表示。它们可能组合使用，但收益、误差和兼容性需分别测量。

### 故障模式与排障

- 缓存路径与全量输出不同：逐层/逐位置核对 token、位置、掩码、缓存长度和精度；关闭 dropout 后做小样本等价测试。

- 并发上升后显存不足：按请求长度、KV 头数和 dtype 粗算，再结合引擎的实际显存和排队监控；限制上下文/并发或使用支持的缓存策略。

- 跨请求内容串扰或答非所问：核对缓存所有权与复用键；隔离会话，只有满足安全和完全匹配条件时才共享前缀缓存。

### 工程 trick 与坑

- 示例只支持无 padding 的固定批次、单头、浮点张量和简单位置；没有 RoPE、GQA、分页、滑窗或跨请求缓存。

- 手写示例每步 torch.cat 会复制缓存，用于理解而非性能实现；是否加速需在目标模型、硬件、序列长度与并发下压测。

- Transformers 的缓存对象和位置处理随模型与版本变化，严格核对目标版本；真实请求需正确处理 padding、位置和会话隔离。

### Toy code 一：从零手写单头 KV Cache

运行前提：Python 3.10+、PyTorch；CPU 可运行。随机权重、无 padding，不加载模型。prefill 与 decode 只演示单层注意力。

```python
"""手写单头因果注意力 KV cache；只演示推理数据流，不实现 padding。"""
from dataclasses import dataclass
import math
import torch
from torch import Tensor


@dataclass(frozen=True)
class Cache:
    """缓存 K/V，形状均为 (B, cached_tokens, D)。"""
    key: Tensor
    value: Tensor


class CachedAttention:
    """单头无偏置注意力，权重固定；缓存只属于一次序列会话。"""
    def __init__(self, wq: Tensor, wk: Tensor, wv: Tensor, max_length: int) -> None:
        if wq.ndim != 2 or wq.shape[0] == 0 or wq.shape[0] != wq.shape[1]:
            raise ValueError('权重必须是非空方阵')
        if wk.shape != wq.shape or wv.shape != wq.shape:
            raise ValueError('Q/K/V 权重形状不一致')
        if not wq.is_floating_point() or any(t.dtype != wq.dtype or t.device != wq.device for t in (wk, wv)):
            raise ValueError('权重必须为同设备同 dtype 浮点张量')
        if max_length <= 0:
            raise ValueError('缓存上限必须为正')
        self.wq, self.wk, self.wv = wq, wk, wv
        self.dim, self.max_length = wq.shape[0], max_length

    def _validate(self, x: Tensor) -> None:
        """检查 (B,T,D) 非空输入、dtype 和有限值。"""
        if x.ndim != 3 or x.shape[0] == 0 or x.shape[1] == 0 or x.shape[2] != self.dim:
            raise ValueError('输入必须是非空 (B,T,D)')
        if x.device != self.wq.device or x.dtype != self.wq.dtype or not torch.isfinite(x).all():
            raise ValueError('输入的设备、dtype 或数值不合法')

    @torch.no_grad()
    def prefill(self, x: Tensor) -> tuple[Tensor, Cache]:
        """处理完整前缀，每个位置只能看到自身和过去。"""
        self._validate(x)
        batch, length, _ = x.shape
        if length > self.max_length:
            raise ValueError('前缀超过缓存上限')
        q, k, v = x @ self.wq, x @ self.wk, x @ self.wv
        scores = q @ k.transpose(-2, -1) / math.sqrt(self.dim)
        blocked = torch.ones(length, length, device=x.device, dtype=torch.bool).triu(1)
        weights = torch.softmax(scores.masked_fill(blocked, float('-inf')), dim=-1)
        output = weights @ v
        assert output.shape == (batch, length, self.dim)
        return output, Cache(k, v)

    @torch.no_grad()
    def decode(self, x: Tensor, cache: Cache) -> tuple[Tensor, Cache]:
        """追加一个 token；新的查询能看到全部已缓存 token 和自身。"""
        self._validate(x)
        if x.shape[1] != 1 or cache.key.ndim != 3 or cache.value.shape != cache.key.shape:
            raise ValueError('decode 输入须为一个 token，且 K/V 形状相同')
        if cache.key.shape[0] != x.shape[0] or cache.key.shape[2] != self.dim or cache.key.shape[1] == 0:
            raise ValueError('缓存与输入批次或维度不匹配')
        if any(t.device != x.device or t.dtype != x.dtype or not torch.isfinite(t).all()
               for t in (cache.key, cache.value)):
            raise ValueError('缓存设备、dtype 或数值不合法')
        if cache.key.shape[1] + 1 > self.max_length:
            raise ValueError('缓存超过上限，需要结束或采用另行设计的淘汰策略')
        q = x @ self.wq
        key = torch.cat((cache.key, x @ self.wk), dim=1)
        value = torch.cat((cache.value, x @ self.wv), dim=1)
        weights = torch.softmax((q @ key.transpose(-2, -1)) / math.sqrt(self.dim), dim=-1)
        output = weights @ value
        assert output.shape == x.shape and key.shape[1] == cache.key.shape[1] + 1
        return output, Cache(key, value)


def main() -> None:
    """检查全量与缓存解码一致、因果性和缓存边界。"""
    torch.manual_seed(13)
    dim = 8
    attn = CachedAttention(*(torch.randn(dim, dim) for _ in range(3)), max_length=5)
    x = torch.randn(2, 5, dim)
    full, _ = attn.prefill(x)
    first, cache = attn.prefill(x[:, :2])
    pieces = [first]
    for index in range(2, x.shape[1]):
        piece, cache = attn.decode(x[:, index:index + 1], cache)
        pieces.append(piece)
    cached = torch.cat(pieces, dim=1)
    assert torch.allclose(full, cached, atol=1e-5, rtol=1e-5)
    changed = x.clone(); changed[:, -1] += 50
    alternative, _ = attn.prefill(changed)
    assert torch.allclose(full[:, :-1], alternative[:, :-1], atol=1e-5)
    assert cache.key.numel() * cache.key.element_size() * 2 == 2 * 2 * 5 * dim * 4
    for bad_x, bad_cache in ((x[:, :2], cache), (x[:, :1], cache)):
        try:
            attn.decode(bad_x, bad_cache)
        except ValueError:
            pass
        else:
            raise AssertionError('错误形状或超长缓存必须拒绝')
    print('全量与 KV cache 解码一致；缓存字节:', cache.key.numel() * cache.key.element_size() * 2)


if __name__ == '__main__':
    main()

```

逐段理解。 prefill 用上三角 mask 禁止看未来并保存 K/V；decode 只投影新 token 并追加缓存；自检将拼接结果与全量前向比较，同时验证因果性、字节数及上限。

这段代码怎么在面试里讲： ① Q/K/V 均为 [B,T,D]，decode 输入为 [B,1,D]，K/V 随长度增长；② 前缀先做因果注意力，新 token 复用过去 K/V 后计算注意力；③ 说明缓存归属、位置/mask、显存公式和 cat 的性能局限。

排障： 结果不一致先查因果 mask 方向和输入切片；维度错误检查批次、长度与缓存形状；超限时拒绝或采用经验证的缓存管理策略。

### Toy code 二：Transformers 缓存对照

运行前提：Python 3.11、PyTorch、transformers==4.57.1；CPU 可运行。随机 GPT-2 只验证接口和数值一致性，不下载模型，也不评估生成质量。

```python
"""用 Transformers 随机 GPT-2 验证全量前向与 KV cache 解码等价。"""
import torch
from torch import Tensor
from transformers import GPT2Config, GPT2LMHeadModel


def validate_ids(ids: Tensor, vocab: int, max_len: int, prefix: int) -> None:
    """只处理无 padding 的二维 token 批次。"""
    if ids.ndim != 2 or ids.dtype != torch.long or ids.shape[0] == 0:
        raise ValueError('token 必须是非空二维 long 张量')
    if not 1 <= prefix < ids.shape[1] <= max_len:
        raise ValueError('前缀或序列长度非法')
    if int(ids.min()) < 0 or int(ids.max()) >= vocab:
        raise ValueError('token 超出词表')


def cache_length(cache: object) -> int:
    """兼容本示例使用的缓存对象或旧版 tuple 结构。"""
    if hasattr(cache, 'get_seq_length'):
        return int(cache.get_seq_length())
    if isinstance(cache, tuple) and cache:
        return int(cache[0][0].shape[-2])
    raise TypeError('未知缓存结构，请核对当前 Transformers 版本')


@torch.no_grad()
def compare(model: GPT2LMHeadModel, ids: Tensor, prefix: int) -> tuple[Tensor, Tensor]:
    """先 prefill，再逐 token decode；输出两种方式的 logits。"""
    validate_ids(ids, model.config.vocab_size, model.config.n_positions, prefix)
    model.eval()
    full = model(input_ids=ids, attention_mask=torch.ones_like(ids), use_cache=False).logits
    start = model(input_ids=ids[:, :prefix], attention_mask=torch.ones_like(ids[:, :prefix]), use_cache=True)
    if start.past_key_values is None:
        raise RuntimeError('模型未返回缓存')
    cache = start.past_key_values
    assert cache_length(cache) == prefix
    parts = [start.logits]
    for pos in range(prefix, ids.shape[1]):
        result = model(input_ids=ids[:, pos:pos + 1], past_key_values=cache,
                       attention_mask=torch.ones_like(ids[:, :pos + 1]), use_cache=True)
        if result.past_key_values is None:
            raise RuntimeError('decode 未返回缓存')
        cache = result.past_key_values
        assert cache_length(cache) == pos + 1
        parts.append(result.logits)
    cached = torch.cat(parts, dim=1)
    assert full.shape == cached.shape == (*ids.shape, model.config.vocab_size)
    return full, cached


def main() -> None:
    """验证分段输出相等和非法输入；随机模型不用于效果评估。"""
    torch.manual_seed(17)
    cfg = GPT2Config(vocab_size=32, n_positions=16, n_ctx=16, n_embd=16, n_layer=2, n_head=2)
    model = GPT2LMHeadModel(cfg)
    ids = torch.tensor([[1, 5, 3, 7, 2], [1, 8, 6, 4, 2]], dtype=torch.long)
    full, cached = compare(model, ids, prefix=3)
    assert torch.allclose(full, cached, atol=2e-5, rtol=2e-5)
    for bad, prefix in ((torch.tensor([[32, 1]]), 1), (ids, 0), (ids, 5)):
        try:
            validate_ids(bad, cfg.vocab_size, cfg.n_positions, prefix)
        except ValueError:
            pass
        else:
            raise AssertionError('非法 token 或前缀必须拒绝')
    print('Transformers 全量与缓存解码一致；随机权重未验证任务效果。')


if __name__ == '__main__':
    main()

```

逐段理解。 先全量前向，再对相同输入做 prefill 和逐 token decode；每一步检查缓存长度并传递覆盖历史与当前 token 的 attention mask，最后比较各位置 logits。

这段代码怎么在面试里讲： ① 输入 token 为 [B,T]，两条路径 logits 都是 [B,T,V]；② 库维护各层缓存，调用方只输入新增 token 并传回正确 cache 和 mask；③ eval、位置、批次/padding 与缓存对象生命周期必须一致，随机模型不能证明性能或效果。

排障： 缓存长度异常检查是否重复送入前缀；logits 不一致核对 mask/位置及模型模式；API 异常检查 Transformers 与模型版本。

手写与调库怎么选。 手写单层帮助理解数据流和因果约束；实际推理用成熟模型和服务框架维护多层 cache、调度及显存。vLLM 的分页管理以[官方文档](https://docs.vllm.ai/en/latest/design/paged_attention/)和目标版本实测为准，本节没有运行 vLLM。

### 本节收尾：费曼自述与闪卡

费曼自述： prefill 算并保存前缀 K/V，decode 只追加新 token 的 K/V，却仍要读取历史做注意力。缓存省重复计算，代价是随长度和并发增长的显存。

- 问：缓存显存粗算的头数用哪个？答：用 KV 头数，并考虑层数、批次、长度、头维度与 dtype。

- 问：缓存让长上下文注意力计算消失吗？答：不会，当前查询仍需访问允许范围内的历史 K/V。

- 问：模型或适配器变了能直接复用旧缓存吗？答：通常不能，应按引擎规则重新计算。

- 问：分页等于 KV 量化吗？答：不等于；前者管理存储块，后者改变数值表示。

- 问：本节 torch.cat 示例能证明生产加速吗？答：不能，必须在真实模型与负载下压测。

## 6.3 量化：权重、激活和 KV Cache【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 如果模型显存或内存不足，可以评估权重、激活或 KV Cache 量化；同样标为 INT4 的方案可能采用不同量化和计算方式，质量、设备支持与速度都需验证。

### 概念与数据流

| 五要素 | 推理量化 |
| --- | --- |
| 输入 | 浮点权重、运行输入、量化配置；某些方法需要代表性的校准数据。 |
| 做什么 | 将目标数值映射到低精度表示，推理时按实现执行低精度运算或还原。 |
| 输出 | 量化模型或缓存，以及相对于浮点基线可能存在偏差的输出。 |
| 哪里出错 | 校准分布不匹配、离群值和精度损失、模型/硬件不支持、误以为显存下降必然更快。 |
| 参数影响 | 位宽、分组、缩放、校准数据和计算 dtype 影响精度、体积与性能。 |

权重量化主要影响权重存储；激活量化影响中间计算；KV Cache 量化影响缓存表示，它们可以分别启用。GPTQ 是利用近似二阶信息的训练后权重量化方法；AWQ 利用激活信息识别敏感权重并设计缩放策略。它们是不同方法，而不是 INT4 的同义词；具体实现、校准与硬件支持要核对版本。

### 面试追问

【🔥 必会】INT4 一定比 INT8 更快吗？ 结论：不一定。性能取决于硬件内核、量化布局、反量化开销、批次和瓶颈；必须测端到端延迟、吞吐和质量。

【🔥 必会】量化后回答明显退化怎么查？ 结论：先固定基线并定位受影响场景。核对权重格式、校准分布和计算精度，在相同任务集按场景评估，再调整配置或回退精度。

【⭐ 理解】权重量化和 KV Cache 量化有何不同？ 结论：作用对象不同。前者压缩模型权重，后者压缩推理时历史 K/V；长上下文和高并发时缓存也可能成为主要占用。

### 故障模式与排障

- 量化模型无法加载或算子报错：检查模型格式、算子、设备与库版本；使用受支持的组合并保留浮点基线。

- 数值误差或任务质量下降：固定数据比对输出与任务指标，检查校准样本和量化粒度；调整配置或回退精度。

- 内存下降但速度更慢：分离加载、prefill 和 decode，检查硬件支持与反量化开销；在真实负载下压测，不只测单个矩阵。

### 工程 trick 与坑

- 下例只在 CPU 上演示 PyTorch 动态 INT8 线性层，测试环境为 torch==2.5.1；不等于 GPTQ、AWQ、INT4 或 KV Cache 量化。

- 随机网络的误差阈值仅用于本例回归；真实模型需在独立任务集上检查质量，且不能用小网络结果推断速度。

- 不同库对量化算子和硬件的支持随版本变化，升级前先运行小规模兼容测试。

### Toy code：CPU 动态 INT8 对照

运行前提：Python 3.10+、CPU 版或带 CPU 支持的 PyTorch；本次验证 torch==2.5.1。示例不读取模型权重或真实数据。

```python
"""比较 CPU 上浮点小网络与 PyTorch 动态 INT8 量化输出。"""
from copy import deepcopy
import torch
from torch import Tensor, nn
from torch.ao.quantization import quantize_dynamic


def validate(x: Tensor, features: int) -> None:
    """只接受非空、有限、CPU float32 的二维输入。"""
    if x.ndim != 2 or x.shape[0] == 0 or x.shape[1] != features:
        raise ValueError('输入必须为非空 (B, features)')
    if x.device.type != 'cpu' or x.dtype != torch.float32 or not torch.isfinite(x).all():
        raise ValueError('动态量化示例要求有限的 CPU float32 输入')


def make_model() -> nn.Sequential:
    """创建用于对比的随机双层网络。"""
    return nn.Sequential(nn.Linear(8, 16), nn.ReLU(), nn.Linear(16, 4)).eval()


@torch.no_grad()
def evaluate(model: nn.Module, quantized: nn.Module, x: Tensor) -> tuple[Tensor, Tensor, float]:
    """返回浮点输出、量化输出与最大绝对误差。"""
    validate(x, 8)
    reference, actual = model(x), quantized(x)
    if reference.shape != actual.shape or not torch.isfinite(actual).all():
        raise RuntimeError('量化输出形状或数值异常')
    error = float((reference - actual).abs().max())
    assert reference.shape == (x.shape[0], 4)
    return reference, actual, error


def main() -> None:
    """验证动态量化层、数值误差及输入边界。"""
    torch.manual_seed(23)
    model = make_model()
    quantized = quantize_dynamic(deepcopy(model), {nn.Linear}, dtype=torch.qint8)
    assert isinstance(quantized[0], torch.ao.nn.quantized.dynamic.Linear)
    assert isinstance(model[0], nn.Linear)
    x = torch.randn(4, 8)
    original, converted, max_error = evaluate(model, quantized, x)
    mse = float((original - converted).square().mean())
    assert max_error < 0.1 and mse < 0.01  # 仅为此固定随机样例的回归阈值
    for bad in (torch.empty(0, 8), torch.randn(2, 7), torch.full((1, 8), float('nan'))):
        try:
            validate(bad, 8)
        except ValueError:
            pass
        else:
            raise AssertionError('错误输入必须拒绝')
    print(f'CPU 动态 INT8 对照通过: max_error={max_error:.6f}, mse={mse:.6f}')
    print('随机小网络不代表模型质量、吞吐、显存或其他硬件效果。')


if __name__ == '__main__':
    main()

```

逐段理解。 先建立浮点随机网络并复制，再由 quantize_dynamic 转换指定线性层；比较相同输入的输出与误差；自检检查量化层类型、原网络未被替换和非法输入。

### 这段代码怎么在面试里讲

- 不变量：输入是有限的 CPU float32 [B,8]，浮点与量化网络输出均为 [B,4]。

- 关键过程：动态量化线性层，使用相同输入计算最大误差和均方误差，并用固定随机种子做回归。

- 边界与坑：误差阈值只针对本随机样例，不能证明真实模型质量或速度；本例也不覆盖 INT4、GPU 和 KV 量化。

### 本节收尾：费曼自述与闪卡

费曼自述： 量化降低某些数值的表示精度，可能节省内存，也可能带来误差或额外开销；应分别确认对象、硬件支持和真实任务表现。

- 问：INT4 一定比 INT8 快吗？答：不一定，要测目标硬件和真实负载。

- 问：GPTQ 和 AWQ 是什么？答：不同的训练后权重量化方法，具体实现与校准不同。

- 问：权重量化是否自动量化 KV Cache？答：不一定，两者是不同对象。

- 问：随机小网络误差低能否证明业务效果？答：不能，必须评估真实模型和任务。

## 6.4 推理压测：吞吐、P95 与失败率【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 比较服务版本时，构造接近真实的输入长度、输出长度和并发分布，逐请求记录总延迟、首 token 时间与失败；吞吐高但失败率或尾延迟超标，仍不能算满足目标。

### 概念与数据流

| 五要素 | 请求级压测统计 |
| --- | --- |
| 输入 | 每个请求的状态、耗时、首 token 时间、输出 token 数，以及实际测试墙钟时长。 |
| 做什么 | 对齐统计口径，计算成功请求的延迟分位数和吞吐，并将失败纳入失败率。 |
| 输出 | 请求量、成功数、失败率、成功请求 P95、TTFT、TPOT 和输出 token 吞吐。 |
| 哪里出错 | 只统计成功隐藏失败、平均各批 P95、墙钟时长不一致、单 token 计算 TPOT 除零。 |
| 参数影响 | 并发、到达速率、输入输出长度、预热和硬件资源会改变延迟与吞吐。 |

TTFT 通常表示从请求开始到首 token 返回的时间；TPOT 的具体口径应写清。下例以每个成功请求 (总耗时 - TTFT)/(输出 token 数 - 1) 计算，再对有至少两个 token 的请求取均值；这不等于所有 token 间隔的全局均值。P95 采用 nearest-rank，其他系统可能采用插值，应核对定义。

### 面试追问

【🔥 必会】吞吐更高为什么还不能上线？ 结论：还要看尾延迟、失败和业务目标。并发增加可能推高排队和超时；同负载下同时看成功率、P95、首 token 和资源占用。

【🔥 必会】线上 P95 突然升高怎么查？ 结论：按请求阶段和负载定位。检查并发与排队、输入输出长度、prefill/decode、缓存命中、资源利用和失败；与同条件基线对照。

【⭐ 理解】能把不同批次 P95 再平均吗？ 结论：不能得到整体 P95。应汇总请求级数据或使用支持合并的分位数统计结构，再按统一口径计算。

### 故障模式与排障

- P95 看起来下降但超时更多：同时查看失败率及失败请求耗时；不要只报告成功请求分位数而隐藏失败。

- 吞吐计算偏高：核对实际墙钟时长和 token 计数是否包含重试、失败和预热；声明统计窗口与分母。

- TPOT 异常或除零：检查输出 token 数、首 token 与总时长；单 token 没有后续 token 间隔，应标记不可计算。

### 工程 trick 与坑

- 下例只统计成功请求的 P95、吞吐及输出 token；失败全部进入失败率，且简化为失败没有部分输出。真实服务可能先输出部分 token 再失败，应另记。

- 三条虚构记录只是验证计算边界，不能代表真实 P95、容量或统计稳定性。

- 完整的 golden set、回归和发布门禁见[系统设计与评测](横切-系统设计与评测.md)专题。

### Toy code：请求级指标统计

运行前提：Python 3.10+，标准库；不发起真实网络请求，也不执行实际压测。

```python
"""汇总虚构请求级压测数据；P95 使用 nearest-rank 定义。"""
from dataclasses import dataclass
import math
from statistics import mean


@dataclass(frozen=True)
class Request:
    """一次请求的状态、总时长、首 token 时长和成功输出 token 数。"""
    request_id: str
    success: bool
    duration_s: float
    ttft_s: float | None
    output_tokens: int


def p95(values: list[float]) -> float | None:
    """nearest-rank P95；空列表没有分位数。"""
    if not values:
        return None
    return sorted(values)[math.ceil(0.95 * len(values)) - 1]


def summarize(requests: list[Request], wall_seconds: float) -> dict[str, float | int | None]:
    """失败进入失败率分母，延迟只统计成功请求并明确其口径。"""
    if not requests or not math.isfinite(wall_seconds) or wall_seconds <= 0:
        raise ValueError('请求不能为空，测试总时长须为正有限数')
    ids: set[str] = set()
    for request in requests:
        if not request.request_id.strip() or request.request_id in ids:
            raise ValueError('请求 ID 必须唯一且非空')
        ids.add(request.request_id)
        if not isinstance(request.success, bool) or not math.isfinite(request.duration_s) or request.duration_s < 0:
            raise ValueError('状态或总时长非法')
        if isinstance(request.output_tokens, bool) or not isinstance(request.output_tokens, int) or request.output_tokens < 0:
            raise ValueError('输出 token 数必须是非负整数')
        if request.success:
            if request.ttft_s is None or not math.isfinite(request.ttft_s) or not 0 <= request.ttft_s <= request.duration_s or request.output_tokens < 1:
                raise ValueError('成功请求需要有效 TTFT 和至少一个输出 token')
        elif request.ttft_s is not None or request.output_tokens != 0:
            raise ValueError('本简化示例的失败请求不记录部分输出')
    success = [r for r in requests if r.success]
    tpots = [(r.duration_s - r.ttft_s) / (r.output_tokens - 1)
             for r in success if r.output_tokens > 1 and r.ttft_s is not None]
    result: dict[str, float | int | None] = {
        'requests': len(requests), 'successes': len(success),
        'failure_rate': (len(requests) - len(success)) / len(requests),
        'success_latency_p95_s': p95([r.duration_s for r in success]),
        'success_ttft_p95_s': p95([r.ttft_s for r in success if r.ttft_s is not None]),
        'mean_request_tpot_s': mean(tpots) if tpots else None,
        'successful_requests_per_s': len(success) / wall_seconds,
        'successful_output_tokens_per_s': sum(r.output_tokens for r in success) / wall_seconds,
    }
    assert 0 <= float(result['failure_rate']) <= 1
    return result


def main() -> None:
    """验证失败分母、单 token TPOT、无成功请求和非法输入。"""
    data = [Request('a', True, 2.0, 0.5, 4), Request('b', True, 1.0, 0.4, 1),
            Request('c', False, 3.0, None, 0)]
    report = summarize(data, 4.0)
    assert report['failure_rate'] == 1 / 3 and report['success_latency_p95_s'] == 2.0
    assert report['mean_request_tpot_s'] == 0.5
    assert summarize([data[2]], 3.0)['success_latency_p95_s'] is None
    for bad, wall in (([], 1.0), (data, 0.0), ([Request('x', True, 1, 2, 3)], 1.0)):
        try:
            summarize(bad, wall)
        except ValueError:
            pass
        else:
            raise AssertionError('非法压测数据必须拒绝')
    print('虚构请求级统计自检通过:', report)
    print('少量样本不能代表真实 P95 或服务容量。')


if __name__ == '__main__':
    main()

```

逐段理解。 Request 保存请求级输入；p95 实现 nearest-rank；summarize 校验时长和输出 token 后，分别按全部请求及成功请求计算指标；自检覆盖失败和单 token。

### 这段代码怎么在面试里讲

- 不变量：请求 ID 唯一，成功请求有非负 TTFT 且不超过总时长；失败率以所有请求为分母。

- 关键过程：从成功请求计算分位数和 TPOT，用实际测试墙钟时长计算成功吞吐；没有样本的指标返回 None。

- 边界与坑：失败可能有部分输出，本例未覆盖；分位数算法、预热窗口、token 统计和负载分布都要明确。

### 本节收尾：费曼自述与闪卡

费曼自述： 推理压测按请求记录成功、延迟和 token，再用实际墙钟时间计算吞吐；只看成功请求的 P95 会掩盖超时，必须同时报告失败率。

- 问：平均各批 P95 等于整体 P95 吗？答：不等于，应汇总请求级数据后计算。

- 问：单 token 请求能算本例 TPOT 吗？答：不能，因为没有后续 token 间隔。

- 问：成功 P95 下降就一定变好了吗？答：不一定，还要看失败率和负载。

- 问：三次请求能可靠估计 P95 吗？答：不能，需要足够且具有代表性的样本。

## 10.1 先问任务，再看模型名称【🔥】

给模型分类至少看六个维度：**输入模态、输出形式、核心架构、训练阶段、部署方式、使用许可**。同名系列的 base、instruct、vision 版本可能面向不同任务；参数量也不直接等于你的业务效果。

| 问题 | 要确认什么 | 例子 |
|---|---|---|
| 输入是什么？ | 纯文本、图片、视频、音频、混合 | 图文问答需视觉输入 |
| 输出是什么？ | 文本、结构化字段、向量、框/区域 | 检索要向量，检测要位置 |
| 用来做什么？ | 生成、编码、重排、分类 | RAG 常有多种模型 |
| 能怎么部署？ | API、自己托管、离线 | 数据边界和延迟不同 |
| 资源约束？ | 显存、并发、上下文长度、费用 | 图片数量影响视觉计算 |
| 能否商用？ | 权重/数据/服务许可 | 使用前查模型卡和协议 |

**例子。** “给 5 万份政策做问答”不该只选一个聊天模型：还要考虑文档解析、Embedding/关键词检索、可选 Reranker 和生成模型。若答案要附页码，检索系统要存来源元数据。

**费曼自述：** “选模型先问输入、输出、数据、延迟和许可；排行榜高分不能替代我自己的测试集。”

**概念闪卡：** Q：参数量大就一定适合业务吗？A：不一定，还要看任务质量、成本、延迟和许可。Q：模型卡至少核对什么？A：能力、输入限制、部署方法、许可和已知局限。

## 10.2 Encoder、Decoder、Encoder-Decoder【🔥】

**Encoder 型**模型通常让每个位置利用输入的双向上下文，常用于表示学习、分类和检索编码。**自回归 Decoder 型**模型在训练/生成时按因果约束预测下一 token，适合开放式文本生成。**Encoder-Decoder 型**先编码输入，再让 Decoder 基于编码结果生成，常见于条件生成任务。这里是典型用法，不是所有模型或任务的硬边界；具体仍看 Mask 和训练目标。

~~~text
分类：输入句子 → 编码器 → 类别
生成：前文 token → 因果 Decoder → 下一个 token
翻译：源句 → Encoder → 条件 Decoder → 目标句
~~~

**面试追问。** “为什么 Decoder 训练时不能看到未来 token？”因为若当前位置看到了目标答案，训练损失会变得虚假地容易；推理时没有未来答案可看，训练与实际生成不一致。Mask 在 Softmax 前屏蔽不可见位置。

**费曼自述：** “区别要从每个位置能看哪些内容、输出目标是什么来讲，不靠模型名字猜内部结构。”

**概念闪卡：** Q：典型双向 Encoder 的优势？A：利用完整输入形成表示。Q：自回归 Decoder 为什么有因果 Mask？A：防止利用未来 token 作弊。

## 10.3 Dense 与 MoE【⭐】

**Dense** 模型一次前向通常会激活每层的主要参数；**Mixture of Experts（MoE）** 在部分层用路由机制为 token 选择若干专家，以增加总参数容量而控制每个 token 的活跃计算。MoE 的实际性能还受路由、通信、专家负载和部署实现影响，不能只比较“总参数”。

[Qwen3 技术报告](https://arxiv.org/abs/2505.09388)给出同一系列包含 Dense 与 MoE 模型的实例。读模型报告时应区分 **总参数、活跃参数、推理显存、吞吐和质量**；“活跃参数少”不表示整个模型权重就不需存放或加载。

**例子。** 两个模型在你 50 道政策题上均答对 45 道，但一个需要更高显存和更复杂的多卡路由，另一个单卡可运行。对于低并发内部系统，后者可能更合适；高吞吐服务要进一步压测。

**面试追问。** “MoE 一定比 Dense 便宜吗？”回答要分训练、推理、硬件通信和负载规模。相同 benchmark 分数不代表相同的真实部署成本。

**费曼自述：** “MoE 让不同 token 选择部分专家参与计算；我评估它时看活跃计算、权重占用、通信和任务指标，而不只看总参数。”

**概念闪卡：** Q：总参数与活跃参数差在哪？A：前者是模型全部权重规模，后者是一次 token 处理实际用到的部分。Q：为何要测实际吞吐？A：路由和通信成本会影响真实速度。

## 10.4 生成模型、Embedding 与 Reranker 不是一回事【🔥】

**生成模型**根据上下文产出文本；**Embedding 模型**把文本/图像编码成可比较的向量；**Reranker**对“问题—候选证据”对重新打分排序。它们可能共享基础 Transformer 思想，但训练目标和输出不同。

~~~text
用户问题
  → Embedding/BM25 找候选
  → Reranker 重排候选
  → 生成模型依据证据回答并引用
~~~

**例子。** 用户问“安全帽处罚条款第 17 条”，Embedding 可能找到语义相近的“头部防护用品”；BM25 对精确“第 17 条”更有优势；Reranker 只能重排已召回的候选；生成模型把最终证据组织成回答。若正确条款从没进入候选，单换更大的生成模型不一定能解决问题。

**费曼自述：** “RAG 是多模型/多组件系统。我能说出每个模型的输入、输出、错误类型，以及谁不能补救谁的错误。”

**概念闪卡：** Q：Reranker 能找回没被召回的文档吗？A：不能。Q：Embedding 模型会直接生成用户答案吗？A：通常不负责生成答案，它负责表示和召回。

## 10.5 VLM：视觉编码、对齐与多模态生成【🔥】

一类常见 VLM 用视觉编码器提取图片特征，经连接模块传给 LLM。LLaVA 的[视觉指令微调论文](https://arxiv.org/abs/2304.08485)是理解“视觉编码器 + 投影 + 语言模型”的入口。后续模型还会改进多分辨率、多图、视频帧、长上下文与训练数据；[Qwen3-VL 技术报告](https://arxiv.org/abs/2511.21631)是一个图像、视频与长上下文结合的实例。别把某一家架构当成全部 VLM 的固定模板。

**选型问题。**
1. 只需物体类别，还是要开放式推理和问答？如果只需稳定类别/框，专门检测模型可能更易评估。
2. 要读小字、表格、长文档吗？检查分辨率策略、OCR/文档测试，而不只看自然图片示例。
3. 输入是单图、多图还是视频？检查模型实际支持的格式、采样和上下文成本。
4. 输出需要框、时间戳或引用吗？自然语言描述不足以替代可核对的空间/时间证据。

**费曼自述：** “VLM 把视觉表示带入语言生成链路。我用目标任务的数据验证它是否真正看见了需要的细节。”

**概念闪卡：** Q：VLM 能回答图片问题就一定能精确检测吗？A：不一定，要测框/区域准确率。Q：视频比单图多了什么难点？A：抽帧、时间顺序、视觉 token 和事件定位。

## 10.6 API、开源权重与本地服务怎样取舍【⭐】

**托管 API** 适合快速基线和少运维；**可自托管权重** 有助于数据边界、定制微调和成本可控，但需处理模型加载、显存、并发、量化、升级与监控。两类都要检查服务条款与数据使用方式；开源代码、可下载权重、可商用许可是不同的概念。

**比较表应自己实测：**

| 候选 | 任务成功率 | P95 延迟 | 每千次成本 | 数据边界 | 部署复杂度 |
|---|---:|---:|---:|---|---|
| 托管模型 A | 待测 | 待测 | 待算 | 查协议 | 低 |
| 自托管模型 B | 待测 | 待测 | GPU/运维估算 | 本地 | 高 |

**例子。** 在可公开的图文问答项目里，先用 API 测业务上限，再用可自托管模型做成本/数据边界对比。不能因为某模型的公开榜单高，就说它在你的工业图片、中文小字和时限要求下最好。

**费曼自述：** “模型选型不是选一个名字，而是在同一测试集、同一负载与同一约束下比较质量和代价。”

**概念闪卡：** Q：可下载权重等于可任意商用吗？A：不等于，查具体许可。Q：为什么要同一评估集？A：否则模型结果不可公平比较。

## 10.7 面试里的模型选型题怎么答【🔥】

面试官问“你为什么选这个模型”，可以按六步回答：
1. 任务：输入、输出、数据、错误代价。
2. 候选：至少一个简单基线和一个较强候选。
3. 测试集：公开/内部合规样本，切分规则与关键子集。
4. 指标：正确率/召回、引用、格式、P95、吞吐、费用。
5. 结果：真实数值与失败样例，说明改动前后。
6. 决策：收益是否值得增加的成本和运维复杂度。

**练习题。** “公司要做中文长合同问答，选长上下文模型还是 RAG？”先在少量文档上做直接塞上下文的基线，再用相同问题集测检索链路；比较证据命中、回答正确性、引用、延迟和成本。合同更新、权限隔离和文档量会影响选择。不要预设某一方案永远赢。

**代码/表格要记住什么？** 不需要背最新模型排行榜。要能写测试样本的输入/输出记录、简单正确率统计、P95 延迟统计，以及错误分析表；模型版本、prompt、处理器和推理参数都应一起记录。

**费曼自述：** “我能把模型选择从‘听说它强’转成明确的任务、候选、基线、测试和取舍。”

**概念闪卡：** Q：为什么选型要报失败样例？A：总分可能掩盖业务关键错误。Q：什么时候该换模型？A：当前方案在明确任务和约束下达不到目标，且别的候选经同条件测试更合适。

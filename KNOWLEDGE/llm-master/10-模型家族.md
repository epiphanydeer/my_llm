## 10.1 模型选型：先确认任务与能力边界【🔥 必会】

### 为什么要关注这个问题

给模型分类至少看六个维度：**输入模态、输出形式、核心架构、训练阶段、部署方式、使用许可**。同名系列的 base、instruct、vision 版本可能面向不同任务；参数量也不直接等于你的业务效果。

〔本次新补，参考当前面试趋势〕

目标 + 例子。 安全图片问答至少需要处理图片和文本并输出文本；先筛查模型接口和限制，再用同一数据集比较准确性、延迟、成本与部署条件。

### 概念与数据流

| 五要素 | 候选模型初筛 |
| --- | --- |
| 输入 | 任务需要的输入模态、输出类型、上下文容量与模型元数据。 |
| 做什么 | 对照已知能力，区分满足、不满足和信息未知。 |
| 输出 | 每个候选的初筛状态，后续仍需质量与部署评测。 |
| 哪里出错 | 模型版本混淆、信息过期、未知能力误判为支持、只看参数量或榜单。 |
| 参数影响 | 输入模态、上下文、输出要求和资源约束决定哪些候选值得进一步测试。 |

选型先确认任务、数据、输入输出、质量目标、延迟与预算，再看模型卡、部署方式与适用许可。元数据的“支持”不代表目标任务做得好；图片小目标、文档长上下文和安全性都需要独立评测。涉及公司数据时应核对实际处理规则与授权。

### 面试追问

【🔥 必会】怎样为图片问答选模型？ 结论：先筛输入输出和数据约束，再做同条件评测。覆盖小目标、遮挡和幻觉，同时比较延迟、成本及部署能力。

【🔥 必会】模型榜单高但业务效果差怎么查？ 结论：先看任务和数据分布差异。检查预处理、图像尺寸、提示、评测口径和失败切片，再与目标场景基线比较。

【⭐ 理解】模型资料缺少上下文上限怎么办？ 结论：标记未知并核实。不能把未知直接当作支持或不支持；查目标版本文档并做兼容测试。

### 故障模式与排障

- 模型不能处理目标输入：检查模型卡与实际接口，区分 text 与 vision 变体；用最小请求验证。

- 输出格式或上下文不满足：核对版本与配置，记录限制；按需求选择其他候选或调整流程。

- 初筛通过但质量差：查看任务切片与数据预处理；使用独立标注集测质量，不用参数量代替评估。

### 工程 trick 与坑

- 本例只检查虚构的输入、输出和上下文字段，不判断质量、速度、价格或许可。

- 未知字段标记为 unknown，但已知硬约束不满足时仍为 fail。

- 真实模型的能力、版本及许可会变化，使用前核对官方资料和目标部署环境。

### Toy code：模型元数据初筛

运行前提：Python 3.10+，标准库；模型名称与能力均为虚构。

```python
"""按任务输入输出筛查虚构模型元数据；不评估模型质量。"""
from dataclasses import dataclass


@dataclass(frozen=True)
class ModelInfo:
    """模型名、输入模态、输出类型和上下文上限；None 表示未知。"""
    name: str
    input_modes: frozenset[str] | None
    output_kind: str | None
    context_tokens: int | None


def screen(models: list[ModelInfo], required_inputs: frozenset[str],
           required_output: str, min_context: int) -> dict[str, str]:
    """给出 pass/fail/unknown；未知信息不当作能力不支持。"""
    if not isinstance(required_inputs, frozenset) or not required_inputs or any(not isinstance(v, str) or not v.strip() for v in required_inputs):
        raise ValueError('输入模态必须是非空字符串集合')
    if isinstance(min_context, bool) or not isinstance(min_context, int):
        raise ValueError('上下文要求必须是整数')
    if not models or not isinstance(required_output, str) or not required_output.strip() or min_context <= 0:
        raise ValueError('模型、需求或上下文要求非法')
    result: dict[str, str] = {}
    for model in models:
        if not model.name.strip() or model.name in result:
            raise ValueError('模型名必须非空且唯一')
        if model.context_tokens is not None and (isinstance(model.context_tokens, bool) or
                not isinstance(model.context_tokens, int) or model.context_tokens <= 0):
            raise ValueError('上下文容量必须是正整数或未知')
        if model.input_modes is not None and (not model.input_modes or any(not item.strip() for item in model.input_modes)):
            raise ValueError('已知输入模态不能为空')
        if model.output_kind is not None and not model.output_kind.strip():
            raise ValueError('输出类型不能是空白字符串')
        failed = (model.input_modes is not None and not required_inputs <= model.input_modes or
                  model.output_kind is not None and model.output_kind != required_output or
                  model.context_tokens is not None and model.context_tokens < min_context)
        unknown = model.input_modes is None or model.output_kind is None or model.context_tokens is None
        result[model.name] = 'fail' if failed else 'unknown' if unknown else 'pass'
    assert len(result) == len(models)
    return result


def main() -> None:
    """检查满足、不满足、信息未知和重复模型名。"""
    models = [ModelInfo('A', frozenset({'text', 'image'}), 'text', 4096),
              ModelInfo('B', frozenset({'text'}), 'text', 8192),
              ModelInfo('C', None, 'text', None)]
    report = screen(models, frozenset({'text', 'image'}), 'text', 2048)
    assert report == {'A': 'pass', 'B': 'fail', 'C': 'unknown'}
    try:
        screen(models + models[:1], frozenset({'text'}), 'text', 10)
    except ValueError:
        pass
    else:
        raise AssertionError('重复模型名必须拒绝')
    print('虚构能力元数据筛查自检通过:', report)
    print('此结果不代表质量、价格、许可或实际部署可用性。')


if __name__ == '__main__':
    main()

```

逐段理解。 ModelInfo 保存能力元数据；screen 根据需求返回通过、不通过或未知；自检覆盖三种状态与重复名称。

### 这段代码怎么在面试里讲

- 不变量：模型名唯一，已知上下文容量为正；未知信息不能当作已验证支持。

- 关键过程：先判断已知硬约束是否失败，再区分信息完整和未知。

- 边界与坑：初筛不评估模型质量、费用、许可或部署可行性；真实资料可能变化。

### 本节收尾：费曼自述与闪卡

费曼自述： 先明确任务与约束，再核对模型输入输出和上下文；初筛后仍需用目标数据比较质量和成本。

- 问：模型支持图片就一定适合小目标吗？答：不一定，需要针对小目标评测。

- 问：上下文容量未知怎么办？答：标记未知并核对目标版本资料。

- 问：参数量大就一定适合业务吗？答：不一定，还要看任务质量和资源。

- 问：本例是否检查许可和价格？答：没有，需在真实选型时另行核对。

## 10.2 Encoder、Decoder 与 Encoder-Decoder 的可见性【🔥 必会】

### 为什么要关注这个问题

**Encoder 型**模型通常让每个位置利用输入的双向上下文，常用于表示学习、分类和检索编码。**自回归 Decoder 型**模型在训练/生成时按因果约束预测下一 token，适合开放式文本生成。**Encoder-Decoder 型**先编码输入，再让 Decoder 基于编码结果生成，常见于条件生成任务。这里是典型用法，不是所有模型或任务的硬边界；具体仍看 Mask 和训练目标。

〔本次新补，参考当前面试趋势〕

目标 + 例子。 用注意力的可见范围理解常见架构：encoder 可双向编码输入，decoder-only 常采用因果自注意力，encoder-decoder 可让目标查询关注源序列。完整模型对照见第 8.2 节。

### 概念与数据流

| 五要素 | 可见性与跨注意力 |
| --- | --- |
| 输入 | 源隐藏态 [B,Ts,C]、目标隐藏态 [B,Tt,C] 和可见性规则。 |
| 做什么 | 双向或因果自注意力使用同一序列的 Q/K/V；跨注意力用目标 Q 和源 K/V。 |
| 输出 | 源自注意力输出 [B,Ts,C]；跨注意力输出 [B,Tt,C]。 |
| 哪里出错 | 因果 mask 反向、把源长度当作目标长度、padding 未屏蔽。 |
| 参数影响 | 源/目标长度、隐藏维、头数和 mask 影响计算、内存及可见信息。 |

这是对典型结构的概括，不是所有 encoder/decoder 的统一实现。分类、检索、生成和翻译等任务仍需看具体模型训练目标和接口；本例只是随机注意力层，不是完整的三类模型。

### 面试追问

【🔥 必会】cross-attention 的输出长度由谁决定？ 结论：由 query 目标长度决定。Q 来自目标序列时，输出为 [B,Tt,C]，K/V 的源长度可以不同。

【🔥 必会】因果输出被未来输入影响怎么查？ 结论：核对 mask 方向和 API 语义。固定层参数，只改未来位置，比较之前输出；同时检查位置和 padding。

【⭐ 理解】双向 encoder 一定只能做分类吗？ 结论：不是。它也可用于向量表示等任务；实际能力取决于训练和模型结构。

### 故障模式与排障

- 跨注意力形状错误：检查目标 Q 的长度、源 K/V 长度及通道投影。

- 未来泄漏：检查因果 mask 并进行未来输入扰动测试。

- 模型类型选对但任务质量差：核对具体 checkpoint、训练目标、输入处理与业务测试集。

### 工程 trick 与坑

- 本例没有 padding、位置编码、FFN 或预训练权重；不能以此比较实际架构效果。

- nn.MultiheadAttention 在本例的 bool mask 中 True 表示禁止；其他接口语义可能不同。

- 实际三类随机模型的接口及输出形状见第 8.2 节，避免在此重复完整代码。

### Toy code：可见性与跨注意力形状

运行前提：Python 3.10+、PyTorch；CPU float32，随机张量。

```python
"""用多头注意力演示双向、因果和跨注意力的可见范围。"""
import torch
from torch import Tensor, nn


def compare_visibility(source: Tensor, target: Tensor) -> tuple[Tensor, Tensor, Tensor]:
    """构造随机层并返回双向自注意力、因果自注意力和跨注意力。"""
    if source.ndim != 3 or target.ndim != 3 or source.shape[0] == 0 or source.shape[0] != target.shape[0]:
        raise ValueError('输入须为同批次非空三维张量')
    if source.shape[1] == 0 or target.shape[1] == 0 or source.shape[2] == 0 or source.shape[2] != target.shape[2] or source.shape[2] % 2:
        raise ValueError('序列不能为空，通道维须相同且可被两头整除')
    if source.dtype != torch.float32 or target.dtype != torch.float32 or source.device.type != 'cpu' or target.device.type != 'cpu':
        raise ValueError('示例只处理 CPU float32')
    if not torch.isfinite(source).all() or not torch.isfinite(target).all():
        raise ValueError('输入必须有限')
    layer = nn.MultiheadAttention(source.shape[-1], 2, batch_first=True, dropout=0.0).eval()
    blocked = torch.ones(source.shape[1], source.shape[1], dtype=torch.bool).triu(1)
    bidirectional, _ = layer(source, source, source, need_weights=False)
    causal, _ = layer(source, source, source, attn_mask=blocked, need_weights=False)
    cross, _ = layer(target, source, source, need_weights=False)
    assert bidirectional.shape == causal.shape == source.shape
    assert cross.shape == target.shape
    changed = source.clone(); changed[:, -1] += 20
    causal_changed, _ = layer(changed, changed, changed, attn_mask=blocked, need_weights=False)
    assert torch.allclose(causal[:, :-1], causal_changed[:, :-1], atol=1e-6)
    return bidirectional, causal, cross


def main() -> None:
    """检查不同源目标长度、因果边界、梯度与非法输入。"""
    torch.manual_seed(97)
    source = torch.randn(2, 4, 8, requires_grad=True)
    target = torch.randn(2, 3, 8, requires_grad=True)
    enc, dec, cross = compare_visibility(source, target)
    assert enc.shape == dec.shape == (2, 4, 8) and cross.shape == (2, 3, 8)
    (enc.square().mean() + dec.square().mean() + cross.square().mean()).backward()
    assert source.grad is not None and target.grad is not None
    assert torch.isfinite(source.grad).all() and torch.isfinite(target.grad).all()
    for bad in (torch.empty(2, 0, 8), torch.randn(2, 4, 7)):
        try:
            compare_visibility(bad, target.detach())
        except ValueError:
            pass
        else:
            raise AssertionError('空序列或不匹配通道必须拒绝')
    print('双向、因果和跨注意力形状与因果边界自检通过。')
    print('随机注意力层并非完整模型，也不能比较实际任务质量。')


if __name__ == '__main__':
    main()

```

逐段理解。 用同一个随机注意力层分别执行无 mask 自注意力、因果自注意力和目标到源的跨注意力；自检对比源/目标长度、未来扰动和梯度。

### 这段代码怎么在面试里讲

- 不变量：源与目标 batch 和通道一致；自注意力保持源长度，跨注意力保持目标长度。

- 关键过程：为因果路径屏蔽未来；跨注意力将目标作为 Q，源作为 K/V。

- 边界与坑：示例只是子层，不能代表完整模型或任务质量；真实使用还需 padding、位置和模型具体配置。

### 本节收尾：费曼自述与闪卡

费曼自述： 可见性区分双向和因果自注意力；跨注意力让目标查询读取源表示，输出长度跟目标查询一致。

- 问：跨注意力的 Q 通常来自哪里？答：目标侧；K/V 可来自源侧。

- 问：输出长度等于源长度吗？答：不一定，通常由 Q 的目标长度决定。

- 问：此例是否是完整 decoder？答：不是，只演示注意力子层。

- 问：本例的 bool mask True 含义？答：对该 MultiheadAttention 调用表示禁止。

## 10.3 Dense 与 MoE：路由、负载和部署【🔥 必会】

### 为什么要关注这个问题

**Dense** 模型一次前向通常会激活每层的主要参数；**Mixture of Experts（MoE）** 在部分层用路由机制为 token 选择若干专家，以增加总参数容量而控制每个 token 的活跃计算。MoE 的实际性能还受路由、通信、专家负载和部署实现影响，不能只比较“总参数”。

〔本次新补，参考当前面试趋势〕

目标 + 例子。 Dense 层通常对每个 token 使用同一组参数；MoE 层由路由器为 token 选择部分专家。用随机线性专家模拟 top-k 权重和负载，理解总参数、激活参数和资源不是同一指标。

### 概念与数据流

| 五要素 | top-k MoE 层 |
| --- | --- |
| 输入 | token 隐藏态 [B,T,C]、路由器、E 个专家和每 token 选择数 k。 |
| 做什么 | 计算路由分数，选择 k 个专家并归一化权重，聚合各专家输出。 |
| 输出 | [B,T,C]、选中专家 ID 和路由权重；可统计专家负载。 |
| 哪里出错 | 路由极不均衡、专家容量溢出、跨设备通信开销、推理框架不兼容。 |
| 参数影响 | 专家数、top-k、容量限制和负载策略影响质量、计算、内存与吞吐。 |

MoE 的总参数可能远大于单 token 激活的专家参数，但部署仍需存储或访问相应专家权重；显存、通信、延迟和吞吐由实现与负载决定。示例先计算所有专家再聚合，目的是解释路由，不实现稀疏计算、容量、丢 token 或分布式通信。

### 面试追问

【🔥 必会】MoE 的总参数和激活参数有什么区别？ 结论：总参数包含全部专家，单 token 只选部分专家。实际计算和存储还包括路由器、共享层及实现开销，不能只看一个数字。

【🔥 必会】某个专家负载特别高怎么排查？ 结论：先统计各专家接收的 token 和溢出。检查输入分布、路由配置、容量与服务版本，再评估负载均衡策略及质量影响。

【⭐ 理解】MoE 一定比 Dense 更快或更省显存吗？ 结论：不一定。专家权重、通信和调度开销可能主导；应在目标硬件和负载下测量。

### 故障模式与排障

- 路由权重不归一：检查 top-k 后 softmax 的维度；验证每个 token 的选中权重和为 1。

- 专家分布极不均衡：统计每个专家的路由次数与溢出，按数据切片检查；依模型实现评估容量与负载策略。

- 显存或延迟不符合预期：区分总参数、激活计算、权重驻留和跨设备通信；在实际服务上压测。

### 工程 trick 与坑

- 本例计算所有专家输出，不提供真正的稀疏执行或速度比较。

- topk 分数并列时顺序可能因实现或设备变化；不要把固定随机样例当作负载保证。

- 不同 MoE 可能包含共享专家、不同归一化或容量策略，应阅读具体模型实现。

### Toy code：top-k 路由与负载统计

运行前提：Python 3.10+、PyTorch；CPU 可运行。随机线性专家只演示数据流。

```python
"""用 PyTorch 模拟 top-k MoE 路由；不实现稀疏加速或分布式执行。"""
import torch
from torch import Tensor, nn


class ToyMoE(nn.Module):
    """对每个 token 选择 k 个线性专家并加权求和。"""
    def __init__(self, channels: int, experts: int, top_k: int) -> None:
        super().__init__()
        if min(channels, experts, top_k) <= 0 or top_k > experts:
            raise ValueError('维度须为正且 top_k 不超过专家数')
        self.channels, self.experts, self.top_k = channels, experts, top_k
        self.router = nn.Linear(channels, experts)
        self.layers = nn.ModuleList(nn.Linear(channels, channels) for _ in range(experts))

    def forward(self, x: Tensor) -> tuple[Tensor, Tensor, Tensor]:
        """输入 (B,T,C)，返回输出、选择索引和选中权重。"""
        if x.ndim != 3 or x.shape[0] == 0 or x.shape[1] == 0 or x.shape[2] != self.channels:
            raise ValueError('输入必须是非空 (B,T,C)')
        if x.dtype != self.router.weight.dtype or x.device != self.router.weight.device or not torch.isfinite(x).all():
            raise ValueError('输入设备、类型或数值非法')
        scores = self.router(x)
        selected_scores, indices = scores.topk(self.top_k, dim=-1)
        weights = torch.softmax(selected_scores, dim=-1)
        # 为了简洁，对所有专家计算；真实稀疏实现会按路由分派 token。
        all_outputs = torch.stack([expert(x) for expert in self.layers], dim=-2)
        selected = all_outputs.gather(-2, indices.unsqueeze(-1).expand(*indices.shape, self.channels))
        output = (selected * weights.unsqueeze(-1)).sum(dim=-2)
        assert output.shape == x.shape and indices.shape == (*x.shape[:2], self.top_k)
        return output, indices, weights


def main() -> None:
    """检查路由权重、专家计数、单专家退化与梯度。"""
    torch.manual_seed(83)
    moe = ToyMoE(channels=8, experts=3, top_k=2)
    x = torch.randn(2, 4, 8, requires_grad=True)
    output, indices, weights = moe(x)
    assert torch.allclose(weights.sum(-1), torch.ones(2, 4), atol=1e-6)
    counts = torch.bincount(indices.reshape(-1), minlength=3)
    assert counts.sum().item() == 2 * 4 * 2
    output.square().mean().backward()
    assert x.grad is not None and torch.isfinite(x.grad).all()
    assert moe.router.weight.grad is not None
    single = ToyMoE(8, 1, 1)
    single_out, _, _ = single(x.detach())
    assert torch.allclose(single_out, single.layers[0](x.detach()), atol=1e-6)
    for invalid in ((8, 2, 3), (8, 0, 1)):
        try:
            ToyMoE(*invalid)
        except ValueError:
            pass
        else:
            raise AssertionError('非法专家数或 top-k 必须拒绝')
    print('MoE 路由与专家计数自检通过:', counts.tolist())
    print('示例计算了所有专家，不代表真实稀疏性能或模型质量。')


if __name__ == '__main__':
    main()

```

逐段理解。 router 给每个 token 产生专家分数；选择 top-k 并归一化；示例计算所有专家后按索引取出、加权求和；自检核对输出形状、权重、专家计数和梯度。

### 这段代码怎么在面试里讲

- 不变量：输入输出 [B,T,C]，每个 token 选 k 个专家，选中权重和为 1。

- 关键过程：路由分数→top-k→softmax→收集专家输出→加权求和，并统计各专家选择次数。

- 边界与坑：这里没有稀疏计算、容量限制或通信，不能用其速度推断生产 MoE；实际参数和实现可能不同。

调库与手写怎么选。 用 PyTorch 张量演示路由便于理解；真实 MoE 应使用模型和推理框架支持的实现，按目标硬件测内存、质量和吞吐，不自行构建分布式框架。

### 本节收尾：费曼自述与闪卡

费曼自述： MoE 路由器为 token 选择部分专家，输出按权重组合；总参数和单次激活参数不同，实际部署还要考虑负载与通信。

- 问：MoE 单 token 是否一定执行所有专家？答：稀疏设计通常只选择部分；本教学代码为简洁仍计算全部。

- 问：路由严重不均衡有什么影响？答：可能造成热点、溢出或通信瓶颈，需按实现测量。

## 10.4 生成模型、Embedding 与 Reranker【🔥 必会】

### 为什么要关注这个问题

**生成模型**根据上下文产出文本；**Embedding 模型**把文本/图像编码成可比较的向量；**Reranker**对“问题—候选证据”对重新打分排序。它们可能共享基础 Transformer 思想，但训练目标和输出不同。

```mermaid
flowchart LR
    A[问题] --> B[召回候选]
    B --> C[重排证据]
    C --> D[生成回答与引用]
```

〔本次新补，参考当前面试趋势〕

目标 + 例子。 文档问答通常需要不同模型分工：embedding 将文本编码为向量以便召回，reranker 对问题与候选逐对打分，生成模型再根据证据组织回答。

### 概念与数据流

| 五要素 | 检索编码与重排 |
| --- | --- |
| 输入 | 查询和候选文档；embedding 编码单条文本，cross-encoder 接收查询-文档对。 |
| 做什么 | 比较向量相似度；再用交叉编码器对候选相关性打分并排序。 |
| 输出 | 每份候选的相似度与重排分数；生成模型另行输出文本。 |
| 哪里出错 | embedding 版本或维度不一致、截断、候选未召回、把不同模型分数当同一概率。 |
| 参数影响 | 向量维度、归一化、候选数量、最大长度和模型版本影响质量、成本与延迟。 |

Bi-encoder 可以预先编码文档，适合构建候选检索；cross-encoder 一般联合编码查询和候选，适合在较少候选上重排。两者分数尺度不同，也不天然是校准概率；实际速度和质量取决于模型、硬件及候选数量。完整 RAG 流程和评测见[第 3 章](03-RAG检索增强/README.md)。

### 面试追问

【🔥 必会】为什么不直接对全部文档运行 reranker？ 结论：逐对交叉编码通常成本较高。先检索出候选再重排是常见折中，最终需按数据规模和目标延迟评测。

【🔥 必会】重排后仍然找不到正确证据怎么查？ 结论：先看正确文档是否进入候选。若召回阶段已遗漏，reranker 无法恢复；若已召回，再查分数、截断和模型适配。

【⭐ 理解】余弦 0.8 和 reranker 分数 0.8 能直接比较吗？ 结论：不能。它们来自不同模型与计算方式，不天然共享量纲或概率解释。

### 故障模式与排障

- 召回质量下降：核对查询/文档编码模型、版本、归一化及索引；用固定标注集分别测召回与重排。

- 相关文档重排靠后：检查候选、文本截断、查询语言和模型适配；对失败样例逐对分析。

- 分数被错误当作置信概率：检查消费端阈值与模型文档；需要概率时应基于独立数据校准并验证。

### 工程 trick 与坑

- 下例运行真实预训练编码器和重排器，但只有两条虚构文档；不能推断真实业务效果。

- 检索与重排输入应保留来源和版本；生成阶段还需验证答案与证据关系。

- 模型权重、许可、设备、最大长度与库版本须按实际部署核对。

### Toy code：真实 embedding 与 reranker 对照

运行前提：Python 3.11、PyTorch、NumPy、sentence-transformers==5.1.1；提前下载 [BGE-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 和 [mMARCO CrossEncoder](https://huggingface.co/cross-encoder/mmarco-mMiniLMv2-L12-H384-v1)，分别用 BGE_MODEL_PATH、RERANK_MODEL_PATH 指向本地目录。示例使用 local_files_only=True，运行时不联网。首次准备权重需网络、存储和足够内存。

```python
"""对同一虚构检索任务比较 embedding 相似度和 reranker 分数。"""
import os
from pathlib import Path
import numpy as np
from sentence_transformers import CrossEncoder, SentenceTransformer


def model_path(variable: str) -> str:
    """读取本地模型目录，避免示例运行时自动联网。"""
    raw = os.environ.get(variable, '')
    if not raw or not Path(raw).is_dir():
        raise ValueError(f'{variable} 必须指向已准备的本地模型目录')
    return raw


def compare(query: str, documents: list[str], encoder: SentenceTransformer,
            reranker: CrossEncoder) -> tuple[np.ndarray, np.ndarray]:
    """对输入分别计算余弦相似度和 query-document 交叉编码分数。"""
    if not isinstance(query, str) or not query.strip() or not documents:
        raise ValueError('问题和文档列表不能为空')
    if any(not isinstance(doc, str) or not doc.strip() for doc in documents):
        raise ValueError('文档必须为非空字符串')
    vectors = encoder.encode([query] + documents, normalize_embeddings=True,
                             convert_to_numpy=True, show_progress_bar=False)
    if vectors.ndim != 2 or vectors.shape[0] != len(documents) + 1 or not np.isfinite(vectors).all():
        raise ValueError('embedding 形状或数值异常')
    if not np.allclose(np.linalg.norm(vectors, axis=1), 1.0, atol=1e-4):
        raise ValueError('向量未正确归一化')
    similarities = vectors[1:] @ vectors[0]
    scores = np.asarray(reranker.predict([(query, doc) for doc in documents], show_progress_bar=False)).reshape(-1)
    if scores.shape != (len(documents),) or not np.isfinite(scores).all():
        raise ValueError('reranker 分数形状或数值异常')
    assert similarities.shape == scores.shape == (len(documents),)
    return similarities, scores


def main() -> None:
    """运行虚构文本对并测试空输入；不保证任何排名结果。"""
    encoder = SentenceTransformer(model_path('BGE_MODEL_PATH'), device='cpu', local_files_only=True)
    reranker = CrossEncoder(model_path('RERANK_MODEL_PATH'), device='cpu', local_files_only=True)
    question = '高处作业需要什么防护？'
    documents = ['虚构制度：高处作业应使用安全带。', '虚构记录：仓库货架需要编号。']
    similarities, scores = compare(question, documents, encoder, reranker)
    assert len(similarities) == len(documents) and len(scores) == len(documents)
    try:
        compare('', documents, encoder, reranker)
    except ValueError:
        pass
    else:
        raise AssertionError('空问题必须拒绝')
    print('embedding 余弦:', similarities.tolist())
    print('cross-encoder 分数:', scores.tolist())
    print('两个分数不能直接比较或解释成概率；样本不证明业务效果。')


if __name__ == '__main__':
    main()

```

逐段理解。 model_path 明确本地权重；compare 用归一化向量计算余弦，再对每个查询-文档对计算交叉编码分数；自检检查形状、有限值和空输入。

### 这段代码怎么在面试里讲

- 不变量：查询和文档非空，向量与分数有限，两个分数数组长度都等于候选数。

- 关键过程：分别编码查询和文档并计算相似度，再把每对输入重排模型得到独立分数。

- 边界与坑：两个分数不可直接比较，示例未做真实索引和生成；小样本不证明业务效果。

### 本节收尾：费曼自述与闪卡

费曼自述： Embedding 用向量帮助找候选，reranker 对问题和候选逐对精排，生成模型再组织答案；每阶段都有独立评测与成本。

- 问：reranker 能恢复未召回文档吗？答：不能，它只能重排输入的候选。

- 问：embedding 与 reranker 分数能直接相加吗？答：不能默认同尺度，需要明确融合和评测。

- 问：示例用了真实预训练权重吗？答：是，但只处理两条虚构文本，不证明业务效果。

- 问：生成模型输出能替代来源核验吗？答：不能，仍需检查证据与结论。

## 10.5 VLM 选型：视觉编码、对齐与生成【🔥 必会】

### 为什么要关注这个问题

一类常见 VLM 用视觉编码器提取图片特征，经连接模块传给 LLM。LLaVA 的[视觉指令微调论文](https://arxiv.org/abs/2304.08485)是理解“视觉编码器 + 投影 + 语言模型”的入口。后续模型还会改进多分辨率、多图、视频帧、长上下文与训练数据；[Qwen3-VL 技术报告](https://arxiv.org/abs/2511.21631)是一个图像、视频与长上下文结合的实例。别把某一家架构当成全部 VLM 的固定模板。

〔本次新补，参考当前面试趋势〕

目标 + 例子。 图片问答模型需要处理视觉输入并与文本任务对齐；以随机视觉编码器和投影层观察 patch 形状，再到第 7 章学习完整多模态输入、微调和评测。

### 概念与数据流

| 五要素 | 视觉编码器与投影层 |
| --- | --- |
| 输入 | 经目标模型处理的像素张量 [B,3,H,W]；此例直接使用随机张量。 |
| 做什么 | 视觉编码器产生 patch 特征，投影层把特征映射到另一个隐藏维。 |
| 输出 | 视觉特征 [B,N,Cv]，投影后 [B,N,Cl]；本例没有语言模型。 |
| 哪里出错 | 图像预处理不匹配、patch/特殊 token 处理错误、投影维度或模型版本不一致。 |
| 参数影响 | 分辨率、patch 大小、特征维和图像数量影响 token 数、显存、延迟与细节保留。 |

常见 VLM 可由视觉编码器、对齐/投影模块和语言模型构成，但具体架构及特征融合方式因模型而异。固定 patch 划分的简单示例中，patch 数可按图像尺寸估算；动态分辨率、切图和特殊 token 会改变真实序列长度。

### 面试追问

【🔥 必会】图片如何进入语言模型？ 结论：通常先编码视觉特征再进行跨模态对齐。具体可能是投影、交叉注意力或其他融合方式；需要按模型实现解释。

【🔥 必会】视觉模型漏掉小隐患怎么查？ 结论：先检查原图、缩放和细节是否保留。按目标大小、光照和遮挡分桶评测，再比较分辨率、切图及模型方案。

【⭐ 理解】图像分辨率越高一定越好吗？ 结论：不一定。更高分辨率可能保留细节，也会增加 token、内存和延迟；需要按任务实测。

### 故障模式与排障

- 输入或投影形状错误：核对 processor 输出、视觉隐藏维、projector 输入维和特殊 token 布局。

- 小目标识别失败：回查原图和预处理，检查缩放或切图是否丢失区域；用难例集对照。

- 延迟或显存超标：记录图片尺寸、数量、视觉 token 与生成长度；在目标硬件上比较配置。

### 工程 trick 与坑

- 示例使用随机 CLIP 配置和随机像素，没有真实图像预处理、预训练权重、语言模型或生成效果。

- 删除第一个 token 只适用于本例的 CLIP CLS + patch 布局，其他视觉模型不可盲目套用。

- VLM 数据、微调和失败分析详见[第 7 章](07-多模态入门.md)。

### Toy code：视觉 patch 与投影形状

运行前提：Python 3.11、PyTorch、transformers==4.57.1；CPU 可运行，无网络和权重下载。

```python
"""用随机 CLIP 视觉编码器和线性投影演示 VLM 的特征形状。"""
import torch
from torch import Tensor, nn
from transformers import CLIPVisionConfig, CLIPVisionModel


def encode_image(pixels: Tensor, encoder: CLIPVisionModel, projector: nn.Linear) -> Tensor:
    """编码像素并投影视觉 patch；不连接语言模型。"""
    config = encoder.config
    if pixels.ndim != 4 or pixels.shape[0] == 0 or pixels.shape[1:] != (3, config.image_size, config.image_size):
        raise ValueError('输入应为固定尺寸的非空 (B,3,H,W)')
    weight = next(encoder.parameters())
    if pixels.dtype != weight.dtype or pixels.device != weight.device or not torch.isfinite(pixels).all():
        raise ValueError('像素设备、dtype 或数值非法')
    if projector.in_features != config.hidden_size or projector.weight.device != pixels.device or projector.weight.dtype != pixels.dtype:
        raise ValueError('projector 维度、设备和 dtype 须匹配视觉特征')
    result = encoder(pixel_values=pixels).last_hidden_state
    patches = result[:, 1:, :]  # 仅适用于本例 CLIP 的 CLS + patch 布局
    projected = projector(patches)
    expected_patches = (config.image_size // config.patch_size) ** 2
    assert projected.shape == (pixels.shape[0], expected_patches, projector.out_features)
    return projected


def main() -> None:
    """验证 patch 形状、梯度和非法图像尺寸。"""
    torch.manual_seed(89)
    config = CLIPVisionConfig(hidden_size=16, intermediate_size=32, num_hidden_layers=1,
                              num_attention_heads=2, image_size=32, patch_size=8)
    encoder = CLIPVisionModel(config)
    projector = nn.Linear(16, 24)
    pixels = torch.randn(2, 3, 32, 32, requires_grad=True)
    output = encode_image(pixels, encoder, projector)
    assert output.shape == (2, 16, 24) and torch.isfinite(output).all()
    output.square().mean().backward()
    assert pixels.grad is not None and projector.weight.grad is not None
    assert torch.isfinite(pixels.grad).all()
    for invalid in (torch.empty(0, 3, 32, 32), torch.randn(1, 3, 16, 16)):
        try:
            encode_image(invalid, encoder, projector)
        except ValueError:
            pass
        else:
            raise AssertionError('空批次或错误尺寸必须拒绝')
    print('随机视觉 encoder 与 projector 的 patch 形状自检通过:', tuple(output.shape))
    print('没有图像预处理、预训练权重、语言模型或视觉任务评测。')


if __name__ == '__main__':
    main()

```

逐段理解。 创建随机 CLIP 视觉编码器；encode_image 检查输入与 projector，取本例 patch 特征并投影；自检核对 patch 数、维度和梯度。

### 这段代码怎么在面试里讲

- 不变量：输入 [B,3,32,32]，8×8 patch 得到 16 个 patch，投影维度从 16 变为 24。

- 关键过程：视觉编码器提取特征，按本例布局去掉 CLS，线性层映射特征维。

- 边界与坑：模型和输入均随机，没有真实预处理或语言生成；CLS/patch 布局与动态分辨率依模型而异。

### 本节收尾：费曼自述与闪卡

费曼自述： VLM 先处理图片得到视觉特征，再按模型结构与语言部分对齐；分辨率和预处理影响细节、成本及效果。

- 问：本例是否运行了语言模型？答：没有，只演示视觉编码与投影。

## 10.6 API、托管与自部署：核对约束【⭐ 理解】

### 为什么要关注这个问题

**托管 API** 适合快速基线和少运维；**可自托管权重** 有助于数据边界、定制微调和成本可控，但需处理模型加载、显存、并发、量化、升级与监控。两类都要检查服务条款与数据使用方式；开源代码、可下载权重、可商用许可是不同的概念。

〔本次新补，参考当前面试趋势〕

目标 + 例子。 选择 API、托管权重或自部署时，先核对数据使用、许可和资源等硬约束；信息缺失时标记待确认，再做质量、延迟与成本测试。

### 概念与数据流

| 五要素 | 部署候选约束筛查 |
| --- | --- |
| 输入 | 候选部署方式，以及经实际审查得到的数据、许可和资源状态。 |
| 做什么 | 已知不满足则拒绝，存在未知项则待确认，全部满足才进入下一轮测试。 |
| 输出 | 通过、失败或待确认的初筛状态。 |
| 哪里出错 | 把开放权重误当无条件可商用、把未知合同或数据规则当作允许、硬件估算不足。 |
| 参数影响 | 模型许可、数据边界、吞吐、并发与硬件容量影响可行性和总成本。 |

不同服务和模型的使用条件、部署方式及价格可能变化；权重开放不自动意味着对所有用途都无限制。实际决策应核对目标版本的模型卡、协议和公司要求，再用目标负载评测。成本方法见第 6.1 节，完整系统评测见[系统设计与评测](横切-系统设计与评测.md)专题。

### 面试追问

【🔥 必会】自部署和 API 怎么选？ 结论：先看硬约束，再按同负载比较。核对数据、许可、资源与运维条件，同时测质量、延迟和成本。

【🔥 必会】模型许可或数据规则未知怎么办？ 结论：标记待确认，不能默认允许。核对目标模型和服务的实际条款，并按组织流程处理。

【⭐ 理解】开放权重一定能直接用于所有商业场景吗？ 结论：不能一概而论。应以具体版本的模型许可和使用条件为准。

### 故障模式与排障

- 上线前发现数据不能发送到目标环境：核对数据流、服务处理规则与实际授权；重新选择可行部署路径。

- 权重能下载但用途受限：核对目标版本许可及依赖，必要时由相关人员确认；不要仅凭“开源”标签判断。

- 模型能加载但并发不足：在目标硬件和请求分布下测内存、吞吐及 P95，再调整资源或方案。

### 工程 trick 与坑

- 下例的布尔值是假定已经完成的外部审查结果，程序不检查真实合同、许可、硬件或数据。

- 已知失败优先于未知；即使初筛通过，也不代表质量和成本满足要求。

- 价格、模型能力和协议会变化；需要在实际选型时查目标版本资料。

### Toy code：部署约束状态

运行前提：Python 3.10+，标准库；全部候选和审查状态均为虚构。

```python
"""按虚构审查记录筛查部署路径，不解释许可条款或访问模型。"""
from dataclasses import dataclass


@dataclass(frozen=True)
class Deployment:
    """记录部署方式以及预先核实的三类约束状态。"""
    name: str
    mode: str
    data_use_allowed: bool | None
    license_allowed: bool | None
    resource_sufficient: bool | None


def assess(options: list[Deployment]) -> dict[str, str]:
    """已知不满足则 fail；未知则 review；全部确认才返回 pass。"""
    if not options:
        raise ValueError('部署选项不能为空')
    result: dict[str, str] = {}
    for option in options:
        if not option.name.strip() or option.name in result:
            raise ValueError('名称必须非空且唯一')
        if option.mode not in {'api', 'hosted', 'self_hosted'}:
            raise ValueError('未知部署方式')
        checks = (option.data_use_allowed, option.license_allowed, option.resource_sufficient)
        if any(value is not None and not isinstance(value, bool) for value in checks):
            raise ValueError('审查状态必须为布尔值或未知')
        result[option.name] = 'fail' if False in checks else 'review' if None in checks else 'pass'
    assert len(result) == len(options)
    return result


def main() -> None:
    """覆盖通过、失败、未知及非法重复输入。"""
    options = [Deployment('A', 'api', True, True, None),
               Deployment('B', 'self_hosted', False, None, True),
               Deployment('C', 'hosted', True, True, True)]
    assert assess(options) == {'A': 'review', 'B': 'fail', 'C': 'pass'}
    for bad in ([], options + options[:1], [Deployment('D', 'other', True, True, True)]):
        try:
            assess(bad)
        except ValueError:
            pass
        else:
            raise AssertionError('空列表、重复名称或未知模式必须拒绝')
    print('虚构部署约束审查自检通过:', assess(options))
    print('本程序不验证真实合同、许可或硬件。')


if __name__ == '__main__':
    main()

```

逐段理解。 Deployment 保存三类约束状态；assess 先检查已知失败，再处理未知；自检覆盖通过、失败、待确认和非法选项。

### 这段代码怎么在面试里讲

- 不变量：候选名称唯一，部署方式属于限定集合，审查值为真、假或未知。

- 关键过程：任一硬约束不满足则失败；没有失败但有未知则待确认；全部已确认才通过初筛。

- 边界与坑：程序不作法律判断，也不测真实性能；通过初筛后仍需实际核验和评测。

### 本节收尾：费曼自述与闪卡

费曼自述： 部署先核对数据、许可和资源等硬约束；未知要确认，通过后还要比较质量、延迟、成本与运维。

- 问：开放权重代表所有用途都允许吗？答：不能一概而论，要看具体许可。

- 问：约束信息未知怎么办？答：标记待确认，不默认通过。

- 问：通过约束初筛就能上线吗？答：不能，还需验证质量与部署表现。

- 问：本例能判断真实合同吗？答：不能，只处理虚构输入状态。

## 10.7 模型选型面试：同任务与失败切片【🔥 必会】

### 为什么要关注这个问题

面试官问“你为什么选这个模型”，可以按六步回答：
1. 任务：输入、输出、数据、错误代价。
2. 候选：至少一个简单基线和一个较强候选。
3. 测试集：公开/内部合规样本，切分规则与关键子集。
4. 指标：正确率/召回、引用、格式、P95、吞吐、费用。
5. 结果：真实数值与失败样例，说明改动前后。
6. 决策：收益是否值得增加的成本和运维复杂度。

〔本次新补，参考当前面试趋势〕

目标 + 例子。 比较两个视觉问答候选时，让它们处理同一批带标注的图片任务；除总体通过率外，分别看小目标、遮挡等难例以及延迟和成本。

### 概念与数据流

| 五要素 | 模型分桶评测 |
| --- | --- |
| 输入 | 各模型在相同任务上的独立评测结果、任务 ID 和类别。 |
| 做什么 | 检查任务和类别一致，按模型、场景统计通过数与总数。 |
| 输出 | 每个模型的分桶结果；费用、延迟和统计不确定性另行评估。 |
| 哪里出错 | 测试集不一致、标注偏差、分桶样本过少、只看总体平均。 |
| 参数影响 | 任务覆盖、标注标准、样本量、预处理和模型配置影响结论。 |

同条件比较要求任务集、成功标准和测量口径可比；各模型的输入处理应符合自身要求并记录差异。小目标错误、高风险漏报等需要单独分析。更完整的数据集、离线/线上指标与发布门禁见[系统设计与评测](横切-系统设计与评测.md)专题。

### 面试追问

【🔥 必会】如何比较两个候选模型？ 结论：用同任务与统一标准评测。报告总体和关键切片、失败样例、延迟及成本，并核对预处理与版本。

【🔥 必会】总体分数提升但小目标漏检增加怎么决策？ 结论：先看关键场景及业务门槛。核对分桶样本和标注，分析漏检成本；必要时不发布或采用人工复核。

【⭐ 理解】一个难例就能证明模型 B 更好吗？ 结论：不能。单例可用于定位问题，但性能结论需要足量、有代表性的独立样本。

### 故障模式与排障

- 模型结果不可比：核对任务 ID、标注、配置和预处理，固定基准集后重新运行。

- 总体好但关键场景差：按目标尺寸、遮挡或任务类型切片，回查具体失败与标注质量。

- 小样本波动大：扩大独立样本或明确不确定性；不要把单个样例差异写成稳定收益。

### 工程 trick 与坑

- 下例每桶只有一条虚构任务，只演示分组与对齐，不证明模型性能。

- 二元通过状态须由明确规则和独立标注获得；本例不自动评判图像或回答。

- 〔补充自原仓库镜像〕模型路由可用规则或小模型选择候选，但不能预设“多数请求都简单”，也不能把模型自报置信度直接当正确率。用同一批独立标注任务比较各候选，分别测路由成本、误路由、整体质量和关键场景退化；路由本身也要留出独立测试集。

- 生产评测还需来源、成本、延迟、版本与统计不确定性；参见横切专题[系统设计与评测](横切-系统设计与评测.md)。

### Toy code：同任务分桶比较

运行前提：Python 3.10+，标准库；记录均为虚构，不调用模型。

```python
"""按同一虚构任务集比较模型分桶通过率，不推断统计显著性。"""
from dataclasses import dataclass


@dataclass(frozen=True)
class Judgment:
    """独立评测给出的单任务模型结果及场景类别。"""
    model: str
    task_id: str
    category: str
    passed: bool


def compare(records: list[Judgment]) -> dict[str, dict[str, tuple[int, int]]]:
    """要求不同模型覆盖相同任务和类别，返回各桶 (通过数, 总数)。"""
    if not records:
        raise ValueError('评测记录不能为空')
    by_model: dict[str, dict[str, Judgment]] = {}
    for record in records:
        if any(not isinstance(s, str) or not s.strip() for s in (record.model, record.task_id, record.category)):
            raise ValueError('模型、任务 ID 和类别不能为空')
        if not isinstance(record.passed, bool):
            raise ValueError('通过状态必须是布尔值')
        tasks = by_model.setdefault(record.model, {})
        if record.task_id in tasks:
            raise ValueError('同一模型的任务 ID 不能重复')
        tasks[record.task_id] = record
    first = next(iter(by_model.values()))
    reference = {task_id: row.category for task_id, row in first.items()}
    results: dict[str, dict[str, tuple[int, int]]] = {}
    for model, tasks in by_model.items():
        if {task_id: row.category for task_id, row in tasks.items()} != reference:
            raise ValueError('模型间任务及类别必须一致')
        buckets: dict[str, tuple[int, int]] = {}
        for row in tasks.values():
            passed, count = buckets.get(row.category, (0, 0))
            buckets[row.category] = (passed + int(row.passed), count + 1)
        results[model] = buckets
    assert all(sum(count for _, count in buckets.values()) == len(reference) for buckets in results.values())
    return results


def main() -> None:
    """检查同任务切片、标签变化和缺任务。"""
    records = [Judgment('A', '1', '小目标', False), Judgment('A', '2', '清晰图', True),
               Judgment('B', '2', '清晰图', True), Judgment('B', '1', '小目标', True)]
    result = compare(records)
    assert result['A']['小目标'] == (0, 1) and result['B']['小目标'] == (1, 1)
    for bad in ([], records[:-1], records + records[:1]):
        try:
            compare(bad)
        except ValueError:
            pass
        else:
            raise AssertionError('空数据、缺任务或重复记录必须拒绝')
    print('虚构模型分桶评测自检通过:', result)
    print('每桶仅一条样本，不能证明真实性能或统计差异。')


if __name__ == '__main__':
    main()

```

逐段理解。 Judgment 保存模型-任务-类别结果；compare 校验各模型任务与类别一致，再按类别累计通过数和总数；自检覆盖缺任务与重复记录。

### 这段代码怎么在面试里讲

- 不变量：每个模型的任务 ID 唯一，所有模型任务和类别完全一致。

- 关键过程：先对齐基准任务，再按模型和类别累计通过数及样本数。

- 边界与坑：不计算显著性，也不验证标注真实性；还需独立样本、延迟与成本。

### 本节收尾：费曼自述与闪卡

费曼自述： 模型选型要在可比任务和标准下评测，既看总体也看关键失败切片；少量样本不能支撑稳定收益。

- 问：两个模型测试集不同能直接比较吗？答：不能可靠归因，先对齐任务和评测口径。

- 问：总体更好是否代表所有场景更好？答：不是，要看关键切片和失败案例。

- 问：一个样本能证明模型更优吗？答：不能，需要足够独立样本。

- 问：代码自动评判图片正确吗？答：没有，只汇总虚构的外部标注。

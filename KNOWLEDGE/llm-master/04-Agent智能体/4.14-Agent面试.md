## 4.14 Agent 面试：工具、停止条件与排障【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考中国境内外企应用岗面试高频考点〕

目标 + 例子。 应对外企面试官对“Agent 线上死循环、失控刷爆 API、工具调用死锁”的致命深挖。在工业场景（如安全隐患法规检索与核实系统）中，模型在遇到检索结果为空或参数不匹配时，极易陷入两种恶性循环：一种是“连续相同调用”（连续 3 次用完全相同的参数查询同一个工具），另一种是“交替振荡循环”（A 工具查无果 -> B 工具查无果 -> 又回到 A 工具）。本节实现双模自适应死循环检测与安全熔断器。

### 核心概念与五要素表

| 五要素 | 连续重复与交替死循环双模检测与熔断器 (Level 14) |
| --- | --- |
| 输入 (Input) | 动作历史序列（含工具名、JSON 参数字典）、连续重复阈值（默认 3 次）、交替周期最大窗口（默认 4 步）。 |
| 做什么 (Process) | 规范化 JSON 参数（严格字典序排序），计算动作唯一确定性签名；滑动窗口同步检测“连续重复调用”与“多步周期振荡循环”；命中阈值立即触发熔断并转交人工审核。 |
| 输出 (Output) | 熔断器状态判定（正常、连续重复阻断、交替周期死循环阻断）及阻断诊断明细。 |
| 哪里出错 (Failure Modes) | 1. JSON 参数键值顺序不一致导致哈希匹配漏报；2. 业务合法轮询等待被误判为死循环；3. 仅防连续单步重复而漏防“A→B→A→B”高频交替振荡。 |
| 参数影响 (Parameters) | 连续阈值越小越敏感但易误伤受控重试；滑动窗口过大增加内存开销，窗口过小无法捕捉长周期振荡。 |

### 面试高频追问

【🔥 必会】ReAct 范式在工业落地中如何与受控工具深度结合？
结论先行： 模型仅负责决策意图，程序严格控制执行边界与反馈闭环。
展开解释： 生产环境严禁让模型直接执行外部代码。标准链路是：模型输出符合特定 JSON Schema 的工具调用意图；宿主系统进行白名单校验、权限判别与参数类型清洗；安全执行后将脱敏结果封装为 ToolResult 注入消息流，同时记录步数与耗时，达到预算上限立即退出。

【🔥 必会】Agent 线上发生死循环停不下来，作为算法工程师该如何排查与根治？
结论先行： 必须建立“总步数/超时硬兜底 + 双模循环特征动态检测”。
展开解释： 单纯限制总步数（如 10 步）无法阻止短时间内高频轰炸同一接口。排查时应先调取执行轨迹日志，区分是“同参数连续死重试”还是“多工具交替振荡”；治本策略是对工具调用参数做字典序规范化哈希，内置连续重复与周期振荡检测器，一旦触发立即熔断并向模型注入纠偏系统提示或转人工。

【🔥 必会】Agent 和 RAG 是什么关系？在架构设计上如何做选型？
结论先行： RAG 是 Agent 的感知工具之一；Agent 是 RAG 的动态控制中枢。
展开解释： 简单事实问答优先选择轻量、可预测的静态 RAG 工作流（成本低、延迟稳定）；当涉及多跳推理、跨多个异构系统查询、或根据第一阶段检索结果决定是否需要补全查询词时，才引入 Agent 动态循环路由。在系统设计中切忌“能用线性 Pipeline 解决的硬上 Agent”。

### 生产级代码实现：连续重复与交替死循环双模检测与熔断器 (Level 14)

```python
"""4.14 连续重复与交替死循环双模检测与安全熔断器 (Level 14 进阶实战)

业务场景：
在外企生产级 Agent 运行中，LLM 常因工具结果未达预期而陷入循环死锁：
1. 连续死循环：连续多次以完全相同参数调用同一工具（如连续 3 次调用 search_docs("高空作业")）；
2. 周期振荡死循环：在两个或多个工具间循环打转（如 ToolA -> ToolB -> ToolA -> ToolB）。

本模块实现工业级安全防线：
- JSON 参数深度键序规范化（避免 dict 乱序导致的漏检）；
- 双模检测：同时防范连续相同重复与周期模式死锁；
- 状态机熔断阻断：触发后拦截执行，提供详细诊断指标供上层降级处理。
"""

from __future__ import annotations
import json
from dataclasses import dataclass, field
from enum import Enum
from typing import Any, Dict, List, Optional, Tuple


class CircuitBreakerStatus(Enum):
    """熔断器状态"""
    NORMAL = "normal"                         # 正常状态，允许执行
    TRIPPED_CONSECUTIVE = "tripped_consecutive" # 连续重复调用触发熔断
    TRIPPED_CYCLE = "tripped_cycle"           # 周期性振荡死循环触发熔断


@dataclass(frozen=True)
class ToolCallAction:
    """标准化的工具调用动作"""
    tool_name: str
    args: Dict[str, Any]

    def get_canonical_signature(self) -> str:
        """生成规范化的动作唯一指纹：工具名 + 排序序列化 JSON 参数
        
        关键细节：必须使用 sort_keys=True 保证 JSON 键序绝对一致，
        否则 {"a": 1, "b": 2} 与 {"b": 2, "a": 1} 会被误判为不同调用！
        """
        sorted_args_json = json.dumps(self.args, sort_keys=True, ensure_ascii=False)
        return f"{self.tool_name}::{sorted_args_json}"


@dataclass
class LoopDetectionReport:
    """循环检测诊断报告"""
    status: CircuitBreakerStatus
    action_count: int
    matched_pattern: Optional[List[str]] = None
    reason: str = ""


class AgentLoopCircuitBreaker:
    """生产级 Agent 死循环双模检测熔断器"""

    def __init__(
        self,
        consecutive_repeat_threshold: int = 3,
        max_cycle_period: int = 3,
        cycle_repeat_threshold: int = 2
    ) -> None:
        """
        Args:
            consecutive_repeat_threshold: 允许连续调用完全相同工具与参数的最大阈值（超限即断）
            max_cycle_period: 周期循环检测的最大模式长度（如 period=2 检测 A-B-A-B，period=3 检测 A-B-C-A-B-C）
            cycle_repeat_threshold: 周期模式重复出现的次数阈值
        """
        if consecutive_repeat_threshold < 2:
            raise ValueError("连续重复阈值必须 >= 2")
        if max_cycle_period < 2:
            raise ValueError("最大周期必须 >= 2")

        self.consecutive_repeat_threshold = consecutive_repeat_threshold
        self.max_cycle_period = max_cycle_period
        self.cycle_repeat_threshold = cycle_repeat_threshold
        self.history: List[ToolCallAction] = []

    def record_and_evaluate(self, action: ToolCallAction) -> LoopDetectionReport:
        """记录当前工具调用动作并实时评估是否触发熔断"""
        self.history.append(action)
        signatures = [a.get_canonical_signature() for a in self.history]
        total = len(signatures)

        # 1. 检查连续重复调用 (Consecutive Repeated Invocation)
        if total >= self.consecutive_repeat_threshold:
            recent_consecutive = signatures[-self.consecutive_repeat_threshold:]
            if len(set(recent_consecutive)) == 1:
                # 连续 N 次的指纹完全相同！
                sig = recent_consecutive[0]
                return LoopDetectionReport(
                    status=CircuitBreakerStatus.TRIPPED_CONSECUTIVE,
                    action_count=total,
                    matched_pattern=[sig],
                    reason=f"拦截到工具连续 {self.consecutive_repeat_threshold} 次完全相同重复调用: {sig}"
                )

        # 2. 检查多步周期振荡循环 (Oscillating Cycle Detection)
        # 扫描周期长度 2 到 max_cycle_period
        for period in range(2, self.max_cycle_period + 1):
            needed_window = period * self.cycle_repeat_threshold
            if total >= needed_window:
                window_sigs = signatures[-needed_window:]
                # 提取基准周期模式
                pattern = window_sigs[:period]
                # 验证整个窗口是否恰好等于 pattern 重复 cycle_repeat_threshold 次
                if window_sigs == pattern * self.cycle_repeat_threshold:
                    return LoopDetectionReport(
                        status=CircuitBreakerStatus.TRIPPED_CYCLE,
                        action_count=total,
                        matched_pattern=pattern,
                        reason=f"拦截到周期长度为 {period} 的交替振荡死循环 (重复 {self.cycle_repeat_threshold} 次): {' -> '.join(pattern)}"
                    )

        return LoopDetectionReport(
            status=CircuitBreakerStatus.NORMAL,
            action_count=total,
            reason="运行正常"
        )

    def reset(self) -> None:
        """重置历史状态"""
        self.history.clear()


def self_test():
    """验证连续重复阻断、交替死循环识别与 JSON 参数排序规范化"""
    breaker = AgentLoopCircuitBreaker(
        consecutive_repeat_threshold=3,
        max_cycle_period=2,
        cycle_repeat_threshold=2
    )

    # 1. 测试正常调用链路（参数或工具不同）
    act1 = ToolCallAction("search_regulations", {"keyword": "高处作业", "category": "安全"})
    act2 = ToolCallAction("fetch_document", {"doc_id": "MEM_001"})
    
    r1 = breaker.record_and_evaluate(act1)
    assert r1.status == CircuitBreakerStatus.NORMAL
    r2 = breaker.record_and_evaluate(act2)
    assert r2.status == CircuitBreakerStatus.NORMAL

    # 2. 测试键序不同的相同字典是否能正确归一化识别
    # {"category": "安全", "keyword": "高处作业"} 语义等价于 act1
    act1_different_key_order = ToolCallAction("search_regulations", {"category": "安全", "keyword": "高处作业"})
    assert act1.get_canonical_signature() == act1_different_key_order.get_canonical_signature()

    # 3. 验证触发【连续重复调用熔断】
    breaker.reset()
    # 连续调用 3 次相同的 action
    breaker.record_and_evaluate(act1)
    breaker.record_and_evaluate(act1)
    report_consecutive = breaker.record_and_evaluate(act1_different_key_order)
    
    assert report_consecutive.status == CircuitBreakerStatus.TRIPPED_CONSECUTIVE
    assert "连续 3 次完全相同重复调用" in report_consecutive.reason
    print("✅ 连续重复调用熔断成功触发并拦截！")

    # 4. 验证触发【交替振荡死循环熔断】 (A -> B -> A -> B)
    breaker.reset()
    act_a = ToolCallAction("check_risk_db", {"item": "安全帽佩戴"})
    act_b = ToolCallAction("web_search", {"query": "安全帽国标规范"})

    breaker.record_and_evaluate(act_a)  # A
    breaker.record_and_evaluate(act_b)  # B
    breaker.record_and_evaluate(act_a)  # A
    report_cycle = breaker.record_and_evaluate(act_b)  # B -> 形成 A-B-A-B 周期振荡！

    assert report_cycle.status == CircuitBreakerStatus.TRIPPED_CYCLE
    assert report_cycle.matched_pattern is not None
    assert len(report_cycle.matched_pattern) == 2
    assert "交替振荡死循环" in report_cycle.reason
    print("✅ 交替振荡死循环熔断成功触发并拦截！")

    # 5. 边界校验测试：非法参数拦截
    try:
        AgentLoopCircuitBreaker(consecutive_repeat_threshold=1)
        raise AssertionError("未拦截非法阈值")
    except ValueError as e:
        assert "连续重复阈值必须 >= 2" in str(e)

    print("✅ 4.14 连续重复与交替死循环双模检测熔断器自检全部通过！")


if __name__ == "__main__":
    self_test()
```

### 排障指南（常见故障、定位方法、修复策略）

| 常见故障 (Failure) | 定位方法 (Diagnosis) | 修复策略 (Mitigation) |
| --- | --- | --- |
| 合法轮询被误杀 | 任务需要每隔 5 秒查询一次异步任务进度，结果第 3 次调用被熔断器阻断。 | 对“轮询类只读工具”引入白名单机制，或要求在入参中附带自增 poll_iteration 计数，或放宽该特定工具的阈值。 |
| 参数无序导致漏判 | 模型连续重试同一个请求，但 dict key 随机生成导致 signature 字符串不一致。 | 核心修复：必须在生成签名时使用 json.dumps(args, sort_keys=True) 严格固定键序。 |
| 熔断后系统假死 | 熔断器抛出异常后外层未做捕获，导致整个接口崩溃报错 HTTP 500。 | 熔断器作为安全中间件，捕获后应平滑降级：在消息流中追加 System 纠偏消息，提示模型“当前工具参数重复无效，请尝试其他策略或直接总结回答”。 |

### 工程落地经验（生产防坑小贴士）

- 总步数与双模熔断双管齐下：不能只设一个 max_steps=10，因为在 10 步内完全可能发生 8 次死循环，浪费大量 Token 并增加用户等待；必须结合实时签名比对。

- 对敏感写工具零容忍：如果是只读检索工具，可以容忍 2~3 次重试；但对于创建工单、删除记录、划转资金等写操作，consecutive_repeat_threshold 必须硬性设为 1（禁止相同参数重复执行两次），必须配合幂等性 Token。

- 熔断记录打入可观测平台：所有触发 TRIPPED_CONSECUTIVE 或 TRIPPED_CYCLE 的日志必须打上告警标签，作为离线 Badcase 挖掘与 Prompt 优化的第一手数据源。

### 面试怎么讲（三段式：项目背景与选型理由、架构设计与核心机制、踩坑排障与量化收益）

**使用约定：**下面的项目情境和数字仅为虚构示例，不能直接当作本人经历或结果；只使用自己实际参与且有证据的内容。

面试官提问：“在复杂的实际业务中，Agent 经常会因为工具调用参数不对或者找不到信息而无限循环，你们在线上是怎么解决这个问题的？”

回答范式：

- 背景与选型：“在工业安全规程多工具 Agent 的落地过程中，我们发现当检索无结果时，基座大模型经常会‘执迷不悟’，要么连续多次以一模一样的入参重试同一个工具，要么在两个相似工具之间交替打转，造成高昂的 API 账单和延迟恶化。单纯靠 Prompt 提示‘不要重复调用’根本无法保证确定性。”

- 架构与机制：“为此我在 Agent 工具执行分发层实现了一套轻量级的自适应双模熔断器。每次工具调用前，先将入参执行严格的键序字典规范化并生成确定性签名。在滑动窗口内，实时比对连续单步重复（阈值设为 3）和多步周期性振荡（基于模式周期展开匹配，阈值设为 2 次完整周期）。一旦检测到死循环，熔断器立即拦截执行。”

- 踩坑与收益：“早期上线时，由于异步任务查询的合法轮询被误杀，我将只读轮询工具引入了防抖白名单策略并附带轮询衰减因子。上线该机制后，线上失控死循环故障发生率直接降为 0，平均会话异常中断率下降了 34%，同时系统每遇到死循环能够秒级优雅降级转人工，极大提升了生产可用性。”

### 费曼自述与闪卡

费曼自述（3 分钟白板口述框架）：
“Agent 死循环主要有两种形态：一种是‘傻子重试’，即连续多次用相同的参数死磕一个工具；另一种是‘左右横跳’，即 A 工具查不到跳到 B 工具，B 工具查不到又跳回 A 工具。解决办法不能只靠限总步数，必须在工具调用中间件里做指纹比对。第一步，把参数字典排好序转 JSON，算出唯一的签名；第二步，滑动窗口看最近 N 次是不是全一样；第三步，看最近的数据是否符合周期字符串的重复规律。一旦抓到，立即熔断，不给它继续调 API 的机会。”

备考闪卡 Q&A：

- Q：为什么做工具调用去重比对时不能直接将 dict 转 str？
A： 因为不同环境下字典遍历顺序或序列化实现可能不同，导致 key 顺序不一致。必须通过 json.dumps(..., sort_keys=True) 保证绝对确定性。

- Q：除了限制步数和死循环检测，还有哪些核心安全停止条件？
A： 超时硬中断（Wall-clock timeout）、Token 预算消耗上限、用户显式主动取消信号、工具执行出现不可逆致命错误。

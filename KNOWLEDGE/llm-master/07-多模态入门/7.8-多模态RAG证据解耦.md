## 7.8 多模态 RAG：图片证据与文字条款分开核对【⭐ 理解】

〔补充自原仓库镜像〕〔融合 GitHub 教程与本地渐进式例子〕

### 一、提出问题与现实痛点 解决多模态智能体最致命的**“倒果为因”事实幻觉**。在施工安全法规问答中，业务往往涉及两个完全独立的信息源：
1. **视觉画面证据 (Visual Evidence)**：模型在图片里究竟看到了什么（如“右侧工人安全带挂在临边护栏上”）；
2. **制度规程条款 (Regulatory Rules)**：国家或企业现行安全制度究竟是怎么写的（如“高处作业安全带严禁系挂在不稳定结构上”）。

生产排障红线：**“找到了制度条款，绝对不代表图片里有人违规！”**
- 极其恶劣的模型幻觉是：当检索召回了“高空作业必须戴安全帽”的强条款时，大模型在模糊看不清头部的图片上，脑补出“图里工人未戴安全帽”的虚假结论；
- 架构设计原则：**视觉观察与制度条款物理解耦、双路核验**！视觉链只负责如实输出带置信度的目标观察，文本链只负责检索带版本、生效日期的现行有效条款；最后通过确定性规则或结构化判定器合并，证据不充分或制度过期时，坚决路由至“待人工复核”！

---

### 概念：为什么需要这一环

有些项目同时要回答“图中发生什么”和“制度如何规定”。可先用 VLM/检测模型抽取视觉事实，再从文档库检索相关条款，最后把两份证据组合成结论。也可直接索引图像/图文块做跨模态检索，但要单独评估图像召回。

### 二、心智模型与直观图解

大模型最容易犯“有罪推定”。看了严厉的法规，就在看不清的照片里脑补出违规小人。所以看图的和查法规的必须分家。只有图里真拍到了，而且法规是现行有效的，才算数；有一头对不上，老老实实叫人来复核。

```
【多模态 RAG 双路解耦架构】：
切断“以法索图”脑补幻觉，看图的和翻法条的物理隔离！

[现场监控图片] ──> 【视觉链 (只出客观像素事实)】 ──> "画面模糊，无法识别安全带"
                                                        │
[用户问题]     ──> 【文本 RAG 链 (查现行有效规程)】 ──> "《高空规程》第4条(有效)"
                                                        │
                                                        ▼
                                       【后置确定性门禁判定器】
                                       (双路对账：只有图实锤+法有效才放行)
                                                        │
                                                        ▼
                                       判定: 证据不足，【待人工复核】！
                                       (绝不凭严厉法条脑补违规事实！)
```

### 核心概念与五要素表

| 五要素 | 视觉观察与制度法规双路解耦核验器 (Level 8) |
| --- | --- |
| 输入 (Input) | 视觉观察表（含 case_id, image_id, 视觉判定 observation, 引用的 rule_id）、企业制度条款表（含 rule_id, 标题, 版本, 生效起止日期, 页码位置）、核查基准日期 as_of。 |
| 做什么 (Process) | 校验两表字段完整性与 ID 唯一性；将制度生效日期与失效日期解析为标准化对象；验证制度关系约束；执行双路核查：仅当视觉明确判定隐患、且引用的制度在 as_of 处于有效生效期时，才放行状态；任何一方证据不足或过期，一律降级路由为“待人工复核”。 |
| 输出 (Output) | 判定结果表，包含清晰的证据元数据与明确的分流状态 (证据已收集，待核实适用性 / 待人工复核)。 |
| 哪里出错 (Failure Modes) | 1. 引用了已废止的过期制度规程；2. 画面不确定却被制度带偏倒推违规；3. 跨租户制度越权匹配。 |
| 参数影响 (Parameters) | 基准日期 as_of 决定版本有效性；视觉置信度门限控制是否敢于输出确凿的 hazard。 |

### 面试高频追问

【🔥 必会】多模态 RAG 为什么必须将“视觉描述”与“法规检索”解耦为独立链路？
结论先行： 防止模型利用强大的先验语言知识产生“用条款倒推视觉事实”的严重幻觉。
展开解释： 端到端单次 Prompt 混合输入图片和法规时，大模型经常因为读到了严重的法规惩罚条款，潜意识假设输入图片必然存在违法事实，从而将模糊噪点脑补为安全违规。解耦后，视觉模型只以客观观察员身份描述画面像素，检索模块独立寻找现行法规，在控制流中由确定性逻辑核验证据链，彻底切断语言幻觉通道。

【🔥 必会】线上问答引用了准确的制度条款页码，但客户投诉判定结论错误，如何系统化排障？
结论先行： 按照“制度时效性 → 视觉对象归属 → 条款适用除外条件”三步归因。
展开解释： 1. 检查时效性：该制度是否在上个月已由新国标废止替代；2. 检查视觉指代：画面中的作业高度是否满足该制度的起算门槛（如 2 米以上算高处作业，画面中仅 1 米不适用）；3. 检查例外条款：该作业是否具备特许豁免条件，排查模型是否断章取义。

【⭐ 理解】当监控画面严重逆光看不清细节，但向量库召回了强相关安全警示制度时，系统应如何决策？
结论先行： 坚决输出“画面证据不足，待人工复核”，严禁借用制度判定违规。
展开解释： 制度的存在是合规审查的充分条件而非充要条件。在严肃法律与责任溯源场景，必须遵循“无确凿证据即存疑”的原则。系统应如实展示召回的制度作为参考背景，同时明确提示“图像像素受限，已转交现场巡检员实地核查”。

### 生产级代码实现：视觉画面观察与制度法规双路解耦核验器 (Level 8)

```python
"""7.8 视觉画面观察与制度法规双路解耦核验器 (Level 8 进阶实战)

业务场景：
在外企工业合规智能审计中，杜绝“用制度倒推画面事实”的灾难性幻觉。
实现双路证据解耦与时效性审计引擎：
1. 视觉观察链与制度文本链严格分离；
2. 制度起止有效日期的强类型解析与过期校验；
3. 严格规则门禁：只有当“视觉实锤 + 制度在有效期内 + 元数据完整”时，才可放行；
4. 任何证据不充分或制度过期场景，确定性降级路由至“待人工复核”。
"""

from __future__ import annotations
from dataclasses import dataclass
from datetime import date
from typing import Any, Dict, List, Optional


@dataclass(frozen=True)
class VisualObservationRecord:
    """视觉链输出的客观观察记录"""
    case_id: str
    image_id: str
    observation: str      # 必须属于 {"hazard", "clear", "unknown"}
    rule_id: str          # 拟引用的规程 ID


@dataclass(frozen=True)
class RegulatoryRuleRecord:
    """制度文本库中的规程元数据"""
    rule_id: str
    title: str
    version: str
    start_date: str       # YYYY-MM-DD
    end_date: str         # YYYY-MM-DD
    location: str         # 条款位置，如 "第 4 章第 2 条"


@dataclass
class DecoupledVerificationResult:
    """解耦核验判定结果"""
    case_id: str
    image_id: str
    observation: str
    rule_id: str
    rule_version: Optional[str]
    location: Optional[str]
    verification_status: str  # "证据已收集，待核实适用性" 或 "待人工复核"
    audit_notes: str


class MultimodalRAGVerifier:
    """多模态 RAG 双路解耦核验引擎"""

    def __init__(self, rules_catalog: List[RegulatoryRuleRecord]) -> None:
        if not rules_catalog:
            raise ValueError("制度库目录不能为空")

        self.rules_map: Dict[str, RegulatoryRuleRecord] = {}
        self.rules_dates: Dict[str, Tuple[date, date]] = {}

        for r in rules_catalog:
            if not r.rule_id.strip() or r.rule_id in self.rules_map:
                raise ValueError(f"制度 ID 重复或为空: '{r.rule_id}'")
            if not r.title.strip() or not r.version.strip():
                raise ValueError(f"制度 '{r.rule_id}' 缺少有效标题或版本号")

            # 解析生效起止日期
            s_date = date.fromisoformat(r.start_date)
            e_date = date.fromisoformat(r.end_date)
            if s_date > e_date:
                raise ValueError(f"制度 '{r.rule_id}' 生效日期晚于失效日期！")

            self.rules_map[r.rule_id] = r
            self.rules_dates[r.rule_id] = (s_date, e_date)

    def verify_cases(
        self,
        observations: List[VisualObservationRecord],
        as_of_date: date
    ) -> List[DecoupledVerificationResult]:
        """对批量案例执行双路证据与有效性核验"""
        if not observations:
            raise ValueError("视觉观察输入列表不可为空")

        results: List[DecoupledVerificationResult] = []
        seen_case_ids = set()

        for obs in observations:
            if not obs.case_id.strip() or obs.case_id in seen_case_ids:
                raise ValueError(f"case_id 重复或为空: '{obs.case_id}'")
            seen_case_ids.add(obs.case_id)

            if obs.observation not in {"hazard", "clear", "unknown"}:
                raise ValueError(f"未知的视觉观察标签: '{obs.observation}'")

            # 1. 检查引用的制度是否存在
            rule = self.rules_map.get(obs.rule_id)
            if rule is None:
                results.append(
                    DecoupledVerificationResult(
                        case_id=obs.case_id,
                        image_id=obs.image_id,
                        observation=obs.observation,
                        rule_id=obs.rule_id,
                        rule_version=None,
                        location=None,
                        verification_status="待人工复核",
                        audit_notes=f"引用的制度 ID '{obs.rule_id}' 在官方库中不存在"
                    )
                )
                continue

            s_date, e_date = self.rules_dates[obs.rule_id]
            is_rule_in_force = (s_date <= as_of_date <= e_date)

            # 2. 执行核心解耦裁决
            # 必须同时满足：
            # (a) 视觉确凿识别为隐患 (hazard)
            # (b) 图像 ID 真实有效
            # (c) 制度条款在当前日期处于有效生效期
            if obs.observation == "hazard" and obs.image_id.strip() and is_rule_in_force:
                results.append(
                    DecoupledVerificationResult(
                        case_id=obs.case_id,
                        image_id=obs.image_id,
                        observation=obs.observation,
                        rule_id=obs.rule_id,
                        rule_version=rule.version,
                        location=rule.location,
                        verification_status="证据已收集，待核实适用性",
                        audit_notes="画面隐患证据明确，引用规程处于有效施行期"
                    )
                )
            else:
                reason_parts = []
                if obs.observation != "hazard":
                    reason_parts.append(f"视觉证据未确凿证实隐患 (当前判定: {obs.observation})")
                if not is_rule_in_force:
                    reason_parts.append(f"规程已过期或尚未施行 (有效区间: {rule.start_date} ~ {rule.end_date})")

                results.append(
                    DecoupledVerificationResult(
                        case_id=obs.case_id,
                        image_id=obs.image_id,
                        observation=obs.observation,
                        rule_id=obs.rule_id,
                        rule_version=rule.version,
                        location=rule.location,
                        verification_status="待人工复核",
                        audit_notes="; ".join(reason_parts)
                    )
                )

        assert len(results) == len(observations)
        return results


def self_test():
    """验证双路证据解耦、制度时效性过滤与待复核安全路由"""
    # 构建制度库：包含现行制度 r1 和已过期废止制度 r0
    rules_data = [
        RegulatoryRuleRecord(
            rule_id="r1_active",
            title="高处作业安全防护设施规范",
            version="v2.0",
            start_date="2026-01-01",
            end_date="2027-12-31",
            location="第 3 章第 4 条"
        ),
        RegulatoryRuleRecord(
            rule_id="r0_expired",
            title="建筑施工登高作业旧规程（已废止）",
            version="v1.0",
            start_date="2020-01-01",
            end_date="2022-12-31",
            location="第 1 章第 1 条"
        ),
    ]

    verifier = MultimodalRAGVerifier(rules_data)

    current_check_date = date(2026, 11, 11)

    obs_data = [
        # 案例 A：完美闭环（视觉实锤 hazard + 引用现行制度 r1）
        VisualObservationRecord("case_A", "img_001.png", "hazard", "r1_active"),
        # 案例 B：视觉不确定（画面模糊 unknown + 哪怕引用现行制度 r1，也绝不可判定违规！）
        VisualObservationRecord("case_B", "img_002.png", "unknown", "r1_active"),
        # 案例 C：制度过期（视觉实锤 hazard + 但引用的制度 r0 已经过期废止！）
        VisualObservationRecord("case_C", "img_003.png", "hazard", "r0_expired"),
    ]

    results = verifier.verify_cases(obs_data, as_of_date=current_check_date)
    res_dict = {r.case_id: r for r in results}

    # 1. 验证案例 A 放行
    assert res_dict["case_A"].verification_status == "证据已收集，待核实适用性"
    assert "画面隐患证据明确" in res_dict["case_A"].audit_notes
    print("✅ 画面真实且规程现行：合规放行测试通过！")

    # 2. 验证案例 B 拦截（杜绝用制度倒推画面事实！）
    assert res_dict["case_B"].verification_status == "待人工复核"
    assert "视觉证据未确凿证实隐患" in res_dict["case_B"].audit_notes
    print("✅ 画面模糊禁止倒推：安全拦截测试通过！")

    # 3. 验证案例 C 拦截（防引用已过期失效旧制度）
    assert res_dict["case_C"].verification_status == "待人工复核"
    assert "规程已过期" in res_dict["case_C"].audit_notes
    print("✅ 规程失效过期防范：降级复核测试通过！")

    # 4. 边界测试：捕获非法起止日期 (start > end)
    try:
        MultimodalRAGVerifier([
            RegulatoryRuleRecord("bad_r", "错日期", "v1", "2027-01-01", "2026-01-01", "p1")
        ])
        raise AssertionError("未拦截倒挂起止日期")
    except ValueError as e:
        assert "生效日期晚于失效日期" in str(e)
    print("✅ 倒挂日期安全拦截测试通过！")

    print("✅ 7.8 视觉画面观察与制度法规双路解耦核验器自检全部通过！")


if __name__ == "__main__":
    self_test()
```

### 排障指南（常见故障、定位方法、修复策略）

| 常见故障 (Failure) | 定位方法 (Diagnosis) | 修复策略 (Mitigation) |
| --- | --- | --- |
| 模型依据条款倒推幻觉 | 图像明明只拍到脚手架空景，模型却斩钉截铁回答“现场人员未戴安全帽”。 | 在 System Prompt 中注入负向约束，并强制系统执行物理分流：视觉观察模型输出结构化 JSON，文本 RAG 模型不得接触原始图像。 |
| 制度库更新后缓存未失效 | 上周新版安全规范上线，但 RAG 检索仍持续召回废止旧条款。 | 在向量库元数据中建立版本生命周期索引，检索过滤语句强制追加 filter={"status": "in_force", "valid_until": {"$gte": today}}。 |
| 复核率过高造成人工堆积 | 宽松的模糊判定将大量可辨别的合规画面全打成了“待复核”。 | 优化视觉模型的置信度校验逻辑，对于确定无人员作业的空镜头，直接归档为“安全/非作业时段”，无需人工复审。 |

### 工程 trick 与坑

- 不可将检索召回率等同于证据充分度：向量检索即便召回了 Top-1 余弦相似度 0.95 的规程条款，也仅能证明“这段文字很贴切”，绝不代表该条款在此特定工程项目中具有法定约束力。

- 制度版本号必须参与溯源打印：在给终端展示审计卡片时，必须完整打印“《高处作业规程》v2.0 (2026版) 第3章”，严禁只写“根据相关安全规范”，防止法律溯源争议。

- 视觉观察与制度匹配应采用结构化 Schema：视觉模型输出标准化 JSON（如 {"person_detected": true, "safety_belt_hooked": false, "clarity_score": 0.92}），后续由业务规则引擎判定，避免全交给 LLM 生成自由文本。

### 费曼自述与闪卡

费曼自述（3 分钟白板口述框架）：
“多模态 RAG 最容易犯的错误叫‘有罪推定’。比如你让大模型看一张雾蒙蒙的工地照片，同时附带一段《高空作业严禁单人作业，违者扣分》的法规，大模型看完法规手一抖，就会在看不清的雾里脑补出一个违规小人来证明法规有用！这就是经典的倒果为因。怎么破？必须把‘看图的’和‘翻法条的’拆开！看图的模型就专心看图，图里有就是有，没有就是没有，看不清就老老实实写看不清；翻法条的模型去查最新的法规，还要看有没有过期。最后拿到桌面上核对：只有图里真真切切违章了，而且法条还是今天正在施行的，才算数。只要有一头对不上，老老实实叫人来复核！”

备考闪卡 Q&A：

- Q：什么是多模态 RAG 中的“以法索图”幻觉？
A： 模型因为检索到了严厉的处罚条款或安全规定，从而主观臆断并在模糊图像中脑补虚构违规事实的现象。

- Q：双路解耦多模态 RAG 的核心设计是什么？
A： 视觉事实提取与制度条款检索在物理上解耦为独立链路，通过后置确定性门禁比对时效性与证据充分性。

## 7.4 多模态训练数据怎样组织【🔥 必会】

〔补充自原仓库镜像〕〔融合 GitHub 教程与本地渐进式例子〕

### 一、提出问题与现实痛点 彻底根除转行与备考中“按行随机切分数据集”造成的虚假高分与线上翻车。在工地隐患检测等工业场景中，同一监控摄像头可能在几秒内连续抓拍多张作业画面，或者对同一张原图进行了不同角度的裁切标注。如果按照问答行随机切分：
- 极其容易发生**事件级数据泄漏 (Data Leakage)**：相似帧或同图裁切被同时分入了训练集与测试集，导致模型靠“死记硬背背景”获得 99% 的虚假评估高分，一到全新工地准确率就暴跌至 40%；
- 必须严格遵循**事件级隔离 (Event-level Split)**：以同一事件编号 (`event_id`)、拍摄日期或作业场地作为原子隔离切分边界；
- 对无法看清目标的模糊样本建立规范的 `unknown`（不可判断）标注，拒绝让大模型产生强行猜测的幻觉。

---

### 概念：为什么需要这一环

一个可复现的图文样本至少要有媒体路径或 ID、问题/指令、期望输出、数据来源和标注规则。要检查图片能否打开、答案是否只依赖图片、同一图片是否跨训练/验证集泄漏。视频还要标帧时间与片段边界。

### 二、心智模型与直观图解

出考卷绝对不能漏题。工地上一个摄像头几秒内连拍多张，背景完全一样。如果把第一张放训练集，第二张放测试集，模型根本不用认人，光看背景就作弊考了满分。所以切分数据必须以“事件”为边界，严防交叉泄漏！

```
【事件级防泄漏切分 (Event-level Split)】：
同一事件的所有连续帧，作为一个不可拆分的整体打包！

[摄像头 A (10:00:01 抓拍)] ──┐
[摄像头 A (10:00:03 抓拍)] ──┼──> 【同一事件 event_001】 ──> 只能进入【训练集】！
[摄像头 A (10:00:05 抓拍)] ──┘

[摄像头 B (14:30:00 抓拍)] ──┐
[摄像头 B (14:30:02 抓拍)] ──┼──> 【独立事件 event_002】 ──> 才能进入【测试集】！
[摄像头 B (14:30:04 抓拍)] ──┘
```

### 核心概念与五要素表

| 五要素 | 事件级防泄漏多模态数据集校验器 (Level 4) |
| --- | --- |
| 输入 (Input) | 多模态 JSONL 数据清单（每行包含样本 ID、图像路径、事件 ID、分区所属 split、问题、答案、来源元数据）。 |
| 做什么 (Process) | 逐行执行字段非空与规范校验；利用图像库执行文件存在性与尺寸检测；构建 event_id -> split 全局哈希表，执行严格的跨集合重叠防泄漏断言；阻断重复 ID 与坏图。 |
| 输出 (Output) | 清洗后的合规样本清单，或抛出具体的泄漏事件与脏数据行号。 |
| 哪里出错 (Failure Modes) | 1. 同一 event_id 同时出现在 train 与 test 分区；2. 引用了不存在的外部图像路径；3. 标注中的 unknown 样本被随意剔除。 |
| 参数影响 (Parameters) | 切分分组粒度（按秒、按小时、按场地）：粒度越大测试越严苛越贴近真实泛化，但要求数据分布更加广泛。 |

### 面试高频追问

【🔥 必会】多模态数据集为什么绝对不能按问答条目随机 Train/Test Split？
结论先行： 连续帧与同图裁切会引发严重的数据泄漏，造成评估指标严重虚高。
展开解释： 视频监控或现场连拍相隔不足 1 秒，背景、光照、地表纹理几乎完全一致。随机切分会导致模型直接通过记忆特定脚手架形状来回答“是否违规”，而非真正理解安全规则。必须按事件 ID (event_id)、工程标段或拍摄物理日期做隔离切分。

【🔥 必会】线下验证集准确率高达 95%，但部署到新工地后直接跌至 50%，如何系统化排查？
结论先行： 优先排查是否存在事件级数据泄漏以及环境背景的域偏移 (Domain Shift)。
展开解释： 1. 检查数据切分：核验训练集与测试集是否存在同一场景的连拍样本；2. 检查分布偏差：新工地的光照、设备型号、反光背心颜色是否在训练集缺失；3. 建立基线对照：在同分布事件测试集与跨工地的零样本泛化测试集上分别评估，定位泛化盲区。

【⭐ 理解】对于大雾、逆光或镜头遮挡导致人眼也看不清的图片，训练集应该怎么标注？
结论先行： 必须明确标注为统一的“不可判断”(unknown) 标签并参与训练。
展开解释： 绝对不能为了追求正负样本平衡而逼迫标注员强行猜一个“是/否”，这会把脏噪声写入模型参数；更不能直接将这些样本丢弃，否则模型在线上面对恶劣工况时会毫无自知之明地强行编造。教会大模型“在信息不足时诚实拒答”，是应用岗落地极其关键的合规能力。

### 生产级代码实现：事件级防泄漏分组切分与多模态 JSONL 校验器 (Level 4)

```python
"""7.4 事件级防泄漏多模态数据集校验器 (Level 4 进阶实战)

业务场景：
在外企工业合规生产中，构建可追溯、防泄漏的高质量多模态微调与评测数据集。
实现轻量级生产级校验器：
1. 样本字段强类型与必填项校验；
2. 图像文件物理存在性与几何尺寸有效性断言；
3. 严格的跨分区事件级数据泄漏拦截（同一 event_id 绝不可跨集合！）；
4. 重复 ID 冲突防御与不可判断 (unknown) 样本标准化。
"""

from __future__ import annotations
import json
from pathlib import Path
from tempfile import TemporaryDirectory
from typing import Any, Dict, List, Set

try:
    from PIL import Image, UnidentifiedImageError
    HAS_PIL = True
except ImportError:
    HAS_PIL = False


VALID_SPLITS = {"train", "validation", "test"}
REQUIRED_FIELDS = ("id", "image", "event_id", "split", "question", "answer", "source")


def validate_single_record(row_data: Any, dataset_root: Path, line_no: int) -> Dict[str, str]:
    """严格校验单条图文记录"""
    if not isinstance(row_data, dict):
        raise ValueError(f"第 {line_no} 行不是合法的 JSON 对象")

    # 1. 必填字段非空检查
    clean_record: Dict[str, str] = {}
    for f in REQUIRED_FIELDS:
        val = row_data.get(f)
        if not isinstance(val, str) or not val.strip():
            raise ValueError(f"第 {line_no} 行缺少必填文本字段 '{f}'")
        clean_record[f] = val.strip()

    # 2. 分区合法性检查
    if clean_record["split"] not in VALID_SPLITS:
        raise ValueError(f"第 {line_no} 行分区 '{clean_record['split']}' 非法，必须为 {VALID_SPLITS}")

    # 3. 图像文件物理存在性与尺寸检查
    image_file = dataset_root / clean_record["image"]
    if not image_file.is_file():
        raise ValueError(f"第 {line_no} 行引用的图像文件不存在: {image_file}")

    if HAS_PIL:
        try:
            with Image.open(image_file) as img:
                w, h = img.size
                if w <= 0 or h <= 0:
                    raise ValueError(f"第 {line_no} 行图像几何尺寸非法: {w}x{h}")
                img.verify()
        except (UnidentifiedImageError, OSError, Exception) as exc:
            raise ValueError(f"第 {line_no} 行图像文件损坏无法解析: {image_file}") from exc

    return clean_record


def validate_multimodal_manifest(manifest_path: Path) -> List[Dict[str, str]]:
    """读取多模态 JSONL 数据清单，执行全局去重与事件级跨分区泄漏检测"""
    if not manifest_path.is_file():
        raise ValueError(f"数据清单文件不存在: {manifest_path}")

    validated_records: List[Dict[str, str]] = []
    seen_sample_ids: Set[str] = set()
    event_split_mapping: Dict[str, str] = {}  # 记录 event_id -> 所属 split

    dataset_root = manifest_path.parent

    with manifest_path.open("r", encoding="utf-8") as f:
        for line_no, line in enumerate(f, 1):
            line_str = line.strip()
            if not line_str:
                continue

            try:
                raw_json = json.loads(line_str)
            except json.JSONDecodeError as exc:
                raise ValueError(f"第 {line_no} 行 JSON 语法损坏") from exc

            record = validate_single_record(raw_json, dataset_root, line_no)

            # 全局 ID 唯一性校验
            sample_id = record["id"]
            if sample_id in seen_sample_ids:
                raise ValueError(f"第 {line_no} 行存在重复的样本 ID: '{sample_id}'")
            seen_sample_ids.add(sample_id)

            # 核心防线：事件级跨集合防泄漏断言！
            event_id = record["event_id"]
            current_split = record["split"]

            if event_id in event_split_mapping:
                recorded_split = event_split_mapping[event_id]
                if recorded_split != current_split:
                    raise ValueError(
                        f"严重数据泄漏！事件 '{event_id}' 同时出现在 '{recorded_split}' 与 '{current_split}' 分区！"
                    )
            else:
                event_split_mapping[event_id] = current_split

            validated_records.append(record)

    if not validated_records:
        raise ValueError("数据清单不能为空")

    assert len(validated_records) == len(seen_sample_ids)
    return validated_records


def self_test():
    """验证正常数据集加载、事件级数据泄漏拦截与损坏文件防御"""
    with TemporaryDirectory() as tmp_dir:
        root = Path(tmp_dir)

        # 创建两张虚拟真实图片
        img1 = root / "frame_01.png"
        img2 = root / "frame_02.png"
        if HAS_PIL:
            Image.new("RGB", (32, 32), "white").save(img1)
            Image.new("RGB", (32, 32), "white").save(img2)
        else:
            img1.write_bytes(b"dummy")
            img2.write_bytes(b"dummy")

        manifest_file = root / "train_manifest.jsonl"

        # 1. 验证合法合规数据集加载
        legal_rows = [
            {
                "id": "q1",
                "image": "frame_01.png",
                "event_id": "event_tower_crane_001",
                "split": "train",
                "question": "工人是否佩戴安全带？",
                "answer": "已佩戴双钩安全带",
                "source": "site_cam_01"
            },
            {
                "id": "q2",
                "image": "frame_02.png",
                "event_id": "event_scaffold_002",
                "split": "test",
                "question": "脚手架护栏是否合规？",
                "answer": "unknown",  # 合法的不可判断标签
                "source": "site_cam_02"
            }
        ]
        manifest_file.write_text(
            "\n".join(json.dumps(r, ensure_ascii=False) for r in legal_rows),
            encoding="utf-8"
        )

        res = validate_multimodal_manifest(manifest_file)
        assert len(res) == 2
        print("✅ 合规多模态数据清单加载测试通过！")

        # 2. 验证核心防线：拦截事件级跨分区数据泄漏！
        # 故意构造：同一事件 event_tower_crane_001 又在 test 分区出现了一张新图
        leaked_rows = legal_rows + [
            {
                "id": "q3_leak",
                "image": "frame_01.png",
                "event_id": "event_tower_crane_001",  # 泄漏！与 q1 属于同一事件
                "split": "test",                      # 却落入 test 分区！
                "question": "画面中作业高度是多少？",
                "answer": "约 15 米",
                "source": "site_cam_01"
            }
        ]
        manifest_file.write_text(
            "\n".join(json.dumps(r, ensure_ascii=False) for r in leaked_rows),
            encoding="utf-8"
        )
        try:
            validate_multimodal_manifest(manifest_file)
            raise AssertionError("未拦截跨分区事件数据泄漏")
        except ValueError as e:
            assert "严重数据泄漏" in str(e)
            assert "event_tower_crane_001" in str(e)
        print("✅ 跨分区事件数据泄漏拦截测试通过！")

        # 3. 验证损坏/不存在文件拦截
        missing_file_rows = [
            {
                "id": "q4_bad",
                "image": "non_existent.png",
                "event_id": "e3",
                "split": "train",
                "question": "是否存在隐患？",
                "answer": "是",
                "source": "cam"
            }
        ]
        manifest_file.write_text(
            "\n".join(json.dumps(r, ensure_ascii=False) for r in missing_file_rows),
            encoding="utf-8"
        )
        try:
            validate_multimodal_manifest(manifest_file)
            raise AssertionError("未拦截不存在的图像路径")
        except ValueError as e:
            assert "图像文件不存在" in str(e)
        print("✅ 缺失图像文件安全拦截测试通过！")

    print("✅ 7.4 事件级防泄漏分组切分与多模态 JSONL 校验器自检全部通过！")


if __name__ == "__main__":
    self_test()
```

### 排障指南（常见故障、定位方法、修复策略）

| 常见故障 (Failure) | 定位方法 (Diagnosis) | 修复策略 (Mitigation) |
| --- | --- | --- |
| 线下验证高分、跨工地泛化暴跌 | 检查数据划分日志，发现同一次高空作业的连拍截图同时散落在 Train 与 Test 集中。 | 重新生成划分：根据视频源、物理工区 ID 与采集日期做 GroupKFold，确保评估集具备完全独立的工程背景。 |
| 训练中途抛出图片解码崩溃 | 训练跑了 5 个 Epoch 突然因某张损坏图片报 UnidentifiedImageError 崩溃退出。 | 在开始任何微调之前，必须先用校验器进行离线全量扫描与 verify() 检查，将损坏样本提前隔离或重传。 |
| 模型学会把不确定样本强行猜错 | 查看 Badcase，大雾或反光严重时模型依然极其自信地给出错误判断。 | 在训练集中补充至少 5%~10% 的工况受限样本，显式将目标 Label 训练为“图像模糊，请人工复核”。 |

### 工程 trick 与坑

- 不可忽视语义近重复检索：即使 event_id 不同，有些巡检人员在同一工位换了个角度再次拍照。进阶方案是使用离线轻量 ResNet/DINO 提取全量图片 Embedding，过滤余弦相似度 > 0.95 的近重复图像对。

- 严防标注格式污染：在多轮对话 JSONL 中，有些标注员将答案写成带有私有格式的 Markdown 表格或夹杂特定括号，导致 Loss 计算被非核心标点主导；必须在入库前进行规则清洗。

- 保持元数据版本严密回溯：每一批参与训练的 JSONL 必须使用 MD5/Git Commit 锁定版本，训练日志必须记录数据集 SHA256，确保任何一次实验结果都能 100% 精确复现。

### 费曼自述与闪卡

费曼自述（3 分钟白板口述框架）：
“做大模型数据，千万别随手写个 train_test_split。为什么？因为工地上一个摄像头一秒能拍好几张，如果第一张在训练集、第二张在测试集，大模型根本不用看人戴没戴帽子，它看一眼后面的红色脚手架就知道这组图全没戴！这叫‘背景作弊’。怎么防？必须按‘事件’来分。一件事的所有图，要么全进训练集，要么全进测试集，老死不相往来。另外，人眼都看不清的图，千万别逼模型瞎猜，教它老老实实答‘看不清’，这在实际工程里比瞎猜更值钱。”

备考闪卡 Q&A：

- Q：什么是事件级数据切分（Event-level Split）？
A： 将同一时间段、同一机位或同一事件的所有连续帧与裁切图作为一个不可拆分的整体，归入同一个数据分区，严防背景信息泄漏。

- Q：训练集中的 unknown 样本有什么战略价值？
A： 赋予模型认识自身能力边界的自省能力，降低在恶劣模糊条件下的强行幻觉与误报风险。

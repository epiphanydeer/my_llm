# 第十一章：模型动态与产品新闻

> 本章优先级：◻ 按需查阅，37 篇新闻**不纳入背诵和间隔复习**。原仓库把动态文章放在第十一章；它们能提供行业线索，但价格、产品能力、开放范围和岗位都会变化。逐文件目录（详见本仓库逐篇精读索引）列出全部文章。以下总结的是**读新闻的方法**，不把当时的数字当长期事实。

## 11.1 新模型发布怎么看【◻】

**一句话：** 对新模型只问与你任务相关的四件事：输入输出能力、独立评测、运行约束、可复现程度。

**例子：** 一篇 VLM 新闻展示复杂截图识别成功案例，这说明“可能值得试”，不说明你的工业隐患图片能达到同样准确率。先用自己的固定测试集测小目标、遮挡、夜间和条款问答，再看速度与成本。

**费曼自述：** “发布文章让我知道有候选模型；选模型仍靠官方文档和自己的数据。”

**概念闪卡：** Q：单个漂亮案例能证明模型整体能力吗？A：不能。Q：看新 VLM 最该补哪种证据？A：目标数据上的独立测试和失败样本。

## 11.2 价格、缓存与订阅新闻怎么看【◻】

**一句话：** 记住 token 与请求成本的算法，不背某天的单价。核对官方当前定价、缓存规则、长上下文档位及配额。

**例子：** 新闻说 API 降价，实际部署还有输出 token、Rerank、图片输入、重试和 GPU 运维费用。要估算每 1000 次真实请求成本，而不是只看输入单价。

**费曼自述：** “价格是会变的数字；成本模型和计量口径才值得长期记。”

**概念闪卡：** Q：价格变化时先改什么？A：成本表里的官方单价、缓存命中、请求量假设。Q：为什么模型便宜不等于系统便宜？A：可能需要更多调用、较长输出或额外工具链。

## 11.3 Agent harness、AI 编程与工具事件【◻】

**一句话：** 关注“一个任务怎样被规划、执行、测试和恢复”，但不要把某产品的使用教程直接当成通用工程原理。

**例子：** 招聘文章提到 harness，可把它拆成：工具权限、任务循环、状态、验收、日志与恢复。若你以后投 Agent harness 岗，再用具体 JD 检查 Python/后端/系统要求；当前的视觉＋RAG 主项目不因为新闻热词就改方向。

**费曼自述：** “工具名称会变，但让 Agent 可靠完成任务的机制值得学。”

**概念闪卡：** Q：一篇‘某公司招 harness 工程师’能证明所有目标岗位都要求 harness 吗？A：不能。Q：harness 与模型权重有什么区别？A：前者是围绕模型运行任务的工具、控制与反馈系统。

## 11.4 故障、安全与行业事件【◻】

**一句话：** 事件类文章可以启发风险清单，但事实与原因要回到官方公告和可验证材料；不需要背事件日期或传闻。

**例子：** 平台宕机提醒我们做超时和降级；账号或权限事件提醒我们审计谁能看什么资料。某篇报道的猜测不能直接写成系统设计依据。

**费曼自述：** “我从事件里提炼可复用的工程问题，再找一手证据核对事实。”

**概念闪卡：** Q：平台故障对自己项目的直接启发？A：重试、超时、降级、监控。Q：新闻可直接作为模型规格依据吗？A：先核官方说明。

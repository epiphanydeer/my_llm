## 附.7 验证循环：反馈、修正与停止【⭐ 理解】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 一个候选方案经过验证未通过时，可将明确反馈用于下一次尝试；如果达到预算或候选无效，应停止并保留失败状态。工具调用底层协议见第 4.4 节。

### 一、为什么只写 Prompt 不够了？

先别急着把 prompt 贬得一文不值。

Prompt 当然有用。

你问一个概念，让 AI 解释一下。

你贴一段代码，让 AI 帮你改写。

你让它生成一个 SQL、一个正则、一个接口文档。

这些场景里，prompt 就够了。

因为任务短、边界清楚、结果也容易人工判断。

但 AI 编程不是只做这种小任务。

真实项目里，你让 Claude Code 修一个 bug，往往不是一句话就能完成。

它要先读代码。

要定位调用链。

要判断哪个文件该改，哪个文件不能动。

要修改实现。

要跑测试。

测试失败了，还要回头看日志。

日志里可能暴露了另一个问题。

修完之后，还要确认没有引入新的副作用。

这时候你会发现，**prompt 只是任务的起点，不是任务的完成机制。**

你写一句：

“帮我修一下登录失败的问题。”

这句话只表达了目标。

但它没有说：

- 去哪里找入口
- 哪些文件不能动
- 怎么判断修好了
- 测试失败了怎么办
- 什么时候必须停下来问人
- 什么改动算越界

这些东西如果都靠模型自己猜，就会出现两个问题。

第一，模型会浪费大量上下文摸索。

第二，模型可能看起来很努力，最后却朝错方向越走越远。

很多录友说“AI 写代码不稳定”，根源不是它每一行代码都差。

而是你只给了它一个 prompt，却没有给它一个能稳定工作的闭环。

### 概念与数据流

| 五要素 | 验证驱动循环 |
| --- | --- |
| 输入 | 候选生成函数、验证函数和最大尝试数。 |
| 做什么 | 生成候选、验证并反馈；成功、无效候选或预算耗尽时退出。 |
| 输出 | 终止状态及每次候选与验证记录。 |
| 哪里出错 | 验证标准太弱、反馈丢失、循环不终止、重复副作用。 |
| 参数影响 | 最大步数、验证范围与反馈质量影响成功率、成本和延迟。 |

Loop 不是无限重试。验证函数是否覆盖任务目标、生成是否有副作用，以及失败如何恢复，都需要按任务设计；本例完全使用内存中的虚构函数。

### 面试追问

【⭐ 理解】为什么只有提示词还不足以构成可靠任务闭环？ 结论：还需要执行、观察和验证。应明确状态与预算，并能区分真实成功、失败及无法确认。

【🔥 必会】循环总在重复失败怎么排查？ 结论：检查反馈是否进入下一步及终止条件。记录每次候选和验证结果；限制次数，避免重复执行有副作用的操作。

【◻ 按需】验证通过就一定正确吗？ 结论：不一定。验证器可能覆盖不足或标准错误，应结合实际需求和独立测试。

### 故障模式与排障

- 循环停不下来：检查步数与截止条件；预算耗尽返回明确失败。

- 反馈没有改变后续方案：对比每步输入、候选和反馈；检查是否正确传递，并分析重复原因。

- 验证通过但任务仍错误：审查验收标准与覆盖范围，补独立测试和人工复核。

### 工程 trick 与坑

- 本例只模拟内存中的候选和验证，不执行代码、不访问模型或工具。

- 重试有外部副作用时需设计幂等和状态核对，不能简单重复。

- 验证通过仅表示通过了所写规则，不保证全面正确。

### Toy code：有限验证循环

运行前提：Python 3.10+，标准库，所有候选与反馈均为虚构。

```python
"""演示由验证结果驱动的有限状态循环；操作均为虚构。"""
from dataclasses import dataclass
from typing import Callable


@dataclass(frozen=True)
class Step:
    """一次尝试的候选和验证结果。"""
    candidate: str
    valid: bool
    feedback: str


def loop(propose: Callable[[str, int], str], verify: Callable[[str], tuple[bool, str]],
         max_steps: int) -> tuple[str, tuple[Step, ...]]:
    """有界生成与验证；成功、无效候选和预算耗尽分开返回。"""
    if isinstance(max_steps, bool) or not isinstance(max_steps, int) or max_steps <= 0:
        raise ValueError('最大步数必须为正整数')
    history: list[Step] = []
    feedback = ''
    for index in range(1, max_steps + 1):
        candidate = propose(feedback, index)
        if not isinstance(candidate, str) or not candidate.strip():
            return 'invalid_candidate', tuple(history)
        passed, feedback = verify(candidate)
        if not isinstance(passed, bool) or not isinstance(feedback, str):
            raise ValueError('验证器应返回 bool 和字符串')
        history.append(Step(candidate, passed, feedback))
        if passed:
            return 'complete', tuple(history)
    assert len(history) == max_steps
    return 'budget_exhausted', tuple(history)


def main() -> None:
    """覆盖错误反馈后成功、预算耗尽、空候选与非法步数。"""
    def propose(feedback: str, step: int) -> str:
        return '修正方案' if feedback == '需要修正' else '初始方案'
    def verify(candidate: str) -> tuple[bool, str]:
        return (candidate == '修正方案', '通过' if candidate == '修正方案' else '需要修正')
    status, history = loop(propose, verify, 3)
    assert status == 'complete' and len(history) == 2
    assert loop(propose, verify, 1)[0] == 'budget_exhausted'
    assert loop(lambda feedback, step: '', verify, 1)[0] == 'invalid_candidate'
    try:
        loop(propose, verify, 0)
    except ValueError:
        pass
    else:
        raise AssertionError('零步预算必须拒绝')
    print('虚构验证循环的成功、失败和停止条件自检通过。')
    print('验证器只模拟规则，不能证明真实代码或模型任务已完成。')


if __name__ == '__main__':
    main()

```

逐段理解。 Step 保存每次尝试；loop 在步数内生成并验证，根据结果成功退出或返回预算耗尽；自检覆盖反馈修正、空候选与错误预算。

### 这段代码怎么在面试里讲

- 不变量：尝试次数不超过上限，每条历史包含候选和验证结果。

- 关键过程：验证失败后将反馈传给下一次生成，成功时停止。

- 边界与坑：本例验证器是假规则，没有处理超时、权限或真实副作用；通过不等于任务可靠完成。

### 本节收尾：费曼自述与闪卡

费曼自述： 任务循环应生成、验证、反馈并有停止预算；验证的质量和副作用控制决定它能否用于真实系统。

- 问：有循环就可以无限重试吗？答：不可以，要限制预算并明确终止。

- 问：验证通过一定正确吗？答：不一定，可能存在覆盖不足。

- 问：本例是否运行真实模型或工具？答：没有，均为内存模拟。

- 问：重试写操作要注意什么？答：幂等、状态核对及副作用。

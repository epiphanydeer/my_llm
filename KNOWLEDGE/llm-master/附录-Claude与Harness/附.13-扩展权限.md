### 四层能力放在一起，到底怎么选

现在回到最容易混淆的问题：一条新要求来了，应该写到哪里？

![根据常驻知识事件触发专项方法和上下文隔离判断一条要求应该放进CLAUDE.md、Hooks、Skills还是Subagents](https://file1.kamacoder.com/i/web/20260713152556_claude_code_extensions_04_decision_compressed.png?v=20261005)

这张图回答的是：如何根据“是否每次都要知道、是否必须自动发生、是否需要专项推理、是否需要隔离上下文”逐层判断。它不是让你四选一，而是帮你找到一条要求最主要的归属层。

可以记住四个问题：

| 判断问题 | 应该放哪里 | 典型例子 |
|---|---|---|
| Claude 是否每次都应该知道？ | `CLAUDE.md` | 技术栈、目录、构建命令、禁区 |
| 是否命中事件就必须执行？ | Hooks | 格式化、阻止危险命令、记录审计 |
| 是否只在某类任务中需要一套方法？ | Skills | 发布、评审、排障、数据分析 |
| 是否需要独立上下文或独立角色？ | Subagents | 大范围探索、安全复核、并行测试 |

还是支付模块的例子：

1. `CLAUDE.md` 写清金额单位、项目命令和数据库禁区；
2. Hook 在文件修改后跑静态检查，在危险操作前做拦截；
3. Skill 保存支付评审方法、风险规则和验证脚本；
4. Subagents 分别检查安全、测试和性能，主 Agent 汇总证据。

你会发现，四层能力不是互相竞争，而是分别控制 Agent 的四个位置：

**上下文里放什么，生命周期中卡什么，任务需要时加载什么，复杂工作交给谁。**

### 概念与数据流

| 五要素 | 说明 |
| --- | --- |
| 输入 | 工具名、动作、目标范围和已批准的授权条目。 |
| 做什么 | 检查目录无冲突，再匹配工具、动作与范围。 |
| 输出 | 允许或拒绝；配置冲突抛错。 |
| 哪里出错 | 未知扩展默认放行、同名配置冲突、授权检查未落到执行端。 |
| 参数影响 | 权限范围、授权有效期、来源信任和版本影响可用性与风险。 |

### 面试追问

【⭐ 理解】扩展装好就能安全使用吗？ 结论：不能。还要审查来源、版本、具体权限，并在真实执行端强制限制。

【⭐ 理解】为什么检查不应只放在 prompt？ 结论：文本指令不是授权边界。实际工具服务或运行环境必须自行检查身份与权限。

【⭐ 理解】工具意外访问不应访问的数据怎么排查？ 结论：核对身份、范围和执行日志。检查授权决策与工具端实际约束是否一致。

### 故障模式与排障

- 同名扩展配置不一致：列出来源、版本和冲突项，明确唯一配置后再启用。

- 未知工具被调用：检查默认策略，采用拒绝未知项并记录原因。

- 提示词要求只读但仍有写入：检查工具服务的实际授权与审计，不依赖模型自觉。

### 工程 trick 与坑

- 示例的范围是精确字符串匹配，不实现身份认证、文件系统隔离或权限继承。

- 扩展版本和能力有时效性，部署前以实际产品版本与官方文档核对。

- 规则文件、技能和子代理是不同能力，权限不能默认互相继承。

### Toy code：工具授权目录

运行前提：Python 3.10+，标准库，不安装或调用扩展。

```python
"""检查虚构工具的授权目录；不加载或执行真实扩展。"""
from dataclasses import dataclass


@dataclass(frozen=True)
class Grant:
    """工具名、允许的动作及有效范围，均为虚构字符串。"""
    name: str
    actions: frozenset[str]
    scope: str


def authorize(grants: list[Grant], name: str, action: str, scope: str) -> bool:
    """核对唯一工具授权；未知工具、动作或范围均拒绝。"""
    if not all(isinstance(x, str) and x.strip() for x in (name, action, scope)):
        raise ValueError('请求字段不能为空')
    index: dict[str, Grant] = {}
    for grant in grants:
        if (not grant.name.strip() or not grant.scope.strip() or not grant.actions or
                any(not isinstance(x, str) or not x.strip() for x in grant.actions)):
            raise ValueError('授权记录非法')
        if grant.name in index:
            raise ValueError('工具名重复，不能猜测应采用哪条')
        index[grant.name] = grant
    entry = index.get(name)
    allowed = entry is not None and action in entry.actions and scope == entry.scope
    assert isinstance(allowed, bool)
    return allowed


def main() -> None:
    """覆盖允许、未知工具、动作、范围、空字段和配置冲突。"""
    grant = Grant('search', frozenset({'read'}), 'public_docs')
    assert authorize([grant], 'search', 'read', 'public_docs')
    assert not authorize([grant], 'search', 'write', 'public_docs')
    assert not authorize([grant], 'search', 'read', 'private_docs')
    assert not authorize([grant], 'unknown', 'read', 'public_docs')
    assert not authorize([], 'search', 'read', 'public_docs')
    for records, name in (([grant, grant], 'search'), ([grant], '')):
        try:
            authorize(records, name, 'read', 'public_docs')
        except ValueError:
            pass
        else:
            raise AssertionError('冲突或空字段必须拒绝')
    print('虚构授权目录自检通过；实际权限仍需执行端强制检查。')


if __name__ == '__main__':
    main()
```

逐段理解。 Grant 保存授权；authorize 构造唯一索引并做精确匹配；自检覆盖未知工具、越权动作和冲突。

### 这段代码怎么在面试里讲

- 不变量：工具名唯一，请求字段非空，只允许显式匹配的动作和范围。

- 关键过程：先检查配置，再查询条目；未知值返回拒绝。

- 边界与坑：本例不提供认证或真正的执行隔离，真实系统必须在工具端执行授权。

### 本节收尾：费曼自述与闪卡

费曼自述： 扩展提供能力，授权决定谁能对什么执行哪些动作；模型收到的提示不能替代工具端权限检查。

- 问：未知工具默认怎样处理？答：拒绝并记录。

- 问：prompt 能替代权限检查吗？答：不能。

- 问：同名配置冲突如何处理？答：拒绝并明确唯一来源。

- 问：本例实现真实身份认证吗？答：没有。

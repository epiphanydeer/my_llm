## 附.1 CLI：参数、退出码与超时【◻ 按需】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 Agent 调用命令行工具时，程序应区分正常退出、非零退出和超时，记录实际输出，而不是把模型说“执行了”当成执行证据。

### CLI 的前世今生：它从来不只是“黑框里敲字”

先把三个词掰清楚：Terminal 是承载输入输出的终端，Shell 是解释命令的程序，CLI 是用文本命令和软件交互的方式。Claude Code、Codex CLI 今天已经是带面板、状态和快捷键的 TUI，但它们真正依赖的底座，仍然是 Shell、文件系统和一整套命令行工具。

最早的计算机甚至谈不上命令行。人把程序打在卡片上，交给机器批处理，结果晚点再拿回来。**人和机器之间没有实时对话。**

后来分时系统和终端出现，人终于可以输入一行命令，马上看到一行结果。到了 Unix，Shell 又做了一次关键升级：它不只是启动程序的入口，还是一门可以组合程序的控制语言。

`stdin`、`stdout`、`stderr`、退出码、重定向、管道，这几个设计看起来朴素，却把一堆小工具接成了工作流。1978 年 Bourne 对 Unix Shell 的定义里，就已经同时强调了控制流、环境、重定向和进程管道。

GUI 兴起后，命令行没有消失。因为 GUI 解决的是**人的发现成本**：按钮摆在那里，不会写命令也能点。CLI 解决的是**系统的组合成本**：一个命令能进脚本、进 CI、跑远程机器，还能把输出交给下一个程序。

到了云原生时代，Git、Docker、Kubernetes、Terraform、各种云平台，几乎都把 CLI 当成一等公民。原因很简单：服务器没有必要配一块屏幕，自动化也不会拿鼠标点按钮。

Agent 时代，命令行又转了一圈回来。但这次敲命令的主角，开始从人变成模型。

![](https://file1.kamacoder.com/i/web/2026-07-16_10-48-27.jpg?v=20261005)

这张图回答的是：CLI 为什么在 GUI 时代没有死，到了 Agent 时代反而又站到前台。变化的不是命令行突然变好用了，而是“把人的意图翻译成精确语法”这份苦活，从人转移给了 Agent；CLI 原本最劝退人的门槛，恰好被大模型吃掉了。

### 概念与数据流

| 五要素 | 本地 CLI 调用 |
| --- | --- |
| 输入 | 受信任的可执行程序、参数和超时。 |
| 做什么 | 启动子进程、等待完成、收集退出码与标准输出/错误。 |
| 输出 | 成功、失败、启动错误或超时状态及可用输出。 |
| 哪里出错 | 程序不存在、参数错误、超时、输出解码失败、错误地执行不可信命令。 |
| 参数影响 | 超时、工作目录、环境变量和参数影响行为及可复现性。 |

CLI 提供可组合的文本接口，但退出码和输出仍需应用解释。本例仅运行程序内固定的受信任 Python 字符串；shell=False 避免通过 shell 解析参数，但不是执行不可信代码的沙箱。真实 Agent 工具需独立设计权限、执行隔离和审计。

### 面试追问

【⭐ 理解】模型说测试通过，怎样核实？ 结论：查看真实命令结果。检查退出码、输出、运行目录和测试范围；没有执行记录不能声称通过。

【🔥 必会】工具执行超时怎么办？ 结论：记录未完成并按任务处理。检查子进程状态和副作用，再决定重试或人工介入；不能把超时当成功。

【⭐ 理解】shell=False 是否保证运行不可信代码安全？ 结论：不能。它只改变命令解析方式，不限制程序本身的文件、网络和进程能力。

### 故障模式与排障

- 命令启动失败：核对可执行文件、路径和环境；记录错误类型并保持失败状态。

- 非零退出被忽略：检查退出码和 stderr；按工具约定映射状态，不只看 stdout。

- 超时后状态不明确：核查进程及业务副作用；按实际执行环境设计清理与恢复，本例不保证清理所有后代进程。

### 工程 trick 与坑

- 示例固定调用当前 Python 解释器，仅用于运行可信示例；不要将模型生成或用户提供的任意代码直接传入。

- subprocess.run 的超时处理不等于完整的进程树和外部副作用管理。

- 示例不实现真实 Agent 工具权限、容器隔离或跨平台进程管理。

### Toy code：退出码与超时

运行前提：Python 3.10+，标准库；仅启动当前解释器运行代码内的固定示例。

```python
"""在本地运行受信任的 Python 示例，检查退出码、超时与输出。"""
from dataclasses import dataclass
import math
import subprocess
import sys


@dataclass(frozen=True)
class CommandResult:
    """本地子进程的状态、退出码和输出。"""
    status: str
    exit_code: int | None
    stdout: str
    stderr: str


def run_python(source: str, timeout_s: float) -> CommandResult:
    """运行受信任示例代码；此函数不适合执行用户或模型提供的代码。"""
    if not isinstance(source, str) or not source.strip():
        raise ValueError('示例代码不能为空')
    if not math.isfinite(timeout_s) or timeout_s <= 0:
        raise ValueError('超时必须是正有限数')
    try:
        result = subprocess.run([sys.executable, '-c', source], shell=False, capture_output=True,
                                text=True, encoding='utf-8', timeout=timeout_s, check=False)
    except subprocess.TimeoutExpired:
        return CommandResult('timeout', None, '', '')
    except OSError as exc:
        return CommandResult('start_error', None, '', type(exc).__name__)
    return CommandResult('ok' if result.returncode == 0 else 'failed', result.returncode,
                         result.stdout, result.stderr)


def main() -> None:
    """检查成功、非零退出、超时及非法输入。"""
    ok = run_python("print('hello')", 5.0)
    assert ok.status == 'ok' and ok.exit_code == 0 and ok.stdout.strip() == 'hello'
    failed = run_python('import sys; sys.exit(3)', 5.0)
    assert failed.status == 'failed' and failed.exit_code == 3
    timeout = run_python('import time; time.sleep(1)', 0.05)
    assert timeout.status == 'timeout' and timeout.exit_code is None
    for source, seconds in (('', 1.0), ('pass', 0.0), ('pass', float('nan'))):
        try:
            run_python(source, seconds)
        except ValueError:
            pass
        else:
            raise AssertionError('空代码或非法超时必须拒绝')
    print('本地受信任示例的退出码与超时自检通过。')
    print('shell=False 不是执行不可信代码的安全沙箱。')


if __name__ == '__main__':
    main()

```

逐段理解。 CommandResult 保存状态；run_python 使用参数列表和 shell=False，区分正常、非零退出、超时与启动错误；自检覆盖主要分支。

### 这段代码怎么在面试里讲

- 不变量：代码和超时参数非空有效；只有退出码为 0 的结果才标为成功。

- 关键过程：启动受信任子进程，捕获输出并按退出状态映射结果。

- 边界与坑：shell=False 不是沙箱；超时和退出码不能证明副作用已回滚，也不保证清理全部后代进程。

### 本节收尾：费曼自述与闪卡

费曼自述： CLI 工具要看实际退出码和输出，超时就是未完成；执行权限和副作用管理需要独立设计。

- 问：模型说执行成功就够吗？答：不够，要看真实命令与退出结果。

- 问：shell=False 是安全沙箱吗？答：不是。

- 问：超时代表副作用一定没发生吗？答：不一定，应核查实际状态。

- 问：本例运行任意用户代码安全吗？答：不安全，只用于固定可信示例。

目标 + 例子。 Agent 环境可能包含项目规则、按需技能、工具、钩子与插件；先确认各自用途、版本和权限，再决定是否启用。以下清单是通用模拟，不读取真实 Claude Code 配置。

### 一、为什么只会和 Claude Code 聊天，迟早会乱？

刚开始用 Claude Code，临时聊天完全够用。

“这个项目用 pnpm。”

“改完记得跑单测。”

“不要直接改数据库。”

“发版前按我们的清单检查。”

问题是，真实项目不会只聊三轮。

Claude 要读几十个文件、跑一堆命令、处理测试失败，还可能经历上下文压缩。**你临时说过的话，会和越来越多的新信息挤在同一个上下文里。**

团队协作更麻烦。

你告诉过 Claude 的规则，换个同事、换台电脑、换个项目，又要从头再讲一遍。

![临时聊天规则被新消息淹没](https://file1.kamacoder.com/i/web/20260729153229_claude_code_toolkit_02_background-compressed.jpg?v=20261005)

这张图讲的是：**聊天适合表达当前任务，不能承载整套工程制度。** 规则只存在聊天里，任务一长就容易被稀释；经验只存在个人会话里，团队就无法复用。

所以 Claude Code 的扩展能力，本质上都在回答下面六个问题：

| 问题 | 应该用什么 |
|---|---|
| 每次进入项目都应该知道什么？ | `CLAUDE.md` |
| 某类任务应该按什么方法做？ | Skills |
| 哪些工作需要独立上下文或独立角色？ | Subagents |
| 怎么访问仓库外的系统和数据？ | MCP |
| 哪些动作命中事件就必须执行？ | Hooks |
| 怎么把整套能力发给其他项目和队友？ | Plugins |

先记住一句：

**CLAUDE.md 管常驻规则，Skill 管按需方法，Subagent 管独立干活，MCP 管外部连接，Hook 管确定性动作，Plugin 管打包分发。**

### 概念与数据流

| 五要素 | 扩展能力清单 |
| --- | --- |
| 输入 | 扩展名称、类别、版本及启用状态。 |
| 做什么 | 校验名称和类别，统计启用项；具体加载由真实产品负责。 |
| 输出 | 每种类别的启用数量，或明确的配置错误。 |
| 哪里出错 | 名称冲突、版本过期、权限过宽、把说明文件当成自动执行保障。 |
| 参数影响 | 启用范围、版本和权限影响可用能力、上下文及维护成本。 |

项目说明提供上下文和规则，技能可封装按需流程，工具提供可调用能力，钩子响应特定事件，插件可打包扩展；这些是概念性区分。具体发现、覆盖和权限行为取决于产品版本，应查 [Claude Code 扩展官方文档](https://code.claude.com/docs/en/features-overview)。MCP 与工具循环见第 4 章。

### 面试追问

【⭐ 理解】为什么不把所有规则和工具都永久塞进上下文？ 结论：信息过多可能增加成本并干扰任务。按需选择并保留必要约束，具体加载机制以产品版本为准。

【🔥 必会】扩展加载后行为不符合预期怎么查？ 结论：核对实际加载的名称、版本和权限。检查触发条件、配置优先级及日志，再用最小任务复现。

【◻ 按需】说明文件能保证工具操作一定安全么？ 结论：不能。实际授权、执行隔离和校验需要由运行环境与工具共同实现。

### 故障模式与排障

- 扩展未生效：检查发现路径、版本和触发条件，查目标产品文档并做最小复现。

- 同名扩展行为冲突：列出实际加载项和来源，按产品规则去重或重命名。

- 工具权限超出任务需要：核对工具配置和实际调用，按任务缩小授权范围并复测。

### 工程 trick 与坑

- 下面类别是教学抽象，不等于任何产品的真实配置格式或加载顺序。

- 本程序只检查内存数据，不读取、安装、启用或修改真实插件和权限。

- 具体产品功能会变化，使用时按目标版本文档核对。

### Toy code：扩展清单检查

运行前提：Python 3.10+，标准库；所有扩展均为虚构。

```python
"""检查虚构 Agent 扩展目录的名称、类型和版本冲突。"""
from dataclasses import dataclass


@dataclass(frozen=True)
class Extension:
    """扩展名称、类别、版本及加载状态；不代表真实产品配置。"""
    name: str
    kind: str
    version: str
    enabled: bool


def inventory(items: list[Extension]) -> dict[str, int]:
    """按类别统计已启用项，拒绝重复名称和非法字段。"""
    kinds = {'instruction', 'skill', 'tool', 'hook', 'plugin'}
    if not items:
        raise ValueError('扩展清单不能为空')
    counts = {kind: 0 for kind in kinds}
    seen: set[str] = set()
    for item in items:
        if not item.name.strip() or item.name in seen or not item.version.strip():
            raise ValueError('名称须唯一，名称和版本不能为空')
        if item.kind not in kinds or not isinstance(item.enabled, bool):
            raise ValueError('类别或启用状态非法')
        seen.add(item.name)
        if item.enabled:
            counts[item.kind] += 1
    assert sum(counts.values()) == sum(item.enabled for item in items)
    return counts


def main() -> None:
    """覆盖启用统计、重复名称和未知类别。"""
    data = [Extension('project-rules', 'instruction', 'v1', True),
            Extension('local-search', 'tool', 'v2', True),
            Extension('optional', 'plugin', 'v1', False)]
    report = inventory(data)
    assert report['instruction'] == 1 and report['tool'] == 1 and report['plugin'] == 0
    for invalid in ([], data + data[:1], [Extension('x', 'unknown', 'v1', True)]):
        try:
            inventory(invalid)
        except ValueError:
            pass
        else:
            raise AssertionError('空清单、重复名称或非法类别必须拒绝')
    print('虚构扩展清单自检通过:', report)
    print('本程序不读取或修改真实工具、权限和插件。')


if __name__ == '__main__':
    main()

```

逐段理解。 Extension 表示一条模拟能力；inventory 检查名称、类别和版本，按类型统计启用项；自检覆盖重复和非法类别。

### 这段代码怎么在面试里讲

- 不变量：名称唯一、版本非空、类别属于固定集合。

- 关键过程：逐项检查并仅统计启用的能力。

- 边界与坑：记录不代表扩展真实加载，也不检查权限或产品的配置语法。

### 本节收尾：费曼自述与闪卡

费曼自述： 扩展环境可以提供规则、技能和工具，但具体触发及权限属于产品实现；出问题要核对实际加载状态和版本。

- 问：规则说明文件能代替执行权限控制吗？答：不能。

- 问：此例是否真的安装了插件？答：没有，只处理虚构记录。

- 问：同名扩展冲突怎么查？答：检查实际加载来源与优先级。

- 问：产品扩展规则是否永久不变？答：不保证，查对应版本文档。

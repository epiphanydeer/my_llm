## 附.2 AI 编程任务：把完成证据说清楚【◻ 按需】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 使用 AI 编程工具完成任务时，说明具体改动、实际验证和未解决问题；对不需要自动测试的低影响改动，也应记录适当的人工核对或不适用原因。

### 第三件事：把「每次都得手动做的事」交给 Hooks 自动跑

有些事不是「让 Claude 决定做不做」，而是**每次都必须做**——比如每次改完文件自动格式化、提交前必须跑一遍 lint。

这种事靠你盯着、靠提醒 Claude，都不靠谱。**这是 Hooks 的活儿。**

Hooks 让你在 Claude Code 动手**之前或之后**自动执行 shell 命令。配一条「文件编辑后自动 format」、一条「commit 前先 lint」，从此这些动作脱离「人的注意力」，变成确定性发生的流程。

**Skill 和 Hooks 的区别记住这一句：Skill 是「需要时才调的能力」，Hooks 是「每次都确定触发的动作」。**

### 概念与数据流

| 五要素 | 任务完成证据 |
| --- | --- |
| 输入 | 任务 ID、变更描述、验证状态、验证说明和未解决问题。 |
| 做什么 | 检查记录完整性，并区分可复核与仍需处理。 |
| 输出 | 每项任务的状态；不自动认定描述真实。 |
| 哪里出错 | 只报告“完成”、未运行测试却说通过、遗漏失败和未解决问题。 |
| 参数影响 | 改动风险、验证范围和任务验收条件决定需要什么证据。 |

AI 工具可以辅助阅读、修改和测试，但最终报告应基于真实文件和实际运行结果。程序中的“可复核”只说明记录字段齐全，并不证明代码正确或任务已经交付。

### 面试追问

【⭐ 理解】如何说明 AI 辅助编程中的个人贡献？ 结论：区分自己判断、修改和验证的部分。给出真实任务、代码或实验结果，不把工具生成的内容直接当作本人独立实现。

【🔥 必会】工具说任务完成但测试失败怎么办？ 结论：以实际测试与文件状态为准。定位失败并继续修复，或明确说明未完成和原因。

【◻ 按需】每个改动都必须新增自动测试吗？ 结论：不一定。按影响和风险选择适当验证；例如文档链接可人工或脚本核对。

### 故障模式与排障

- 报告与实际状态不符：检查修改文件、命令退出码和输出；根据证据修正报告。

- 失败被省略：汇总未通过检查和未解决问题，保持任务未完成状态。

- 验证不适用却没有说明：记录理由及替代核对方式，便于复核。

### 工程 trick 与坑

- 本例只检查文字字段，不执行测试或验证文字真实性。

- 验证应与改动相称，不必为可逆、低影响修改机械地新增测试。

- 涉及外部发布或写入时，按实际任务授权和环境要求处理。

### Toy code：任务证据记录检查

运行前提：Python 3.10+，标准库；记录均为虚构。

```python
"""整理虚构任务的实现和验证证据，不判断证据真实性。"""
from dataclasses import dataclass


@dataclass(frozen=True)
class Evidence:
    """单项任务的变更说明、验证结果和未解决问题。"""
    task_id: str
    change: str
    verification_status: str
    verification_detail: str
    unresolved: tuple[str, ...]


def evaluate(items: list[Evidence]) -> dict[str, str]:
    """将缺证据、验证失败、未解决问题与可复核状态区分。"""
    if not items:
        raise ValueError('任务证据不能为空')
    result: dict[str, str] = {}
    for item in items:
        if not item.task_id.strip() or item.task_id in result or not item.change.strip():
            raise ValueError('任务 ID 须唯一，变更说明不能为空')
        if item.verification_status not in {'passed', 'failed', 'not_applicable'}:
            raise ValueError('验证状态非法')
        if not item.verification_detail.strip():
            raise ValueError('验证结果或不适用原因不能为空')
        if any(not isinstance(x, str) or not x.strip() for x in item.unresolved):
            raise ValueError('未解决问题须为非空字符串')
        if item.verification_status == 'failed' or item.unresolved:
            result[item.task_id] = 'needs_work'
        else:
            result[item.task_id] = 'reviewable'
    assert len(result) == len(items)
    return result


def main() -> None:
    """验证通过、测试不适用、失败和未解决问题。"""
    items = [Evidence('a', '修改解析', 'passed', '固定样本通过', ()),
             Evidence('b', '调整文档', 'not_applicable', '人工核对链接', ()),
             Evidence('c', '修改逻辑', 'failed', '边界检查失败', ('待修复',))]
    assert evaluate(items) == {'a': 'reviewable', 'b': 'reviewable', 'c': 'needs_work'}
    for invalid in ([], [items[0], items[0]], [Evidence('x', '变更', 'passed', '', ())]):
        try:
            evaluate(invalid)
        except ValueError:
            pass
        else:
            raise AssertionError('空清单、重复 ID 或缺证据必须拒绝')
    print('虚构任务证据状态自检通过:', evaluate(items))
    print('非空描述不证明测试真实执行或任务确已完成。')


if __name__ == '__main__':
    main()

```

逐段理解。 Evidence 保存改动和验证；evaluate 检查字段并标记仍需处理的项目；自检覆盖失败、不适用和缺说明。

### 这段代码怎么在面试里讲

- 不变量：任务 ID 唯一，验证状态明确，验证说明不为空。

- 关键过程：失败或存在未解决问题时返回 needs_work，否则标记为可复核。

- 边界与坑：文字非空不能证明真实执行；reviewable 不是实际交付或自动审批。

### 本节收尾：费曼自述与闪卡

费曼自述： AI 协助完成任务后，要依据真实变更和验证结果汇报；失败和未解决问题必须保留。

- 问：工具声称完成就足够吗？答：不够，应核查文件和验证结果。

- 问：所有改动必须新增自动测试吗？答：不一定，按风险选择适当验证。

- 问：字段非空是否证明测试通过？答：不证明，程序不检查真实性。

- 问：AI 生成代码能否全部算个人独立贡献？答：应如实说明本人工作与验证。

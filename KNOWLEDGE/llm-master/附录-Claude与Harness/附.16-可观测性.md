## 附.16 可观测性：trace 关联与阶段失败【◻ 按需】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 将一次应用请求拆成检索、模型调用、工具调用等阶段，用 trace 关联错误；示例不接入真实遥测。

### 概念与数据流

| 五要素 | 说明 |
| --- | --- |
| 输入 | 虚构 trace ID、span ID、父 ID、阶段、耗时和成功状态。 |
| 做什么 | 校验标识、耗时和父引用，统计每阶段样本和失败数。 |
| 输出 | 每阶段的调用数与失败数。 |
| 哪里出错 | 跨请求关联错乱、丢 span、把父子耗时简单相加导致重复计数。 |
| 参数影响 | 采样率、标签基数、脱敏规则和保留时间影响可观测性与成本。 |

### 面试追问

【⭐ 理解】为什么要用 trace 而不只看总体错误率？ 结论：trace 能关联一次请求中的各阶段。结合日志和指标，才能缩小故障所在步骤。

【⭐ 理解】父 span 与子 span 耗时可以直接相加吗？ 结论：通常不能。阶段可能嵌套或并行，加总会重复统计，端到端延迟应按实际时间线计算。

【⭐ 理解】检索阶段失败率突然上升怎么排查？ 结论：先按版本、来源和错误类型分组。检查超时、依赖、输入变化及缺失 span。

### 故障模式与排障

- trace 不完整：检查埋点覆盖、上下文传递和采样丢失，再修复关联。

- 阶段延迟总和大于端到端：检查嵌套和并行，不对重叠时段直接相加。

- 日志暴露敏感内容：限制记录字段、脱敏、权限和保留时间，按实际要求处理。

### 工程 trick 与坑

- 此示例只检查父引用存在和自引用，不完整验证多节点环或严格时间顺序。

- span 次数不是独立请求数；采样后的比例也可能带偏差。

- 耗时指标需区分整体与阶段，P95 计算要有明确窗口及足够样本。

### Toy code：虚构 trace 阶段统计

运行前提：Python 3.10+，标准库，无网络和真实日志。

```python
"""汇总虚构 trace 的阶段失败数；不采集生产数据。"""
from collections import defaultdict
from dataclasses import dataclass
import math


@dataclass(frozen=True)
class Span:
    """trace 内唯一 span ID、父节点、阶段、耗时和成功状态。"""
    trace_id: str
    span_id: str
    parent_id: str | None
    stage: str
    duration_ms: float
    ok: bool


def summarize(spans: list[Span]) -> dict[str, tuple[int, int]]:
    """核对同一 trace 中的父子引用并汇总每阶段样本与失败数。"""
    if not spans:
        raise ValueError('没有 span')
    keys: set[tuple[str, str]] = set()
    for s in spans:
        key = (s.trace_id, s.span_id)
        if not all(isinstance(x, str) and x.strip() for x in (s.trace_id, s.span_id, s.stage)):
            raise ValueError('标识和阶段不能为空')
        if key in keys or not isinstance(s.ok, bool) or not math.isfinite(s.duration_ms) or s.duration_ms < 0:
            raise ValueError('重复 ID、状态或耗时非法')
        keys.add(key)
    counts: dict[str, list[int]] = defaultdict(lambda: [0, 0])
    for s in spans:
        if s.parent_id is not None and ((s.trace_id, s.parent_id) not in keys or s.parent_id == s.span_id):
            raise ValueError('父 span 缺失或自引用')
        counts[s.stage][0] += 1
        counts[s.stage][1] += int(not s.ok)
    result = {stage: (n, failed) for stage, (n, failed) in counts.items()}
    assert sum(n for n, _ in result.values()) == len(spans)
    return result


def main() -> None:
    """覆盖失败统计、不同 trace 同 ID、父节点缺失与非法耗时。"""
    rows = [Span('t1', 'root', None, 'request', 12.0, True),
            Span('t1', 'child', 'root', 'retrieve', 4.0, False),
            Span('t2', 'root', None, 'request', 7.0, True)]
    assert summarize(rows) == {'request': (2, 0), 'retrieve': (1, 1)}
    for bad in ([], rows + rows[:1], [Span('t', 'a', 'missing', 'x', 1.0, True)],
                [Span('t', 'a', None, 'x', float('nan'), True)]):
        try:
            summarize(bad)
        except ValueError:
            pass
        else:
            raise AssertionError('非法 trace 必须拒绝')
    print('虚构 trace 分阶段计数:', summarize(rows))
    print('未验证多节点环；不采集正文、凭据或真实日志。')


if __name__ == '__main__':
    main()
```

逐段理解。 Span 保存关联字段；summarize 检查同 trace 父引用并统计；自检覆盖重复 ID、缺父节点与 NaN。

### 这段代码怎么在面试里讲

- 不变量：同一 trace 内 span ID 唯一、耗时有限且非负，阶段计数之和等于 span 数。

- 关键过程：先建复合键集合，再核对父引用并按阶段计算失败数。

- 边界与坑：未检验多节点环，也没有真实采样、日志或敏感数据处理。

### 本节收尾：费曼自述与闪卡

费曼自述： trace 把一次请求中的多阶段调用关联起来；统计前要确认采样和父子关系，不能把重叠耗时相加。

- 问：span 数就是请求数吗？答：不是。

- 问：父子耗时能直接相加吗？答：可能重复计算。

- 问：本例检测多节点环吗？答：没有。

- 问：生产遥测为何需要脱敏？答：降低敏感数据暴露。

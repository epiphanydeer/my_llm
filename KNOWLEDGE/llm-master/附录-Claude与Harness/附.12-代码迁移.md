### 概念与数据流

| 五要素 | 说明 |
| --- | --- |
| 输入 | 规范相对路径、迁移前后摘要、验证状态。 |
| 做什么 | 检查清单内路径、摘要格式和状态是否自洽，汇总待处理与变化数。 |
| 输出 | 待处理、已变更、未变更三类计数。 |
| 哪里出错 | 路径重复、摘要缺失、未产出结果却标记验证通过。 |
| 参数影响 | 批次大小、覆盖测试和回滚策略影响风险与推进速度，本例不实现。 |

### 面试追问

【⭐ 理解】大规模迁移怎样降低返工？ 结论：先建基线，再小批验证。按依赖顺序迁移并保留测试结果、变更记录与可用回滚点。

【⭐ 理解】摘要相同是否证明迁移正确？ 结论：不能。摘要只能比较指定字节，还要确认对象、运行行为和测试覆盖。

【⭐ 理解】迁移后测试失败怎么定位？ 结论：先比对失败批次与基线。缩小到受影响接口、依赖和数据格式，再修复并回归。

### 故障模式与排障

- 清单漏文件：核对源文件发现范围和清单总数，再补录。

- 状态与结果矛盾：检查是否缺少迁移后摘要，纠正状态并重跑验证。

- 回归失败：按批次比较接口和测试证据，修复后复跑；回滚能力必须预先验证。

### 工程 trick 与坑

- 本例只检查字符串格式，不验证文件存在、摘要真实、测试通过或可回滚。

- 同一摘要不能代替端到端行为验证；依赖关系与历史兼容需要实测。

- 原镜像案例的规模和速度不外推到自己的项目。

### Toy code：迁移清单一致性

运行前提：Python 3.10+，标准库，不读取任何项目文件。

```python
"""检查虚构迁移清单，不读取、修改或删除任何项目文件。"""
from dataclasses import dataclass
from pathlib import PurePosixPath
import re


@dataclass(frozen=True)
class Item:
    """相对路径、迁移前后摘要和验证状态；None 表示尚无结果。"""
    path: str
    before_sha256: str
    after_sha256: str | None
    verified: bool


def review(items: list[Item]) -> dict[str, int]:
    """检查清单一致性并统计未处理、已更改和未改变项。"""
    if not items:
        raise ValueError('迁移清单不能为空')
    counts = {'pending': 0, 'changed': 0, 'unchanged': 0}
    seen: set[str] = set()
    for item in items:
        if not isinstance(item.path, str):
            raise ValueError('路径必须为字符串')
        pure = PurePosixPath(item.path)
        if (not item.path or item.path == '.' or ':' in item.path or '\\' in item.path or pure.is_absolute() or '..' in pure.parts or
                str(pure) != item.path or item.path in seen):
            raise ValueError('路径须唯一、规范且为相对路径')
        seen.add(item.path)
        if not isinstance(item.before_sha256, str):
            raise ValueError('迁移前摘要不能为空')
        for digest in (item.before_sha256, item.after_sha256):
            if digest is not None and (not isinstance(digest, str) or not re.fullmatch(r'[0-9a-f]{64}', digest)):
                raise ValueError('摘要必须为小写 SHA-256 十六进制字符串')
        if not isinstance(item.verified, bool):
            raise ValueError('验证状态必须是布尔值')
        if item.after_sha256 is None:
            if item.verified:
                raise ValueError('没有迁移结果不能标记已验证')
            counts['pending'] += 1
        else:
            counts['unchanged' if item.after_sha256 == item.before_sha256 else 'changed'] += 1
    assert sum(counts.values()) == len(items)
    return counts


def main() -> None:
    """覆盖更改、未处理、非法路径和矛盾状态。"""
    a, b = 'a' * 64, 'b' * 64
    items = [Item('src/a.py', a, b, True), Item('src/b.py', a, None, False)]
    assert review(items) == {'pending': 1, 'changed': 1, 'unchanged': 0}
    for bad in ([], [Item('../outside', a, b, False)], [Item('C:/outside', a, b, False)],
                [Item('src/x.py', a, None, True)], items + items[:1]):
        try:
            review(bad)
        except ValueError:
            pass
        else:
            raise AssertionError('非法路径、状态或重复记录必须拒绝')
    print('虚构迁移清单自检通过:', review(items))
    print('未验证文件存在、摘要真实性、测试或回滚能力。')


if __name__ == '__main__':
    main()
```

逐段理解。 Item 描述一条记录；review 校验路径、摘要和状态并计数；自检覆盖重复、越界路径和矛盾状态。

### 这段代码怎么在面试里讲

- 不变量：路径唯一、摘要格式合法，三种状态计数之和等于条目数。

- 关键过程：逐项校验再汇总；尚无迁移结果时不允许标记已验证。

- 边界与坑：这是内存元数据检查，不证明文件、摘要或测试结果真实。

### 本节收尾：费曼自述与闪卡

费曼自述： 迁移需要可复现的基线、按依赖的小批交付和可核对的验证与回滚证据。清单自洽只是第一步。

- 问：摘要相同能证明业务行为正确吗？答：不能，还要做行为与回归测试。

- 问：未生成结果可以标记验证通过吗？答：不可以。

- 问：例子会修改文件吗？答：不会，只检查虚构记录。

- 问：为什么按批迁移？答：缩小排障与恢复范围。

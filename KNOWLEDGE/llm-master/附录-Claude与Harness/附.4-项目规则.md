### 一、为什么你总是在重复教育 Claude Code？

先说一个很常见的场景。

你打开一个老项目，让 Claude Code 帮你改一个接口。

你会先说一大堆：

- 这个项目是 VuePress 1.x，不要按 VuePress 2.x 写
- 命令要在 `docs/` 目录下执行
- 依赖版本别乱升
- 不要改部署脚本
- Markdown 图片必须有 ALT
- 改完之后跑 `npm run build`

这些话有用吗？

有用。

但问题是：**你每次开新任务都要说一遍。**

更麻烦的是，复杂任务跑久了以后，上下文越来越长，前面那些要求会被一堆文件内容、命令输出、错误日志淹没。

你以为 Claude Code "记得"这些规则，其实它只是当前上下文里还能看到这些规则。

一旦上下文压缩、裁剪、切换任务，它就可能忘。

所以项目规则不能只靠聊天输入。

它需要一个更稳定的入口。

这就是 `CLAUDE.md`。

**你可以把它理解成：写给 Claude Code 的项目交接文档。**

新人进组之前，你会告诉他：

- 项目怎么启动
- 哪些目录放什么
- 哪些地方不能动
- 常见坑在哪里
- 提 PR 前要跑什么检查

Claude Code 也是一样。

你不能指望它每次都自己摸索一遍。

摸索会浪费 token，也会制造风险。

### 概念与数据流

| 五要素 | 项目规则文件读取 |
| --- | --- |
| 输入 | 项目根目录、规则文件路径和大小限制。 |
| 做什么 | 解析路径、确认文件在指定目录内、读取 UTF-8 文本并保留来源。 |
| 输出 | 相对路径、文本与提取的标题。 |
| 哪里出错 | 文件缺失、路径越界、编码不对、规则过期、误判产品加载与优先级。 |
| 参数影响 | 规则范围、文件大小和加载时机影响上下文与维护成本。 |

Claude Code 的 CLAUDE.md 等机制用于提供项目说明；具体查找路径、优先级及产品行为会变化，以[官方说明](https://code.claude.com/docs/en/memory)为准。项目文件内容应被理解为有来源的指令或数据，适用范围和冲突处理取决于运行环境；不要假设此例实现了产品规则。

### 面试追问

【⭐ 理解】项目规则文件适合写什么？ 结论：写稳定、具体、可验证的约定。例如常用检查命令、目录职责和项目特殊约束；避免塞入过时或敏感信息。

【🔥 必会】AI 工具没有遵守项目规则怎么查？ 结论：先确认规则是否被加载且适用。核对路径、优先级、内容和运行环境，再做最小复现；不能仅凭文件存在假定生效。

【◻ 按需】路径检查就能完全防止文件访问风险吗？ 结论：不能。本例没有解决文件系统竞态、并发变更或完整权限隔离。

### 故障模式与排障

- 规则文件未加载：检查实际目录、产品发现规则及版本；查看工具状态和日志。

- 文件读取失败：核对路径、UTF-8、大小和权限；显式返回错误。

- 规则过期或冲突：比较来源与适用范围，按实际用户要求和环境规则处理并更新过时内容。

### 工程 trick 与坑

- 下例只读取 TemporaryDirectory 内的虚构文件，不创建或修改真实项目 CLAUDE.md。

- 路径解析和大小检查只是教学示例，不提供防竞态的安全边界。

- 文件内容不应包含凭据；具体项目管理规则须结合实际工具与组织要求。

### Toy code：临时规则文件的来源和标题

运行前提：Python 3.10+，标准库；只在临时目录读写示例文件。

```python
"""读取临时示例规则文件，保留来源与标题；不修改真实项目说明。"""
from dataclasses import dataclass
from pathlib import Path
from tempfile import TemporaryDirectory


@dataclass(frozen=True)
class RuleFile:
    """文件相对路径、内容和二级标题。"""
    relative_path: str
    text: str
    headings: tuple[str, ...]


def read_rules(root: Path, path: Path, max_bytes: int) -> RuleFile:
    """读取工作目录内的 UTF-8 文件；此例只演示路径边界。"""
    if isinstance(max_bytes, bool) or not isinstance(max_bytes, int) or max_bytes <= 0:
        raise ValueError('大小限制必须为正整数')
    try:
        base = root.resolve(strict=True)
        target = path.resolve(strict=True)
    except OSError as exc:
        raise ValueError('目录或文件不存在') from exc
    if not base.is_dir() or not target.is_file() or not target.is_relative_to(base):
        raise ValueError('文件必须位于指定目录内')
    if target.stat().st_size > max_bytes:
        raise ValueError('规则文件超出大小限制')
    try:
        text = target.read_text(encoding='utf-8')
    except (OSError, UnicodeError) as exc:
        raise ValueError('规则文件不可读取或不是 UTF-8') from exc
    headings = tuple(line[3:].strip() for line in text.splitlines() if line.startswith('## ') and line[3:].strip())
    assert target.is_relative_to(base)
    return RuleFile(str(target.relative_to(base)), text, headings)


def main() -> None:
    """只在临时目录构造规则文件，验证读取、越界与大小限制。"""
    with TemporaryDirectory() as temp:
        outer = Path(temp)
        root = outer / 'project'; root.mkdir()
        path = root / 'CLAUDE.md'; path.write_text('# 示例\n\n## 验证\n运行自检\n', encoding='utf-8')
        outside = outer / 'outside.md'; outside.write_text('外部示例', encoding='utf-8')
        result = read_rules(root, path, 1000)
        assert result.relative_path == 'CLAUDE.md' and result.headings == ('验证',)
        for bad_path, limit in ((outside, 1000), (path, 1), (root / 'missing.md', 1000)):
            try:
                read_rules(root, bad_path, limit)
            except ValueError:
                pass
            else:
                raise AssertionError('越界、过大或缺失文件必须拒绝')
    print('临时规则文件的来源与标题读取自检通过。')
    print('示例不解析产品优先级，也不构成防竞态安全边界。')


if __name__ == '__main__':
    main()

```

逐段理解。 read_rules 解析根目录和文件路径，检查范围、大小及 UTF-8；自检在临时目录测试正常、越界、过大与缺失文件。

### 这段代码怎么在面试里讲

- 不变量：目标是根目录内的文件，大小在限制内，内容可按 UTF-8 解码。

- 关键过程：先解析路径并检查范围，再读取并提取二级标题。

- 边界与坑：没有防竞态、没有实现 Claude Code 的规则加载或优先级，真实环境需核对产品文档。

### 本节收尾：费曼自述与闪卡

费曼自述： 项目规则文件提供有来源的约定；实际生效范围和优先级要按工具与环境核对，不能只看文件是否存在。

- 问：本例会修改真实 CLAUDE.md 吗？答：不会，只在临时目录创建虚构文件。

- 问：路径解析是否解决所有安全问题？答：不是，还可能有竞态和权限问题。

- 问：规则文件存在就说明已加载吗？答：不一定，应核查工具实际状态。

- 问：产品加载规则以什么为准？答：目标版本的官方文档及实际运行环境。

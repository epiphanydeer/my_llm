## 附.11 托管任务：状态、等待与恢复【◻ 按需】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 长任务可能排队、运行、等待输入、完成或失败；跟踪时应依据真实任务状态，而不是把一次观察超时当作任务已停止。

### 概念与数据流

| 五要素 | 简化任务状态 |
| --- | --- |
| 输入 | 任务 ID、当前状态、版本号和期望的新状态。 |
| 做什么 | 检查允许的转换和预期版本，产生新状态快照。 |
| 输出 | 更新后的任务状态与递增版本；非法转换显式失败。 |
| 哪里出错 | 观察超时误判终止、重复执行、旧状态覆盖新状态、真实并发更新冲突。 |
| 参数影响 | 超时、轮询频率、重试与状态保留策略影响成本和恢复能力。 |

真实托管服务的状态机、重试和取消语义以具体接口为准。本例不连接服务，只说明状态转换和旧版本检查；它不提供数据库事务或并发原子性。

### 面试追问

【⭐ 理解】轮询超时后能否立即重新启动任务？ 结论：不能仅凭观察超时判断任务已停止。先查询同一任务句柄或权威状态，避免重复执行。

【🔥 必会】任务状态被旧结果覆盖怎么排查？ 结论：检查版本、事件顺序和持久化写入。真实系统需使用支持并发控制的原子更新或事务。

【◻ 按需】取消请求发出就一定取消成功吗？ 结论：不一定。要读取实际服务返回和后续状态，副作用可能已发生。

### 故障模式与排障

- 观察超时被误判为失败：继续核对原任务状态，不仅凭一次超时重新创建。

- 旧版本写入覆盖新状态：使用实际存储系统的版本检查与原子更新，记录冲突。

- 任务取消但外部动作已发生：检查真实结果和副作用，按业务设计恢复与幂等。

### 工程 trick 与坑

- 本例完全在内存中运行，不创建任务、访问服务或模拟真正的并发。

- expected_revision 只演示乐观检查；若没有原子存储操作，不能保证并发正确。

- 状态名称和允许转换是示例，不代表任何特定托管产品协议。

### Toy code：任务状态转换

运行前提：Python 3.10+，标准库，无网络和外部任务。

```python
"""检查虚构托管任务的状态转换；不创建或控制真实代理。"""
from dataclasses import dataclass


ALLOWED: dict[str, frozenset[str]] = {
    'queued': frozenset({'running', 'cancelled'}),
    'running': frozenset({'waiting', 'completed', 'failed', 'cancelled'}),
    'waiting': frozenset({'running', 'cancelled'}),
    'completed': frozenset(), 'failed': frozenset(), 'cancelled': frozenset(),
}


@dataclass(frozen=True)
class Job:
    """任务 ID、状态和单调递增的本地版本号。"""
    job_id: str
    status: str
    revision: int


def transition(job: Job, new_status: str, expected_revision: int) -> Job:
    """校验状态和预期版本，返回新的不可变快照。"""
    if not job.job_id.strip() or job.status not in ALLOWED or new_status not in ALLOWED:
        raise ValueError('任务 ID 或状态非法')
    if isinstance(job.revision, bool) or not isinstance(job.revision, int) or job.revision < 0:
        raise ValueError('版本号必须是非负整数')
    if expected_revision != job.revision:
        raise ValueError('版本已变化，需要重新读取')
    if new_status not in ALLOWED[job.status]:
        raise ValueError('不允许的状态转换')
    result = Job(job.job_id, new_status, job.revision + 1)
    assert result.revision == job.revision + 1
    return result


def main() -> None:
    """检查排队、运行、等待恢复、完成和非法更新。"""
    job = Job('demo', 'queued', 0)
    job = transition(job, 'running', 0)
    job = transition(job, 'waiting', 1)
    job = transition(job, 'running', 2)
    job = transition(job, 'completed', 3)
    assert job.status == 'completed' and job.revision == 4
    for current, target, rev in ((job, 'running', 4), (Job('x', 'queued', 0), 'completed', 0),
                                 (Job('x', 'running', 2), 'failed', 1)):
        try:
            transition(current, target, rev)
        except ValueError:
            pass
        else:
            raise AssertionError('终态、非法转换或旧版本必须拒绝')
    print('虚构任务状态转换自检通过:', job)
    print('版本检查只是单进程演示，不提供真实并发原子性。')


if __name__ == '__main__':
    main()

```

逐段理解。 ALLOWED 定义示例状态图；transition 检查状态和预期版本；自检覆盖等待恢复、终态和旧版本。

### 这段代码怎么在面试里讲

- 不变量：任务 ID 非空、版本非负，每次合法转换版本递增。

- 关键过程：检查预期版本与允许边，再生成不可变的新快照。

- 边界与坑：示例没有原子存储、网络或真实代理；观察超时和任务终止是不同状态。

### 本节收尾：费曼自述与闪卡

费曼自述： 长任务要依据真实状态处理等待、恢复和终止；观察超时并不自动证明任务停止，状态更新还需并发控制。

- 问：轮询超时就能重新创建任务吗？答：不能，应先核实原任务状态。

- 问：本例的版本检查能保证并发原子性吗？答：不能，需要存储层支持。

- 问：取消请求是否保证没有副作用？答：不保证，要检查实际状态。

- 问：本例是否创建真实代理？答：没有，仅模拟状态转换。

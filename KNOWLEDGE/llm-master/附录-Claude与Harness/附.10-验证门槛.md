## 附.10 任务闭环：验证门槛与未知状态【◻ 按需】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 迭代模型应用时，先定义任务验收与回归，再检查关键指标；未知或失败的项目不能自动当作通过。本例只展示指标状态，不执行发布。

### Loop 不是免费的，先问四个问题

Loop 很诱人，但它不是免费午餐。**它烧 token、要花时间搭、出了问题你还得去 debug 一个你没亲眼看它跑的系统。**

动手之前，先把这四个问题想清楚：

<!-- drawio源文件: ./drawio/loop_engineering_guide_01_decision.drawio -->

![判断是否需要 Loop](https://file1.kamacoder.com/i/web/20260708113429_loop_decision.jpg?v=20261005)

**任务是重复的吗？** Loop 的搭建成本要靠多次运行摊回来。一次性的活儿，写个好 prompt 更快。

**有自动检查机制吗？** 测试、类型检查、linter，随便哪个都行。**没有自动检查，你就得自己逐行读 diff**，loop 就并没有帮你节省时间。

**Token 预算够吗？** Loop 会反复读上下文、重试、试探，不管有没有产出都在烧 token。

**Agent 能跑自己写的代码吗？** 需要有日志、能复现、看得到哪里崩。

还有个附加题，**比上面四个都重要**：**你打算 review 它产出的代码吗？** 不打算，就别建 loop。

**谁适合上手：** 有强测试套件的团队，干 CI 失败分类、依赖升级、lint-and-fix 这类任务。

**谁不适合：** 消费级套餐的个人开发者（token 预算不够烧）、测试覆盖不够的代码库（没闸门）、瓶颈在 review 而不在打字速度的团队。

### 概念与数据流

| 五要素 | 虚构评测门槛 |
| --- | --- |
| 输入 | 指标名称、测量值、最低阈值和样本数。 |
| 做什么 | 检查数据，分别标记通过、失败或未知。 |
| 输出 | 每项指标的状态，供人工或上层流程进一步判断。 |
| 哪里出错 | 测试缺失被当作通过、样本太少、阈值或指标方向设置错误。 |
| 参数影响 | 阈值、样本量和测试分布影响门槛的意义。 |

本例只处理“越高越好”的 [0,1] 比例指标；延迟和成本等“越低越好”或其他单位需另行设计。即便所有指标通过，也要考虑标注质量、统计不确定性与实际业务风险。通用评测系统见[系统设计与评测](../%E6%A8%AA%E5%88%87-%E7%B3%BB%E7%BB%9F%E8%AE%BE%E8%AE%A1%E4%B8%8E%E8%AF%84%E6%B5%8B.md)专题。

### 面试追问

【⭐ 理解】为什么要在迭代前定义验收标准？ 结论：便于判断改动是否达成目标。先固定任务、指标和基线，再检查改动、失败和副作用。

【🔥 必会】某项指标缺失但其他都通过怎么办？ 结论：将该项标为未知。补充测量或按业务流程处理，不能自动记作通过。

【◻ 按需】门槛通过就能证明系统可靠么？ 结论：不能。还要看数据覆盖、标注、样本量及线上情况。

### 故障模式与排障

- 未评测项被当成通过：保留未知状态，补充评测或明确剩余限制。

- 指标方向写反：核对越高越好或越低越好及单位，本例只支持前者。

- 少量样本误导结论：检查每个切片的样本数和不确定性，补充有代表性的数据。

### 工程 trick 与坑

- 门槛数值和样本均为虚构，程序不发布系统或做审批。

- 本例不验证指标的统计可信度、标注质量，也不处理延迟等低值更好的指标。

- 测试不适用时应记录原因和适当替代验证，而不是机械添加无意义检查。

### Toy code：虚构比例指标状态

运行前提：Python 3.10+，标准库，无模型或网络。

```python
"""检查虚构回归指标的门槛；不执行发布或替代业务决策。"""
from dataclasses import dataclass
from math import isfinite


@dataclass(frozen=True)
class Gate:
    """指标名称、测量值、最低阈值和已评估样本数。"""
    name: str
    measured: float | None
    minimum: float
    sample_count: int


def evaluate(gates: list[Gate]) -> dict[str, str]:
    """返回 pass/fail/unknown，未知不当作通过。"""
    if not gates:
        raise ValueError('至少需要一个指标')
    result: dict[str, str] = {}
    for gate in gates:
        if not gate.name.strip() or gate.name in result:
            raise ValueError('指标名必须唯一且非空')
        if not isfinite(gate.minimum) or not 0 <= gate.minimum <= 1:
            raise ValueError('示例阈值必须位于 [0,1]')
        if isinstance(gate.sample_count, bool) or not isinstance(gate.sample_count, int) or gate.sample_count < 0:
            raise ValueError('样本数必须为非负整数')
        if gate.measured is None:
            result[gate.name] = 'unknown'
            continue
        if not isfinite(gate.measured) or not 0 <= gate.measured <= 1 or gate.sample_count == 0:
            raise ValueError('测量值须在 [0,1] 且有样本')
        result[gate.name] = 'pass' if gate.measured >= gate.minimum else 'fail'
    assert len(result) == len(gates)
    return result


def main() -> None:
    """覆盖通过、失败、未知和非法结果。"""
    checks = [Gate('格式', 0.95, 0.9, 20), Gate('忠实度', 0.7, 0.8, 10), Gate('安全', None, 0.9, 0)]
    assert evaluate(checks) == {'格式': 'pass', '忠实度': 'fail', '安全': 'unknown'}
    for bad in ([], [Gate('x', 1.1, 0.5, 1)], [Gate('x', 0.5, 0.4, 0)]):
        try:
            evaluate(bad)
        except ValueError:
            pass
        else:
            raise AssertionError('空指标或非法数据必须拒绝')
    print('虚构评测门槛自检通过:', evaluate(checks))
    print('阈值和输入均为虚构，程序不发布系统或验证标签。')


if __name__ == '__main__':
    main()

```

逐段理解。 Gate 保存比例指标；evaluate 校验取值和样本数，分别标为通过、失败或未知；自检覆盖空值及无样本。

### 这段代码怎么在面试里讲

- 不变量：指标名称唯一、阈值在 [0,1]，有测量值时样本数大于零。

- 关键过程：未知保留为 unknown，其他值与最低阈值比较。

- 边界与坑：只支持越高越好的比例指标，不验证统计显著性或真实发布条件。

### 本节收尾：费曼自述与闪卡

费曼自述： 迭代前定义可验证目标，失败和未知状态要明确；指标通过也要结合数据质量和业务风险。

- 问：没测的指标可直接算通过吗？答：不可以，应标未知。

- 问：本例能直接评估延迟门槛吗？答：不能，它只处理越高越好的比例。

- 问：门槛通过保证系统可靠么？答：不保证，还需看覆盖与样本质量。

- 问：示例是否执行发布？答：没有，只统计虚构状态。

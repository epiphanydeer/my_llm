目标 + 例子。 可复用技能通常包含用途说明和执行流程，便于按需加载；读懂其来源、触发条件与限制，比背产品中的分类数量更有价值。

### 先纠正一个误解：Skill 不是一个 markdown 文件

很多录友一听 Skill，第一反应是「不就是写个 `.md` 文件告诉 Claude 怎么做嘛」。

**这个理解是错的，而且会让你写出来的 Skill 特别弱。**

官方原话：Skill 是「指令、脚本和资源的文件夹」（folders of instructions, scripts, and resources）。注意，是**文件夹**，不是文件。

![Skill文件夹解剖](https://file1.kamacoder.com/i/web/20260616181017_skill_anatomy.png?v=20261005)

一个像样的 Skill 长这样：

- `SKILL.md`：主指令 + 一段描述。这段描述很关键，它决定了 Claude **什么时候**会触发这个 Skill。
- `references/`：参考文档。Claude 不会一上来全读，而是用到哪份才读哪份。
- `scripts/`：可执行脚本。能跑代码就别让 Claude 现写，直接调。
- `assets/`：模板、示例数据这类资源。
- `config.json`：配置信息，缺了 Claude 还能反问你来补。

为什么这个区别重要？因为一旦你把 Skill 当成「一个文档」，你就会拼命往一个 md 里塞东西，最后塞成一坨谁也读不动的长文。而把它当成「一个文件夹」，你才会去想：哪些是脚本、哪些是按需读的参考、哪些是模板。这才是 Skill 真正的威力。

### 概念与数据流

| 五要素 | 简化技能元数据 |
| --- | --- |
| 输入 | 含 YAML 头部和正文的文本。 |
| 做什么 | 安全解析示例头部，检查名称、描述和正文。 |
| 输出 | 三个已校验的文本字段，或明确格式错误。 |
| 哪里出错 | 头部格式错误、描述不清、路径或版本过期、将外部说明当成必然可信。 |
| 参数影响 | 名称、描述、触发范围和正文长度影响发现、适用性与上下文成本。 |

技能可把可复用流程与资源组织起来；具体文件格式、触发、权限和优先级取决于运行环境。下面的 YAML 规则只是独立教学示例，不是 Claude Code 或其他系统完整规范，也不会安装或执行技能。

### 面试追问

【⭐ 理解】技能说明应包含什么？ 结论：清楚写用途、适用条件和执行步骤。实际元数据及支持字段需查目标工具文档。

【🔥 必会】技能似乎没有触发怎么排查？ 结论：检查发现路径、名称、描述和调用方式。核对版本和实际加载状态，再做最小任务验证。

【◻ 按需】YAML 安全解析是否代表内容可信？ 结论：不代表。它只限制解析方式，正文仍可能包含错误或不适用指令。

### 故障模式与排障

- 元数据解析失败：检查分隔符、缩进及字段类型；使用目标工具支持的格式验证。

- 技能未加载：检查目录、发现机制和版本；确认工具实际加载结果。

- 说明与任务冲突：核对来源、适用范围与用户要求；不要盲目执行不适用内容。

### 工程 trick 与坑

- 示例只接受 name 和 description，这是教学限制，不代表目标产品只支持这些字段。

- yaml.safe_load 不等于完整安全审计；实际系统还要处理输入大小、来源与权限。

- 不要在公开技能说明中放凭据或私有数据。

### Toy code：简化技能元数据校验

运行前提：Python 3.10+、PyYAML==6.0.3；只解析内存中的虚构字符串，不读取或安装技能。

```python
"""检查虚构技能说明的 YAML 头部；不安装或加载真实技能。"""
import re
from dataclasses import dataclass
from typing import Any
import yaml


@dataclass(frozen=True)
class Metadata:
    """示例所需的名称、描述和正文。"""
    name: str
    description: str
    body: str


def parse_skill(text: str) -> Metadata:
    """解析简化 YAML front matter；不代表任何产品的完整规范。"""
    if not isinstance(text, str) or not text.startswith('---\n'):
        raise ValueError('示例要求以 YAML 分隔符开头')
    parts = text.split('\n---\n', 1)
    if len(parts) != 2:
        raise ValueError('缺少结束分隔符')
    try:
        metadata: Any = yaml.safe_load(parts[0][4:])
    except yaml.YAMLError as exc:
        raise ValueError('YAML 解析失败') from exc
    if not isinstance(metadata, dict) or set(metadata) != {'name', 'description'}:
        raise ValueError('示例头部只接受 name 与 description')
    name, description = metadata['name'], metadata['description']
    if not isinstance(name, str) or not re.fullmatch(r'[a-z0-9-]{1,50}', name):
        raise ValueError('name 必须是小写字母、数字或连字符')
    if not isinstance(description, str) or not description.strip() or len(description) > 200:
        raise ValueError('description 必须非空且不超过 200 字符')
    if not parts[1].strip():
        raise ValueError('正文不能为空')
    return Metadata(name, description, parts[1].strip())


def main() -> None:
    """验证合法元数据、缺字段、非法名称和空正文。"""
    sample = '---\nname: demo-skill\ndescription: 演示任务\n---\n按步骤核对结果。'
    result = parse_skill(sample)
    assert result.name == 'demo-skill' and result.body == '按步骤核对结果。'
    invalid = ('', '---\nname: bad\n---\nbody',
               '---\nname: INVALID\ndescription: x\n---\nbody',
               '---\nname: ok\ndescription: x\n---\n')
    for item in invalid:
        try:
            parse_skill(item)
        except ValueError:
            pass
        else:
            raise AssertionError('不合规则的示例元数据必须拒绝')
    print('虚构技能元数据格式自检通过；未加载或执行技能。')


if __name__ == '__main__':
    main()

```

逐段理解。 parse_skill 解析前置 YAML，检查名称、描述和正文；自检覆盖缺字段、非法名称与空正文。

### 这段代码怎么在面试里讲

- 不变量：头部含示例要求的字段，名称满足约束，正文非空。

- 关键过程：拆分头部、使用 safe_load、验证类型和范围，再返回结构化元数据。

- 边界与坑：这是简化格式，不证明真实工具可加载；安全解析不代表正文可信。

## 横.1 端到端系统设计【🔥 必会】

〔本次新补，参考当前面试趋势〕

目标 + 例子。 面试题“设计工业安全隐患图片助手”：用户上传图片并提出问题，系统输出可核查的风险描述、依据和需要人工复核的项目；具体风险和业务规则应由实际业务确认。

### 概念与数据流

| 五要素 | 通用应用设计 |
| --- | --- |
| 输入 | 用户任务、文本/图片、权限、预算、质量与响应目标。 |
| 做什么 | 权限及输入检查→图像处理/模型推理→按需检索→生成带证据答复→验证与记录。 |
| 输出 | 答复、来源或无法确定原因，及脱敏追踪、成本和阶段状态。 |
| 哪里出错 | 图像模糊、召回遗漏、证据过期、注入、工具失败、超时或结论缺乏支持。 |
| 参数影响 | 图像分辨率、chunk、召回 K、模型、上下文长度、并发和重试影响质量、延迟、成本。 |

### 六步答题顺序

- 需求澄清：用户是谁、输入输出是什么、是否允许自动动作、权限与数据边界？明确可接受错误、业务指标、质量/延迟/成本目标，先选规则或人工基线。

- 架构分层：接入与身份、数据加工及索引、编排与模型/工具、结果验证、可观测与评测。RAG、Agent、VLM 均可以复用这些层；无需一开始就选复杂 Agent。

- 画数据流：对示例图像检查格式与访问权限，视觉模型提取候选描述；按用户问题检索已授权且有版本的文件；用来源生成答复，并对缺证据或模糊图片转人工。视觉判断与法规依据分别评估。

- 算约束：说明串行与并行阶段，粗估每次调用 token、图片与工具成本；用真实负载测端到端 P50/P95、吞吐、错误率及成本。不要把各阶段 P95 相加当端到端 P95。

- 可靠性：为外部调用设置超时、有限重试与降级，明确幂等和副作用；隔离不可信文档指令，工具端做授权，限制高风险动作并保留可审计证据。

- 评测迭代：建立固定版本的数据与基线，拆分组件指标、端到端质量和线上业务指标；按错误类型归因，改动后复跑，满足门槛再逐步上线并监测回退。

| 题型 | 关注数据流 | 重点取舍 |
| --- | --- | --- |
| RAG | 文档更新→分块→召回→重排→带来源回答 | 召回覆盖、权限、引用与时效；见 [第 3 章](03-RAG检索增强/README.md)。 |
| Agent | 任务→模型选择工具→服务校验→执行观察→停止 | 工具权限、预算、重复调用、失败恢复；见 [第 4 章](04-Agent智能体/README.md)。 |
| 多模态 | 图片/视频→预处理→视觉表征→文本与证据 | 小目标、分辨率、图文对齐、来源及人工复核；见 [第 7 章](07-多模态入门.md)。 |
| 评测平台 | 样本与标签→运行候选→评分→对比→门槛 | 数据版本、泄漏、人工一致性、可靠性和费用；见本专题横.2。 |

### 面试追问

【🔥 必会】何时不引入 Agent？ 结论：流程固定时先用工作流。明确步骤更易测试、控制时延及副作用；动态工具选择有价值时再增加 Agent。

【🔥 必会】为什么不能只优化模型分数？ 结论：业务结果和模型指标不同。需要同时衡量用户任务完成、成本、延迟及错误影响。

【🔥 必会】上线后 P95 升高怎么定位？ 结论：先拆解端到端 trace。按版本、阶段、并发和错误类型对比，再判断排队、依赖超时或生成长度。

### 故障模式与排障

- 答案无依据：查看图像解析、检索结果、引用与断言之间的对应；修复召回或改为明确无法判断。

- 延迟突然上升：查看端到端和分阶段耗时、排队、并发及重试；定位瓶颈后调整批量、模型或缓存，并在真实负载下复测。

- 工具产生越权动作：核对身份、服务端授权、操作日志和副作用；限制真实工具权限并完善可恢复策略。

### 工程 trick 与坑

- 并行阶段的端到端耗时不等于各阶段简单求和；排队、网络和重试也必须计入。

- 固定模型名和提示词仍不足以复现实验，还要记录数据、索引、依赖和配置版本。

- 工业安全示例的误判后果由实际场景决定；系统是否能自动处置需由业务授权与验证，不由示例代码决定。

### Toy code：虚构单次请求预算

运行前提：Python 3.10+，标准库；耗时和费用均为虚构单次观测，假设串行。

```python
"""检查虚构串行路径的预算；不声称模拟真实 P95。"""
from dataclasses import dataclass
import math


@dataclass(frozen=True)
class Stage:
    """一个阶段的名称、示例耗时与每次调用费用。"""
    name: str
    latency_ms: float
    cost: float


def assess(stages: list[Stage], max_ms: float, max_cost: float) -> dict[str, float | bool]:
    """汇总单次串行耗时和成本，并检查是否满足预算。"""
    values = (max_ms, max_cost)
    if any(not math.isfinite(x) or x < 0 for x in values):
        raise ValueError('预算须为非负有限数')
    if not stages:
        raise ValueError('至少需要一个阶段')
    names: set[str] = set()
    for stage in stages:
        if not isinstance(stage.name, str) or not stage.name.strip() or stage.name in names:
            raise ValueError('阶段名须非空且唯一')
        if any(not math.isfinite(x) or x < 0 for x in (stage.latency_ms, stage.cost)):
            raise ValueError('耗时和费用须为非负有限数')
        names.add(stage.name)
    elapsed = sum(s.latency_ms for s in stages)
    cost = sum(s.cost for s in stages)
    if not math.isfinite(elapsed) or not math.isfinite(cost):
        raise ValueError('汇总结果溢出')
    assert elapsed >= 0 and cost >= 0
    return {'latency_ms': elapsed, 'cost': cost,
            'within_budget': elapsed <= max_ms and cost <= max_cost}


def main() -> None:
    """检验通过、超预算、空输入和非有限数。"""
    stages = [Stage('检索', 80, 0.01), Stage('生成', 420, 0.04)]
    result = assess(stages, 600, 0.06)
    assert result['latency_ms'] == 500 and abs(float(result['cost']) - 0.05) < 1e-12
    assert result['within_budget'] is True
    assert assess(stages, 499, 0.06)['within_budget'] is False
    for bad in ([], [Stage('x', float('nan'), 0.1)], stages + stages[:1]):
        try:
            assess(bad, 600, 1)
        except ValueError:
            pass
        else:
            raise AssertionError('空阶段、非法数值或重复阶段必须拒绝')
    print('虚构单次串行预算:', result)
    print('不能将此结果或各阶段 P95 之和称为端到端 P95。')


if __name__ == '__main__':
    main()
```

逐段理解。 Stage 描述一次阶段；assess 校验有限非负数并累加；自检覆盖超预算、空阶段和重复名称。

### 这段代码怎么在面试里讲

- 不变量：阶段唯一，成本与耗时均为非负有限数。

- 关键过程：对假设串行的一次样本求和，并分别比较延迟与费用预算。

- 边界与坑：它不模拟并发、分布或排队，也不能用于计算 P95。

费曼自述： 设计先问目标与约束，再画数据流、选组件、估成本、设计可靠性，最后用版本化评测推动迭代。

## 横.2 评测数据、指标与发布闭环【🔥 必会】

〔本次新补，参考当前面试趋势〕

目标 + 例子。 为安全隐患图片问答做一版可复现的评测：先准备带来源的图片、问题、参考答案和人工标签，再分别测视觉、检索和最终答复；以下数字只是虚构计算示例。

### 概念与数据流

| 五要素 | 评测系统 |
| --- | --- |
| 输入 | 版本化样本、人工参考与相关文档、候选输出、评测规则和运行配置。 |
| 做什么 | 检查标注与切分，运行系统，逐项评分并按场景聚合，与基线比较。 |
| 输出 | 样本级结果、分母与不确定性、失败分类、回归与发布决策记录。 |
| 哪里出错 | 标签错误、数据泄漏、重复文档、judge 偏差、评估服务失败或样本太少。 |
| 参数影响 | 数据分布、K、标注口径、judge 提示、模型版本、门槛和采样影响结果。 |

### 数据：golden set 与难例

- 采集与标注：先按真实可授权场景采样，记录任务、时间、输入、参考答案、支持证据、是否可回答、图像质量和版本。让有领域知识的标注者按书面规则标注，抽样双标并仲裁分歧。

- 切分与防泄漏：按业务实体、原始文档或时间等合理分组切分，避免同一图片及其裁剪、同源段落或近重复记录跨训练、调参和测试集；固定测试集不用于反复调参。

- 难例挖掘：从经授权的错误案例中补充漏召回、相似但不相关、过期依据、无法回答、图像模糊、小目标、文字遮挡、提示注入和工具失败；保留来源及预期行为。

- 版本与分布：记录样本数、类别比例、时间和授权；明确合成与真实数据的比例。分层报告和整体报告同时保留，不能让容易样本掩盖关键风险。

### 指标：先写清分子和分母

| 层次 | 例子 | 解释与限制 |
| --- | --- | --- |
| 检索 | Hit@K、Recall@K、MRR@K | 单查询 hit 是 Top-K 是否至少包含一个相关项；recall 是命中相关项数/该查询全部已标注相关项；MRR 是首个相关项排名倒数，再按查询求平均。标注不全会影响上限和解释。 |
| 生成 | 忠实度、回答相关性、引用支持率 | 忠实度看回答断言能否由给定证据支持，不能直接等同世界事实正确；相关性和忠实度需分别检查。引用可打开也不等于支持结论。 |
| LLM-as-judge | 指定维度、评分标准、输入与解释 | 先用人工标签校准并抽检分歧，监控评分器版本、位置偏差与失效；judge 调用失败应记为未知，不能算通过。 |
| 多模态/Agent | 按场景拆图像识别、VQA、幻觉；任务成功、无效调用、终止 | 分析小目标、模糊、文本遮挡、图片与问题不一致；任务成功要定义可检查结果，不只数工具调用。 |
| 在线 | A/B 完成率、人工修正、反馈、延迟、费用 | 随机分组与分母明确，预设主要指标、护栏与观察窗口；用户反馈有选择偏差，需结合抽检。 |

此处 Recall@K 是文档 ID 级召回；Ragas 的 context recall 可使用参考答案断言衡量可归因性，口径不一定相同。相关性、忠实度与事实正确性也不可互相替代。

### 从回归到上线

- 保存数据、标注、索引、模型/提示词/解码和评测器版本；固定基线和硬例集。改动后比较逐例差异，尤其关注高风险分组。

- 发布门禁由业务确定：关键场景最低表现、质量退化容忍、未知/失败率、时延和成本；缺数据或评分失败应为待确认，而不是自动通过。

- 先离线回归，再按实际条件灰度或 A/B；同时监控异常、用户反馈、人工复核与漂移。预先明确暂停或回退负责人、触发条件和实际可用的回退路径。

- 评测指标只是代理信号。不要用模型判分单独证明安全或业务有效，必要时由领域人员复核。

### 面试追问

【🔥 必会】Hit 高但 Recall 低说明什么？ 结论：常有一个命中但覆盖不足。检查每题相关文档数、Top-K 和标注完整性，再判断需要增大召回或改查询。

【🔥 必会】忠实度高就一定回答正确吗？ 结论：不一定。上下文可能过期或本身错误；还需验证来源、时效和实际事实。

【🔥 必会】线上变差而离线分数上升怎么排查？ 结论：先比较数据和指标口径。核查分布漂移、切流、样本量、在线错误及业务指标是否一致。

### 故障模式与排障

- 分数异常高：检查重复与切分泄漏、评测集是否反复用于调参；按源文档或实体重新切分并留出测试集。

- judge 与人分歧大：抽样对比评分维度、依据和错误类型；修订标准并重新校准，不把 judge 当真值。

- 召回评测看似变差：核对索引版本、相关文档 ID、重复和分母；修复标注或索引后再比较。

### 工程 trick 与坑

- 返回结果少于 K 时按实际返回项评估；没有相关文档标注的题，本示例拒绝输入，真实系统可单列不可回答类别并定义口径。

- 宏平均先算每个问题再平均；微平均先汇总命中与相关项数，二者权重不同。

- 置信区间、统计显著性与实验样本量需根据实际实验设计决定；本例仅演示公式和边界。

### Toy code：检索指标与分母

运行前提：Python 3.10+，标准库。两条虚构查询，其中一条没有检索结果。

```python
"""在虚构 query 上计算宏平均 Hit、Recall 和 MRR。"""
from dataclasses import dataclass
import math


@dataclass(frozen=True)
class QueryResult:
    """一个查询的相关文档集合与按分数排序的结果 ID。"""
    query_id: str
    relevant: frozenset[str]
    ranked: tuple[str, ...]


def evaluate(rows: list[QueryResult], k: int) -> dict[str, float]:
    """有标注相关文档的查询参与宏平均；重复结果视为输入错误。"""
    if not rows or isinstance(k, bool) or not isinstance(k, int) or k <= 0:
        raise ValueError('查询不能为空且 k 必须为正整数')
    seen: set[str] = set()
    hit_sum = recall_sum = mrr_sum = 0.0
    for row in rows:
        if not row.query_id.strip() or row.query_id in seen or not row.relevant:
            raise ValueError('查询 ID 重复、为空或无相关文档标注')
        if any(not isinstance(x, str) or not x.strip() for x in (*row.relevant, *row.ranked)):
            raise ValueError('文档 ID 必须为非空字符串')
        if len(set(row.ranked)) != len(row.ranked):
            raise ValueError('排序结果中存在重复文档')
        seen.add(row.query_id)
        top = row.ranked[:k]
        matches = row.relevant.intersection(top)
        hit_sum += float(bool(matches))
        recall_sum += len(matches) / len(row.relevant)
        first = next((rank for rank, doc in enumerate(top, 1) if doc in row.relevant), None)
        mrr_sum += 0.0 if first is None else 1.0 / first
    result = {'hit': hit_sum / len(rows), 'recall': recall_sum / len(rows), 'mrr': mrr_sum / len(rows)}
    assert all(math.isfinite(x) and 0 <= x <= 1 for x in result.values())
    return result


def main() -> None:
    """验证多个相关文档、空排序、重复 ID 和无标注。"""
    rows = [QueryResult('q1', frozenset({'a', 'b'}), ('x', 'a')),
            QueryResult('q2', frozenset({'c'}), ())]
    result = evaluate(rows, 2)
    assert result == {'hit': 0.5, 'recall': 0.25, 'mrr': 0.25}
    for bad in ([], [QueryResult('q', frozenset(), ('a',))],
                [QueryResult('q', frozenset({'a'}), ('a', 'a'))]):
        try:
            evaluate(bad, 2)
        except ValueError:
            pass
        else:
            raise AssertionError('空数据、无标注或重复结果必须拒绝')
    print('虚构查询宏平均:', result)
    print('只评估已标注相关文档，不代表生成忠实度。')


if __name__ == '__main__':
    main()
```

逐段理解。 每个 QueryResult 携带相关 ID 和排序；evaluate 检查数据后计算逐题指标并宏平均；自检覆盖重复、无标注与空结果。

### 这段代码怎么在面试里讲

- 不变量：每个查询 ID 唯一且有至少一个相关标注，返回列表不含重复 ID。

- 关键过程：截取 Top-K，分别算命中、相关项覆盖率和首个相关项排名倒数，再按查询平均。

- 边界与坑：空结果得零；无相关标注被拒绝；该分数不评价生成忠实度。

### 本节收尾：费曼自述与闪卡

费曼自述： 评测从数据和标注开始，分层测检索、生成与业务效果；记录版本、解释分母、复核失败，再用回归和在线反馈闭环。

- 问：Hit 和 Recall 有何区别？答：前者看是否命中，后者看相关项覆盖比例。

- 问：忠实度高是否证明事实正确？答：不能，证据本身可能有误或过期。

- 问：judge 失败能算通过吗？答：不能，应记录未知并处理。

- 问：为什么按实体或文档分组切分？答：降低同源样本跨集合泄漏。

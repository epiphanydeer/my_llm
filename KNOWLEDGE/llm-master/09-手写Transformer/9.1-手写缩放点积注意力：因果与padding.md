### 一、提出问题与真实痛点

在自然语言处理实际生产批处理（Batch Processing）中，不同句子的长度几乎从来都不一样：
- 句子 1：“今天天气真好”（6 个字）
- 句子 2：“你好”（2 个字 + 4 个 Padding 占位符 `[PAD]`）
- **两大致命工程陷阱**：
  1. **Padding 键泄漏（Key Masking）**：模型在计算自注意力时，绝不能把注意力分给无意义的 `[PAD]`。如果让正常字关注了 `[PAD]`，有效语义会被大量无用噪点严重稀释！
  2. **Padding 查询污染（Query Masking）**：对于 `[PAD]` 自身的查询，其输出必须被严格置为 0，不能在反向传播时向模型注入虚假梯度。
- 本节目标：从零手写支持**右侧变长 Padding 掩码**与**因果未来屏蔽**的双重掩码缩放点积注意力内核！

---

### 概念主线：前面的问题如何解决

**目标：** 给输入 X=(B,T,C)，独立写投影、点积、缩放、mask、softmax、加权求和，并用断言验证输出形状。

### 二、心智模型与 ASCII 图解

```
【双重掩码缩放点积注意力执行矩阵】
输入 Query 与 Key 点积后形成的原始分数矩阵:
            K1(真)  K2(真)  K3(PAD)  K4(PAD)
  Q1(真)   [  S11    S12     S13      S14  ]
  Q2(真)   [  S21    S22     S23      S24  ]
  Q3(PAD)  [  S31    S32     S33      S34  ]
  Q4(PAD)  [  S41    S42     S43      S44  ]
                      │
                      ▼ 叠加因果 Mask (未来遮蔽) + Padding Key Mask (PAD 遮蔽)
            K1(真)  K2(真)  K3(PAD)  K4(PAD)
  Q1(真)   [  S11   -inf    -inf     -inf  ] ──> 只看自己
  Q2(真)   [  S21    S22    -inf     -inf  ] ──> 看 Q1 和 Q2，绝不看 PAD！
  Q3(PAD)  [ -inf   -inf    -inf     -inf  ] ──> 无效行后续输出硬置为 0
  Q4(PAD)  [ -inf   -inf    -inf     -inf  ]
```

---

### 三、核心概念与五要素表

| 五要素 | 带 Padding 的因果注意力算子 |
|---|---|
| **输入 (Input)** | 投影特征 $Q, K, V \in \mathbb{R}^{B 	imes T 	imes D}$，布尔有效掩码 `valid_mask` $\in \{0, 1\}^{B 	imes T}$。 |
| **做什么 (Process)** | 缩放点积 $Q K^T / \sqrt{D}$；构造因果下三角掩码；将无效 Key 位置注入 $-1e9$；Softmax；加权 Value；将无效 Query 输出硬置为零。 |
| **输出 (Output)** | 上下文表征 $Y \in \mathbb{R}^{B 	imes T 	imes D}$，注意力权重矩阵 $W \in \mathbb{R}^{B 	imes T 	imes T}$。 |
| **哪里出错 (Failure Modes)** | 1. 误将无效 Key 的 mask 漏掉；2. 出现整行全为 $-1e9$ 时直接做普通 Softmax 导致 NaN 溢出。 |
| **参数影响 (Parameters)** | 掩码极小值 $-1e9$ 必须保证经 $\exp(-1e9) = 0.0$ 且不破坏 FP32 动态范围。 |

### 四、代码动手实践与严格断言

```python
"""9.1 纯手撕带变长 Padding 与因果双重掩码的缩放点积注意力

纯 NumPy 实现：
1. 校验 Q, K, V 形状与有效掩码；
2. 构造因果掩码与 Key Padding 掩码；
3. 防 NaN 安全 Softmax 处理；
4. 将无效 Query 行输出强制置零；
5. 严格断言：Padding Key 权重必为 0，Padding Query 输出必全为 0。
"""
import numpy as np

def manual_causal_padding_attention(
    Q: np.ndarray,
    K: np.ndarray,
    V: np.ndarray,
    valid_mask: np.ndarray
) -> tuple[np.ndarray, np.ndarray]:
    """
    Q, K, V: (B, T, D)
    valid_mask: (B, T), 1 为真实 token, 0 为 PAD
    """
    B, T, D = Q.shape
    assert K.shape == (B, T, D) and V.shape == (B, T, D)
    assert valid_mask.shape == (B, T)
    
    # 1. 缩放点积: (B, T, D) @ (B, D, T) -> (B, T, T)
    scores = np.matmul(Q, K.swapaxes(-1, -2)) / np.sqrt(D)
    
    # 2. 构造复合掩码
    # (a) 因果掩码：上三角为 False (禁止关注未来)
    causal_allowed = np.tril(np.ones((T, T), dtype=bool))  # (T, T)
    
    # (b) Key 掩码：只有真实 Key 允许被关注
    key_allowed = valid_mask[:, np.newaxis, :]  # (B, 1, T)
    
    # 综合允许矩阵: (B, T, T)
    allowed = causal_allowed[np.newaxis, :, :] & (key_allowed > 0)
    
    # 将不允许关注的位置填入 -1e9
    scores = np.where(allowed, scores, -1e9)
    
    # 3. 数值稳定 Softmax (防止全 -1e9 行产生 NaN)
    # 对于全为 -1e9 的无效 Query 行，显式处理
    max_scores = np.max(scores, axis=-1, keepdims=True)
    # 若某行全被遮蔽，max 也是 -1e9，exp 后全为 0
    exp_scores = np.where(allowed, np.exp(scores - max_scores), 0.0)
    sum_exp = np.sum(exp_scores, axis=-1, keepdims=True)
    # 避免除以 0
    attn_weights = np.where(sum_exp > 0, exp_scores / (sum_exp + 1e-12), 0.0)
    
    # 4. 加权聚合: (B, T, T) @ (B, T, D) -> (B, T, D)
    out = np.matmul(attn_weights, V)
    
    # 5. Query 掩码：无效的 Query 位置输出必须严格为 0
    query_mask = valid_mask[:, :, np.newaxis]  # (B, T, 1)
    out = out * query_mask
    
    return out, attn_weights

def self_test():
    B, T, D = 2, 4, 8
    np.random.seed(42)
    Q = np.random.randn(B, T, D)
    K = np.random.randn(B, T, D)
    V = np.random.randn(B, T, D)
    
    # Batch 0: 前 3 个有效，最后 1 个为 PAD -> [1, 1, 1, 0]
    # Batch 1: 前 2 个有效，后 2 个为 PAD -> [1, 1, 0, 0]
    valid_mask = np.array([
        [1, 1, 1, 0],
        [1, 1, 0, 0]
    ], dtype=np.int32)
    
    out, weights = manual_causal_padding_attention(Q, K, V, valid_mask)
    
    # 1. 验证输出形状
    assert out.shape == (B, T, D)
    assert weights.shape == (B, T, T)
    
    # 2. 验证 Batch 0:
    # 位置 3 是 PAD，输出向量必须严格为全 0
    assert np.all(out[0, 3, :] == 0.0), "无效 Query 输出必须为 0！"
    # 位置 0, 1, 2 对位置 3 (PAD) 的注意力权重必须严格为 0
    assert np.all(weights[0, :3, 3] == 0.0), "真实 Token 绝不能关注 PAD Key！"
    
    # 3. 验证 Batch 1:
    # 位置 2, 3 是 PAD，输出必全为 0
    assert np.all(out[1, 2:, :] == 0.0)
    assert np.all(weights[1, :2, 2:] == 0.0)
    
    # 4. 验证有效行的概率和为 1.0
    row_sums_b0 = np.sum(weights[0, :3], axis=-1)
    assert np.allclose(row_sums_b0, 1.0, atol=1e-5)
    print("✅ 9.1 手写因果与 Padding 双重掩码缩放点积注意力自检全部通过！")

if __name__ == '__main__':
    self_test()
```

### 五、面试通关口述与避坑

- **高频追问**：如果在计算 Attention 时某一行所有 Key 全被 Mask 掉了（例如全 Padding 行），直接做 Softmax 会发生什么？怎么解决？
  - **白板口述框架**：
    1. **直接 Softmax 会引发 NaN 污染**：全被 Mask 的行元素全为 $-\infty$。在 Softmax 计算时，分子为 $e^{-\infty} = 0$，分母求和也为 0。出现 $ rac{0}{0}$ 不定式，在 IEEE 754 浮点标准下产生 `NaN`（Not a Number），进而污染后续所有的残差加和与整个网络权重！
    2. **工程防御标准做法**：
       - 在计算 Softmax 分母时增加微小防零项：$ rac{\exp(S)}{\sum \exp(S) + \epsilon}$；
       - 或者在 Softmax 前识别有效位置掩码，对全遮蔽行直接显式赋予全 0 权重，并在输出端将无效 Query 对应的特征向量强制乘零置零。

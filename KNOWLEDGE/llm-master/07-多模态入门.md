## 7.1 先分清 VQA、识别、检测、定位和描述【🔥】

**概念。** VQA 输入图片和问题，输出答案；图像分类通常输出预定义类别；目标检测输出类别与边框；视觉定位（grounding）根据文字找区域；图像描述输出自然语言。VLM 可以尝试多种任务，但不能因为回答里出现“左上角有安全帽”就当它给出了合格的检测框。

**例子。** 同一张工地图片：
- VQA：“工人是否戴安全帽？”→“没有。”
- 检测：输出工人、头部、安全帽的类别与坐标。
- 定位：“未戴安全帽的人在哪里？”→某个框或区域。
- 文档理解：“图中的告示牌写了什么？”→需要识别文字和布局。
这些任务的金标准和指标不同。回答看起来流畅，可能仍把第二个人认成第一个人。

**面试怎么讲。** 先说业务到底需要文本答案、边框还是可追溯证据；再选基线模型和评估单位。不要拿 VQA 的答对率冒充检测的 mAP。

**费曼自述：** “不同任务要求的输出不同。我要先定义系统交付什么，才能知道用什么模型、怎样标注和怎样评估。”

**概念闪卡：** Q：VQA 和目标检测的输出差别？A：前者回答问题，后者通常给类别和空间位置。Q：语言答案能证明定位准确吗？A：不能，需用框、区域或对应标注核验。

## 7.2 视觉特征如何接到 LLM【🔥】

常见的一类 VLM 包含**视觉编码器、连接模块、语言模型**。视觉编码器把图像变成一组特征；连接模块把它们映射到语言模型能处理的维度或表示；语言模型结合视觉信息和问题生成文本。LLaVA 是理解这种基本结构的好例子，但具体模型可能使用不同的视觉 token 压缩、分辨率处理和融合方式。[LLaVA 原论文](https://arxiv.org/abs/2304.08485)说明了视觉编码器与 LLM 的连接思路；[Qwen3-VL 技术报告](https://arxiv.org/abs/2511.21631)展示了图像、视频和长上下文场景的进一步设计。

~~~text
图像 → resize / patch / 视觉编码器 → 视觉表示
文字问题 → tokenizer → 文本 token
视觉表示 + 文本 token → 多模态模型 → 答案 token
~~~

**形状例子。** 两张图片组成一个 batch，视觉编码后每张得到 N 个视觉 token，每个 token 是 D 维；文字则是长度 T 的 token 序列。具体 N 会随模型、分辨率和裁切方式变化。图像变大可能导致视觉 token、显存和推理时间增长，所以不能只按“图片张数”估算成本。

**要理解的训练关系。** 视觉编码器负责提取信息，连接模块负责表示对齐，LLM 负责结合指令生成。训练时可以只更新连接模块、给语言层加 LoRA，或根据任务训练更多模块；冻结范围要与数据量、显存和基线结果一起决定。

**面试怎么讲。** 画出三块结构，指出信息可能在哪一步丢失：图片预处理模糊小字、视觉编码看不到细节、连接模块对齐不足、语言模型误读问题。排障比只报模型名称有价值。

**费曼自述：** “图片不能直接当文本送进 LLM。视觉部分先把它编码成可用表示，再通过连接方式让语言模型利用这些信息。”

**概念闪卡：** Q：连接模块解决什么？A：让视觉表示能被后续语言模型利用。Q：高分辨率为什么会影响成本？A：可能增加视觉 token/裁切和计算量，具体取决于模型实现。

## 7.3 Processor、对话模板和输入校验【🔥】

纯文本模型通常用 tokenizer 处理消息。多模态模型还要处理图片、视频帧等，常由 **Processor** 负责聊天模板、文字 token 化和媒体预处理。Hugging Face 的[多模态聊天模板文档](https://huggingface.co/docs/transformers/en/chat_templating_multimodal)展示了消息里混合 image/text 的形式；处理后可包含 input_ids、attention_mask、pixel_values 等字段。实际字段取决于模型，不能把一个模型的输出键写死到所有 VLM。

~~~python
# 结构示意：具体类名和模型 ID 以所选模型官方示例为准
messages = [{
    "role": "user",
    "content": [
        {"type": "image", "path": "sample.jpg"},
        {"type": "text", "text": "图中有人没有佩戴安全帽吗？"}
    ]
}]
processed = processor.apply_chat_template(
    messages,
    tokenize=True,
    add_generation_prompt=True,
    return_dict=True,
    return_tensors="pt",
)
print(processed.keys())  # 检查实际输入字段
~~~

**先学会的纯 Python 校验：**

~~~python
def validate_image_question(item):
    if not isinstance(item, dict):
        raise TypeError("item 必须是字典")
    if not item.get("image_path"):
        raise ValueError("缺少 image_path")
    if not item.get("question"):
        raise ValueError("缺少 question")
    return item

assert validate_image_question({
    "image_path": "sample.jpg", "question": "是否戴安全帽？"
})["image_path"] == "sample.jpg"
~~~

这个小练习不需要 GPU，却能训练你检查输入结构的习惯。上真实模型时再查文件是否存在、图片能否解码、尺寸是否超限，以及输入张量和模型是否在兼容设备上。

**费曼自述：** “Processor 是多模态输入的准备者。我要确认它产出了模型真正需要的字段，不能照搬另一个模型的模板。”

**概念闪卡：** Q：为什么文字 tokenizer 不够？A：图片/视频还需预处理并放入多模态消息结构。Q：图片加载失败应在哪一步发现？A：在调用模型前的输入校验与解码阶段。

## 7.4 多模态训练数据怎样组织【🔥】

一个可复现的图文样本至少要有媒体路径或 ID、问题/指令、期望输出、数据来源和标注规则。要检查图片能否打开、答案是否只依赖图片、同一图片是否跨训练/验证集泄漏。视频还要标帧时间与片段边界。

~~~json
{
  "image_id": "public_001",
  "image_path": "images/public_001.jpg",
  "question": "图中有几个人？",
  "answer": "2",
  "task": "counting",
  "split": "train",
  "source": "公开授权数据集"
}
~~~

**例子。** 如果同一工地照片的不同裁切分别进入训练和测试，模型可能记住场景而不是真会识别。按原图或拍摄事件划分，比随机按问答行划分更可靠。若“未戴安全帽”样本只出现在夜间照片，模型也可能学到背景捷径。

**标注质量。** 对开放问答要写可接受的同义答案规则；对边框需要坐标体系和边界规范；对无答案样本需要明确“无法判断”标签。训练集大不等于可靠，先抽样审查和建立固定评估集。

**费曼自述：** “训练样本不仅有图和答案，还应说明任务、来源与切分。我要防止同一画面进入训练和测试，避免虚高指标。”

**概念闪卡：** Q：为什么按问答行随机划分可能泄漏？A：同一图片可对应多道问题并跨集合出现。Q：无答案样本有什么用？A：测试模型是否能拒绝没有视觉依据的回答。

## 7.5 VLM 微调从基线开始【🔥】

先用零样本或少样本 Prompt 跑固定测试集，记录每类错误。只有确认输出格式、领域视觉理解或任务行为达不到目标时，再准备 SFT/LoRA。Hugging Face 的[VLM SFT 指南](https://huggingface.co/docs/trl/main/training_vlm_sft)给出多图数据与训练流程的官方例子；其 API 参数随版本变化，用时核对。

**一个实验表：**

| 版本 | 改动 | 固定测试集指标 | 代价 | 主要错误 |
|---|---|---:|---|---|
| B0 | 原模型 + 固定 Prompt | 待实测 | 基线推理 | 小目标漏判 |
| B1 | 更清晰的输入裁切 | 待实测 | 视觉 token 增加 | 是否改善小目标 |
| B2 | LoRA + 公开训练数据 | 待实测 | 训练显存/时间 | 是否过拟合 |

**训练关注点。** 需要看 processor 输出、标签 mask（哪些 token 参与 loss）、冻结/训练参数集合、batch 和梯度累积、图片分辨率、学习率、验证集。VLM 的显存不只由语言模型参数决定，视觉 token 和图片处理同样重要。不要把文本 LLM 的 LoRA 配置直接搬来。

**面试怎么讲。** 解释为何微调、微调了哪些模块、训练多少可用样本、哪类指标改善/退化、有没有训练集泄漏。没有真实数值时先做实验，简历里不能写示例表的“待实测”为成果。

**费曼自述：** “我先测原模型，找出可重复的错误，再决定改输入、数据还是权重。训练不是项目成果，固定测试集的改进才是证据。”

**概念闪卡：** Q：VLM 的显存为何可能随图片增大？A：视觉 token/裁切和序列计算可能增加。Q：LoRA 后只看训练 loss 够吗？A：不够，需独立验证集和任务指标。

## 7.6 评估要把视觉错误与语言错误分开【🔥】

一个“图片问答正确率”会掩盖很多不同失败。建议给每条错误标：图片不可读、目标太小/遮挡、OCR 错、定位错、计数错、模型凭常识猜、回答格式错、引用错。对可数答案可做规范化准确率；对边框用 IoU/mAP；开放问答需要人工核查或有约束的判分规则。

**例子。** 用户问“第 3 个人是否戴帽”，模型答“有人戴帽”。文本似乎相关，却没回答指定对象；应归为定位/指代错误，而非只看关键词命中。图像资料还可能有地理/时间分布差异，必须在评估集记录这类切片。

**最小错误分析表：**

| 样本 ID | 真实答案 | 模型答案 | 错误类型 | 可能原因 | 下一步验证 |
|---|---|---|---|---|---|
| img_07 | 右侧人员未戴帽 | 所有人均戴帽 | 小目标漏判 | 缩放后头部太小 | 比较裁切输入 |

**面试怎么讲。** 报总指标之外再报分组指标：小目标、夜间、遮挡、文字密集图、无答案；展示一次改动如何改变这些分组，而不是只展示最好看的样例。

**费曼自述：** “一句回答错了，我要先判断是看错图、理解错问题，还是输出格式/引用错，再有针对性地改。”

**概念闪卡：** Q：开放问答只做字符串完全匹配有什么问题？A：同义表达会被误判，含糊回答可能被误判正确。Q：错误分析表最低要留什么？A：输入 ID、金标、输出、错误类别和验证计划。

## 7.7 视频比图片多了时间轴【⭐】

视频输入常要抽帧、编码时间信息，再让模型处理多帧与问题。不同模型可接受的视频长度、采样方式和输入格式不同；[Transformers 多模态消息说明](https://huggingface.co/docs/transformers/en/chat_templating_multimodal)展示视频消息的结构。视频结果可能因抽帧漏掉关键瞬间。

**例子。** “工人在进入危险区域前是否戴上安全帽？”需要判断动作先后。只抽到进入前和进入后的两帧可能不够；系统应保存帧时间戳，必要时增加采样密度或事件检测。

**成本与评估。** 记录帧率、总帧数、分辨率、输入 token、延迟与错误类型。答案正确还要检查时间定位是否正确。长视频先做片段检索/筛选再提问，可能比把所有帧塞进模型更可控。

**费曼自述：** “视频不只是多张图片；问题往往依赖事件顺序。抽帧如果丢掉关键瞬间，模型再强也无从判断。”

**概念闪卡：** Q：视频输入的新增信息是什么？A：时间顺序和事件持续过程。Q：为什么要保存帧时间戳？A：便于核对答案和回看证据片段。

## 7.8 多模态 RAG：图片证据与文字条款分开核对【⭐】

有些项目同时要回答“图中发生什么”和“制度如何规定”。可先用 VLM/检测模型抽取视觉事实，再从文档库检索相关条款，最后把两份证据组合成结论。也可直接索引图像/图文块做跨模态检索，但要单独评估图像召回。

~~~text
图片 → 视觉事实及置信/定位证据
文字问题 → 文档检索 → 条款及版本/页码
两路证据 → 生成结论 → 分别核对视觉判断和条款引用
~~~

**例子。** 视觉模型说“未佩戴安全帽”，条款检索找到“进入施工区域必须佩戴安全帽”。最终回答应区分图像观察与制度要求，不应把条款当成图片事实。若图片模糊，应写“无法确定”，而不是因制度要求就推断工人一定没戴帽。

**费曼自述：** “视觉和文本有不同的证据来源。我先判断图片事实，再找对应规则，最后分别检查两边是否支持结论。”

**概念闪卡：** Q：制度条款能证明图片里发生了违规吗？A：不能，需视觉证据。Q：图片判断正确但引用旧条款属于哪段错误？A：检索版本或引用错误。

## 7.9 面试与作品集：你该拿出什么【🔥】

针对应用算法/MLE，能写进简历的 VLM 项目至少要有：公开且可复现的数据、可运行基线、固定评估集、错误分类、一次针对错误的改进、前后指标、成本/延迟、README 和演示。现有工作中的私有数据和代码不要复制到公开作品；可用公开数据做结构相同的独立项目。

**推荐顺序。**
1. 纯图像/文本问答基线：固定 30～50 条公开样本，跑模型并保存输出。
2. 错误分析：统计 OCR、小目标、指代、无答案等失败。
3. 有证据的改进：裁切/分辨率、Prompt、LoRA 或检索，选择一个并测前后结果。
4. 服务化：输入校验、日志、失败处理、可重现脚本。
5. 简历表达：“基线 X，在 Y 类公开测试集上针对 Z 错误做 A 改动，指标和代价分别变化为……”。数值必须来自真实实验。

**常见追问。** 为什么选 VLM 而非检测器？视觉 token 增长如何影响延迟？哪些模块冻结？测试集怎么防泄漏？图片模糊时怎么拒答？多模态答案怎么引用原始证据？以上问题要结合自己的数据与实验回答。

**费曼自述：** “我能把一个视觉问题定义成可测任务，跑出基线，定位错误，做一次能复现的改动，并清楚说明收益和代价。”

**概念闪卡：** Q：运行官方 Demo 能直接写成强项目吗？A：还需任务定义、数据、基线、评估、错误分析和可复现改进。Q：为什么要记录代价？A：效果提升可能伴随显存、延迟或标注成本增加。

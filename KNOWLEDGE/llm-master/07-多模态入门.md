## 7.1 先分清 VQA、分类、检测、定位和描述【🔥 必会】

〔本次新补，参考当前面试趋势〕

### 目标与例子

同一张工地图片可以提出不同任务：分类问“是否有安全帽”；VQA 问“右侧工人是否戴帽”；检测要求输出目标类别和框；视觉定位按文本找对应目标；描述生成一段自然语言。业务需要可核验的位置时，只有流畅文本还不够，需要单独检验定位证据。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 单图或多图；VQA/定位还需要问题或指代文本。 |
| 做什么 | 模型按任务生成答案、类别或空间位置；评估器按相应标注规则比较预测和金标准。 |
| 输出 | 分类标签、文本答案、边框/区域等，结构与任务有关。 |
| 哪里出错 | 目标太小、遮挡、错认对象、文本答非所问、框坐标或类别定义不一致。 |
| 参数影响 | 检测的置信度与 IoU 阈值影响匹配和误报；分辨率影响细节与成本；评测标注单位决定指标口径。 |

### 面试追问

- 【🔥 必会】VQA 正确率能当检测 mAP 吗？ 一句话：不能，任务输出和计算方式不同。展开：VQA 比较答案；检测需要按类别、置信度和位置匹配，计算不同召回水平下的精度，再聚合得到 AP/mAP。

- 【🔥 必会】检测看起来有框但指标接近零，怎么排查？ 一句话：先核对坐标、类别和匹配阈值。展开：把预测和金标叠回原图，确认归一化、缩放、坐标顺序与类别映射，再检查置信度和 IoU 阈值。

- 【⭐ 理解】模型说“有人没戴帽”能证明找对人了吗？ 一句话：不能，需单独核验对象位置。展开：如果业务问指定的人，正确输出要能关联到该对象；要用框、区域或人工检查验证指代。

### 故障模式与排障

- **框整体偏移：**对照原图绘制预测框，检查 resize、padding、归一化及坐标还原；按实际变换链恢复原图坐标后回归。

- **同一目标被多次统计为命中：**查看匹配结果与重复框；按置信度排序并一对一匹配，必要时在模型后处理阶段调 NMS。

- **低阈值召回高但误报多：**在固定验证集扫描阈值，分别看目标召回、误报及关键场景切片；以业务代价选阈值。

### 工程 trick 与坑

- 框常见格式有 (x1,y1,x2,y2) 和 (x,y,w,h)；必须先统一格式、单位和图像坐标系。

- 匹配同一金标时每个金标最多被一个预测使用；先按置信度排序，再在未匹配金标中选择最大 IoU。

- 下例只算单类别、单 IoU 阈值的一张图的匹配计数，不等于 AP、mAP 或数据集指标；生产评估应使用成熟检测评估工具并明确其版本与口径。

### Toy code：调用 torchvision 计算框的 IoU 并一对一匹配

运行前提：Python 3.10+、PyTorch 和 torchvision。本机可用 D:/Miniconda3/envs/pytorch/python.exe。全部坐标都是同一张图片的像素坐标；例子为虚构方框，不做图像识别。

```python
from typing import Optional

import torch
from torch import Tensor
from torchvision.ops import box_iou


def validate_boxes(boxes: Tensor, name: str) -> None:
    """校验形状 (N,4)、有限坐标和严格正面积。"""
    if boxes.ndim != 2 or boxes.shape[1] != 4:
        raise ValueError(f"{name} 必须是 (N,4)")
    if not boxes.is_floating_point() or not bool(torch.isfinite(boxes).all()):
        raise ValueError(f"{name} 必须为有限浮点坐标")
    if boxes.numel() and not bool((boxes[:, 2:] > boxes[:, :2]).all()):
        raise ValueError(f"{name} 必须满足 x2>x1 且 y2>y1")


def match_one_class(
    predicted: Tensor, scores: Tensor, gold: Tensor, threshold: float = 0.5
) -> dict[str, int | Optional[float]]:
    """按置信度降序，一对一匹配单图单类别预测框和金标框。"""
    validate_boxes(predicted, "预测框")
    validate_boxes(gold, "金标框")
    if scores.ndim != 1 or len(scores) != len(predicted):
        raise ValueError("置信度必须是一维且与预测数相同")
    if not scores.is_floating_point() or not bool(torch.isfinite(scores).all()):
        raise ValueError("置信度必须为有限浮点数")
    if not bool(((scores >= 0) & (scores <= 1)).all()) or not 0 <= threshold <= 1:
        raise ValueError("置信度和 IoU 阈值必须在 [0,1]")
    if predicted.device != gold.device or scores.device != predicted.device:
        raise ValueError("预测、置信度和金标需位于同一设备")
    overlaps = box_iou(predicted, gold)
    assert overlaps.shape == (len(predicted), len(gold))
    used: set[int] = set()
    hits = 0
    for pred_index in torch.argsort(scores, descending=True).tolist():
        candidates = [j for j in range(len(gold)) if j not in used]
        if not candidates:
            continue
        best = max(candidates, key=lambda j: float(overlaps[pred_index, j]))
        if float(overlaps[pred_index, best]) >= threshold:
            used.add(best)
            hits += 1
    false_positive = len(predicted) - hits
    false_negative = len(gold) - hits
    assert 0 <= hits <= min(len(predicted), len(gold))
    return {"tp": hits, "fp": false_positive, "fn": false_negative,
            "precision": hits / len(predicted) if len(predicted) else None,
            "recall": hits / len(gold) if len(gold) else None}


def main() -> None:
    """验证重复预测、空金标和非法坐标。"""
    prediction = torch.tensor([[0., 0., 10., 10.], [0., 0., 10., 10.]])
    scores = torch.tensor([0.9, 0.8])
    gold = torch.tensor([[0., 0., 10., 10.]])
    result = match_one_class(prediction, scores, gold)
    assert result == {"tp": 1, "fp": 1, "fn": 0, "precision": 0.5, "recall": 1.0}
    empty = torch.empty((0, 4), dtype=torch.float32)
    assert match_one_class(prediction, scores, empty)["recall"] is None
    try:
        match_one_class(torch.tensor([[1., 1., 0., 0.]]), torch.tensor([0.5]), gold)
    except ValueError:
        pass
    else:
        raise AssertionError("反向坐标应报错")
    print("单类框匹配自检通过:", result)


if __name__ == "__main__":
    main()
```

逐段讲解：validate_boxes 统一校验框的形状、数值及面积；box_iou 产生预测框与金标的两两 IoU；主循环按置信度将预测与尚未使用的最佳金标匹配。分母为零返回 None，不把无样本误报为零分。

### 这段代码怎么在面试里讲

- **声明不变量：**输入框形状为 (N,4)、均有正面积；IoU 矩阵形状为 (预测数,金标数)，一个金标最多匹配一次。

- **解释关键行：**先计算所有 IoU，再按置信度顺序对未匹配金标贪心匹配；未匹配预测为 FP，未匹配金标为 FN。

- **主动说边界：**仅限一张图、一个类别、一个阈值；不计算 AP/mAP，也不处理分割、crowd 标注、类别映射和完整数据集聚合。

### 本节收尾：费曼自述与闪卡

**费曼自述：**不同视觉任务要交付不同的输出。检测不仅要判断类别，还要核对位置；评估前必须统一坐标、类别、阈值和匹配规则。

- Q：VQA 答案正确能代表检测框准确吗？A：不能，需按检测标注和位置指标验证。

- Q：两个预测框都覆盖同一个金标，可以算两个 TP 吗？A：不能，一对一匹配下最多一个。

- Q：这段单图单阈值代码是 mAP 吗？A：不是；mAP 需要更完整的置信度排序、数据集聚合与评估协议。

- Q：预测框与原图对不上先看什么？A：看 resize、padding、坐标格式和坐标还原。

## 7.2 视觉特征如何接到语言模型【🔥 必会】

〔本次新补，参考当前面试趋势〕

### 目标与例子

闭卷画出一种常见 VLM 的数据流，并说明错误可能在哪一段发生。例子：输入安全图片和“右侧工人是否戴帽？”视觉部分把图片变成一串特征，连接模块将其映射到语言模型使用的维度，再与文本信息一起参与生成。视觉特征中如果丢掉了很小的头部目标，后面的语言模型不能凭空恢复可靠证据。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 图片 (B, 3, H, W) 与问题文本；具体预处理、视觉切块和文本模板随模型而变。 |
| 做什么 | 视觉编码器抽取视觉表示，连接模块对齐到语言模型输入空间；语言模型根据视觉与文本上下文生成答案。 |
| 输出 | 视觉 token/特征、中间投影结果与最终文本；有些模型还能给定位或其他结构化输出。 |
| 哪里出错 | 图片缩放丢失小目标、视觉 token 与文本占位符不匹配、维度不匹配、投影与编码器权重未对齐、模型凭常识猜测。 |
| 参数影响 | 分辨率、切块与帧数影响保留的细节和计算量；投影维度必须匹配语言模型；冻结范围影响可训练参数与显存。 |

这只是常见结构：如 [LLaVA](https://arxiv.org/abs/2304.08485) 将视觉编码器连接到语言模型。不同 VLM 的视觉 token 压缩、多图和视频处理方式可能不同，不能认为所有模型均为同一拼接方式。维度匹配只是计算能运行的必要条件；训练后的语义对齐也不可缺少。

### 面试追问

- 【🔥 必会】投影层为什么需要训练？ 一句话：维度对上不等于语义对齐。展开：视觉特征空间与语言模型输入表示不同；需要训练连接模块或更多组件，让模型学会利用视觉信息。

- 【🔥 必会】小字始终识别不对，怎么定位？ 一句话：先检查预处理是否保留文字。展开：比较原图、缩放与裁切结果，确认文字是否可辨；再对比 OCR、视觉模型输出和语言回答，分别定位视觉与生成错误。

- 【⭐ 理解】分辨率翻倍，成本一定翻倍吗？ 一句话：不一定，要看模型的视觉处理。展开：固定 patch 方案中，宽高都翻倍时 patch 数可能变为四倍；实际模型可能采用裁切、压缩或动态分辨率，须实测。

### 故障模式与排障

- **投影层维度异常：**打印视觉输出和语言模型输入最后一维，核对 checkpoint 与模型配置；让投影输入/输出维度分别匹配，不能通过随意 reshape 伪造语义对齐。

- **图片明明有字但回答漏掉：**查看实际输入分辨率、裁切后区域和视觉 token 数，比较局部裁切与原图；同时记录延迟和错误切片。

- **模型只凭常识回答：**构造图像替换或问题反事实测试，人工检查定位证据；输入信息不足时应拒答，而不是把自然流畅当作看对图。

### 工程 trick 与坑

- Processor、视觉编码器、投影层和语言模型要使用同一 checkpoint 对应的配置，不能随便混搭。

- 减少视觉 token 可能降低成本，但也可能损失小字、密集目标和空间信息；用分组数据测。

- 训练时分别记录视觉编码器、连接层和语言模型是否冻结，推理排障还要检查媒体 token 与图片顺序。

- 下方只做结构和形状练习，权重随机，没有语言模型，不可用其输出做安全识别。

### Toy code：用 torchvision 构造微型视觉编码器并投影

运行前提：Python 3.10+、PyTorch、torchvision；本机使用 D:/Miniconda3/envs/pytorch/python.exe。代码用库的 VisionTransformer 构造小尺寸随机模型，不下载权重、不具备视觉语义能力，也不是完整 VLM。它演示图片如何变为视觉 token，以及线性层如何改变最后一维。

```python
import torch
from torch import Tensor, nn
from torchvision.models.vision_transformer import VisionTransformer


class VisualBridge(nn.Module):
    """演示微型 ViT 的 patch 编码和视觉到语言维度的映射。"""

    def __init__(self, llm_dim: int = 48) -> None:
        super().__init__()
        if llm_dim <= 0:
            raise ValueError("语言模型维度必须为正")
        self.encoder = VisionTransformer(
            image_size=32, patch_size=8, num_layers=2, num_heads=4,
            hidden_dim=32, mlp_dim=64, num_classes=2,
        )
        self.projector = nn.Linear(32, llm_dim)

    def forward(self, images: Tensor) -> Tensor:
        """(B,3,32,32) -> (B,16,llm_dim)，不含 cls token。"""
        if images.ndim != 4 or tuple(images.shape[1:]) != (3, 32, 32):
            raise ValueError("输入必须是 (B,3,32,32)")
        if images.shape[0] == 0 or not images.is_floating_point():
            raise ValueError("batch 非空且图片必须是浮点数")
        if not bool(torch.isfinite(images).all()):
            raise ValueError("图片包含非有限值")
        patches = self.encoder.conv_proj(images)
        batch, channels, height, width = patches.shape
        assert (channels, height, width) == (32, 4, 4)
        tokens = patches.flatten(2).transpose(1, 2)
        cls = self.encoder.class_token.expand(batch, -1, -1)
        encoded = self.encoder.encoder(torch.cat([cls, tokens], dim=1))
        visual = encoded[:, 1:, :]
        projected = self.projector(visual)
        assert projected.shape == (batch, 16, self.projector.out_features)
        assert bool(torch.isfinite(projected).all())
        return projected


def main() -> None:
    """验证形状、非法输入和有限输出；不评估语义。"""
    torch.manual_seed(7)
    model = VisualBridge(llm_dim=48).eval()
    images = torch.rand(2, 3, 32, 32)
    with torch.inference_mode():
        output = model(images)
    assert output.shape == (2, 16, 48)
    try:
        model(torch.rand(2, 3, 16, 16))
    except ValueError:
        pass
    else:
        raise AssertionError("错误图片尺寸应报错")
    try:
        model(torch.full((1, 3, 32, 32), float("nan")))
    except ValueError:
        pass
    else:
        raise AssertionError("非有限输入应报错")
    print("视觉 token:", tuple(output.shape), "形状自检通过")


if __name__ == "__main__":
    main()
```

逐段讲解：库中的卷积投影把 32×32 图片划成 4×4 个 patch；展平并转置成 (B,16,32)，加入分类 token 后送入 ViT 编码器；去掉分类 token 后用线性投影得到 (B,16,48)。真实模型可能采用不同视觉编码、连接或压缩策略，且需要训练权重。

### 这段代码怎么在面试里讲

- **声明不变量：**输入为 (B,3,32,32)，patch 数为 16，视觉隐藏维度 32，投影后每个 token 为 48 维。

- **解释关键行：**先由库的 patch 投影和 ViT 编码获得特征，再投影最后一维，保留 batch 和 token 数。

- **主动说边界：**随机权重仅能验数据流，不能识图；真实语义对齐需要匹配 processor、已训练的视觉模块及连接器，且不同 VLM 结构可能不同。

### 本节收尾：费曼自述与闪卡

**费曼自述：**视觉编码器把图片变成表示，连接模块让表示能进入语言模型。维度匹配只能让运算成立，理解图片还需要训练后的语义对齐。

- Q：维度相同就代表视觉和文本语义对齐吗？A：不代表，还需要合适的训练及匹配的权重。

- Q：小目标消失先查哪里？A：检查预处理、分辨率和裁切后是否仍看得见，再查后续模型。

- Q：宽高均翻倍时 patch 数一定翻倍吗？A：固定 patch 下通常变为四倍；具体实现可能不同。

- Q：随机初始化的 ViT 能证明安全识别能力吗？A：不能，它只用于验证数据形状和代码路径。

## 7.3 Processor、对话模板和输入校验【🔥 必会】

〔本次新补，参考当前面试趋势〕

### 目标与例子

把图片和问题转换为模型能消费的输入，同时在调用模型前发现缺图、坏图和模板不匹配。例子：一条用户消息包含工地图片和“右侧工人是否戴帽？”；processor 要按对应模型的规范处理图片、渲染对话模板并编码文本，得到文本 token 与图像张量。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 消息角色、图像/视频及文本，模型配套的 processor、模板和媒体预处理配置。 |
| 做什么 | 渲染对话模板，加载/缩放图像，转换成张量并编码文本；部分模型需要额外的视觉网格、尺寸或 token 信息。 |
| 输出 | 常见字段包括 input_ids、attention_mask、pixel_values，具体键和形状以所用模型为准。 |
| 哪里出错 | 路径错误或图片损坏、颜色模式不符、模板与权重不匹配、图像顺序错、图像占位 token 数与特征数不一致。 |
| 参数影响 | 图片缩放、patch 大小和切块规则影响细节、视觉 token 与开销；生成提示标志影响模板末尾与模型响应起点。 |

Processor 不等于模型推理：它准备输入，模型前向或 generate() 才产出预测。不同模型的输出字段不一定相同，避免把某一个 VLM 的键名和 token 规则硬套到全部模型。使用真实 checkpoint 时应从同一模型及版本加载配套 processor 和模型，参阅 [Transformers 多模态聊天模板](https://huggingface.co/docs/transformers/en/chat_templating_multimodal)。

与目标 Qwen 项目的衔接〔本次新补，参考当前面试趋势〕。 以 [Qwen2.5-VL 模型卡](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct)为例，实际使用时需按指定版本加载配套 processor 与预训练模型，用其聊天模板编码图片和问题，再生成并只解码新增 token；不同版本的类名和依赖以模型卡为准。先用公开图片验证图像输入和错误处理，再对授权脱敏数据做固定集评测；图片观察、检索条款和最终结论分别保存证据。**待补充：**本节只验证随机微型模型与本地 processor 数据流，尚未运行 Qwen 预训练 checkpoint，也没有验证真实业务准确率。

### 面试追问

- 【🔥 必会】为什么纯文本 tokenizer 不够？ 一句话：多模态还需要媒体预处理和模板。展开：processor 除文本 token 化外，还负责模型所需的图像预处理及媒体占位规则；实际分工因模型而异。

- 【🔥 必会】报图像 token 数量不匹配，怎么定位？ 一句话：核对同模型的 processor 与配置。展开：打印图像数量、顺序、预处理形状、占位 token 数和模型视觉特征数；确认没有截断及 processor/权重混用。

- 【⭐ 理解】processor 能输出张量就表示图像被正确理解吗？ 一句话：不能，它只证明输入路径可执行。展开：还要测试模型输出、视觉证据及任务指标；图片缩放或指代问题仍可能让模型看错。

### 故障模式与排障

- **文件存在但不能解码：**记录路径和错误，用图片库检查文件内容；修复损坏文件或拒绝请求，不要把空白图片悄悄送进模型。

- **模型始终忽略图片：**检查消息中媒体顺序、渲染后的模板和图像 token；使用配套 processor，做换图反事实测试并核查视觉输出。

- **小字在结果里消失：**查看实际 resize/crop 后的图片和模型视觉 token；比较更高分辨率或局部裁切，同时测延迟、显存和任务效果。

### 工程 trick 与坑

- 针对真实模型，优先用该 checkpoint 的 AutoProcessor.from_pretrained(...) 和官方示例；模型版本和 processor 版本一起记录。

- 记录解码后的图像尺寸、颜色模式和 processor 输出形状；不要在日志里泄漏私有图片或敏感内容。

- add_generation_prompt 的具体作用取决于模板；不同模型未必支持相同消息角色、媒体格式或返回字段。

- 下例使用本地合成词表和模板构造真实 LlavaProcessor，仅演示接口与形状；它不与任何真实预训练 checkpoint 兼容，也不执行生成。

### Toy code：用 Transformers 的 LlavaProcessor 准备图文输入

运行前提：Python 3.10+、PyTorch、Pillow、transformers==4.57.1。本机工作区 work/vlm_deps 包含额外依赖；在该工作区 PowerShell 中设置 $env:PYTHONPATH="$(Get-Location)\work\vlm_deps"，再用 D:/Miniconda3/envs/pytorch/python.exe 运行。无需下载模型或数据，示例自动创建虚构图片。

```python
from pathlib import Path
from tempfile import TemporaryDirectory

import torch
from PIL import Image, UnidentifiedImageError
from tokenizers import Tokenizer
from tokenizers.models import WordLevel
from tokenizers.pre_tokenizers import Whitespace
from transformers import CLIPImageProcessor, LlavaProcessor, PreTrainedTokenizerFast


def build_processor() -> LlavaProcessor:
    """构造离线教学用处理器；词表与模板不匹配任何真实权重。"""
    vocab = {"[UNK]": 0, "<image>": 1, "[PAD]": 2, "user": 3,
             "assistant": 4, "hazard": 5, "?": 6}
    backend = Tokenizer(WordLevel(vocab=vocab, unk_token="[UNK]"))
    backend.pre_tokenizer = Whitespace()
    tokenizer = PreTrainedTokenizerFast(
        tokenizer_object=backend, unk_token="[UNK]", pad_token="[PAD]",
        additional_special_tokens=["<image>"],
    )
    image_processor = CLIPImageProcessor(
        size={"shortest_edge": 28}, crop_size={"height": 28, "width": 28}
    )
    template = (
        "{% for message in messages %}{{ message['role'] }} "
        "{% for item in message['content'] %}"
        "{% if item['type'] == 'image' %}<image> "
        "{% elif item['type'] == 'text' %}{{ item['text'] }} "
        "{% endif %}{% endfor %}{% endfor %}"
        "{% if add_generation_prompt %}assistant {% endif %}"
    )
    return LlavaProcessor(
        image_processor=image_processor, tokenizer=tokenizer, patch_size=14,
        num_additional_image_tokens=1, vision_feature_select_strategy="default",
        chat_template=template,
    )


def prepare(processor: LlavaProcessor, path: Path, question: str) -> dict:
    """加载图像并生成教学模板的文本和图像张量。"""
    if not path.is_file():
        raise ValueError(f"图片不存在: {path}")
    if not isinstance(question, str) or not question.strip():
        raise ValueError("问题必须是非空文本")
    try:
        with Image.open(path) as image:
            rgb = image.convert("RGB")
            rgb.load()
    except (UnidentifiedImageError, OSError) as exc:
        raise ValueError(f"图片无法解码: {path}") from exc
    messages = [{"role": "user", "content": [
        {"type": "image", "image": rgb}, {"type": "text", "text": question},
    ]}]
    encoded = processor.apply_chat_template(
        messages, tokenize=True, add_generation_prompt=True,
        return_dict=True, return_tensors="pt",
    )
    required = {"input_ids", "attention_mask", "pixel_values"}
    if not required.issubset(encoded.keys()):
        raise RuntimeError("本例处理器未返回预期字段")
    assert encoded["input_ids"].shape == encoded["attention_mask"].shape
    assert encoded["pixel_values"].shape == (1, 3, 28, 28)
    assert bool(torch.isfinite(encoded["pixel_values"]).all())
    return dict(encoded)


def main() -> None:
    """验证图像 token 数量、张量形状以及坏图错误。"""
    processor = build_processor()
    with TemporaryDirectory() as tmp:
        root = Path(tmp)
        path = root / "sample.png"
        Image.new("RGB", (32, 32), "white").save(path)
        encoded = prepare(processor, path, "hazard ?")
        image_id = processor.tokenizer.convert_tokens_to_ids("<image>")
        assert int((encoded["input_ids"] == image_id).sum()) == 4
        invalid = root / "invalid.png"
        invalid.write_bytes(b"not an image")
        try:
            prepare(processor, invalid, "hazard ?")
        except ValueError as exc:
            assert "无法解码" in str(exc)
        else:
            raise AssertionError("坏图必须报错")
        print({key: tuple(value.shape) for key, value in encoded.items()})
    print("多模态 processor 自检通过；没有运行生成模型。")


if __name__ == "__main__":
    main()
```

逐段讲解：构造一个教学用途的 tokenizer、图像处理器和模板；prepare 先确认路径和解码，再调用 apply_chat_template 生成张量。本例 28×28 图片按 14×14 patch 得到 2×2 个视觉 patch，校验四个图像 token；不同模型有不同规则，不能照搬这一数字。

### 这段代码怎么在面试里讲

- **声明不变量：**单图经处理后 pixel_values 为 (1,3,28,28)，文本 token 与 attention mask 形状一致，视觉占位 token 数为四。

- **解释关键行：**先校验并解码图像，再用 processor 的对话模板生成图片和文本输入，检查字段和数值。

- **主动说边界：**自制模板和词表只为离线自检，不能与真实 checkpoint 混用；本例未做模型前向、生成或视觉质量评估。

### 本节收尾：费曼自述与闪卡

**费曼自述：**Processor 把图和问题整理为模型需要的输入。我要核对真实模型的模板和字段，检查图片是否真的被处理，而不是只看程序有没有输出。

## 7.4 多模态训练数据怎样组织【🔥 必会】

〔本次新补，参考当前面试趋势〕

### 目标与例子

把一批公开图片与问答整理成可训练、可检查的数据。例子：一张安全图片对应“右侧工人是否戴帽？”及人工答案；同一拍摄事件的原图、裁切图及其问答应放在同一数据分区。事件编号比问答行更适合作为防泄漏分组依据。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 样本 ID、图像路径、原图或事件 ID、训练/验证/测试分区、问题、答案、来源与标注规则版本。 |
| 做什么 | 校验必填项、标签规则和图片解码；按事件分组检查跨集合泄漏；训练前再按模型 processor 转成其支持的图文对话。 |
| 输出 | 符合规则的记录，或明确指出重复 ID、坏图、缺字段和跨分区事件。 |
| 哪里出错 | 原图裁切进入不同集合、图片被替换、问题与图片错配、标签依据不一致、小目标在缩放后消失。 |
| 参数影响 | 分组粒度决定泄漏风险和测试难度；图片分辨率影响细节及视觉 token/显存；标签规范决定评估是否可复现。 |

训练框架的数据格式并非统一标准。例如 TRL 的视觉对话格式使用图像列以及包含 image/text 类型的消息；实际字段和模板应以所选模型及版本的[官方数据格式文档](https://huggingface.co/docs/trl/dataset_formats)为准。下面的 JSONL 是项目中间格式，不是可直接喂给所有训练器的格式。

### 面试追问

- 【🔥 必会】为什么不能按问答行随机切分？ 一句话：同一图片可能出现在不同集合。展开：同图、裁切图或连续帧高度相似，模型可能记住背景；按原图、视频或拍摄事件分组切分，并检查每组是否跨集合。

- 【🔥 必会】测试结果异常高怎么排查？ 一句话：先查相似样本泄漏和标注。展开：核对事件 ID、原图 ID、图片哈希及相邻帧；人工查看高相似跨集合样本，再建立固定无泄漏测试集。

- 【⭐ 理解】看见图片路径就能训练吗？ 一句话：还要确认解码、标注和模板。展开：路径存在不代表文件可读；图文顺序、image token、答案和 loss mask 还需适配具体 processor 与训练器。

### 故障模式与排障

- **训练时偶发图片解码失败：**记录样本 ID 和路径，先用图片库重现；隔离损坏文件并检查复制、下载和转换过程，修复后再建数据清单。

- **线下指标高、换工地后下降：**对照训练和测试的原图、拍摄事件、时间和场地，查泄漏或场景偏差；按目标部署场景建立独立测试切片。

- **答案流畅但没回答指定对象：**抽查问题与图片配对、对象指代和标注规范，按指代错误统计；补充可核验对象信息和难例。

### 工程 trick 与坑

- 至少保存稳定的样本 ID、来源许可、标注版本、事件 ID 和原图 ID；真实数据不得未经允许公开。

- 本节按 event_id 检测交叉分区；它不能检测 ID 标错、近似重复图、同一场景不同事件或内容相似性，需要哈希、近重复检索和人工复核补充。

- 对无法看清目标的样本使用明确的不可判断标注规则；不要把模型自己的拒答直接当作金标准。

- 训练前检查实际多模态模板、图像占位符与监督位置；这些与所用训练器版本有关。

### Toy code：验证 JSONL 与事件级数据泄漏

运行前提：Python 3.10+ 和 Pillow。本机可用 D:/Miniconda3/envs/pytorch/python.exe。保存以下代码为 validate_vlm_data.py 后运行；示例自动生成虚构图片与记录，不下载模型。Image.verify() 检查文件完整性，后续实际解码需要重新打开，见 [Pillow 文档](https://pillow.readthedocs.io/en/stable/reference/Image.html#PIL.Image.Image.verify)。

```python
import json
from pathlib import Path
from tempfile import TemporaryDirectory
from typing import Any

from PIL import Image, UnidentifiedImageError

SPLITS = {"train", "validation", "test"}
FIELDS = ("id", "image", "event_id", "split", "question", "answer", "source")


def validate_record(row: Any, root: Path, line: int) -> dict[str, str]:
    """验证一条图文记录，并用 Pillow 检查图像文件。"""
    if not isinstance(row, dict):
        raise ValueError(f"第 {line} 行不是 JSON 对象")
    for field in FIELDS:
        if not isinstance(row.get(field), str) or not row[field].strip():
            raise ValueError(f"第 {line} 行缺少非空文本字段 {field}")
    item: dict[str, str] = {field: row[field].strip() for field in FIELDS}
    if item["split"] not in SPLITS:
        raise ValueError(f"第 {line} 行 split 不受支持")
    image_path = root / item["image"]
    if not image_path.is_file():
        raise ValueError(f"第 {line} 行图片不存在: {image_path}")
    try:
        with Image.open(image_path) as image:
            width, height = image.size
            if width <= 0 or height <= 0:
                raise ValueError(f"第 {line} 行图片尺寸无效")
            image.verify()
    except (UnidentifiedImageError, OSError) as exc:
        raise ValueError(f"第 {line} 行图片无法解析: {image_path}") from exc
    return item


def validate_manifest(path: Path) -> list[dict[str, str]]:
    """读取 UTF-8 JSONL，拒绝重复 ID 和事件跨分区。"""
    rows: list[dict[str, str]] = []
    seen_ids: set[str] = set()
    event_splits: dict[str, str] = {}
    with path.open(encoding="utf-8") as stream:
        for line_no, raw in enumerate(stream, 1):
            if not raw.strip():
                continue
            try:
                raw_item = json.loads(raw)
            except json.JSONDecodeError as exc:
                raise ValueError(f"第 {line_no} 行 JSON 无效") from exc
            item = validate_record(raw_item, path.parent, line_no)
            if item["id"] in seen_ids:
                raise ValueError(f"第 {line_no} 行 ID 重复: {item['id']}")
            previous = event_splits.setdefault(item["event_id"], item["split"])
            if previous != item["split"]:
                raise ValueError(f"事件跨分区: {item['event_id']}")
            seen_ids.add(item["id"])
            rows.append(item)
    if not rows:
        raise ValueError("数据清单为空")
    assert len(rows) == len(seen_ids)
    return rows


def main() -> None:
    """使用本地生成的图片测试正常、泄漏和坏图场景。"""
    with TemporaryDirectory() as tmp:
        root = Path(tmp)
        Image.new("RGB", (8, 8), "white").save(root / "frame.png")
        record = {"id": "q1", "image": "frame.png", "event_id": "e1",
                  "split": "train", "question": "是否戴帽？", "answer": "无法判断",
                  "source": "synthetic"}
        manifest = root / "data.jsonl"
        def write_rows(rows: list[dict[str, str]]) -> None:
            manifest.write_text("\n".join(json.dumps(r, ensure_ascii=False) for r in rows),
                                encoding="utf-8")

        write_rows([record])
        assert len(validate_manifest(manifest)) == 1
        leak = {**record, "id": "q2", "split": "test"}
        write_rows([record, leak])
        try:
            validate_manifest(manifest)
        except ValueError as exc:
            assert "跨分区" in str(exc)
        else:
            raise AssertionError("应检测到事件泄漏")
        (root / "bad.png").write_bytes(b"not an image")
        write_rows([{**record, "image": "bad.png"}])
        try:
            validate_manifest(manifest)
        except ValueError as exc:
            assert "无法解析" in str(exc)
        else:
            raise AssertionError("应检测到坏图")
    print("图文数据校验自检通过")


if __name__ == "__main__":
    main()
```

逐段讲解：validate_record 检查字段和图片，validate_manifest 逐行解析并维护样本 ID 与事件分区映射；main 生成测试文件，验证正确数据、跨分区事件和坏图。完整业务还要人工审查标注、检测相似图并记录数据版本，本例不声称完成这些工作。

### 这段代码怎么在面试里讲

- **声明不变量：**样本 ID 唯一、字段非空、图片可解析、同一个事件只落在一个分区。

- **解释关键行：**逐行读取 JSONL，使用 Pillow 检查图片，以字典保存事件所属分区；发现冲突立即报出事件 ID。

- **主动说边界：**事件编号可能错误，本例无法发现近重复图片；图像能通过 verify 也不代表问题和答案正确，更不替代训练时的实际解码。

### 本节收尾：费曼自述与闪卡

**费曼自述：**图文数据既要保证图片能读、问题答案匹配，也要保证相关画面不泄漏到不同集合。格式通过只是第一步，标签和业务覆盖仍需人工核查。

- Q：为什么按问答行随机切分不可靠？A：同图或同事件的不同问答可能跨分区。

- Q：事件 ID 不跨分区就一定没有泄漏吗？A：不能保证，ID 可能有误，近重复图仍需检查。

- Q：图片通过 verify() 后能直接用同一对象读取像素吗？A：按 Pillow 文档应重新打开。

- Q：记录里为什么需要来源与标注版本？A：便于授权核查、追溯与复现。

## 7.5 VLM 微调从基线开始【🔥 必会】

〔本次新补，参考当前面试趋势〕

### 目标与例子

先用固定图片问答测试集评估原模型，再决定是否改提示、图片处理或权重。假设工地安全任务在小目标裁切后仍稳定出现领域术语和输出格式错误，可比较零样本基线、输入改进与 SFT/LoRA。所有结果必须在同样的独立测试集上测，不能把训练 loss 下降当作业务效果提升。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 图片、问题、人工答案，模型对应的 processor、预训练权重及训练配置。 |
| 做什么 | 对齐图像与文本 token，构造只监督目标答案的标签，冻结或训练选定参数，反向传播并更新可训练参数。 |
| 输出 | 训练后的连接层/LoRA 或模型权重、训练日志、独立验证指标与可复现配置。 |
| 哪里出错 | 图片 token 数量与视觉特征不一致、标签 mask 把答案全遮住、数据泄漏、训练错模块、视觉 token 过长导致 OOM。 |
| 参数影响 | 训练模块与 LoRA rank 决定参数和显存；分辨率影响视觉 token；学习率、batch、梯度累积和数据质量影响训练稳定性。 |

实际 VLM 的可训练模块有多种选择：只训练投影层、语言层 LoRA、视觉层 LoRA 或组合，适配情况取决于具体模型和资源。训练前打印可训练参数名/数量；训练后同时测视觉细节、拒答、格式和成本变化。通用 LoRA 底层与 SFT/RAG 取舍见第 5 章；评测数据与门禁见横切专题[系统设计与评测](横切-系统设计与评测.md)。

### 面试追问

- 【🔥 必会】什么时候值得微调 VLM？ 一句话：有稳定错误与合适数据时再考虑。展开：先固定测试集跑基线，排查分辨率、裁切、提示和检索；只有明确需求及足够标注时，比较微调收益与代价。

- 【🔥 必会】loss 下降但效果没提升，怎么排查？ 一句话：先核查标签、数据切分和验证口径。展开：打印输入和 labels 的对齐位置、可训练参数及梯度，再核对重复事件和真实任务指标；loss 只能证明训练目标在拟合。

- 【⭐ 理解】为什么图片多一点就 OOM？ 一句话：视觉 token 和序列计算会增加。展开：检查图片分辨率、切块、总 token、batch、激活与优化器状态；逐项缩小配置并监控质量，不只按图片张数估算。

### 故障模式与排障

- **报 image token 与图像特征数量不一致：**打印 processor 生成的 token、图像元数据和实际图片顺序；使用同一个模型的 processor/模板与官方数据整理流程，不手工拼生产 token。

- **训练正常但参数没变：**打印 requires_grad 参数及其梯度，确认优化器包含它们；检查是否全部冻结、损失掩码全为 -100 或学习率为零。

- **验证集分数异常高，真实场景差：**检查同图、裁切图和事件是否跨集合；补充不同场地、夜间、小目标与不可判断样本，用独立测试集复测。

### 工程 trick 与坑

- 语言模型的 labels 里 -100 通常表示该位置不参与交叉熵；实际模板、图像 token 处理和监督范围要以所用模型及 trainer 为准。

- 随机输入用于验证形状与梯度，不能证明真实 VLM 学会了看图；正式训练必须使用合适的预训练权重和符合许可的数据。

- 视觉 token 可能被截断。TRL 官方提示对其 VLM SFT 场景要避免误截断图像 token；具体 max_length 和资源取舍应核对[当前文档](https://huggingface.co/docs/trl/sft_trainer)。

- 训练结果应记录 processor、模型、数据版本、可训练模块、种子、超参数、验证指标与错误样本。下例只演示投影层训练，不是真实 LoRA/SFT 项目效果。

### Toy code：使用 Transformers 的微型 LLaVA 验证多模态训练链路

运行前提：Python 3.10+、PyTorch、transformers==4.57.1，不需下载模型或数据。本机已将 Transformers 依赖放在本工作区的 work/vlm_deps；可在该工作区的 PowerShell 中设置 $env:PYTHONPATH="$(Get-Location)\work\vlm_deps"，再用 D:/Miniconda3/envs/pytorch/python.exe 运行。其他机器可在独立环境安装对应版本。此例构造随机初始化、尺寸极小的 LLaVA，只训练连接层并验证梯度，绝不具备识图或语言能力。

```python
import torch
from torch import Tensor
from transformers import (
    CLIPVisionConfig, LlamaConfig, LlavaConfig, LlavaForConditionalGeneration,
)


def make_model() -> LlavaForConditionalGeneration:
    """创建随机微型 VLM，冻结视觉和语言主干，只训练多模态投影层。"""
    vision = CLIPVisionConfig(
        hidden_size=32, intermediate_size=64, num_hidden_layers=2,
        num_attention_heads=4, image_size=28, patch_size=14,
    )
    text = LlamaConfig(
        vocab_size=128, hidden_size=32, intermediate_size=64,
        num_hidden_layers=2, num_attention_heads=4, num_key_value_heads=4,
        max_position_embeddings=64,
    )
    config = LlavaConfig(vision_config=vision.to_dict(), text_config=text.to_dict(),
                         image_token_index=127, vision_feature_layer=-1)
    model = LlavaForConditionalGeneration(config)
    for parameter in model.parameters():
        parameter.requires_grad_(False)
    for parameter in model.model.multi_modal_projector.parameters():
        parameter.requires_grad_(True)
    return model


def make_batch() -> tuple[Tensor, Tensor, Tensor, Tensor]:
    """生成一张虚构图片及模拟 token，只在答案位置计算损失。"""
    # 28/14 = 2，视觉 patch 为 2*2=4；127 是图像占位 token。
    ids = torch.tensor([[1, 127, 127, 127, 127, 11, 12, 2]])
    attention = torch.ones_like(ids)
    labels = ids.clone()
    labels[:, :5] = -100  # 不监督提示和四个图像占位符
    pixels = torch.rand(1, 3, 28, 28)
    assert ids.shape == attention.shape == labels.shape == (1, 8)
    assert (ids == 127).sum().item() == 4 and (labels != -100).sum().item() == 3
    return ids, attention, labels, pixels


def main() -> None:
    """检查损失、可训练梯度、冻结梯度及连接层参数更新。"""
    torch.manual_seed(17)
    torch.set_num_threads(2)
    model = make_model().train()
    trainable = [parameter for parameter in model.parameters() if parameter.requires_grad]
    frozen = [parameter for parameter in model.parameters() if not parameter.requires_grad]
    if not trainable or not frozen:
        raise RuntimeError("训练和冻结参数不应为空")
    optimizer = torch.optim.AdamW(trainable, lr=1e-3)
    ids, attention, labels, pixels = make_batch()
    before = trainable[0].detach().clone()
    for step in range(2):
        optimizer.zero_grad(set_to_none=True)
        output = model(input_ids=ids, attention_mask=attention,
                       pixel_values=pixels, labels=labels)
        if output.loss is None or not bool(torch.isfinite(output.loss)):
            raise RuntimeError("损失不存在或不是有限数")
        output.loss.backward()
        assert any(p.grad is not None and bool(torch.isfinite(p.grad).all())
                   and bool((p.grad != 0).any()) for p in trainable)
        assert all(p.grad is None for p in frozen)
        optimizer.step()
        print(f"第 {step + 1} 步 loss={output.loss.item():.4f}")
    assert not torch.equal(before, trainable[0].detach())
    print("多模态训练数据流自检通过；示例不代表真实模型效果。")


if __name__ == "__main__":
    main()
```

逐段讲解：make_model 用实际 Transformers 模型类构造小尺寸架构，并冻结除连接器以外的参数；make_batch 构造四个视觉 patch 对应的占位符和答案标签；训练循环验证损失有限、连接器存在非零梯度、冻结参数无梯度且优化器更新了连接器。图像和 token 均为虚构，不能把 loss 数值解释成任务准确率。

### 这段代码怎么在面试里讲

- **声明不变量：**输入图片 (1,3,28,28)，视觉 patch 数为 4，四个图像占位符与特征数对应，标签只监督三个答案位置。

- **解释关键行：**先冻结主干、只把连接层放入优化器；前向产生语言模型损失，反传后检查连接层梯度和参数更新。

- **主动说边界：**随机模型不是预训练 VLM；手工 token 只为解释数据流，真实训练需配套 processor、真实标注、验证集及模型特定模板。

### 本节收尾：费曼自述与闪卡

**费曼自述：**我先测基线并定位错误，再决定是否微调。训练时要确保图片与文本对齐、只监督需要的答案、更新正确参数，并在独立测试集验证收益。

- Q：训练 loss 下降能证明视觉任务变好了吗？A：不能，还要用独立测试集、切片和失败案例验证。

- Q：labels=-100 的常见作用是什么？A：让这些位置不参与交叉熵损失，具体仍看模型实现。

- Q：训练连接层时为什么检查冻结参数梯度？A：确认训练范围与预期一致，避免意外更新主干。

- Q：图像 token 与视觉特征数不一致时先查什么？A：检查 processor、模板、图像数量与模型配置是否一致。

## 7.6 多模态评测与失败分析【🔥 必会】

〔本次新补，参考当前面试趋势〕本节讨论视觉任务；总体评测体系见横切专题[系统设计与评测](横切-系统设计与评测.md)。

### 目标与例子

将“看起来回答得不错”变成可重复的评测。对于工业安全图片，先明确评测单位是一张图对应的一个问题，例如“这位工人是否未佩戴安全帽”。人工标注正例、负例或不可判断，再分别统计可判断样本的召回与误报，以及不可判断样本的拒答率。对于小目标、夜间和遮挡等切片，单独统计，不能只看平均值。

### 概念与五要素

| 项目 | 本节约定 |
| --- | --- |
| 输入 | 每行包含样本 ID、真实标签、预测标签、图像切片；标签只能为 hazard、safe、unknown。 |
| 做什么 | 将可判断样本按二分类统计，同时统计 unknown 标签上的拒答率；逐切片重复计算。 |
| 输出 | 每组样本数、漏报数、误报数、模型拒答数、隐患召回率与不可判断样本的拒答率；分母为零记为不可计算。 |
| 哪里出错 | 标注错误、同图泄漏、样本少、视觉/语言错误混淆、将拒答悄悄排除会掩盖失败。 |
| 参数影响 | 切片定义和标签规则改变统计口径；判定阈值改变召回与误报。下面的例子接收已离散化预测，不负责调阈值。 |

**注意口径：**对真实 hazard，预测 unknown 不算命中，因此属于召回分母中的未召回；漏报数只统计错误判断为 safe 的个数，拒答另计。对真实 safe，预测 unknown 不算误报，但仍单独报告拒答量。unknown 标签依赖人工规则，并不保证模型真的识别出了不可判断原因。未知样本误判为任一确定标签，也应在详细案例中检查。

### 面试追问

- 【🔥 必会】总准确率高就够了吗？ 一句话：不够，要看隐患召回和分组表现。展开：类别可能失衡，小目标或夜间可能大量漏判；同时报告样本数和模型拒答，排查对困难样本的退化。

- 【🔥 必会】模型总把模糊图判断为安全，怎么排查？ 一句话：先确认标注与输入，再切片定位。展开：核对原图、裁切和缩放后尺寸，抽查不可判断标签与预测；再比较分辨率或裁切方案，并监控误报和延迟。

- 【⭐ 理解】语言回答正确能证明看对图了吗？ 一句话：不能，还要检查视觉依据。展开：模型可能凭常识猜对；可用反事实问题、图像证据或人工复核验证，避免把答案匹配当成视觉定位能力。

### 故障模式与排障

- **整体好、夜间差：**核对分组样本数及拍摄条件，再抽查夜间图像；补充有代表性的夜间数据，分别回归，避免仅凭极少样本下结论。

- **隐患召回虚高：**检查是否只评估模型愿意回答的样本；将隐患上的 unknown 纳入召回分母，并报告拒答率和漏报数。

- **新模型表现异常提升：**检查原图、裁切图或同一拍摄事件是否跨训练与测试；按来源或事件重新分组切分，固定测试集后重测。

### 工程 trick 与坑

- 预先定义 unknown：例如目标被遮挡到标注员也无法判断，记录标注分歧；不要把模型不会答自动当作真实 unknown。

- 测试集按原图或事件分组，避免同一场景的裁切泄漏；记录标注版本与模型版本。

- 分组规模小时附样本数，必要时扩大样本或给区间；本例几条虚构记录只能用于自检，不代表真实效果。

- 对开放文本先用经过验证的规则或人工标注转换为标签；不能把未经校准的 LLM judge 当作金标准。

### Toy code：用 scikit-learn 评估离散标签

运行前提：Python 3.10+、scikit-learn。保存为 vlm_eval.py，运行 python vlm_eval.py；本机也可用 D:/Miniconda3/envs/pytorch/python.exe vlm_eval.py。真实使用时可把 demo 改成从 CSV 读取的记录，先明确标注与解析规则。本例使用 scikit-learn 的混淆矩阵处理标签，不加载视觉模型，不声称完成图片推理。

```python
from collections import defaultdict
from dataclasses import dataclass
from typing import Optional

from sklearn.metrics import confusion_matrix

LABELS = frozenset({"hazard", "safe", "unknown"})
ORDER = ("hazard", "safe", "unknown")


@dataclass(frozen=True)
class Case:
    """一个已标注、已预测的图像问答样本。"""

    sample_id: str
    gold: str
    pred: str
    group: str


def ratio(numerator: int, denominator: int) -> Optional[float]:
    """分母为零时返回 None，避免把无数据误写为零分。"""
    assert 0 <= numerator <= denominator
    return numerator / denominator if denominator else None


def evaluate(cases: list[Case]) -> dict[str, int | float | None]:
    """统计隐患召回、误报数和不可判断样本拒答率。"""
    if not cases:
        raise ValueError("评估集不能为空")
    if any(not c.sample_id.strip() or not c.group.strip() for c in cases):
        raise ValueError("样本 ID 和切片不能为空")
    if len({c.sample_id for c in cases}) != len(cases):
        raise ValueError("样本 ID 必须唯一")
    if any(c.gold not in LABELS or c.pred not in LABELS for c in cases):
        raise ValueError("发现未知标签")

    matrix = confusion_matrix(
        [c.gold for c in cases], [c.pred for c in cases], labels=list(ORDER)
    )
    assert matrix.shape == (3, 3) and int(matrix.sum()) == len(cases)
    hazard_n, safe_n, unknown_n = (int(n) for n in matrix.sum(axis=1))
    hit, missed_safe = int(matrix[0, 0]), int(matrix[0, 1])
    false_alarm = int(matrix[1, 0])
    abstained = int(matrix[:, 2].sum())
    correct_unknown = int(matrix[2, 2])
    assert hit + missed_safe <= hazard_n
    return {
        "n": len(cases),
        "hazard_n": hazard_n,
        "hazard_recall": ratio(hit, hazard_n),
        "missed_as_safe": missed_safe,
        "safe_n": safe_n,
        "false_alarm": false_alarm,
        "abstained": abstained,
        "unknown_n": unknown_n,
        "unknown_abstain_rate": ratio(correct_unknown, unknown_n),
    }


def report(cases: list[Case]) -> dict[str, dict[str, int | float | None]]:
    """返回总体及每个切片的指标，组名不会覆盖总体结果。"""
    overall = evaluate(cases)
    groups: dict[str, list[Case]] = defaultdict(list)
    for case in cases:
        groups[case.group].append(case)
    result = {"overall": overall}
    result.update({f"group:{name}": evaluate(rows) for name, rows in groups.items()})
    assert sum(len(rows) for rows in groups.values()) == len(cases)
    return result


def main() -> None:
    """运行虚构数据自检；不是业务效果评测。"""
    demo = [
        Case("a", "hazard", "hazard", "day"),
        Case("b", "hazard", "unknown", "night"),
        Case("c", "safe", "hazard", "night"),
        Case("d", "unknown", "unknown", "night"),
    ]
    result = report(demo)
    assert result["overall"]["hazard_recall"] == 0.5
    assert result["overall"]["false_alarm"] == 1
    assert result["overall"]["abstained"] == 2
    assert result["group:day"]["unknown_abstain_rate"] is None
    try:
        evaluate([demo[0], demo[0]])
    except ValueError:
        pass
    else:
        raise AssertionError("重复 ID 必须拒绝")
    for group, metrics in result.items():
        print(group, metrics)


if __name__ == "__main__":
    main()
```

逐段解释：Case 固定一条记录的字段；evaluate 先校验输入，再调用 confusion_matrix：行是真值、列是预测，标签顺序由 ORDER 固定；report 对每个切片使用相同口径。None 意味着没有分母，不能解读为零分。生产任务还需保存原始图片 ID、问题、模型原始输出、标注版本和错误原因，确保可回溯。

### 这段代码怎么在面试里讲

- **不变量：**每个 ID 唯一、标签来自固定集合，指标分子不超过分母；无分母显示 None。

- **关键行：**先按真实标签分组，隐患召回分母包含模型拒答；再按图像条件分组，定位整体指标掩盖的退化。

- **边界与坑：**空集、非法标签和重复 ID 要拒绝；少样本波动大，拒答数要单独报告；该脚本不负责生成标注和检测图像泄漏。

### 本节收尾：费曼自述与闪卡

**费曼自述：**评测要先定义任务和标签，再看总体及困难切片。把漏报、误报和拒答分开，才能知道模型是否真的看清了图。

- Q：隐患真实存在但模型拒答，算召回成功吗？A：不算；留在隐患召回分母，并计入拒答数。

- Q：切片没有隐患样本，隐患召回是多少？A：不可计算，不能写成 0 或 1。

- Q：图像问答正确是否证明视觉定位正确？A：不能；需检查证据或通过人工/反事实验证。

- Q：为什么要按事件切分数据？A：减少相似场景及其裁切跨训练、测试集造成泄漏。

## 7.7 视频比图片多了时间轴【⭐ 理解】

### 目标与例子

给工地作业视频和问题，抽取带时间信息的关键画面，再交给支持视频的模型。问题“工人进入危险区之前是否戴上安全帽？”依赖动作顺序；只看视频末尾可能答错。先确保关键片段被抽到，再讨论模型是否理解。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 视频、问题、抽帧策略，以及模型允许的帧数和尺寸。 |
| 做什么 | 解码并按时间采帧，保留时间戳；用 processor 组装模型支持的视频输入。 |
| 输出 | 每帧图像及其时间位置，或最终附可回看片段的回答。 |
| 哪里出错 | 抽帧漏掉瞬时事件、帧顺序错、颜色通道错、遮挡或模型把先后关系说反。 |
| 参数影响 | 帧率和分辨率越高通常能保留更多细节，但可能增加视觉 token、延迟和显存；要结合模型实际处理规则测量。 |

视频模型既可能直接接收视频文件，也可能接收帧列表；模板及支持格式以具体模型的 [Transformers 多模态文档](https://huggingface.co/docs/transformers/en/chat_templating_multimodal)和模型卡为准。本例专练解码与抽帧，不宣称完成模型推理。

### 面试追问

- 【🔥 必会】视频理解相比单图多了什么？ 一句话：多了时间顺序和持续过程。展开：先定义事件与可接受的时间误差，核对抽帧是否覆盖关键时刻，再分别评估视觉识别和事件时序。

- 【🔥 必会】模型漏掉两秒的违规动作怎么办？ 一句话：先验证抽帧覆盖，再查模型。展开：回看原视频和抽出帧的时间戳，确认关键片段是否存在；若未覆盖，针对该片段加密采样，再测延迟与召回。

- 【⭐ 理解】帧越多结果一定越好吗？ 一句话：不一定，还受模型和资源限制。展开：更多帧可能提高覆盖，也可能引入冗余、触发模型帧数上限或增加延迟，须在固定数据集比较。

### 故障模式与排障

- **短暂事件完全没出现：**把抽帧时间和人工标注的起止时间画在同一时间轴；提高采样密度或先检索片段，再比较事件召回和计算代价。

- **模型把颜色或对象看错：**保存一张处理后的帧人工查看，检查 OpenCV 的 BGR 与模型期望的 RGB；统一通道顺序并做回归。

- **事件顺序或时间引用不准：**核对排序、时间基准和视频帧率；对变帧率视频读取容器中的呈现时间戳，不能用帧序号除以单一 FPS 当作可靠真值。

### 工程 trick 与坑

- 先定义采样上限和任务时长，避免长视频使请求成本失控；帧数上限要结合实际模型。

- 保留原视频 ID、时间基准、采样配置与模型版本，便于回放错误片段。

- 下面示例仅按固定帧率计算相对时间，并不处理变帧率、音轨或绝对拍摄时间。生产处理应使用可读取逐帧 PTS 的解码方案。

- 模型回答“发生违规”不等于已定位违规时间；应分别评估事件识别与时间定位。

### Toy code：用 OpenCV 解码并均匀抽帧

运行前提：Python 3.10+、OpenCV 和 NumPy。本机可用 D:/Miniconda3/envs/pytorch/python.exe。示例构造固定帧率的虚构 AVI；系统需有可用的 MJPG 编码/解码器。实际模型的 processor 需另外加载，视频帧上限以对应模型配置为准。

```python
from dataclasses import dataclass
from pathlib import Path
from tempfile import TemporaryDirectory
import math

import cv2
import numpy as np
from numpy.typing import NDArray


@dataclass(frozen=True)
class Frame:
    """一张 RGB 帧及其固定帧率近似相对时间。"""
    index: int
    seconds: float
    rgb: NDArray[np.uint8]


def sample_video(path: Path, target_fps: float, max_frames: int) -> list[Frame]:
    """顺序解码固定帧率视频，返回有限数量的 RGB 帧。"""
    if not path.is_file():
        raise ValueError(f"视频不存在: {path}")
    if not math.isfinite(target_fps) or target_fps <= 0 or max_frames <= 0:
        raise ValueError("采样率和帧上限必须为正")
    capture = cv2.VideoCapture(str(path))
    if not capture.isOpened():
        capture.release()
        raise ValueError(f"无法打开视频: {path}")
    try:
        source_fps = float(capture.get(cv2.CAP_PROP_FPS))
        if not math.isfinite(source_fps) or source_fps <= 0:
            raise ValueError("视频帧率无效；无法使用固定帧率时间估计")
        step = max(1, round(source_fps / target_fps))
        frames: list[Frame] = []
        index = 0
        while len(frames) < max_frames:
            ok, bgr = capture.read()
            if not ok:
                break
            if index % step == 0:
                rgb = cv2.cvtColor(bgr, cv2.COLOR_BGR2RGB)
                if rgb.ndim != 3 or rgb.shape[2] != 3:
                    raise ValueError("解码帧不是三通道图像")
                frames.append(Frame(index, index / source_fps, rgb))
            index += 1
        if not frames:
            raise ValueError("视频没有可解码的帧")
        assert len(frames) <= max_frames
        assert all(a.seconds < b.seconds for a, b in zip(frames, frames[1:]))
        return frames
    finally:
        capture.release()


def main() -> None:
    """构造固定帧率小视频，验证抽帧、通道、上限和错误路径。"""
    with TemporaryDirectory() as tmp:
        path = Path(tmp) / "demo.avi"
        writer = cv2.VideoWriter(str(path), cv2.VideoWriter_fourcc(*"MJPG"),
                                 5.0, (64, 48))
        if not writer.isOpened():
            raise RuntimeError("MJPG 编码器不可用，无法运行此自检")
        try:
            for _ in range(10):
                bgr = np.zeros((48, 64, 3), dtype=np.uint8)
                bgr[:, :, 2] = 255  # 红色：OpenCV 输入按 BGR 排列
                writer.write(bgr)
        finally:
            writer.release()
        frames = sample_video(path, target_fps=2.5, max_frames=3)
        assert [frame.index for frame in frames] == [0, 2, 4]
        assert [round(frame.seconds, 1) for frame in frames] == [0.0, 0.4, 0.8]
        assert frames[0].rgb.shape == (48, 64, 3)
        assert frames[0].rgb[0, 0, 0] > frames[0].rgb[0, 0, 2]
        try:
            sample_video(path, target_fps=0, max_frames=3)
        except ValueError:
            pass
        else:
            raise AssertionError("零采样率应报错")
    print("视频抽帧自检通过")


if __name__ == "__main__":
    main()
```

逐段讲解：先读取视频的名义帧率并计算整数间隔，再顺序读取、把 BGR 转为 RGB、保存近似时间；max_frames 限制内存，但达到上限时可能尚未扫描完整视频。整数间隔导致实际采样率可能与目标略有差异；目标高于原帧率也不会凭空创造新帧。

### 这段代码怎么在面试里讲

- **声明不变量：**采样率大于零，每帧为 RGB 三通道，返回帧数不超过上限，时间严格递增。

- **解释关键行：**从名义 FPS 算采样间隔，按帧索引顺序读取并转换颜色；用索引/FPS 给固定帧率视频生成近似时间。

- **主动说边界：**变帧率须读真实 PTS；视频截断或达到上限会漏后续内容；还没调用视频模型，不能将抽帧成功当作任务完成。

### 本节收尾：费曼自述与闪卡

**费曼自述：**视频的价值不仅是多张图，还包括事件发生的时间和先后。如果抽帧漏掉关键瞬间，模型无法从没有看到的画面可靠作答。

- Q：为什么要保存帧时间？A：方便核对事件顺序并回看证据片段。

- Q：帧序号除以 FPS 对所有视频都准确吗？A：不一定；变帧率视频应读取逐帧 PTS。

- Q：OpenCV 默认读出的三通道顺序是什么？A：通常是 BGR，输入 RGB 模型前需转换并验证。

- Q：增加帧率需要同时测什么？A：事件召回、视觉 token 或显存、延迟及模型帧数上限。

## 7.8 多模态 RAG：图片证据与文字条款分开核对【⭐ 理解】

〔本次新补，参考当前面试趋势〕

### 目标与例子

工地图片问答常同时涉及两件事：图里看到了什么，以及现行制度怎么规定。视觉模型或检测器给出可回看的画面观察，文档检索提供条款、版本和位置，最后再组织结论。例如模糊图片无法看清安全帽时，即使查到了“必须佩戴安全帽”的制度，也不能由制度推断图片中有人违规。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 图像或视频、问题、用户权限及当前有效的制度库。 |
| 做什么 | 视觉链输出带来源的观察；文本链检索带版本与位置的条款；按任务规则组合，并对不足证据的情况拒答。 |
| 输出 | 可分别核查的画面证据、制度证据与结论，或明确的“无法判断/待复核”。 |
| 哪里出错 | 看错人、画面不可辨、召回过期条款、引用错页、把条款当视觉事实、对检索结果中的指令盲从。 |
| 参数影响 | 视觉分辨率影响细节与成本；检索 top-k、文档版本过滤及 rerank 决定上下文；拒答阈值影响覆盖和误判。 |

检索与生成的底层流程、召回指标和排障见本笔记第 3 章；通用方法见横切专题[系统设计与评测](横切-系统设计与评测.md)。本节聚焦证据如何组合。

### 面试追问

- 【🔥 必会】制度要求戴帽，模型就能判定图片违规吗？ 一句话：不能，违规需要独立视觉证据。展开：制度只说明规则；还需判断图片中的对象、动作和适用场景是否符合，模糊或缺失时应待复核。

- 【🔥 必会】回答引用正确但结论错误，怎么排查？ 一句话：分查视觉、条款和推理三段。展开：先看目标与原图，再核对条款版本、适用范围及引用，最后验证两类证据是否支持结论。

- 【⭐ 理解】为什么不能直接把视觉描述当作真实事实？ 一句话：视觉描述也可能产生幻觉。展开：保存原图或片段与定位信息，独立评估视觉链；没有可靠证据时不能让生成模型凭常识补全。

### 故障模式与排障

- **描述流畅但人认错：**回看图像区域和指代对象，对照人手标注；改进指代标注、目标裁切或检测器，并用固定测试集复测。

- **引用了过期制度：**核对生效区间、索引更新时间与过滤条件；修复文档版本元数据，重建或更新相关索引并回归。

- **检索命中不等于引用支持结论：**逐条检查引用内容是否真正覆盖条件；将证据不充分样本标为待复核，避免仅凭引用存在作正确判断。

### 工程 trick 与坑

- 原图/视频证据与制度文档分开记录；视觉输出应包括可回看的对象位置、时间或图像 ID，不把模型自评分当成已校准概率。

- 对制度按业务时间筛选有效版本；日期规则与时区须与业务约定一致，下例仅使用日期示意。

- 对外部资料按不可信数据处理；权限过滤应在受控检索阶段执行，而非依赖提示词让模型自觉遵守。

- 示例只校验证据字段和制度有效期；不会证明画面判断、条款适用性或引用语义正确。

### Toy code：用 pandas 组合两路证据

运行前提：Python 3.10+ 和 pandas。本机可用 D:/Miniconda3/envs/pytorch/python.exe。这是虚构数据的证据编排自检；已经假设 rule_id 由上游给出，不执行视觉识别、检索、法律适用或模型生成。

```python
from datetime import date
from typing import Any

import pandas as pd


def assemble(
    observations: pd.DataFrame, rules: pd.DataFrame, as_of: date
) -> pd.DataFrame:
    """合并视觉观察与有效制度元数据，缺证据时标为待复核。"""
    required_obs = {"case_id", "image_id", "observation", "rule_id"}
    required_rules = {"rule_id", "title", "version", "start", "end", "location"}
    if observations.empty or not required_obs.issubset(observations.columns):
        raise ValueError("视觉观察为空或缺少字段")
    if not required_rules.issubset(rules.columns):
        raise ValueError("制度表缺少字段")
    if observations["case_id"].isna().any() or observations["case_id"].duplicated().any():
        raise ValueError("case_id 必须非空且唯一")
    if observations["image_id"].isna().any():
        raise ValueError("image_id 不得为空")
    allowed = {"hazard", "clear", "unknown"}
    if not observations["observation"].isin(allowed).all():
        raise ValueError("不支持的视觉观察标签")
    if rules["rule_id"].isna().any() or rules["rule_id"].duplicated().any():
        raise ValueError("rule_id 必须非空且唯一")
    checked = rules.copy()
    checked["start"] = pd.to_datetime(checked["start"], errors="raise").dt.date
    checked["end"] = pd.to_datetime(checked["end"], errors="raise").dt.date
    if checked[["start", "end"]].isna().any().any():
        raise ValueError("制度日期不得为空")
    if (checked["start"] > checked["end"]).any():
        raise ValueError("制度生效时间晚于失效时间")
    joined = observations.merge(checked, how="left", on="rule_id", validate="many_to_one")
    assert len(joined) == len(observations)
    rows: list[dict[str, Any]] = []
    for row in joined.to_dict("records"):
        has_metadata = all(pd.notna(row[key]) and str(row[key]).strip()
                           for key in ("title", "version", "location"))
        in_force = (pd.notna(row["start"]) and pd.notna(row["end"])
                    and row["start"] <= as_of <= row["end"])
        has_visual = bool(str(row["image_id"]).strip())
        status = "待人工复核"
        if row["observation"] == "hazard" and has_visual and has_metadata and in_force:
            status = "证据已收集，待核实适用性"
        rows.append({"case_id": row["case_id"], "image_id": row["image_id"],
                     "observation": row["observation"], "rule_id": row["rule_id"],
                     "rule_version": row["version"], "location": row["location"],
                     "status": status})
    result = pd.DataFrame(rows)
    assert result["case_id"].is_unique and len(result) == len(observations)
    return result


def main() -> None:
    """验证正常、视觉不确定和制度过期三种情形。"""
    observations = pd.DataFrame([
        {"case_id": "a", "image_id": "img1", "observation": "hazard", "rule_id": "r1"},
        {"case_id": "b", "image_id": "img2", "observation": "unknown", "rule_id": "r1"},
        {"case_id": "c", "image_id": "img3", "observation": "hazard", "rule_id": "r0"},
    ])
    rules = pd.DataFrame([
        {"rule_id": "r1", "title": "虚构制度", "version": "v2", "start": "2026-01-01",
         "end": "2027-12-31", "location": "第2页"},
        {"rule_id": "r0", "title": "过期制度", "version": "v1", "start": "2020-01-01",
         "end": "2021-12-31", "location": "第1页"},
    ])
    result = assemble(observations, rules, date(2026, 11, 11)).set_index("case_id")
    assert result.loc["a", "status"] == "证据已收集，待核实适用性"
    assert result.loc["b", "status"] == "待人工复核"
    assert result.loc["c", "status"] == "待人工复核"
    print(result[["image_id", "rule_version", "location", "status"]])


if __name__ == "__main__":
    main()
```

逐段讲解：先校验两张表的必需字段、ID 和日期；用 merge(validate="many_to_one") 约束制度关系；最后检查视觉标签、证据元数据和有效期，仅将满足条件的样本标为“证据已收集，待核实适用性”。这是证据整理状态，不是违规判断。

### 这段代码怎么在面试里讲

- **声明不变量：**每个 case ID 唯一，关联后行数不变，制度 ID 不重复，观察标签来自明确集合。

- **解释关键行：**按 rule_id 连接视觉结果与制度，检验条款元数据和有效日期；证据不足就留待人工复核。

- **主动说边界：**这段代码不校验视觉判断是否正确、不检索条款，也不做适用性或权限判断；生产中需要分别评估这些链路。

### 本节收尾：费曼自述与闪卡

**费曼自述：**视觉证据回答图里发生什么，制度证据回答规则写了什么。两者必须分别核验；只找到制度，不代表图片里发生了违规。

- Q：条款存在能证明照片违规吗？A：不能，还需要可靠的视觉观察和适用性判断。

- Q：图片清楚但制度版本过期，属于哪类问题？A：文本证据的版本或检索过滤问题。

- Q：merge(validate="many_to_one") 保证证据语义正确吗？A：不能，它只检查连接键的关系约束。

- Q：视觉不确定时如何处理？A：保留图像证据并待人工复核，不用制度倒推出画面事实。

## 7.9 面试与作品集：拿可复现的证据说话【🔥 必会】

〔本次新补，参考当前面试趋势〕

### 目标与例子

把“我接过视觉模型”变成可核验的项目描述。以公开的工地图片为例，先固定测试集和任务，记录模型基线；再针对小目标错误比较一个改动，例如局部裁切，并保存逐样本预测、分组效果、延迟和失败案例。现有公司项目的数据、代码和业务信息按授权范围脱敏描述；公开作品使用可公开的数据及独立实现。

### 概念与五要素

| 要素 | 说明 |
| --- | --- |
| 输入 | 测试集版本、样本 ID、金标、基线与候选预测、运行配置、延迟记录。 |
| 做什么 | 按样本 ID 对齐基线和候选，核验金标及数据版本，统计总体与切片表现，并抽查退化样本。 |
| 输出 | 实验记录：任务指标、分组差异、成本/延迟、失败案例与可复现配置。 |
| 哪里出错 | 测试集换了、同一数据泄漏、只展示成功案例、把多次试验挑选出的测试结果当无偏评估。 |
| 参数影响 | 切片定义、样本规模与金标规则影响结论；阈值、分辨率、模型和采样配置影响质量与成本。 |

项目汇报可以按“问题与约束 → 我的具体工作 → 基线和实验 → 结果及代价 → 失败和后续”组织。没有测量的数字写“待测”，不能把示例数字当成自己的成果；论文或公司项目中自己的贡献也要按事实说明。

### 面试追问

- 【🔥 必会】为什么选 VLM 而不是检测器？ 一句话：看业务输出和实测取舍。展开：固定类别与框可能更适合检测基线；需要开放问答或复杂指代时可以比较 VLM，并在同一测试集上测质量、成本和延迟。

- 【🔥 必会】改动后总分提高，怎么判断是否真的更好？ 一句话：核对同样本、分组和退化案例。展开：确认测试集及金标一致，逐样本比较并检查关键切片；报告样本数和延迟，样本少时不夸大结论。

- 【🔥 必会】测试集分数比线上高很多，怎么排查？ 一句话：先查泄漏和数据分布差异。展开：按原图与事件去重，比较场地、时间、光照、设备和任务比例；补充独立测试集，避免用线上事故反复调同一测试集。

### 故障模式与排障

- **前后指标不能比较：**检查样本 ID、金标、版本、评测口径与配置；在一致的固定样本上重新运行，保留逐样本记录。

- **总体提升掩盖关键场景退化：**按夜间、小目标、遮挡等业务切片比较新增正确和新增错误；优先检查高代价错误并记录每组数量。

- **演示能跑但别人无法复现：**核对依赖、模型版本、提示词、随机参数、数据授权和运行命令；整理最小 README 与受控公开数据。

### 工程 trick 与坑

- 按样本配对比较可以展示“改对了哪些、改错了哪些”；样本 ID 相同还要检查金标和测试集版本。

- 延迟要注明硬件、并发、输入长度、预热和测量范围；少量样本的 P95 只是示例，不足以代表线上尾延迟。

- 避免对同一测试集反复调参后只报告最佳结果；训练/验证/最终测试的职责要分开。

- 生产级实验记录应进一步记录依赖版本、模型/processor、提示词、采样参数、错误、费用和数据分组规则；下例只覆盖核心配对检查。

### Toy code：用 pandas 配对比较基线与候选

运行前提：Python 3.10+、pandas 和 NumPy。本机可用 D:/Miniconda3/envs/pytorch/python.exe。示例数据完全虚构，不调用模型；生产数据中仍需自行定义语义正确性，不能假设所有开放回答都能用字符串精确匹配。

```python
from typing import Any

import numpy as np
import pandas as pd

FIELDS = {"id", "dataset", "group", "gold", "prediction", "latency_ms"}


def validate(frame: pd.DataFrame, label: str) -> pd.DataFrame:
    """验证离散标签实验记录，保留输入表不变。"""
    if frame.empty or not FIELDS.issubset(frame.columns):
        raise ValueError(f"{label}: 记录为空或缺少字段")
    data = frame.copy()
    text_fields = ["id", "dataset", "group", "gold", "prediction"]
    for field in text_fields:
        if data[field].isna().any() or not data[field].map(
            lambda value: isinstance(value, str) and bool(value.strip())
        ).all():
            raise ValueError(f"{label}: {field} 必须为非空文本")
    if data["id"].duplicated().any():
        raise ValueError(f"{label}: 样本 ID 重复")
    data["latency_ms"] = pd.to_numeric(data["latency_ms"], errors="raise")
    latency = data["latency_ms"].to_numpy(dtype=float)
    if not np.isfinite(latency).all() or (latency < 0).any():
        raise ValueError(f"{label}: 延迟必须是非负有限数")
    return data


def compare(base: pd.DataFrame, candidate: pd.DataFrame) -> dict[str, Any]:
    """配对比较离散标签，返回总体与每个切片的结果。"""
    a, b = validate(base, "基线"), validate(candidate, "候选")
    paired = a.merge(b, on="id", how="outer", suffixes=("_base", "_new"),
                     validate="one_to_one", indicator=True)
    if not paired["_merge"].eq("both").all():
        raise ValueError("样本 ID 集合不一致")
    for field in ("dataset", "group", "gold"):
        if not paired[f"{field}_base"].eq(paired[f"{field}_new"]).all():
            raise ValueError(f"配对样本的 {field} 不一致")
    paired["base_ok"] = paired["prediction_base"].eq(paired["gold_base"])
    paired["new_ok"] = paired["prediction_new"].eq(paired["gold_new"])

    def summarize(rows: pd.DataFrame) -> dict[str, Any]:
        """在非空样本子集上计算准确率、变化和延迟。"""
        assert len(rows) > 0
        return {
            "n": len(rows),
            "base_accuracy": float(rows["base_ok"].mean()),
            "new_accuracy": float(rows["new_ok"].mean()),
            "fixed": int((~rows["base_ok"] & rows["new_ok"]).sum()),
            "regressed": int((rows["base_ok"] & ~rows["new_ok"]).sum()),
            "base_p95_ms": float(rows["latency_ms_base"].quantile(0.95)),
            "new_p95_ms": float(rows["latency_ms_new"].quantile(0.95)),
        }

    return {"overall": summarize(paired),
            "groups": {name: summarize(rows) for name, rows in paired.groupby("group_base")}}


def main() -> None:
    """用虚构记录测试配对、退化和不一致金标。"""
    base = pd.DataFrame([
        {"id": "a", "dataset": "v1", "group": "night", "gold": "yes",
         "prediction": "no", "latency_ms": 10.0},
        {"id": "b", "dataset": "v1", "group": "day", "gold": "no",
         "prediction": "no", "latency_ms": 12.0},
    ])
    candidate = base.copy()
    candidate.loc[candidate["id"] == "a", "prediction"] = "yes"
    candidate.loc[candidate["id"] == "b", "prediction"] = "yes"
    candidate["latency_ms"] = [14.0, 15.0]
    result = compare(base, candidate)
    assert result["overall"]["fixed"] == 1
    assert result["overall"]["regressed"] == 1
    assert result["groups"]["night"]["new_accuracy"] == 1.0
    wrong_gold = candidate.copy()
    wrong_gold.loc[0, "gold"] = "different"
    try:
        compare(base, wrong_gold)
    except ValueError as exc:
        assert "gold" in str(exc)
    else:
        raise AssertionError("金标不一致必须报错")
    print("配对比较自检通过:", result)


if __name__ == "__main__":
    main()
```

逐段讲解：先校验样本 ID、必填值和延迟；用一对一外连接检查是否缺样本，再确认数据版本、切片和金标一致；统计总体、分组、改对及改错。分位数由 pandas 默认线性插值得到，真实压测前必须固定口径及样本规模。

### 这段代码怎么在面试里讲

- **声明不变量：**每个实验的 ID 唯一，基线与候选的样本集合、金标、数据版本和切片一致。

- **解释关键行：**先用一对一外连接核验配对关系，再计算逐样本正确变化和分组统计，避免只看总体分数。

- **主动说边界：**精确匹配仅适用于已规范化的离散标签；示例没有统计显著性、费用、模型调用或完整线上压测。

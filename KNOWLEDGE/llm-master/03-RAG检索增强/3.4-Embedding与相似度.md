### 一、Embedding 到底是什么？

Embedding 是一种将文本（或图片、音频等）映射到高维向量空间的技术。一个句子经过 Embedding 模型处理后，会变成一个由几百到几千个浮点数组成的数组，比如 `[0.23, -0.87, 0.14, ..., 0.56]`（维度通常是 384、768 或 1536 维）。

关键不在于这串数字本身，而在于它在空间里的**位置**：语义相似的文本，它们的向量在这个高维空间里彼此距离近；语义不相关的文本，距离远。

这是 Embedding 的核心承诺：**用空间距离来表达语义相似度。**

下面这张图用二维空间来直觉化这件事。真实的向量是几百到几千维，但投影到二维平面后，语义聚类的模式仍然清晰可见：

![语义向量空间直觉图](https://file1.kamacoder.com/i/bagu/embedding_semantic_space.png?v=20261005)

图中的每个点都是一段文本经过 Embedding 后在向量空间中的位置。真实维度远不止两维（通常是几百到几千维），但语义聚类的规律是一致的：出行报销类的文档彼此靠近，动物类、编程类各自聚集。

用户的 Query 向量化后，系统计算它与所有文档向量的距离，找到最近的几个，这就是向量检索的本质。

### 目标与例子

目标：掌握稠密向量（Dense Embedding）的数学与几何本质，理解余弦相似度（Cosine Similarity）、内积（Dot Product）与欧氏距离（L2 Distance）的几何等价条件，能手撕抗数值崩溃的向量归一化与 Top-K 检索排序算法。
例子：用户提问“高空作业必须做好哪些防跌落措施？”，数据库中的条款是“高处作业人员必须佩戴全身式五点安全带”。
虽然两句话在字面上没有一个词完全相同（高空 vs 高处，防跌落措施 vs 安全带），传统 BM25 词频匹配得分为零；但经由高质量双塔 Embedding 模型映射后，两个句子在高维潜空间（如 768 维）中指向相近的方向，两者的夹角余弦值可能高达 0.88，从而被精准召回。

### 概念与五要素

| 核心要素 | 说明 |
| --- | --- |
| 输入 | 离线端为切片文本序列，在线端为用户查询文本（按模型要求可能附加 query:  前缀）。 |
| 做什么 | 经由深度双塔模型（如 BERT/RoBERTa/SigLIP 架构）的 Pooling 层，将变长文本映射为定长稠密向量，并计算几何夹角余弦。 |
| 输出 | 归一化后的浮点数向量 np.ndarray，形状为 (N, D)，以及两两匹配的相似度分数。 |
| 哪里出错 | 前缀漏加（如 BGE 非对称前缀丢失）、长文本静默截断（超出 512 Token 后半段完全没编入向量）、零向量除零爆炸、模型跨版本混用。 |
| 重要参数影响 | 向量维度 $D$（直接决定索引内存占用）、最大序列长度 max_length、归一化标志 normalize_embeddings。 |

#### 余弦、点积与欧氏距离的几何统一定理

给定两个向量 $\mathbf{u}, \mathbf{v} \in \mathbb{R}^D$：

- 余弦相似度：$\cos(\theta) = \frac{\mathbf{u} \cdot \mathbf{v}}{|\mathbf{u}|_2 |\mathbf{v}|_2}$

- 点积 / 内积（IP）：$\langle \mathbf{u}, \mathbf{v} \rangle = \sum_{i=1}^D u_i v_i$

- 欧氏距离（L2）：$|\mathbf{u} - \mathbf{v}|_2^2 = |\mathbf{u}|_2^2 + |\mathbf{v}|_2^2 - 2 \langle \mathbf{u}, \mathbf{v} \rangle$

🔥 面试必背等价结论：
当且仅当向量 $\mathbf{u}$ 和 $\mathbf{v}$ 均已完成 L2 归一化（即 $|\mathbf{u}|_2 = 1, |\mathbf{v}|_2 = 1$）时：

- 点积严格等于余弦相似度：$\langle \mathbf{u}, \mathbf{v} \rangle = \cos(\theta)$；

- 欧氏距离平方与余弦呈严格单调负相关：$|\mathbf{u} - \mathbf{v}|_2^2 = 2 - 2\cos(\theta)$。
此时，三者计算出的 Top-K 检索排序顺序完全等价！这也是工业向量库（如 FAISS、Milvus）统一使用内积加速余弦检索的底层原理。

### 面试追问

- 【🔥 必会】既然余弦相似度要算模长除法开销大，为什么工业界向量库通常用内积（IP）来代替余弦？
一句话结论：离线入库和在线查询时把向量预先做 L2 归一化，内积就等于余弦，且无需每次查询实时开根号求模。
展开原理/取舍：直接算余弦每次都要在内存中遍历向量求范数开方，属于高开销运算；而在工程落地中，我们在向量出 Embedding 模型的瞬间执行一次 L2 归一化（模长化为 1.0），底层向量库即可直接调用 SIMD 硬件指令（如 AVX-512、CUDA GEMM）执行纯矩阵点积乘法，计算吞吐提升 3~5 倍。

- 【🔥 必会】【排障题】线上切换了新发布的 1024 维 Embedding 模型，发现所有 Query 的相似度全在 0.85 到 0.92 之间扎堆，毫无区分度，为什么？
一句话结论：排查是否发生“各向异性（Anisotropy）崩塌”或输入漏加了指令前缀。
展开原理/取舍：① 各向异性问题：未经精细对比学习微调的语言模型，其向量表征容易退化挤在潜空间的一个狭窄锥体（Cone）内，导致任意两个毫不相关的句子余弦都在 0.8 以上。② 非对称前缀丢失：以 BGE/E5 为代表的现代检索模型，训练时 Query 必须携带特定 Instruct 前缀（如 为这个句子生成表示以用于检索相关文章：），若漏加前缀，Query 向量将漂移到错误分布中；③ Pooling 方式错配：模型设计要求 mean pooling 却错误配置成了 cls pooling。

- 【⭐ 理解】向量相似度 0.85，能代表有 85% 的概率答案正确吗？
一句话结论：不能，余弦分数只是几何流形上的相对距离，不具备后验概率的校准性。
展开原理/取舍：余弦相似度数值极大程度受模型架构、预训练数据分布和温度系数影响。同一个文本对，在 Model-A 上测是 0.65，在 Model-B 上可能是 0.88。严禁在生产代码中把特定数值（如 score > 0.8）作为通用的真理阈值硬编码；必须在业务验证集上通过绘制 PR 曲线（Precision-Recall Curve）确定最合适的截断阈值（Cut-off Score）。

### 故障模式与排障

- 故障模式：零向量除零崩溃（Zero Division / NaN Leakage）

- 定位：排查输入中是否存在全空白字符、生僻未登录特殊字符（OOV），导致模型 Pooling 输出全 0 向量；归一化时未加极小值 $\epsilon$ 导致出现 float("nan") 污染后续全部排序。

- 修复：手写归一化算子时必须加入数值稳定平滑项：norm = np.linalg.norm(v) + 1e-12；对全 0 向量在准入层拦截并抛出受控告警。

- 故障模式：超长条款被后置静默截断（Silent Truncation）

- 定位：Embedding 模型的 Tokenizer 默认设置了 truncation=True, max_length=512。一段 1500 字符的施工流程，后 1000 字符被默默扔掉，向量仅能代表前 500 字符。

- 修复：在离线 Ingestion 阶段增加 Token 长度监控日志；超过 400 Token 的文本必须强制触发 3.3 节的滑动窗口切片，严禁依赖 Embedding 模型的自动截断。

### 工程 trick 与坑

- BGE 等模型的非对称前缀规范：记住口诀——Query 加前缀，Document 绝不加前缀！如果在 Document 入库时也拼接了检索指令，会把“指令语义”反向污染到知识库切片中。

- 浮点精度溢出：在海量存储时，Float32（4字节）通常可以通过 FP16（半精度）甚至 INT8 标量量化存储，内存直接缩减 50%~75%，而召回率损失通常小于 1%~2%。

### 循序渐进 Toy Code：Level 4 — 抗数值崩溃的余弦相似度与批量矩阵检索

代码难度定位：Level 4（数值计算进阶）。手写带有严格维度断言、L2 归一化平滑项、矩阵乘法广播与 NaN 防御的向量检索核心算子。

```python
"""
3.4 Toy Code: Level 4 - 数值稳定的余弦相似度与向量检索核心算子
依赖：Python 3.10+ 标准库 / 纯数学实现（无需第三方库）
"""
from dataclasses import dataclass
import math
from typing import Optional


@dataclass(frozen=True)
class ScoredResult:
    """检索排序结果条目"""
    doc_id: str
    score: float


def l2_normalize(vector: tuple[float, ...], eps: float = 1e-12) -> tuple[float, ...]:
    """
    向量 L2 归一化（带防除零平滑项）
    数学定义: v_norm = v / (sqrt(sum(v_i^2)) + eps)
    """
    if not vector:
        raise ValueError("输入向量不能为空")
    
    # 检查有限数
    if not all(math.isfinite(x) for x in vector):
        raise ValueError("向量包含非有限浮点数 (NaN 或 Inf)")

    sum_sq = sum(x * x for x in vector)
    norm = math.sqrt(sum_sq)
    
    # 零向量保护
    if norm < eps:
        raise ValueError("检测到零向量或极小全零输入，无法完成归一化")
        
    return tuple(x / norm for x in vector)


def dot_product(u: tuple[float, ...], v: tuple[float, ...]) -> float:
    """计算两等长向量的纯点积 (Dot Product)"""
    if len(u) != len(v):
        raise ValueError(f"向量维度不匹配: {len(u)} vs {len(v)}")
    return sum(x * y for x, y in zip(u, v))


def cosine_similarity_matrix_search(
    query_vec: tuple[float, ...],
    doc_vecs: list[tuple[float, ...]],
    doc_ids: list[str],
    top_k: int = 3
) -> list[ScoredResult]:
    """
    手撕余弦相似度批量检索算子
    
    不变量保证：
    1. query 与 doc 维度必须严格对齐
    2. 归一化后点积严格约束在 [-1.0, 1.0] 浮点容差区间
    3. 输出按相似度严格降序排列
    """
    if not doc_vecs or len(doc_vecs) != len(doc_ids):
        raise ValueError("文档向量与文档 ID 数量必须一致且非空")
    if top_k <= 0:
        raise ValueError("top_k 必须为正整数")

    dim = len(query_vec)
    if any(len(d) != dim for d in doc_vecs):
        raise ValueError("存在与 Query 维度不一致的文档向量")

    # 1. 对 Query 执行 L2 归一化
    norm_q = l2_normalize(query_vec)
    
    # 2. 对所有 Document 向量归一化并计算点积（归一化后的点积恒等于余弦）
    scored_list: list[ScoredResult] = []
    for doc_id, raw_d in zip(doc_ids, doc_vecs):
        norm_d = l2_normalize(raw_d)
        cos_score = dot_product(norm_q, norm_d)
        
        # 浮点数截断保护（防止出现 1.0000000000000002 越界）
        cos_score = max(-1.0, min(1.0, cos_score))
        assert -1.0 <= cos_score <= 1.0, "余弦相似度超出理论几何界限"
        
        scored_list.append(ScoredResult(doc_id=doc_id, score=cos_score))

    # 3. 稳定排序取 Top-K
    scored_list.sort(key=lambda item: (-item.score, item.doc_id))
    return scored_list[:top_k]


def self_test():
    """测试余弦相似度算法的不变量与边界防御"""
    # 模拟 3 维特征向量
    # Q 与 D1 完全同向，Q 与 D2 正交，Q 与 D3 完全反向
    query = (1.0, 2.0, 3.0)
    d_same_dir = (2.0, 4.0, 6.0)     # 同向不同模长 -> 归一化后余弦应为 1.0
    d_orthogonal = (2.0, -1.0, 0.0)   # 点积 1*2 + 2*(-1) + 3*0 = 0 -> 正交余弦应为 0.0
    d_opposite = (-1.0, -2.0, -3.0)   # 反向 -> 余弦应为 -1.0

    doc_vecs = [d_same_dir, d_orthogonal, d_opposite]
    doc_ids = ["DOC_SAME", "DOC_ORTHO", "DOC_OPP"]

    results = cosine_similarity_matrix_search(query, doc_vecs, doc_ids, top_k=3)
    
    # 验证排序与数学精度
    assert results[0].doc_id == "DOC_SAME"
    assert math.isclose(results[0].score, 1.0, abs_tol=1e-6)
    
    assert results[1].doc_id == "DOC_ORTHO"
    assert math.isclose(results[1].score, 0.0, abs_tol=1e-6)
    
    assert results[2].doc_id == "DOC_OPP"
    assert math.isclose(results[2].score, -1.0, abs_tol=1e-6)

    # 边界测试 1：零向量输入防御
    try:
        l2_normalize((0.0, 0.0, 0.0))
        raise AssertionError("零向量应抛出 ValueError")
    except ValueError:
        pass

    # 边界测试 2：维度不匹配防御
    try:
        cosine_similarity_matrix_search((1.0, 2.0), [(1.0, 2.0, 3.0)], ["D1"])
        raise AssertionError("维度不匹配应抛出 ValueError")
    except ValueError:
        pass

    print("✅ 3.4 余弦相似度与向量检索核心算子自检全部通过！")


if __name__ == "__main__":
    self_test()
```

#### 这段代码怎么在面试里讲（三段式）

- 声明不变量：我的检索算子确保输入向量维度完全同构。核心数学不变量是：对于任意非零向量，经 l2_normalize 变换后，其模长 $|\mathbf{v}|_2 \equiv 1.0$。在此前提下，两个单位向量的点积严格受限于 $[-1.0, 1.0]$，并且严格等于余弦相似度。

- 关键行解析：在第 21-36 行，我实现了抗除零崩溃的 L2 归一化，通过 eps=1e-12 规避零向量与极小浮点下溢；第 64-75 行，我没有直接套用复杂的除法公式，而是先两两归一化再求点积，并施加了 max(-1.0, min(1.0, cos_score)) 浮点越界保护，这是防止下游出现 NaN 的关键工程细节。

- 主动说边界与坑：这段代码是精确暴力搜索（Flat Search），计算复杂度为 $O(N \cdot D)$。当文档量 $N > 10^5$ 时，单机遍历延迟会迅速超过 100ms；在下一节 3.5 中，必须引入向量索引（如 HNSW / IVF）以牺牲极少量精度的代价将搜索时间复杂度降为 $O(\log N)$。

### 调库对照：Sentence-Transformers 工业写法

在实际生产应用中，调用成熟预训练模型（如 BAAI/bge-small-zh-v1.5）的标准调库写法：

可选：通过环境变量指定兼容的本地模型目录；若更换模型，先核对其查询前缀、输入格式和效果。

```python
import os
from sentence_transformers import SentenceTransformer

# 1. 加载模型
model = SentenceTransformer(os.environ.get("BGE_MODEL_PATH", "BAAI/bge-small-zh-v1.5"))

# 2. 离线编码文档（Document 绝不加指令前缀）
docs = ["高处作业应佩戴全身式安全带。", "动火作业前需办理审批单。"]
doc_embeddings = model.encode(docs, normalize_embeddings=True)  # 关键：开启内部 L2 归一化

# 3. 在线编码查询（按 BGE 规范拼接非对称检索指令）
query = "高空施工有什么防护要求？"
query_instruct = f"为这个句子生成表示以用于检索相关文章：{query}"
query_embedding = model.encode([query_instruct], normalize_embeddings=True)

# 4. 矩阵点积即为标准余弦值
cosine_scores = (query_embedding @ doc_embeddings.T)[0]
```

### 本节收尾：费曼自述与闪卡

费曼自述：
“Embedding 就是把世间万物变成一串有意义的坐标。意思相近的句子，坐标方向就差不多。算两个句子的相似度，就是算它们在坐标系里的夹角：如果事先把每根箭头的长度都拉成标准的 1 米长（归一化），那算夹角余弦就变成了最简单的乘法加总，算得飞快。”

- Q：为什么归一化后，内积（Dot Product）就等于余弦相似度（Cosine Similarity）？
A：因为余弦公式的分母是两向量的 L2 模长乘积；当双方模长均为 1 时，分母为 1，分子点积直接等于余弦值。

- Q：为什么在微调 Embedding 模型时常使用对比学习损失（Contrastive Loss / InfoNCE）？
A：通过拉近正样本对距离、推开负样本对距离，克服向量空间的各向异性（Anisotropy）退化问题，使语义分布更均匀。

- Q：BGE 模型的“非对称检索指令”应该加在 Query 侧还是 Document 侧？
A：必须仅加在 Query 侧。文档侧只编码客观知识内容，不可掺杂任务指令。

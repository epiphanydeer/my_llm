### 目标与例子

目标：掌握 RAG 的标准端到端工程闭环，闭卷画出离线处理（Offline）与在线推理（Online）全链路，理解数据在各阶段的状态变化与故障级联。
例子：用户输入“高处作业需要佩戴什么护具？”，系统经历如下完整路径：

```text
【离线阶段】原始规章文件 (PDF/Markdown) 
  → 文本提取与清洗 
  → 结构化切片 (Chunks) 
  → 批量向量化 (Embedding) / 词表构建 
  → 写入向量库与全文索引

【在线阶段】用户 Query 
  → 检索过滤 (Top-K Chunks) 
  → 上下文组装 (Prompt Template) 
  → LLM 证据理解与条件生成 
  → 提取引用溯源 (Citation Verification) 
  → 返回带依据的回答
```

### 概念与五要素

| 核心要素 | 说明 |
| --- | --- |
| 输入 | 离线端为非结构化企业文档（PDF/Word/Markdown）；在线端为用户自然语言 Query 及交互会话历史。 |
| 做什么 | 离线将大篇幅文档降维为细粒度语义片段并持久化为索引；在线按意图召回最相关的证据碎片，拼装 Prompt 注入 LLM 生成回答。 |
| 输出 | 携带确凿来源出处（Reference Sources）的事实回答。 |
| 哪里出错 | 离线段：解析漏表格、切片截断语义、编码向量被污染；在线段：召回不准、排序靠后、Prompt 截断、模型未遵从引用格式。 |
| 重要参数影响 | 切片大小（Chunk Size）与重叠（Overlap）、召回数（Top-K）、Prompt 上下文配额（Context Window Token Budget）、LLM 采样温度（Temperature）。 |

### 面试追问

- 【🔥 必会】请画出并详述 RAG 的离线与在线全链路，说明每个阶段的数据结构变化。
一句话结论：离线是“原始文件→清洗文本→片段Chunk→向量/词项索引”；在线是“Query→检索Top-K→Prompt注入→生成与引用校验”。
展开原理/取舍：离线重吞吐与一致性：PDF 解析为纯文本后，切分为定长或语义块，附加文档版本、标题、权限等元数据，经 Embedding 写入向量库；在线重延迟与准确率：Query 经过过滤和检索后拿到 Top-K 个 Chunk 文本，塞进带有严格引用要求的 Prompt 模板中，LLM 在零温（Temperature=0）下自回归生成回答，最后通过正则核验其引用标记是否真实存在。

- 【🔥 必会】【排障题】用户反馈知识库问答完全答非所问，你应该按照什么顺序排查定位？
一句话结论：遵循“原文→解析→召回→上下文→生成”五级下钻排查。
展开原理/取舍：① 查原文：确认企业原始文档中是否有此问题的正确依据；② 查切片：确认解析器是否丢弃了该页（如 OCR 识别失败或表格丢失），或关键句是否被腰斩在两块之间；③ 查检索：看 Top-K 召回列表中是否包含了金标 Chunk，若无，排查关键词/向量相似度打分；④ 查上下文：检查金标 Chunk 是否在重排或 Prompt 截断时被丢弃；⑤ 查生成：若 Context 正确但回答错误，定位是否 Prompt 指令冲突、或上下文太长诱发了注意稀释。

- 【⭐ 理解】为什么在线检索时，Query 与 Document 必须处于同一个对齐的语义空间？
一句话结论：不同模型或未对齐模型映射的几何空间完全不同，余弦相似度将彻底失效。
展开原理/取舍：Embedding 是将高维离散符号投影到连续几何流形中。如果文档库用 Model-A 离线编码，在线 Query 用 Model-B 编码，即便二者输出维度完全相同（如都是 768 维），它们的坐标轴基底和语义距离度量也是毫无关联的随机噪声。即使使用同一个模型，若模型支持“非对称指令”（如 BGE 检索时要求 Query 拼接特定前缀），如果漏加也会导致空间偏移。

### 故障模式与排障

- 故障模式：检索到了正确文档，但 LLM 回答时完全忽略

- 定位：排查 Prompt 拼接时 Chunk 的放置顺序。如果将核心 Chunk 放在几千字 Context 的正中间，LLM 易出现“首尾偏见（Lost in the middle）”而忽略中间证据。

- 修复：对检索到的 Chunks 按照相关度逆向放置，或采用“最相关 Chunk 紧贴用户 Question 放置”的拼接策略；同时降低 Prompt 的总 Token 冗余。

- 故障模式：模型在回答中凭空编造出不存在的引用标记（如 [Doc-999]）

- 定位：Prompt 模板缺乏强硬约束，或模型参数较小（如 7B 以下）对少样本（Few-shot）指令遵循能力弱。

- 修复：后置增加引用拦截校验器：用正则表达式提取回答中的所有 [Doc-ID]，核对是否严格属于本次注入 Context 的 ID 子集；若出现非法 ID，直接将该句子驳回重试或降级拒答。

### 工程 trick 与坑

- Prompt 模板中的“防剧透/防先验”指令：必须在 System Prompt 中加入强约束：“仅依据提供的上下文资料回答，如果上下文中没有明确提及，严禁使用你自己的先验知识推测，直接回答‘依据不足’”。

- 单条 Chunk 的 ID 注入机制：在拼装 Context 时，每一段开头必须显式打上机器和人均易读的锚点标签，例如 --- 证据 [ID: doc_01_chunk_03] ---\n{content}\n，并在指令中要求模型在回答句尾附带该标签。

### 循序渐进 Toy Code：Level 2 — 端到端最小 RAG 链路串联

代码难度定位：Level 2（骨架串联）。在 Level 1 的基础上，不依赖任何第三方 heavyweight 框架或本地 GPU，仅用 Python 标准库手写一个结构极为通透的 MiniRAGPipeline，把切片、检索、Prompt 组装、格式化生成与引用守卫五大环节完整跑通。

```python
"""
3.2 Toy Code: Level 2 - 最小自闭环端到端 RAG 流水线
依赖：Python 3.10+ 标准库
"""
from dataclasses import dataclass
import re
from typing import Optional


@dataclass(frozen=True)
class RawDocument:
    """原始文档数据结构"""
    doc_id: str
    title: str
    text: str


@dataclass(frozen=True)
class DocumentChunk:
    """切片数据结构：携带原文归属元数据"""
    chunk_id: str
    doc_id: str
    chunk_index: int
    content: str


@dataclass(frozen=True)
class RAGOutput:
    """端到端输出结果"""
    query: str
    answer: str
    citations: tuple[str, ...]
    prompt_used: str
    is_citation_valid: bool


class MiniRAGPipeline:
    """轻量级端到端 RAG 流水线骨架实现"""

    def __init__(self, chunk_size: int = 50):
        if chunk_size <= 0:
            raise ValueError("chunk_size 必须为正数")
        self.chunk_size = chunk_size
        self.chunk_store: list[DocumentChunk] = []

    # 阶段 1：离线切片与知识库构建（Offline Ingestion）
    def ingest_documents(self, docs: list[RawDocument]) -> None:
        """解析并切分原始文档，构建内存索引库"""
        if not docs:
            raise ValueError("录入文档列表不能为空")
            
        self.chunk_store.clear()
        for doc in docs:
            clean_text = doc.text.strip().replace("\n", " ")
            if not clean_text:
                continue
            # 按简单定长步长进行教学级切分
            for i in range(0, len(clean_text), self.chunk_size):
                chunk_text = clean_text[i : i + self.chunk_size]
                chunk_obj = DocumentChunk(
                    chunk_id=f"{doc.doc_id}_c{i // self.chunk_size:02d}",
                    doc_id=doc.doc_id,
                    chunk_index=i // self.chunk_size,
                    content=chunk_text
                )
                self.chunk_store.append(chunk_obj)
        
        assert len(self.chunk_store) > 0, "知识库切片存储不能为零"

    # 阶段 2：在线检索与打分（Online Retrieval）
    def retrieve(self, query: str, top_k: int = 2) -> list[DocumentChunk]:
        """基于词项重合度的轻量检索实现"""
        if not query.strip() or top_k <= 0:
            raise ValueError("查询非空且 top_k 必须为正")
        
        query_words = set(query.strip().lower().split())
        scored_chunks: list[tuple[DocumentChunk, int]] = []
        
        for chunk in self.chunk_store:
            chunk_words = set(chunk.content.lower().split())
            score = len(query_words.intersection(chunk_words))
            if score > 0:
                scored_chunks.append((chunk, score))
        
        # 降序排序，相同分数按 chunk_id 稳定排序
        scored_chunks.sort(key=lambda x: (-x[1], x[0].chunk_id))
        return [item[0] for item in scored_chunks[:top_k]]

    # 阶段 3：Prompt 组装（Prompt Assembly）
    def assemble_prompt(self, query: str, retrieved_chunks: list[DocumentChunk]) -> str:
        """组装带严格来源标注规则的 Prompt 上下文"""
        context_parts = []
        for chunk in retrieved_chunks:
            context_parts.append(f"[证据ID: {chunk.chunk_id}]\n内容: {chunk.content}\n")
        
        context_str = "\n".join(context_parts) if context_parts else "（未检索到相关证据）"
        
        prompt = (
            "【系统设定】你是一个严谨的企业安全助手。请严格仅依据给定的上下文回答问题。\n"
            "要求：回答的每个事实依据必须在末尾附带 [引用: 证据ID]。如果证据不足，请直接回答‘无法回答’。\n\n"
            f"【上下文证据】:\n{context_str}\n"
            f"【用户提问】: {query}\n"
            "【正式回答】:"
        )
        return prompt

    # 阶段 4：模型生成与引用提取（Generation & Verification）
    def run(self, query: str, top_k: int = 2) -> RAGOutput:
        """执行端到端 RAG 完整链路"""
        # 1. 召回
        candidates = self.retrieve(query, top_k=top_k)
        
        # 2. 组装 Prompt
        prompt = self.assemble_prompt(query, candidates)
        
        # 3. 模拟 LLM 确定性抽取与生成（真实项目中此处调用 API）
        if not candidates:
            mock_answer = "依据不足，当前资料中未检索到相关依据。"
        else:
            # 教学模拟：从相关度最高的证据中提取核心回答并自动注标
            best_chunk = candidates[0]
            mock_answer = f"根据要求，{best_chunk.content}。[引用: {best_chunk.chunk_id}]"

        # 4. 后置引用合法性核验（Citation Guard）
        extracted_citations = tuple(re.findall(r"\[引用:\s*([A-Za-z0-9_]+)\]", mock_answer))
        retrieved_ids = {c.chunk_id for c in candidates}
        
        # 断言所有提取出的引用必须真正在候选 Context 中出现过
        is_valid = bool(extracted_citations) and set(extracted_citations).issubset(retrieved_ids)
        if not candidates:
            is_valid = (len(extracted_citations) == 0)

        return RAGOutput(
            query=query,
            answer=mock_answer,
            citations=extracted_citations,
            prompt_used=prompt,
            is_citation_valid=is_valid
        )


def self_test():
    """测试完整 pipeline 的端到端流转与边界"""
    pipeline = MiniRAGPipeline(chunk_size=40)
    
    docs = [
        RawDocument(
            doc_id="DOC_SAFETY",
            title="施工高空作业管理要求",
            text="高处作业 人员 必须 佩戴 双挂钩 安全带 并在 登高 前 检查 挂点 稳固 状态"
        ),
        RawDocument(
            doc_id="DOC_FIRE",
            title="动火作业安全细则",
            text="动火作业 必须 提前 办理 动火 审批单 并 现场 配备 至少 两具 灭火器"
        )
    ]
    
    # 1. 执行离线录入
    pipeline.ingest_documents(docs)
    assert len(pipeline.chunk_store) >= 2
    
    # 2. 执行在线查询
    res = pipeline.run("高处作业 安全带 挂点", top_k=1)
    
    # 验证端到端不变量
    assert "佩戴 双挂钩 安全带" in res.answer
    assert res.citations == ("DOC_SAFETY_c00",)
    assert res.is_citation_valid is True
    assert "【上下文证据】" in res.prompt_used
    assert "[证据ID: DOC_SAFETY_c00]" in res.prompt_used
    
    # 3. 验证无证据场景
    empty_res = pipeline.run("未知化学试剂保管要求", top_k=1)
    assert "依据不足" in empty_res.answer
    assert empty_res.citations == ()
    assert empty_res.is_citation_valid is True

    print("✅ 3.2 最小端到端 RAG 链路自检全部通过！")


if __name__ == "__main__":
    self_test()
```

#### 这段代码怎么在面试里讲（三段式）

- 声明不变量：我设计了一个端到端 MiniRAGPipeline，输入输出全链路强类型绑定。核心不变量是：每一个切片拥有全生命周期唯一的 chunk_id，模型输出中捕获的任何 [引用: ID]，其 ID 必须是 retrieved_ids 集合的严格真子集，否则标记为非法引用。

- 关键行解析：

- 离线段在第 45-66 行：做文本规范化并生成携带 doc_id 和分块序号的结构化元数据；

- 在线段在第 69-85 行做召回，第 88-103 行以清晰的标记语言组织带边界提示的 Prompt；

- 最关键的是第 121-127 行：在生成之后使用正则提取引用的 Token 并执行后置集合包含校验，不把未经审计的模型输出直接暴露给用户。

- 主动说边界与坑：这个 Level 2 实现了清晰的骨架。在工业生产中，切片不能仅靠简单字符下标暴力截断（下节3.3展开），检索不能仅靠单字匹配（需要3.4向量与3.7混合检索），LLM 也应通过异步流式 API 调用；但整体的**“离线切分元数据化→在线召回→带约束拼装→后置引用校验”**五步结构在大型商业系统中是完全同构的。

### 调库选型：手写 Pipeline vs 调库（LangChain / LlamaIndex）

- 什么时候应该调高层库？
在产品初期做 PoC（概念验证）或接入多种复杂数据源（如飞书、Notion、S3 等 50+ 种格式连接器）时，优先使用 LlamaIndex / LangChain 的 Loader 与 VectorStore 组件快速打通链路。

- 什么时候必须手写核心流？
当系统进入生产高并发、要求严格 P99 延迟与严密可观测性时。工业界绝大多数外企/大厂的应用算法团队都会弃用臃肿的高层封装链（Chain），转为原生手写 Pipeline：自己精细化控制连接池、重试熔断机制、并行检索线程以及精确的 Token 计数与计费。

### 本节收尾：费曼自述与闪卡

费曼自述：
“RAG 流程其实就是一场‘开卷考试’。离线阶段是把厚书撕成带页码标签的小卡片并排好索引；在线阶段是学生拿到考题后，先快速从索引翻出最相关的两张卡片，照着卡片上的字作答，并在答案末尾老老实实写上页码。出题人最后还要核对一下这个页码是不是真的在那两张卡片里。”

- Q：RAG 完整架构中离线与在线的责任分工是什么？
A：离线负责海量异构文本的抽取、清洗、切片、向量化与索引建库；在线负责实时的 Query 解析、权限过滤、召回重排、Prompt 拼装与生成校验。

- Q：什么是引用后置校验（Citation Verification）？
A：在 LLM 生成回答后，通过程序逻辑核实回答中所声称的引用 ID 是否严格包含在输入上下文内，防止模型编造出处。

- Q：为什么大型生产系统往往选择自研/手写 RAG Pipeline 而非直接套用 LangChain？
A：高层库抽象层级过深，存在隐式开销、调试溯源困难、并发吞吐受限等问题；手写核心流能够精细掌控延迟、熔断降级与数据安全。

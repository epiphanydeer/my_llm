### 从问题理解这一节

RAG评估分为**检索侧评估**和**生成侧评估**两个层次,每一层都有对应的核心指标:

**检索侧评估**:衡量检索系统能不能找到正确的文档片段。

- **召回率(Recall@K)**:正确答案在top-K结果中出现的比例,衡量"相关内容有没有被找到"
- **精准率(Precision@K)**:top-K结果中相关内容的比例,衡量"找到的内容有多少是相关的"
- **MRR(Mean Reciprocal Rank)**:第一个正确结果的排名倒数均值,衡量"最相关的结果排在哪"
- **NDCG(Normalized Discounted Cumulative Gain)**:考虑排序位置和相关度等级的综合排序质量指标

**生成侧评估**:衡量最终生成的答案质量。

- **忠实度(Faithfulness)**:答案是否忠实于检索到的上下文,有没有幻觉
- **答案相关性(Answer Relevancy)**:答案是否真正回答了用户的问题
- **上下文相关性(Context Relevancy)**:检索到的上下文对回答问题是否有用
- **上下文召回(Context Recall)**:生成答案所需的关键信息是否都在检索到的上下文中

一句话:**检索侧保证能找到,生成侧保证用得好。没有评估的优化,就是拿着锤子找钉子。**

### 目标与例子

目标：掌握 RAG 离线量化评估体系，能手撕检索侧核心指标（Hit@K, Recall@K, MRR@K, nDCG@K）与生成侧核心指标（Faithfulness 声明级忠实度），理解基于 LLM-as-a-Judge（如 RAGAS）的自动化评估机制与偏置校准。
例子：针对问题“三级高处作业的防护标准与审批流程是什么？”，标准参考答案中包含切片 A（防护用具）与切片 B（审批流）。

- 若检索系统 Top-3 返回了 [B, C, D]：

- Hit@3 = 1.0（至少命中了一个有效切片 B）；

- Recall@3 = 0.5（只召回了 A、B 中的 1 个，信息缺漏 50%）；

- MRR@3 = 1.0（第一个金标 B 出现在第 1 位，$1/1 = 1.0$）；

- 如果生成模型依据缺失 A 的上下文强行回答了安全带型号，生成侧的 Faithfulness 忠实度 指标将被扣分。

### 概念与五要素

| 核心要素 | 说明 |
| --- | --- |
| 输入 | 固定测试黄金集（Golden Evaluation Set）：包含 Query、标准参考切片集合（Gold Chunks）、标准参考答案（Ground Truth Answer）。 |
| 做什么 | 检索侧：对比模型检索候选列表与金标集合，计算多阶排序匹配度；生成侧：将模型回答原子化为声明（Claims），用裁判判定声明是否受证据支持。 |
| 输出 | 标准化评测报表：包含宏平均 Hit@K、Recall@K、MRR@K、nDCG@K 及声明忠实度得分（0.0 ~ 1.0）。 |
| 哪里出错 | 标注与切片粒度错位（金标标的是文档 ID，算法评的是切片 ID）、空回答刷高忠实度（模型直接拒答被误判为 100% 忠实）、裁判偏置。 |
| 重要参数影响 | 截断深度 $K$（决定指标敏感度）、多金标聚合方式（宏平均 Macro vs 微平均 Micro）。 |

#### RAG 核心评测指标公式全景

| 指标 | 考察核心 | 数学定义 | 工业基线标准 |
| --- | --- | --- | --- |
| Hit@K | 命中底线（Top-K 里有没有哪怕 1 个对的） | $\mathbb{I}(\text{Gold} \cap \text{Top-K} \neq \emptyset)$ | 生产通常要求 Hit@5 $\ge 90%$ |
| Recall@K | 覆盖全面度（找回了百分之多少的必要依据） | $\frac{ | \text{Gold} \cap \text{Top-K} |
| MRR@K | 首位命中效率（第一个对的排在多前面） | $\frac{1}{\text{rank}_{\text{first}}}$，未命中则为 0 | 衡量搜索体感，MRR@3 宜 $\ge 0.75$ |
| nDCG@K | 分级相关排序（最相关的段落是否排在最高位） | $\frac{\text{DCG}@K}{\text{IDCG}@K}$，带对数位置衰减 | 衡量重排器精细度，nDCG@5 宜 $\ge 0.85$ |
| Faithfulness | 生成忠实度（回答有没有胡说八道、脱离证据） | $\frac{\text{受证据支持的声明数}}{\text{总回答声明数}}$ | 严肃企业问答门禁要求 $\ge 95%$ |

### 面试追问

- 【🔥 必会】Hit@K、Recall@K 和 MRR@K 的核心差异是什么？能用同一个例子讲清吗？
一句话结论：Hit 问“有没有”，Recall 问“全不全”，MRR 问“快不快（排在第几）”。
展开原理/取舍：假设一道题有两个必要证据 [A, B]。系统检索前三位返回了 [C, A, D]：
① Hit@3 = 1：因为包含了 A；
② Recall@3 = 0.5：因为两个必要证据只找回了 1 个，还有 B 被漏了；
③ MRR@3 = 0.5：因为第一个正确证据 A 出现在第 2 位，倒数得分为 $1/2 = 0.5$。
如果回答多条件问题，只看 Hit 会盲目乐观，必须结合 Recall 评估完整性。

- 【🔥 必会】RAGAS 框架中的 Faithfulness（忠实度）是如何自动化计算的？
一句话结论：LLM 先把回答拆成独立原子命题（Claims），再逐条核对命题能否由 Context 逻辑推出。
展开原理/取舍：第一步（Claim Decomposition）：Prompt 指令要求模型将 Answer 拆解成无代词、最小粒度的单句声明（如“三级高处作业基准面是 15 米”）；第二步（NLI 自然语言推理验证）：将每条 Claim 与检索出来的 Context 一起送入强模型裁判，打标 Yes / No；第三步统计比例：$\text{Score} = \text{Count(Yes)} / \text{Count(Total)}$。如果模型回答了一句上下文中未提及的自创事实，该声明标为 No，拉低整体忠实度。

- 【⭐ 理解】【排障题】为什么评测系统显示忠实度高达 99%，但业务方仍然投诉产品经常“不干活”？
一句话结论：排查是否发生了“过度拒答掩盖质量缺陷”的评估漏洞。
展开原理/取舍：如果模型面对问题频繁回答“抱歉，资料不足无法回答”，在传统的声明分解中，该回答没有任何虚假断言，甚至根本无法提取出 Claim，被裁判系统误判为 100% 忠实！评估 RAG 严禁单一指标单点决策，必须搭配**Answer Relevance（回答相关性）与拒答率（Rejection Rate）**交叉校验，对合理应该回答却发生拒答的样本判定为严重召回失败。

### 故障模式与排障

- 故障模式：模型裁判出现位置偏置（Position Bias / Self-enhancement Bias）

- 定位：LLM-as-a-Judge 在评判两个答案谁更好时，具有强烈的偏向排列在最前选项（Position Bias）或偏好自身模型生成的文字（Self-preference）。

- 修复：采用双向置换评估（Swap Position Consistency）：将证据和答案的顺序调换两次打分，只有两次判定一致时才采纳；结合横切专题[系统设计与评测](../%E6%A8%AA%E5%88%87-%E7%B3%BB%E7%BB%9F%E8%AE%BE%E8%AE%A1%E4%B8%8E%E8%AF%84%E6%B5%8B.md)中的人工校准机制。

- 故障模式：评测集金标污染（Data Contamination）

- 定位：评测集中的文档切片在开发过程中被拿去做了少量样本微调，导致离线评估虚高，上线后泛化暴跌。

- 修复：严格实行评测集版本锁死与盲测机制，Golden Set 与微调训练集物理隔离。

### 工程 trick 与坑

- 参考仓库根目录 rag_eval_demo.py：用户已写的脚本提供了真实 HNSW 检索与 Cross-Encoder 的评估骨架；在进行大规模工业化评测时，可直接复用其自检逻辑扩展多样本统计。

- nDCG 计算中的折损底数选择：工业标准通常采用以 2 为底的对数 $\log_2(i + 1)$，位置 $i=1$ 时折损为 $\log_2(2)=1$（无折损），位置 $i=2$ 时为 $\log_2(3)\approx 1.585$，位置衰减极为平滑。

### 循序渐进 Toy Code：Level 9 — 纯 Python 手撕 RAG 检索与声明级评测套件

代码难度定位：Level 9（数学与评测体系手撕）。不依赖 scikit-learn 或 ragas，纯 Python 从零手写Hit@K、Recall@K、MRR@K、基于相关度等级的 nDCG@K 以及声明级忠实度微平均计算器。

```python
"""
3.9 Toy Code: Level 9 - 纯 Python 手撕 RAG 检索与声明级忠实度评测套件
依赖：Python 3.10+ 标准库
"""
from dataclasses import dataclass
import math
from statistics import mean
from typing import Optional


@dataclass(frozen=True)
class QueryEvalSample:
    """单个查询样本的评测入参快照"""
    query_id: str
    gold_chunk_ids: frozenset[str]           # 必须召回的金标切片集合（支持多金标）
    retrieved_ranking: tuple[str, ...]      # 算法模型输出的有序切片 ID 列表
    relevance_grades: dict[str, int]        # 各切片的人工分级相关度 (0:无关, 1:部分相关, 2:高度相关)
    claims_supported_labels: tuple[Optional[bool], ...] # 回答拆解出的声明支持标签 (True:支持, False:反驳, None:未判定)


@dataclass(frozen=True)
class EvaluationReport:
    """全量数据集综合评测报告"""
    total_queries: int
    mean_hit_at_k: float
    mean_recall_at_k: float
    mean_mrr_at_k: float
    mean_ndcg_at_k: float
    total_claims: int
    judged_claims_count: int
    faithfulness_rate: Optional[float]
    judgment_coverage: float


def compute_ndcg_at_k(
    ranking: tuple[str, ...],
    relevance_grades: dict[str, int],
    k: int
) -> float:
    """
    纯 Python 手写折损累积增益 (nDCG@K)
    公式: DCG@K = sum_{i=1}^K (2^{rel_i} - 1) / log2(i + 1)
          nDCG@K = DCG@K / IDCG@K
    """
    top_k_items = ranking[:k]
    if not top_k_items:
        return 0.0

    # 1. 计算实际排名的 DCG@K
    dcg = 0.0
    for idx, chunk_id in enumerate(top_k_items, start=1):
        rel = relevance_grades.get(chunk_id, 0)
        gain = (2 ** rel) - 1.0
        discount = math.log2(idx + 1)
        dcg += gain / discount

    # 2. 计算理想最优排名的 IDCG@K (将所有正相关分值降序排列)
    all_grades = sorted([v for v in relevance_grades.values() if v > 0], reverse=True)
    if not all_grades:
        # 若样本没有任何相关标签，nDCG 约定为 1.0 (全无关时未召回不算错)
        return 1.0

    idcg = 0.0
    for idx, rel in enumerate(all_grades[:k], start=1):
        gain = (2 ** rel) - 1.0
        discount = math.log2(idx + 1)
        idcg += gain / discount

    if idcg == 0.0:
        return 0.0

    ndcg = dcg / idcg
    return max(0.0, min(1.0, ndcg))


def evaluate_rag_benchmark(
    dataset: list[QueryEvalSample],
    k: int = 3
) -> EvaluationReport:
    """执行多样本评测批处理，计算检索宏平均与声明微平均"""
    if not dataset:
        raise ValueError("评测数据集不能为空")
    if k <= 0:
        raise ValueError("评测截止深度 k 必须为正整数")

    hit_scores = []
    recall_scores = []
    mrr_scores = []
    ndcg_scores = []

    all_claims = []

    for sample in dataset:
        # 数据合法性前置检查
        if not sample.gold_chunk_ids:
            raise ValueError(f"样本 {sample.query_id} 的金标集合不能为空")
        
        top_k = sample.retrieved_ranking[:k]
        hit_set = sample.gold_chunk_ids.intersection(top_k)

        # 1. Hit@K: 是否命中至少一个
        hit = 1.0 if len(hit_set) > 0 else 0.0
        hit_scores.append(hit)

        # 2. Recall@K: 命中数 / 应命中数
        recall = len(hit_set) / len(sample.gold_chunk_ids)
        recall_scores.append(recall)

        # 3. MRR@K: 第一个命中的位次倒数
        first_hit_rank = next((idx for idx, cid in enumerate(top_k, start=1) if cid in sample.gold_chunk_ids), None)
        mrr = (1.0 / first_hit_rank) if first_hit_rank else 0.0
        mrr_scores.append(mrr)

        # 4. nDCG@K
        ndcg = compute_ndcg_at_k(sample.retrieved_ranking, sample.relevance_grades, k=k)
        ndcg_scores.append(ndcg)

        # 收集生成声明标签
        all_claims.extend(sample.claims_supported_labels)

    # 计算生成侧指标：微平均（Micro-average）
    judged_claims = [c for c in all_claims if c is not None]
    supported_claims_count = sum(1 for c in judged_claims if c is True)
    
    faith_rate = (supported_claims_count / len(judged_claims)) if judged_claims else None
    coverage = (len(judged_claims) / len(all_claims)) if all_claims else 1.0

    return EvaluationReport(
        total_queries=len(dataset),
        mean_hit_at_k=mean(hit_scores),
        mean_recall_at_k=mean(recall_scores),
        mean_mrr_at_k=mean(mrr_scores),
        mean_ndcg_at_k=mean(ndcg_scores),
        total_claims=len(all_claims),
        judged_claims_count=len(judged_claims),
        faithfulness_rate=faith_rate,
        judgment_coverage=coverage
    )


def self_test():
    """测试多指标计算数学精度与除零保护"""
    # 构造两个典型测试样本
    samples = [
        # 样本 1：双金标，Top-2 命中了第 1 个，第 2 个未命中
        QueryEvalSample(
            query_id="Q1",
            gold_chunk_ids=frozenset({"CHUNK_A", "CHUNK_B"}),
            retrieved_ranking=("CHUNK_A", "CHUNK_C", "CHUNK_D"),
            relevance_grades={"CHUNK_A": 2, "CHUNK_B": 2, "CHUNK_C": 0},
            claims_supported_labels=(True, True, False) # 3 条声明中 2 条受支持
        ),
        # 样本 2：单金标，排在第 2 位
        QueryEvalSample(
            query_id="Q2",
            gold_chunk_ids=frozenset({"CHUNK_X"}),
            retrieved_ranking=("CHUNK_Y", "CHUNK_X", "CHUNK_Z"),
            relevance_grades={"CHUNK_X": 2, "CHUNK_Y": 1, "CHUNK_Z": 0},
            claims_supported_labels=(True, None) # 1 条支持，1 条未判定
        )
    ]

    report = evaluate_rag_benchmark(samples, k=2)

    # 理论值手算验证：
    # Q1: Hit@2 = 1.0, Recall@2 = 1/2 = 0.5, MRR@2 = 1.0 (首位即A)
    # Q2: Hit@2 = 1.0, Recall@2 = 1/1 = 1.0, MRR@2 = 0.5 (X排在第2位)
    # 宏平均: Hit@2 = 1.0, Recall@2 = (0.5 + 1.0)/2 = 0.75, MRR@2 = (1.0 + 0.5)/2 = 0.75
    assert math.isclose(report.mean_hit_at_k, 1.0)
    assert math.isclose(report.mean_recall_at_k, 0.75)
    assert math.isclose(report.mean_mrr_at_k, 0.75)
    assert 0.0 <= report.mean_ndcg_at_k <= 1.0

    # 生成侧：有效判定 4 条，支持 3 条 -> 忠实度 3/4 = 0.75
    assert report.total_claims == 5
    assert report.judged_claims_count == 4
    assert math.isclose(report.faithfulness_rate, 0.75)
    assert math.isclose(report.judgment_coverage, 4 / 5)

    print(f"✅ 3.9 RAG 评测套件自检全部通过！"
          f"[Hit@2={report.mean_hit_at_k:.2f}, Recall@2={report.mean_recall_at_k:.2f}, "
          f"MRR@2={report.mean_mrr_at_k:.2f}, nDCG@2={report.mean_ndcg_at_k:.2f}, "
          f"忠实度={report.faithfulness_rate * 100:.1f}%]")


if __name__ == "__main__":
    self_test()
```

#### 这段代码怎么在面试里讲（三段式）

- 声明不变量：我设计了一套零外部依赖的纯数学 RAG 评测套件。检索侧以 (Gold, Ranking, K) 为三元组，保证所有指标严格收敛于 $[0.0, 1.0]$；生成侧以原子命题（Claims）列表为基准，严格区分“不支持（False）”与“未判定（None）”，杜绝覆盖率缺失时的假高分。

- 关键行解析：在第 25-58 行，我完全手写了工业级 compute_ndcg_at_k：计算实际排名的折损增益 $DCG$，并通过理想最大增益 $IDCG$ 归一化；在第 90-115 行，我清晰地在同一个循环中同步提取了 Hit、Recall 与 MRR，既有针对单题检索覆盖的度量，又有针对排名效率的度量。

- 主动说边界与坑：这段代码实现了核心数学逻辑。在真实企业流水线中，声明标签的提取（Claims Decomposition）需要调用经过针对性微调的评测小模型（如 Qwen2.5-7B-Instruct）；同时在数据治理层面，严禁只报一个平均分，必须对长尾 Query 进行 Bad Case 分布聚类（如按切片长度、术语密度做细分切片透视）。

### 本节收尾：费曼自述与闪卡

费曼自述：
“给 RAG 打分就像批改高考卷。Hit@K 是看选择题里你有没有蒙对一个选项；Recall@K 是看简答题的采分点你答全了百分之几；MRR 是看你是不是一眼就找到了正确解法；而忠实度是看你写在卷子上的推导过程，到底是不是从参考书里抄的，还是你自己闭着眼睛编的。”

- Q：Hit@K 与 Recall@K 在什么场景下会发生巨大数值背离？
A：多跳复合问答场景（如“对比A规程与B规程的差异”）。系统只要召回了 A，Hit@K 就判 1.0；但因为缺少 B，Recall@K 只有 0.5，此时只看 Hit 会掩盖严重的证据缺失。

- Q：为什么在 RAG 检索评测中要引入 nDCG 指标？
A：因为很多候选切片并不只是非黑即白的相关或无关，而是分层级（强相关、弱背景补充、完全无关）；nDCG 能科学惩罚“把强相关切片排在弱相关切片后面”的排序倒挂问题。

- Q：如何防范基于大模型的自动化评测框架（LLM-as-a-Judge）产生的评估偏置？
A：实施双向选项对调（Swap Position Bias Mitigation）、多模型交叉投票（Cross-model Ensemble）、人工专家对金标抽样回归校验。

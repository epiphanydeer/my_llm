## 6.3 量化：权重、激活和 KV Cache【🔥 必会】

〔融合 GitHub 教程与本地渐进式例子〕

### 一、提出问题：14B 模型要 28G 显存，手头只有一张 24G 显卡怎么办？

在大模型落地时，很多工程师手头只有一张消费级旗舰卡（如 RTX 4090，24GB 显存）：
- 按照官方原版的 **FP16 精度**，一个参数占 2 个字节，140 亿参数（14B）的光是静态权重就占了整整 $28\text{ GB}$，开机直接 `CUDA out of memory` 崩溃；
- 如果升级去租企业级 80GB A100，成本直接翻了 4 倍以上；
- **唯一的破局解法就是【模型量化】(Quantization)**：把原来 16 位的浮点数（FP16），压缩成 8 位整数（INT8，体积减半为 14GB），甚至压缩成 4 位整数（INT4，体积骤降为原本的 1/4，仅需 7GB）！这样一张 24GB 显卡不仅能轻松装下 14B 模型，还能腾出十几 G 显存支持超大并发！

**但是！为什么很多时候我们粗暴量化之后，模型回答直接变成了满屏乱码？** 怎么在极端压缩的同时保证模型智商不降？

### 概念：为什么需要这一环

**一句话：** 量化用较低精度表示权重、激活或 KV Cache，以减少存储/带宽占用；速度和精度变化依硬件、实现及任务而异。

### 二、心智模型与图解：像“用少色画盒临摹油画”一样做量化

#### 1. 生活中的大白话类比
- **FP16 浮点数**：相当于一个拥有 **65536 种颜色**的高级专业油画盒。画出来的画极其细腻平滑，但画盒太沉（占显存大）；
- **INT4 量化**：相当于把画盒没收，只给你发一个只有 **16 种颜色**的极简儿童画盒（$2^4 = 16$）。你必须拿这 16 种有限的颜色，去尽量还原原本五彩斑斓的画作；
- **Scale（缩放因子）**：相当于调色板的**放大镜倍率**；
- **Zero-point（零点偏移）**：相当于调色板的**基准底色**。

#### 2. 对称量化 vs 非对称量化直观网格图

```
【对称量化 (Symmetric)】：以 0 为绝对对称中心，零点固定为 0
  负数最大值               0                 正数最大值
───────┴───────────────────┼───────────────────┴───────> (浮点数 x)
      -127                 0                  127       (INT8 整数 q)
特点：公式极简，适合大模型权重（因为权重基本是以 0 为中心的正态分布）。


【非对称量化 (Asymmetric)】：带有零点平移 (Zero-point)
  最小值 (min)             0                  最大值 (max)
───────┴───────────────────┼───────────────────┴───────> (浮点数 x)
       0                   Z                  255       (INT8 整数 q)
特点：零点平移到了 Z，适合非对称偏斜分布（如 ReLU/GELU 之后全是正数的激活值）。
```

#### 3. 为什么一刀切量化会崩盘？——“离群太阳”惨剧图解

```
【正常分布】：绝大部分权重都在 [-1.0, 1.0] 的平缓区间
  [ ... -0.8, -0.2, 0.1, 0.5, 0.9 ... ]  -> 用 16 个刻度均匀分，大家都能分到清晰的刻度。

【离群值毁掉量化】：突然冒出一个数值高达 100.0 的极端神经元！
  [ -0.2, 0.1, 0.3, ... 0.8 ... 100.0 (离群大太阳！) ]
                                  ↑
  如果尺子要兼顾这个 100.0，每一个刻度（Scale）就会被拉大到 100/8 = 12.5！
  结果：原来那些在 0.1、0.5 的正常权重，除以 12.5 之后四舍五入【全部变成了 0】！
  --> 整个神经网络绝大部分参数被活生生“抹平抹死”，模型直接痴呆！
```

**AWQ（激活感知权重量化）的神来之笔**：不搞一刀切！先观察模型在真实语料上的激活值，找出那 1% 连着“大太阳”的关键通道，**给这些显著权重施加保护因子不压缩**，剩下的平缓草地再做量化，从而实现 4-bit 压缩下智商几乎零损失！

### 核心概念与五要素表

| 五要素 | INT8/INT4 对称与非对称量化反量化算子 (Level 3) |

|---|---|

| **输入 (Input)** | 原始浮点权重向量/张量 $x$、量化目标位宽 `bits`（如 8 或 4）、量化模式（对称/非对称）。 |

| **做什么 (Process)** | 扫描极值范围；计算缩放因子 $Scale$ 与零点偏移 $Zero\_point$；浮点除以 $Scale$ 并执行舍入与截断 (Clip)；执行逆向反量化重建；计算均方误差 (MSE) 与余弦相似度保真度。 |

| **输出 (Output)** | 量化后的整数张量、量化参数元组 $(Scale, Zero\_point)$、反量化重建浮点张量与保真度审计指标。 |

| **哪里出错 (Failure Modes)** | 1. 存在离群极大值点 (Outliers) 导致绝大部分正常权重被压缩为 0（模型精度崩盘）；2. 截断溢出造成极大反向误差；3. 零除异常（全零张量未处理）。 |

| **参数影响 (Parameters)** | 位宽 bits 越小压缩率越高（INT4 压缩 75%），但重建误差成倍上升；分组大小 (Group Size, 如 128) 越小精度越高但参数量轻微增加。 |

### 面试高频追问

**【🔥 必会】对称量化与非对称量化的数学公式分别是什么？如何做选型取舍？**  

*结论先行：* 对称量化零点固定为 0，公式简练；非对称量化引入平移偏置，更适合偏斜单峰分布。  

*展开解释：* 

- **对称量化**：$q = \text{clip}\left(\text{round}\left(\frac{x}{S}\right), -2^{b-1}, 2^{b-1}-1\right)$，其中 $S = \frac{\max(|x|)}{2^{b-1}-1}$。选型：绝大多数大模型的权重参数均以 0 为中心对称分布，优先选对称量化，能节省算力并免除偏置累加开销；

- **非对称量化**：$q = \text{clip}\left(\text{round}\left(\frac{x}{S}\right) + Z, 0, 2^b - 1\right)$，其中 $S = \frac{\max(x) - \min(x)}{2^b - 1}, Z = \text{round}\left(-\frac{\min(x)}{S}\right)$。选型：神经网络的激活值经过激活函数后通常全为正数，必须使用非对称量化以充分利用全部比特位宽。

**【🔥 必会】为什么直接对大模型进行 4-bit Post-Training Quantization (PTQ) 容易精度崩溃？AWQ 提出了什么突破性思路？**  

*结论先行：* 极少数关键权重通道（约 0.1%~1%）存在巨大的“离群激活值”，一刀切压缩会摧毁关键知识；AWQ 提出保留显著权重不量化或加权保护。  

*展开解释：* 实验表明大模型只有极少数“显著权重”主导了绝大部分推理输出。AWQ（Activation-aware Weight Quantization）通过观察小批量校准集上的真实激活值分布，找出那些对应大激活通道的权重，保护它们免受粗暴量化误差的损伤（例如施加缩放保护系数），使得模型在 4-bit 极端压缩下依然能保持 99% 以上的基座困惑度与任务表现。

**【⭐ 理解】为什么很多 INT8 权重量化模型在 GPU 上跑得比 FP16 还要慢？**  

*结论先行：* 发生了“即时反量化”的计算开销，且未能调用硬件 INT8 矩阵乘加速核。  

*展开解释：* 许多 Weight-only 量化框架只为了省显存。在推理时，每做一次矩阵乘法前，必须在 GPU 显存内先把 INT8 权重“解压回 FP16”，再做 FP16 GEMM。这不仅没有减少计算量，反而额外增加了解压算子的开销！只有进行 Weight-Activation 全量化（W8A8），硬件直接调用 INT8 Tensor Core 执行整数矩阵计算，才能真正做到“又省显存又提速”。

### 生产级代码实现：INT8/INT4 对称与非对称量化反量化算子 (Level 3)

```python

"""6.3 INT8/INT4 对称与非对称量化反量化算子 (Level 3 进阶实战)

业务场景：

在外企模型压缩与边缘端/私有化单卡部署中，

彻底吃透量化底层数学映射与误差审计：

1. 纯 Python 实现对称与非对称量化算子；

2. 动态计算 Scale 与 Zero-point，严格执行比特边界截断 (Clamping)；

3. 执行逆向反量化，评估均方误差 (MSE) 与余弦相似度保真度；

4. 审计离群点对量化精度的致命影响。

"""

from __future__ import annotations

import math

from dataclasses import dataclass

from typing import Any, Dict, List, Optional, Tuple

@dataclass(frozen=True)

class QuantizedTensorData:

    """量化压缩后的整数数据包"""

    quantized_values: List[int]

    scale: float

    zero_point: int

    bits: int

    is_symmetric: bool

@dataclass

class QuantizationAuditReport:

    """量化误差审计大表"""

    bits: int

    is_symmetric: bool

    scale: float

    zero_point: int

    mse_error: float

    cosine_similarity: float

    compression_ratio: float

    max_absolute_error: float

class ModelQuantizationOperator:

    """工业级模型量化与保真度核验算子"""

    @staticmethod

    def quantize(

        values: List[float],

        bits: int = 8,

        symmetric: bool = True

    ) -> QuantizedTensorData:

        """将浮点向量量化为指定位宽的整数向量"""

        if not values:

            raise ValueError("待量化浮点向量不可为空")

        if bits not in {4, 8}:

            raise ValueError(f"当前算子仅支持 4-bit 或 8-bit 量化，不支持 {bits}-bit")

        # 检查数值合法性

        for v in values:

            if not math.isfinite(v):

                raise ValueError(f"发现非有限浮点数: {v}")

        min_val = min(values)

        max_val = max(values)

        # 边界防御：全零常数向量

        if abs(max_val - min_val) < 1e-9:

            scale = 1.0

            zero_point = 0

            q_vals = [0] * len(values)

            return QuantizedTensorData(q_vals, scale, zero_point, bits, symmetric)

        if symmetric:

            # 对称量化：区间对称为 [-q_max, q_max]

            q_max = (2 ** (bits - 1)) - 1

            q_min = -q_max  # 强制对称性（如 8-bit 取 [-127, 127]）

            abs_max = max(abs(min_val), abs(max_val))

            scale = abs_max / q_max

            zero_point = 0

            quantized_vals: List[int] = []

            for x in values:

                # 浮点映射到整数网格: round(x / scale)

                raw_q = round(x / scale)

                # 边界截断保护

                clamped_q = max(q_min, min(q_max, raw_q))

                quantized_vals.append(clamped_q)

        else:

            # 非对称量化：区间为 [0, 2^bits - 1]

            q_min = 0

            q_max = (2 ** bits) - 1

            scale = (max_val - min_val) / (q_max - q_min)

            # 计算零点偏移: Z = round(-min / scale)

            raw_zp = round(-min_val / scale)

            zero_point = max(q_min, min(q_max, raw_zp))

            quantized_vals = []

            for x in values:

                raw_q = round(x / scale) + zero_point

                clamped_q = max(q_min, min(q_max, raw_q))

                quantized_vals.append(clamped_q)

        assert len(quantized_vals) == len(values)

        return QuantizedTensorData(quantized_vals, scale, zero_point, bits, symmetric)

    @staticmethod

    def dequantize(q_data: QuantizedTensorData) -> List[float]:

        """将低比特整数反量化恢复为连续浮点数"""

        scale = q_data.scale

        zp = q_data.zero_point

        if q_data.is_symmetric:

            # 对称反量化: x_hat = q * scale

            return [(q * scale) for q in q_data.quantized_values]

        else:

            # 非对称反量化: x_hat = (q - Z) * scale

            return [((q - zp) * scale) for q in q_data.quantized_values]

    @classmethod

    def audit_fidelity(

        cls,

        original_vals: List[float],

        bits: int = 8,

        symmetric: bool = True

    ) -> QuantizationAuditReport:

        """执行完整量化-反量化闭环并输出精度保真度报告"""

        q_data = cls.quantize(original_vals, bits=bits, symmetric=symmetric)

        reconstructed = cls.dequantize(q_data)

        # 1. 计算均方误差 (MSE) 与最大绝对误差

        diffs = [(orig - rec) for orig, rec in zip(original_vals, reconstructed)]

        mse = sum(d * d for d in diffs) / len(diffs)

        max_abs_err = max(abs(d) for d in diffs)

        # 2. 计算余弦相似度 (Cosine Similarity)

        dot_product = sum(a * b for a, b in zip(original_vals, reconstructed))

        norm_orig = math.sqrt(sum(a * a for a in original_vals))

        norm_rec = math.sqrt(sum(b * b for b in reconstructed))

        if norm_orig > 0 and norm_rec > 0:

            cosine_sim = dot_product / (norm_orig * norm_rec)

        else:

            cosine_sim = 1.0

        # 计算显存压缩比（相比原始 FP16 的 16-bit）

        compression_ratio = 16.0 / bits

        return QuantizationAuditReport(

            bits=bits,

            is_symmetric=symmetric,

            scale=round(q_data.scale, 6),

            zero_point=q_data.zero_point,

            mse_error=round(mse, 6),

            cosine_similarity=round(cosine_sim, 6),

            compression_ratio=compression_ratio,

            max_absolute_error=round(max_abs_err, 6)

        )

def self_test():

    """验证对称与非对称量化反量化保真度、位宽压缩比与数值稳定性"""

    # 模拟一层典型的权重向量 (高斯分布，中心接近 0)

    import random

    random.seed(42)

    sample_weights = [random.gauss(0.0, 0.5) for _ in range(100)]

    # 1. 测试 INT8 对称量化保真度 (最常用方案)

    report_int8_sym = ModelQuantizationOperator.audit_fidelity(sample_weights, bits=8, symmetric=True)

    assert report_int8_sym.compression_ratio == 2.0  # 16-bit 压为 8-bit，压缩比 2.0x

    assert report_int8_sym.zero_point == 0           # 对称量化零点严格为 0！

    # 余弦相似度必须极高（大于 0.999）

    assert report_int8_sym.cosine_similarity > 0.999

    assert report_int8_sym.mse_error < 1e-4

    print(f"✅ INT8 对称量化测试通过！余弦相似度: {report_int8_sym.cosine_similarity}, MSE: {report_int8_sym.mse_error}")

    # 2. 测试 INT4 极限压缩 (如 AWQ/GPTQ)

    report_int4 = ModelQuantizationOperator.audit_fidelity(sample_weights, bits=4, symmetric=True)

    assert report_int4.compression_ratio == 4.0      # 16-bit 压为 4-bit，压缩比 4.0x

    # 4-bit 下精度轻微受损，但相似度仍应高于 0.98

    assert report_int4.cosine_similarity > 0.98

    print(f"✅ INT4 极限量化测试通过！4倍显存压缩，余弦保真度: {report_int4.cosine_similarity}")

    # 3. 测试偏斜激活值分布的非对称量化 (输入全为正数 [0.1 ~ 5.0])

    skewed_activations = [random.uniform(-1.5, 4.0) for _ in range(100)]

    report_asym = ModelQuantizationOperator.audit_fidelity(skewed_activations, bits=8, symmetric=False)

    # 非对称量化零点必然不为 0

    assert report_asym.zero_point > 0

    assert report_asym.cosine_similarity > 0.999

    print(f"✅ 非对称量化测试通过！偏置零点 ZeroPoint: {report_asym.zero_point}, 相似度: {report_asym.cosine_similarity}")

    # 4. 边界测试：非法位宽拦截

    try:

        ModelQuantizationOperator.quantize(sample_weights, bits=3)

        raise AssertionError("未拦截非法位宽")

    except ValueError as e:

        assert "仅支持 4-bit 或 8-bit" in str(e)

    print("✅ 非法位宽安全拦截测试通过！")

    print("✅ 6.3 INT8/INT4 对称与非对称量化反量化算子自检全部通过！")

if __name__ == "__main__":

    self_test()

```

### 排障指南（常见故障、定位方法、修复策略）

| 常见故障 (Failure) | 定位方法 (Diagnosis) | 修复策略 (Mitigation) |

|---|---|---|

| **量化后模型生成内容完全变成乱码** | 检查各层量化误差，发现第一层与最后一层 LM Head 量化后 MSE 巨大。 | 混合精度保护策略：对极其敏感的输入 Embedding 层和最终词表映射 LM Head 保持 FP16/BF16，仅对中间的 Attention/MLP 线性层进行 INT4 量化。 |

| **存在离群值 (Outliers) 导致大面积精度衰减** | 某几个通道的数值突然达到 150，导致 Scale 极大，其余 0.1 左右的正常权重全被整除成了 0。 | 1. 采用分组量化 (Group-wise Quantization，如每 128 个参数单独算一组 Scale)；2. 引入 AWQ 算法，通过激活感知保护关键离群通道。 |

| **INT4 模型在低算力设备上显存反弹** | 部署时发现显存依然占了 16GB。 | 确认部署框架是否支持原生 4-bit 算子。未编译 Marlin/AWQ 内核时，框架可能会在加载后瞬间展开为 FP16，失去压缩意义。 |

### 工程 trick 与坑

1. **PTQ 校准集切忌直接使用生成答案**：在执行离线量化校准（PTQ Calibration）时，输入的数据集必须涵盖领域多样性（约 128~256 条真实行业长短语料），严禁使用未经清洗的代码或单调对话作为校准集。

2. **SmoothQuant 的等价数学搬运**：当激活值量化极为困难时，SmoothQuant 通过一个对角矩阵数学变换 $Y = (X \cdot S^{-1}) \cdot (S \cdot W)$，将激活值上的离群峰值“平滑迁移”到较为平缓的权重矩阵上，使得两端都能使用标准 W8A8 整数计算。

3. **现代推理首选 FP8 原生硬件格式**：如果服务器配备了 Ada Lovelace（RTX 4090）或 Hopper（H100）新一代架构，优先使用 FP8 格式（E4M3 用于权重，E5M2 用于 KV Cache），其硬件天然原生支持，无需复杂的 INT4 模拟即可获得 2 倍吞吐与显存砍半。

### 面试怎么讲（三段式：项目背景与选型理由、架构设计与核心机制、踩坑排障与量化收益）

**使用约定：**下面的项目情境和数字仅为虚构示例，不能直接当作本人经历或结果；只使用自己实际参与且有证据的内容。

> **面试官提问**：“你们在实际将大模型部署到生产环境时，是如何做量化选型的？量化为什么会掉精度，怎么解决？”

> 

> **回答范式**：

> 1. **背景与选型**：“在私有化安监审查项目中，客户要求整个 14B 参数模型必须能塞入单台配备 24GB 显存的工控机运行。若以原汁原味的 FP16 加载，模型权重本身就要占 28GB，开机即崩。为了实现单卡严密运行，我主导了 INT4 权重量化的技术改造。”

> 2. **架构与机制**：“在算法原理上，我们将高精度浮点连续值映射到 4 位离散整数网格。针对大模型普遍存在的‘少量离群通道决定生死’的痛点，我们坚决废弃了传统的全局朴素量化，选型了 AWQ（激活感知权重量化）方案。以 128 为一个 Group，通过观察真实巡检语料的激活流向，为前 1% 的关键权重施加自适应保护缩放因子，仅对平缓通道执行 4-bit 密集压缩。”

> 3. **踩坑与收益**：“初期测试时曾因将 LM Head 输出投影也强行做了 INT4 压缩，导致生成首字标点经常错位。在采用‘主体 INT4 + 首尾关键层保持 BF16’的混合架构后，模型静态权重显存从 28GB 剧烈压缩至 8.2GB，整机运行时显存严格稳定在 17.5GB 以内，余弦相似度保真度高达 0.985，而在下游隐患识别任务上的真实精度损失低于 0.8%，成功达成单卡低成本交付。”

### 费曼自述与闪卡

**费曼自述（3 分钟白板口述框架）**：  

“量化其实就像‘图像压缩打马赛克’。原来大模型是用 16 位浮点数来画画的，就像一个拥有 65536 种颜色的专业画盒，画得特别精细，但画盒太沉（显存太大）。量化就是把这幅画重新用只有 16 种颜色的小画盒（4-bit）重新画一遍。对称量化就像尺子两边一样长，以 0 为中心画对称刻度；非对称量化就是尺子可以平移，适合全都是正数的地方。量化最怕什么？最怕画里突然冒出一个极高极亮的‘太阳’（离群值），如果你拿尺子去迁就那个太阳，地上的小花小草就被压缩得全变成 0 了！所以聪明的做法（像 AWQ）就是把那个太阳单独拿红笔保护起来，剩下的草地再规规矩矩压进小盒子，这样画出来的画既轻巧又逼真！”

**备考闪卡 Q&A**：  

- **Q：什么是模型量化的缩放因子（Scale）与零点（Zero-point）？**  

  *A：* Scale 决定每个离散整数刻度代表的真实浮点步长；Zero-point 是真实世界中的浮点 0 映射在整数网格上的具体离散值。

- **Q：AWQ 算法的核心思想是什么？**  

  *A：* 激活感知权重量化。通过分析真实激活值大小识别出对模型表现起决定作用的少量显著权重，对其进行保护性缩放，避免粗暴量化造成精度崩盘。

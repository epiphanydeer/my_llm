### 一、提出问题与真实痛点

当你在面试中被问到：“为什么现在的开源大语言模型（LLaMA、DeepSeek、Qwen、GPT-4）几乎清一色采用 **Decoder-only** 架构，而放弃了最初 Transformer 论文的 **Encoder-Decoder** 架构（如 T5）或 **Encoder-only**（如 BERT）？”
- 如果你只回答：“因为 GPT 成功了”，面试官当场就会给你扣上缺乏底层认知的小红旗。
- 必须从**预训练任务的统一性、KV Cache 推理效率、零样本上下文泛化（In-Context Learning）以及架构可扩展性（Scaling Law）**全面拆解！

---

### 概念主线：前面的问题如何解决

**一句话：** Encoder 侧重对输入整体编码；自回归 Decoder 每次只依赖已有前文生成下一 token；Encoder-Decoder 用编码后的输入作为条件逐步生成。

### 三、核心概念与五要素表

| 架构类型 | 代表模型 | 注意力机制 | 预训练任务 | 核心擅长领域与局限 |
|---|---|---|---|---|
| **Encoder-only** | BERT, RoBERTa | 全双向注意力 | 掩码语言建模 (MLM) | 擅长文本分类、实体识别、抽取式特征提取；**无法高效自回归生成长文本**。 |
| **Encoder-Decoder** | T5, BART | 编码器双向 + 解码器因果 + 交叉注意力 | 跨序列映射 (Seq2Seq) | 擅长机器翻译、问答摘要；**结构臃肿，推理阶段维护两套 KV Cache，拓展性差**。 |
| **Decoder-only** | GPT-4, LLaMA, Qwen | 因果自回归 (Causal) | 下一个词预测 (Next-token Pred) | **大一统架构**！兼顾少样本自回归生成、零样本指令理解与极简的单路 KV Cache 加速。 |

### 四、代码动手实践与严格断言

```python
"""8.2 三大架构注意力掩码矩阵生成与因果阻断断言

纯 NumPy 实现：
1. 双向注意力全 1 掩码；
2. 因果下三角单向掩码；
3. 交叉注意力非对称掩码；
4. 严格断言因果掩码杜绝未来信息渗透！
"""
import numpy as np

def generate_attention_mask(mode: str, seq_len: int, enc_len: int = None) -> np.ndarray:
    if mode == "encoder_only":
        return np.ones((seq_len, seq_len), dtype=np.float32)
    elif mode == "decoder_only":
        # 下三角矩阵，上三角置为 0
        return np.tril(np.ones((seq_len, seq_len), dtype=np.float32))
    elif mode == "cross_attention":
        if enc_len is None:
            raise ValueError("交叉注意力必须指定编码器长度 enc_len")
        # 解码器 Q 与 编码器 K 的全连接交互矩阵: (seq_len, enc_len)
        return np.ones((seq_len, enc_len), dtype=np.float32)
    else:
        raise ValueError(f"未知架构模式: {mode}")

def self_test():
    T = 4
    # 1. 验证 Encoder-only: 任何词都能看全序列
    enc_mask = generate_attention_mask("encoder_only", T)
    assert np.all(enc_mask == 1.0)
    
    # 2. 验证 Decoder-only: 过去看不到未来！
    dec_mask = generate_attention_mask("decoder_only", T)
    # 第 0 行只能看自己
    assert np.array_equal(dec_mask[0], [1.0, 0.0, 0.0, 0.0])
    # 第 2 行能看前 3 个词
    assert np.array_equal(dec_mask[2], [1.0, 1.0, 1.0, 0.0])
    # 严格断言上三角必须全为 0
    assert np.sum(np.triu(dec_mask, k=1)) == 0.0
    
    # 3. 验证交叉注意力
    cross_mask = generate_attention_mask("cross_attention", seq_len=3, enc_len=5)
    assert cross_mask.shape == (3, 5)
    print("✅ 8.2 三大架构注意力掩码生成与因果阻断断言全部通过！")

if __name__ == '__main__':
    self_test()
```

### 五、面试通关口述与避坑

- **高频追问**：为什么现在的生成式大模型主流都选 Decoder-only 架构？
  - **白板口述框架**：
    1. **任务统一性**：自回归 Next-token prediction 是一种自监督的“万能任务”。无论是翻译、问答、写代码还是多步推理，本质上都可以统一为文本序列的顺流续写。
    2. **工程实现极其简洁**：Encoder-Decoder 需要维护编码器隐藏态与解码器之间的交叉注意力，显存中存在双份参数与两套复杂的通信；Decoder-only 只有一层纯粹的自注意力，易于进行 Tensor 并行与流水线分布式扩展。
    3. **KV Cache 与推理加速**：自回归生成在 Decoder-only 上拥有极为干净的状态累加机制，Prefix Cache（前缀缓存）与 PageAttention 优化能够发挥到极致。

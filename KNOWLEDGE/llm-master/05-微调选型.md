## 5.1 RAG 与 SFT：从需求和基线选方案【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 安全制度经常更新且需要引用时，先测试检索和来源追溯；如果回答格式或领域术语仍不稳定，可评估 SFT/LoRA。方案应在同一任务集比较，而不是凭“用了微调”判断更好。

### 概念与数据流

| 五要素 | 方案选型与评估 |
| --- | --- |
| 输入 | 任务集、可获得知识与标注、质量目标、资源约束，以及各方案的逐任务评测结果。 |
| 做什么 | 按统一口径比较任务质量、证据合格率、时延和成本；分析错误类型与维护代价。 |
| 输出 | 带证据的选型记录、暂不满足项及后续实验计划。 |
| 哪里出错 | 不同任务集比较、标签不独立、只看均值、不计数据和维护成本、误把引用存在当忠实。 |
| 参数影响 | 数据覆盖、文档更新频率、微调样本量、检索配置和评测门槛都会影响结论。 |

RAG 把外部资料带入上下文，便于更新与引用，但受检索覆盖、上下文和来源质量限制；SFT 改变模型参数，可改善特定任务行为，也可能改变事实输出，但权重不是天然可靠、可审计的动态知识库。两者可以组合；提示词与结构化输出也应作为低成本基线。固定基座、任务和评测口径，避免将数据差异误当方案收益。

### 面试追问

【🔥 必会】动态制度与固定输出格式分别怎么处理？ 结论：动态知识先评估检索，格式先评估提示与约束。若行为仍不稳定且有合适标注数据，再试 SFT；组合方案是否更好要靠同任务评测。

【🔥 必会】微调后效果比 RAG 差怎么排查？ 结论：按错误来源分层比较。检查检索命中、训练数据覆盖和标签、数据泄漏、版本和评测口径；再分析知识正确性、格式、延迟与成本。

【⭐ 理解】微调完全不能改变模型知识吗？ 结论：能改变输出中的事实，但不保证可靠更新。对经常变化、需要明确来源的资料，单靠权重难以维护与追溯，通常需外部知识机制。

### 故障模式与排障

- 方案比较结果不可信：核对任务 ID、样本、标注口径和基座版本；使用同一冻结测试集并保留逐任务结果。

- 格式提升但事实仍错：分别检查任务成功与证据支持；补充检索和来源校验，不把格式通过率当正确率。

- 离线收益上线消失：检查真实问题分布、文档更新和延迟成本；补充难例及线上监测，必要时回滚基线。

### 工程 trick 与坑

- 比较成本时考虑模型调用、检索、标注训练、部署和维护；下面的成本和 P95 只是外部输入示意，不在代码内计算。

- 以下两道虚构任务均要求证据，evidence_ok 假定来自独立标注；两个样本不足以支撑生产决策。

- 通用评测集构建和线上护栏见[系统设计与评测](横切-系统设计与评测.md)专题。

### Toy code：同任务集对比两个方案

运行前提：Python 3.10+，标准库。输入为虚构标注和假设的成本、P95，不连接模型也不自动选择最佳方案。

```python
"""在同一虚构任务集上对比方案；不自动替代业务选型。"""
from dataclasses import dataclass
from math import isfinite


@dataclass(frozen=True)
class Score:
    """一条任务由独立评测给出的成功和证据合格标记。"""
    task_id: str
    success: bool
    evidence_ok: bool


@dataclass(frozen=True)
class Candidate:
    """一个方案的任务分数、平均成本和 P95 延迟。"""
    name: str
    scores: tuple[Score, ...]
    avg_cost: float
    p95_seconds: float


def compare(candidates: list[Candidate]) -> list[dict[str, float | str | int]]:
    """检查任务集一致后分别报告成功率和证据合格率。"""
    if not candidates:
        raise ValueError('至少提供一个候选方案')
    expected: set[str] | None = None
    names: set[str] = set()
    rows: list[dict[str, float | str | int]] = []
    for candidate in candidates:
        if not candidate.name.strip() or candidate.name in names or not candidate.scores:
            raise ValueError('方案名称必须唯一且任务集非空')
        names.add(candidate.name)
        if not all(isfinite(v) and v >= 0 for v in (candidate.avg_cost, candidate.p95_seconds)):
            raise ValueError('成本和延迟必须为非负有限数')
        ids = [item.task_id for item in candidate.scores]
        if any(not task_id.strip() for task_id in ids) or len(ids) != len(set(ids)):
            raise ValueError('任务 ID 必须唯一且非空')
        if any(not isinstance(v, bool) for item in candidate.scores for v in (item.success, item.evidence_ok)):
            raise ValueError('任务标记必须是布尔值')
        if expected is None:
            expected = set(ids)
        elif set(ids) != expected:
            raise ValueError('对比方案必须使用相同任务集')
        count = len(ids)
        rows.append({'name': candidate.name, 'tasks': count,
                     'success_rate': sum(item.success for item in candidate.scores) / count,
                     'evidence_rate': sum(item.evidence_ok for item in candidate.scores) / count,
                     'avg_cost': candidate.avg_cost, 'p95_seconds': candidate.p95_seconds})
    assert all(row['tasks'] == len(expected or ()) for row in rows)
    return rows


def main() -> None:
    """检查同任务对比、重复 ID、缺失任务和空输入。"""
    rag = Candidate('RAG 基线', (Score('a', True, True), Score('b', False, True)), 0.01, 2.0)
    sft = Candidate('适配方案', (Score('a', True, True), Score('b', True, False)), 0.02, 1.2)
    rows = compare([rag, sft])
    assert rows[0]['success_rate'] == 0.5 and rows[1]['evidence_rate'] == 0.5
    for bad in ([], [rag, Candidate('不匹配', (Score('x', True, True),), 0, 1)],
                [Candidate('重复', (Score('a', True, True), Score('a', True, True)), 0, 1)]):
        try:
            compare(bad)
        except ValueError:
            pass
        else:
            raise AssertionError('非法比较数据必须拒绝')
    print('虚构方案对比:', rows)
    print('两条任务不足以选择生产方案；标记与耗时均需真实测得。')


if __name__ == '__main__':
    main()

```

逐段理解。 Score 保存逐任务标注；Candidate 保存方案与资源数据；compare 校验任务集、标记及数值，再分别统计成功率和证据合格率；自检覆盖缺任务和重复 ID。

### 这段代码怎么在面试里讲

- 不变量：每个方案任务 ID 相同且唯一，标注为布尔值；成功率和证据合格率分别按任务数计算。

- 关键过程：先检查样本对齐，再计算任务级指标并保留外部测得的成本与 P95。

- 边界与坑：这不是自动评判语义或自动选型；虚构的少量数据不代表线上表现，P95 需要足够请求级数据。

### 本节收尾：费曼自述与闪卡

费曼自述： 选方案先明确任务，再在相同数据上比较质量、证据和资源。RAG 便于引入更新资料，SFT 调整行为，两者可以组合。

- 问：微调能改变模型事实输出吗？答：可以，但不能保证动态、可靠、可追溯。

- 问：两个方案能在不同测试集比较吗？答：不能直接归因，应先对齐样本与口径。

- 问：格式正确就说明事实正确吗？答：不说明，需单独核验证据和结论。

- 问：方案比较应记录哪些成本？答：推理、检索、标注、训练和维护等相关成本。

## 5.2 SFT 与偏好优化：目标、标签和边界【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 对安全制度问答构造“提示→参考回答”，SFT 通过预测目标 token 学习行为；如果有同一提示下的优选和劣选回答，还可评估 DPO 等偏好优化。训练前先检查标签、数据质量和划分。

### 概念与数据流

| 五要素 | 仅监督回答的 decoder-only SFT |
| --- | --- |
| 输入 | 分词后的提示、回答及结束符；按批次填充的 token 与注意力掩码。 |
| 做什么 | 用提示和此前回答预测下一个 token；只在配置为监督的位置计算交叉熵。 |
| 输出 | 标量训练 loss、梯度及后续模型参数或适配器。 |
| 哪里出错 | 提示和 padding 被误监督、结束符被误掩码、标签移位两次、数据泄漏或参考答案错误。 |
| 参数影响 | 模板、最大长度、loss 监督范围、学习率和数据分布会影响训练行为与评测结果。 |

SFT 用参考回答训练；偏好数据通常是同一提示对应 chosen 与 rejected，DPO 等方法利用这些配对及参考策略进行偏好优化，不等于“无须标注”或“保证事实正确”。本节聚焦 SFT 标签，未实现 DPO 训练。训练输入包含提示不等于必须对提示计算 loss：是否监督提示由训练目标决定，下例只监督回答。

### 面试追问

【🔥 必会】为什么 padding 的 label 设为 -100？ 结论：让忽略索引的位置不参与 loss。注意力掩码控制注意力可见性，loss 掩码控制监督位置，两者作用不同。

【🔥 必会】训练 loss 正常但模型总复述提示，怎么排查？ 结论：先抽样检查模板和标签。解码一批 token，逐位置核对提示、回答、结束符及 -100；再检查截断和训练数据分布。

【🔥 必会】DPO 与 SFT 的数据有什么区别？ 结论：SFT 常用参考回答，DPO 常用偏好对。偏好对要保证同一提示、可解释标准和标注质量；实际效果仍需与基线在独立任务集比较。

【⭐ 理解】pad 与 EOS 使用同一个 ID 有何风险？ 结论：不能仅凭 token ID 判断 padding。应保留真实长度或 attention mask，避免把真实结束符的监督也全部抹掉。

### 故障模式与排障

- loss 为 NaN 或没有梯度：检查移位后有效标签数量、logits 与 loss 是否有限；拒绝全掩码样本并检查学习率。

- 模型不停止或结束符学习差：解码样本并核对真实 EOS 与 padding 的标签；按位置和 attention mask 构造监督，而不是盲目按 token 值屏蔽。

- 线下提升、真实任务退化：检查训练/验证是否同源泄漏，按场景切片对比基线；补充难例并追踪泛化。

### 工程 trick 与坑

- 下例手动用 logits[:, :-1] 预测 labels[:, 1:]；如果使用的模型内部已经移位，不要再次移位。具体模型接口见 [GPT-2 官方文档](https://huggingface.co/docs/transformers/model_doc/gpt2)。

- chat template、特殊 token、截断与多轮监督规则随模型和任务而异；本例只处理单轮、右侧 padding。

- 数据划分和标注须与模型实验一起版本化；企业数据权限与隐私处理由实际场景决定。

### Toy code：SFT 标签与因果 loss

运行前提：Python 3.10+、PyTorch，CPU 可运行；随机 logits 和虚构 token 不代表实际模型训练。下例只监督回答，且每条回答已包含所需结束符。

```python
"""构造 decoder-only SFT 批次；监督回答，不监督提示和 padding。"""
from dataclasses import dataclass
import torch
from torch import Tensor
from torch.nn import functional as F


@dataclass(frozen=True)
class Example:
    """事先已分词的提示及回答；回答应包含任务所需结束符。"""
    prompt: tuple[int, ...]
    answer: tuple[int, ...]


def collate(examples: list[Example], pad_id: int, vocab: int) -> tuple[Tensor, Tensor, Tensor]:
    """返回 input_ids、attention_mask、labels，形状均为 (B,T)。"""
    if not examples or vocab <= 1 or not 0 <= pad_id < vocab:
        raise ValueError('批次、词表或 pad ID 非法')
    for ex in examples:
        if not ex.prompt or not ex.answer:
            raise ValueError('提示和回答均不能为空')
        if any(isinstance(t, bool) or not isinstance(t, int) or not 0 <= t < vocab
               for t in ex.prompt + ex.answer):
            raise ValueError('token ID 越界或类型错误')
    length = max(len(ex.prompt) + len(ex.answer) for ex in examples)
    ids = torch.full((len(examples), length), pad_id, dtype=torch.long)
    mask = torch.zeros_like(ids)
    labels = torch.full_like(ids, -100)
    for row, ex in enumerate(examples):
        combined = ex.prompt + ex.answer
        n = len(combined)
        ids[row, :n] = torch.tensor(combined)
        mask[row, :n] = 1
        labels[row, len(ex.prompt):n] = torch.tensor(ex.answer)
    assert ids.shape == labels.shape == mask.shape
    assert torch.all(labels[mask == 0] == -100)
    return ids, mask, labels


def causal_loss(logits: Tensor, labels: Tensor) -> Tensor:
    """用位置 t 的 logits 预测位置 t+1 的标签，忽略 -100。"""
    if logits.ndim != 3 or labels.shape != logits.shape[:2] or logits.shape[1] < 2:
        raise ValueError('logits 和标签形状不匹配')
    shifted_labels = labels[:, 1:].contiguous()
    if not torch.any(shifted_labels != -100):
        raise ValueError('没有有效的预测目标')
    shifted_logits = logits[:, :-1, :].contiguous()
    return F.cross_entropy(shifted_logits.view(-1, logits.shape[-1]),
                           shifted_labels.view(-1), ignore_index=-100)


def main() -> None:
    """检查掩码、pad 与结束符同 ID、移位 loss 以及非法输入。"""
    examples = [Example((1, 3), (5, 2)), Example((1,), (6, 7, 2))]
    ids, mask, labels = collate(examples, pad_id=2, vocab=10)
    assert labels.tolist() == [[-100, -100, 5, 2], [-100, 6, 7, 2]]
    assert mask.tolist() == [[1, 1, 1, 1], [1, 1, 1, 1]]
    padded_ids, padded_mask, padded_labels = collate([examples[0], Example((1,), (2,))], 2, 10)
    assert padded_ids[1, 1].item() == padded_ids[1, 2].item() == 2
    assert padded_mask[1].tolist() == [1, 1, 0, 0]
    assert padded_labels[1].tolist() == [-100, 2, -100, -100]
    torch.manual_seed(3)
    logits = torch.randn(2, 4, 10, requires_grad=True)
    loss = causal_loss(logits, labels)
    assert torch.isfinite(loss)
    loss.backward()
    assert logits.grad is not None and torch.isfinite(logits.grad).all()
    for bad in ([], [Example((), (2,))], [Example((1,), (10,))]):
        try:
            collate(bad, 2, 10)
        except ValueError:
            pass
        else:
            raise AssertionError('非法样本必须拒绝')
    print('SFT 标签掩码与因果移位自检通过，loss:', round(loss.item(), 4))


if __name__ == '__main__':
    main()

```

逐段理解。 collate 用真实长度构造 attention mask，在提示和 padding 位置设置 -100；causal_loss 明确移位后使用 PyTorch 交叉熵；自检覆盖 pad 与 EOS 同 ID、非法样本和反向传播。

### 这段代码怎么在面试里讲

- 不变量：input_ids、attention_mask、labels 同为 [B,T]；提示和 padding 不监督，真实回答及其 EOS 保留标签。

- 关键过程：按长度填充而非按 token 值推断 padding，再用位置 t 的预测计算位置 t+1 的监督。

- 边界与坑：真实 chat template 和多轮掩码因模型而异；不能让模型内部移位和手动移位叠加，也不能让有效标签全部消失。

### 本节收尾：费曼自述与闪卡

费曼自述： SFT 用参考输出训练下一个 token，监督范围由目标决定；padding 和真实结束符即使共用 ID，也要依据真实位置区分。

- 问：attention mask 与 loss mask 一样吗？答：不一样，前者控制可见性，后者决定哪些位置计入 loss。

- 问：pad 和 EOS 共用 ID 时如何保留真实 EOS？答：按真实长度或 attention mask 区分位置。

- 问：模型内部已移位时还要手动移位吗？答：不要；先核对具体模型接口。

- 问：DPO 不需要偏好数据吗？答：需要合适的偏好对或等价监督，并需评估标注质量。

## 5.3 LoRA / QLoRA：低秩注入、梯度与选型【🔥 必会】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 给线性层添加可训练的低秩增量，冻结基座，验证初始化、反向传播和合并；再用 PEFT 在随机微型模型上验证真实库接口。二者都不是实际业务模型效果。

### 概念与数据流

| 五要素 | LoRA 线性层 |
| --- | --- |
| 输入 | X[..., d_in]、冻结权重 W[d_out, d_in]，可选偏置；低秩矩阵 A[r,d_in] 和 B[d_out,r]。 |
| 做什么 | 计算 X Wᵀ + (alpha/r) X Aᵀ Bᵀ，仅更新适配器参数；示例同时冻结基座偏置。 |
| 输出 | [..., d_out]，可选把增量合并到权重副本。 |
| 哪里出错 | 形状方向错误、未冻结基座、目标模块选错、标注或梯度异常、合并精度不一致。 |
| 参数影响 | r 决定增量秩上界及参数量；alpha/r 影响增量缩放；模块覆盖范围影响容量、成本和行为。 |

对单个线性权重，原矩阵参数量为 d_out*d_in，LoRA 新增 r*(d_in+d_out)；是否更省取决于 r 和注入范围。参数省不等于训练总显存同比例减少：激活、基座权重和其他状态仍占内存。示例选择 B=0，初始输出等于基座；首轮对 A 的梯度为零，而 B 可先更新，随后 A 才可获得非零梯度，不能误判首轮 A 零梯度必然有 bug。

QLoRA 的常见做法是冻结低位量化的基座，通过适配器训练；计算时仍需要相应计算精度和量化实现。量化配置、硬件、计算 dtype 与库版本要一并验证，本节不声称已实测 QLoRA 或量化合并效果。LoRA 可与 RAG 配合，不能保证记住最新且可追溯的业务知识。

### 面试追问

【🔥 必会】LoRA 为什么更省可训练参数？ 结论：增量由两个小矩阵表示。单层新增 r*(d_in+d_out)，冻结的基座不需要训练梯度与对应优化器状态；实际显存还受激活和权重影响。

【🔥 必会】微调后效果没变怎么定位？ 结论：先查数据、目标模块和梯度。检查训练标签掩码、适配器是否注入到预期层、可训练参数和梯度，再用同一评测集比较基线；留意零初始化的首步梯度特性。

【🔥 必会】rank 越大越好吗？ 结论：不是，需基于验证集权衡。更大 rank 通常增加参数和显存，也可能过拟合；固定数据、目标模块和训练预算做小范围对照。

【⭐ 理解】QLoRA 和 LoRA 主要区别？ 结论：QLoRA 常结合量化冻结基座。适配器仍可训练，低位权重的存储与计算依赖具体实现；量化误差和硬件支持需要实测。

### 故障模式与排障

- 没有可训练参数或目标层不匹配：打印模块名、requires_grad 和适配器参数数量；核对目标架构与 target_modules，再跑小批次梯度检查。

- 首轮 A 梯度为零：检查 B 是否按预期初始化为零；观察 B 是否获得梯度及更新后 A 的梯度，不要只凭第一步下结论。

- 合并前后输出差异大或加载异常：在 eval() 和相同 dtype 下比较 logits，核对基座版本、缩放及适配器；量化合并须单独测精度与兼容性。

### 工程 trick 与坑

- 注入目标层名称因模型而异；GPT-2 的 c_attn 使用 Conv1D 权重布局，PEFT 示例明确指定 fan_in_fan_out=True，不能照搬到所有架构。

- 保存适配器时同时记录基座版本、tokenizer、配置和训练数据版本；部署和回滚时核对组合。

- r、alpha、目标模块、dropout 都应在固定数据与预算下对照；过早归因于单个参数会误导结论。

### Toy code 一：从零手写线性层 LoRA

运行前提：Python 3.10+、PyTorch；CPU 可运行。示例为随机张量，只验证数学和梯度，不构成业务训练。为便于练习，示例主动限制 r <= min(d_in,d_out)，这不是所有库的强制约束。构造时会冻结传入的 base。

```python
"""从零实现线性层 LoRA；只演示低秩适配，不代表模型微调效果。"""
import math
import torch
from torch import Tensor, nn


class LoRALinear(nn.Module):
    """冻结基座线性层，训练缩放后的低秩增量。"""
    def __init__(self, base: nn.Linear, rank: int, alpha: float) -> None:
        super().__init__()
        if isinstance(rank, bool) or not isinstance(rank, int) or not 1 <= rank <= min(base.in_features, base.out_features):
            raise ValueError('rank 必须位于 1 与较小维度之间')
        if not math.isfinite(alpha) or alpha <= 0:
            raise ValueError('alpha 必须为正有限数')
        if not base.weight.is_floating_point():
            raise ValueError('此示例只支持浮点基座')
        self.base = base
        self.base.requires_grad_(False)
        self.rank = rank
        self.scale = alpha / rank
        self.a = nn.Parameter(base.weight.new_empty(rank, base.in_features))
        self.b = nn.Parameter(base.weight.new_zeros(base.out_features, rank))
        nn.init.kaiming_uniform_(self.a, a=math.sqrt(5))

    def forward(self, x: Tensor) -> Tensor:
        """输入 (..., in_features)，输出 (..., out_features)。"""
        if x.ndim < 1 or x.shape[-1] != self.base.in_features:
            raise ValueError('输入最后一维与基座不一致')
        if x.device != self.base.weight.device or x.dtype != self.base.weight.dtype:
            raise ValueError('输入与基座设备和 dtype 必须一致')
        result = self.base(x) + ((x @ self.a.T) @ self.b.T) * self.scale
        assert result.shape == (*x.shape[:-1], self.base.out_features)
        return result

    def merged_weight(self) -> Tensor:
        """返回合并后的权重副本，不修改训练中的基座。"""
        return self.base.weight.detach() + (self.b @ self.a).detach() * self.scale


def main() -> None:
    """验证零增量、冻结、梯度、参数量、合并与形状异常。"""
    torch.manual_seed(7)
    base = nn.Linear(8, 6)
    layer = LoRALinear(base, rank=2, alpha=4.0)
    x = torch.randn(3, 4, 8)
    reference = base(x).detach().clone()
    assert torch.allclose(layer(x), reference)
    assert sum(p.numel() for p in layer.parameters() if p.requires_grad) == 2 * (8 + 6)
    before = base.weight.detach().clone()
    optimizer = torch.optim.SGD([layer.a, layer.b], lr=0.1)
    optimizer.zero_grad(set_to_none=True)
    loss = (layer(x) - torch.ones(3, 4, 6)).square().mean()
    assert torch.isfinite(loss)
    loss.backward()
    assert base.weight.grad is None and layer.b.grad is not None
    assert layer.b.grad.abs().sum().item() > 0
    assert layer.a.grad is not None and torch.count_nonzero(layer.a.grad).item() == 0
    optimizer.step()
    assert torch.equal(base.weight, before) and not torch.allclose(layer(x), reference)
    optimizer.zero_grad(set_to_none=True)
    (layer(x) - 1).square().mean().backward()
    assert layer.a.grad is not None and layer.a.grad.abs().sum().item() > 0
    merged = nn.functional.linear(x, layer.merged_weight(), base.bias)
    assert torch.allclose(merged, layer(x), atol=1e-6, rtol=1e-5)
    try:
        layer(torch.randn(3, 7))
    except ValueError:
        pass
    else:
        raise AssertionError('错误输入形状必须拒绝')
    print('LoRA 冻结、梯度和合并自检通过；可训练参数:', 2 * (8 + 6))


if __name__ == '__main__':
    main()

```

逐段理解。 A 随机、B 为零，使初始增量为零；前向按两个矩阵依次计算；第一次更新 B 后，再验证 A 梯度非零；merged_weight 不改变训练中的基座。

这段代码怎么在面试里讲： ① 输入最后一维是 d_in，输出最后一维是 d_out，新增参数数为 r*(d_in+d_out)；② 冻结基座后叠加缩放低秩增量，反向传播只训练 A/B；③ 说明零初始化的首步梯度、形状/dtype 和合并误差，量化基座不能直接套用此实现。

排障： 输出初始不等于基座时检查 B 初始化与缩放；基座出现梯度时检查冻结和优化器；合并不一致时检查矩阵方向、dtype 和容差。

### Toy code 二：PEFT 库注入与合并

运行前提：Python 3.11、PyTorch；本次测试 transformers==4.57.1、peft==0.17.1、accelerate==1.10.1。在隔离环境安装兼容依赖，示例随机创建 GPT-2、无需下载模型和网络。随机 token 仅用于验证计算，未构造真实 SFT 标签。库版本可能影响 API 和行为。

```python
"""用 PEFT 向随机微型 GPT-2 注入 LoRA，仅验证调用与梯度。"""
import torch
from peft import LoraConfig, TaskType, get_peft_model
from transformers import GPT2Config, GPT2LMHeadModel


def validate_tokens(ids: torch.Tensor, vocab_size: int, max_len: int) -> None:
    """避免空序列、越界 token 和超出位置容量。"""
    if ids.ndim != 2 or ids.dtype != torch.long or ids.shape[0] == 0:
        raise ValueError('token 必须是非空二维 long 张量')
    if not 2 <= ids.shape[1] <= max_len:
        raise ValueError('序列长度必须在 2 和位置容量之间')
    if int(ids.min()) < 0 or int(ids.max()) >= vocab_size:
        raise ValueError('token ID 超出词表')


def main() -> None:
    """构建随机模型、注入适配器、完成一次反向传播。"""
    torch.manual_seed(11)
    config = GPT2Config(vocab_size=32, n_positions=16, n_ctx=16,
                        n_embd=16, n_layer=2, n_head=2)
    base = GPT2LMHeadModel(config)
    lora_config = LoraConfig(r=2, lora_alpha=4, lora_dropout=0.0,
                             target_modules=['c_attn'], fan_in_fan_out=True,
                             task_type=TaskType.CAUSAL_LM)
    model = get_peft_model(base, lora_config)
    names = [name for name, p in model.named_parameters() if p.requires_grad]
    assert names and all('lora_' in name for name in names)
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
    total = sum(p.numel() for p in model.parameters())
    assert 0 < trainable < total
    ids = torch.tensor([[1, 4, 9, 2], [1, 5, 7, 2]], dtype=torch.long)
    validate_tokens(ids, config.vocab_size, config.n_positions)
    for invalid in (torch.tensor([[32, 1]]), torch.tensor([[1]])):
        try:
            validate_tokens(invalid, config.vocab_size, config.n_positions)
        except ValueError:
            pass
        else:
            raise AssertionError('非法 token 或长度必须拒绝')
    output = model(input_ids=ids, attention_mask=torch.ones_like(ids), labels=ids)
    assert output.loss is not None and torch.isfinite(output.loss)
    output.loss.backward()
    gradients = [p.grad for name, p in model.named_parameters()
                 if p.requires_grad and 'lora_B' in name]
    assert gradients and any(g is not None and g.abs().sum().item() > 0 for g in gradients)
    assert all(p.grad is None for p in model.parameters() if not p.requires_grad)
    optimizer = torch.optim.SGD((p for p in model.parameters() if p.requires_grad), lr=0.1)
    optimizer.step()
    model.eval()
    with torch.no_grad():
        before = model(input_ids=ids).logits
        merged = model.merge_and_unload()
        after = merged(input_ids=ids).logits
    assert before.shape == (2, 4, config.vocab_size)
    assert torch.allclose(before, after, atol=1e-5, rtol=1e-5)
    print(f'PEFT 注入和梯度自检通过: {trainable}/{total} 可训练参数')
    print('随机模型和虚构 token：没有训练真实任务或验证模型效果。')


if __name__ == '__main__':
    main()

```

逐段理解。 构造随机小模型后用 LoraConfig 指定目标和缩放；检查仅 LoRA 可训练，验证 token、loss 和梯度；一步更新后在 eval 模式比较合并前后 logits。

这段代码怎么在面试里讲： ① 输入是 [batch, sequence] 的合法 token，输出 logits 为 [batch, sequence, vocab]；② 库负责识别并替换目标层、冻结基座及合并适配器；③ 核对实际模块名和权重布局，随机模型不证明任务效果，真实训练还需数据、评测与版本管理。

排障： 找不到目标模块时打印模型结构；无梯度时核查 trainable 列表与 loss mask；合并后差异时固定 eval、dtype 和模型/适配器版本。

手写与调库怎么选。 手写单层用于理解权重、梯度和形状；真实模型训练优先使用 PEFT 等成熟库，并以小批次确认注入、梯度、保存与加载。不能据此宣称手写实现覆盖量化、分布式或所有模型结构。

费曼自述： LoRA 冻结基座，用两个小矩阵产生受缩放的权重增量；参数、梯度和合并都要验证。QLoRA 还涉及基座量化，真实效果由数据和评测决定。

### Toy code：检查来源组跨集

运行前提：Python 3.10+，标准库，不读取公司数据。来源组必须由上游可靠地构造。

```python
"""检查训练、验证和测试划分是否共享同一来源组。"""
from dataclasses import dataclass
from itertools import combinations


@dataclass(frozen=True)
class Row:
    """一条样本的匿名 ID、来源组和划分。"""
    sample_id: str
    group_id: str
    split: str


def audit_groups(rows: list[Row]) -> dict[str, object]:
    """检查唯一 ID 和组跨划分泄漏；不检查近重复文本。"""
    if not rows:
        raise ValueError('样本不能为空')
    allowed = {'train', 'validation', 'test'}
    groups: dict[str, set[str]] = {split: set() for split in allowed}
    ids: set[str] = set()
    counts = {split: 0 for split in allowed}
    for row in rows:
        if not row.sample_id.strip() or row.sample_id in ids or not row.group_id.strip():
            raise ValueError('样本 ID 须唯一，来源组须非空')
        if row.split not in allowed:
            raise ValueError('未知数据划分')
        ids.add(row.sample_id)
        groups[row.split].add(row.group_id)
        counts[row.split] += 1
    overlaps: dict[str, list[str]] = {}
    for left, right in combinations(sorted(allowed), 2):
        shared = sorted(groups[left] & groups[right])
        if shared:
            overlaps[f'{left}/{right}'] = shared
    assert sum(counts.values()) == len(rows)
    return {'counts': counts, 'overlapping_groups': overlaps,
            'has_overlap': bool(overlaps)}


def main() -> None:
    """验证来源组跨集、无泄漏、重复 ID 和非法划分。"""
    safe = [Row('a', 'doc1', 'train'), Row('b', 'doc2', 'validation'),
            Row('c', 'doc3', 'test')]
    assert not audit_groups(safe)['has_overlap']
    leaky = safe + [Row('d', 'doc1', 'test')]
    report = audit_groups(leaky)
    assert report['has_overlap'] and report['overlapping_groups'] == {'test/train': ['doc1']}
    for invalid in ([], [safe[0], safe[0]], [Row('x', 'doc', 'holdout')]):
        try:
            audit_groups(invalid)
        except ValueError:
            pass
        else:
            raise AssertionError('不合法输入必须拒绝')
    print('来源组泄漏自检通过:', report)
    print('该检查不能发现不同 group ID 下的相同或近似内容。')


if __name__ == '__main__':
    main()

```

逐段理解。 Row 记录匿名样本与来源；audit_groups 统计每个划分的来源集合并比较交集；自检覆盖同组跨集、唯一 ID 和非法划分。

### 这段代码怎么在面试里讲

- 不变量：样本 ID 唯一，来源组非空，划分属于指定集合；汇总样本数与输入一致。

- 关键过程：按划分收集来源组，再两两求交集，发现重叠则报告。

- 边界与坑：是否构成泄漏取决于业务任务与来源定义；本例不能发现不同 ID 的重复内容，也不能代替时间切分检查。

### 本节收尾：费曼自述与闪卡

费曼自述： 微调收益要和固定基线比较，并用独立、贴近目标分布的数据评测。来源分组能发现一种泄漏，但还需检查近重复与时间边界。

- 问：为什么同一文档切片不能随意跨训练和验证集？答：可能让验证看到训练来源，夸大泛化。

- 问：组 ID 不重叠就一定没有泄漏吗？答：不一定，副本或近重复可能有不同 ID。

- 问：训练 loss 下降是否证明业务收益？答：不能，要用独立任务指标与基线比较。

- 问：编码贡献较少的论文怎么介绍？答：准确区分本人职责与团队工作。

## 5.5 微调面试专题：用配对结果解释收益【⭐ 理解】

〔补充自原仓库镜像〕〔本次新补，参考当前面试趋势〕

目标 + 例子。 面试官问“微调真的有用吗”，先说明目标和基线，再对同一组任务逐条比较，报告改善和退化；不能只展示一两个成功例子。

### 概念与数据流

| 五要素 | 配对任务比较 |
| --- | --- |
| 输入 | 基线和微调版本在同一任务集的独立二元评测结果。 |
| 做什么 | 按任务 ID 配对，计算各自通过率、差值，以及改善和退化任务数。 |
| 输出 | 样本量、两版通过率、变化量和逐任务变化方向的汇总。 |
| 哪里出错 | 任务不一致、评测规则变动、测试集调参泄漏、只看总体而忽视切片。 |
| 参数影响 | 样本数量、任务分布、标注一致性、随机生成和评测门槛影响比较可信度。 |

SFT 适合用高质量参考答案改善目标行为，DPO 利用偏好数据调整偏好，是否比提示词或 RAG 有收益需通过具体任务验证；PPO 等强化学习方法按需求选读，不应当作每个应用项目必选步骤。独立测试集之外，还需关注训练和部署成本及负面回归。

### 面试追问

【🔥 必会】微调提升 5 个百分点说明一定有效吗？ 结论：不一定，要看样本和不确定性。先核对评测集与标注，再报告样本量、配对改善与退化、分场景结果及必要的不确定性分析。

【🔥 必会】整体指标涨了但用户抱怨变多，怎么查？ 结论：按任务和用户场景切片。检查退化样本、线上分布、失败成本和潜在数据泄漏；必要时回滚并补充回归。

【⭐ 理解】为什么需要基线？ 结论：基线给收益提供参照。固定模型、数据与评测条件，比较提示、检索或微调方案，才能更可靠地归因。

### 故障模式与排障

- 通过率变化无法解释：保留任务级配对结果，分别查看改善和退化；定位各类别并抽查标签。

- 结果不可比：检查两版任务 ID、标注和版本；使用同一冻结测试集，不能简单比较不同样本的均值。

- 小样本结论不稳定：核对样本数和分布，补充独立样本与重复实验；必要时报告合适的区间而非只报点估计。

### 工程 trick 与坑

- 下例只计算二元通过率变化，不计算置信区间或统计显著性；三条虚构任务不能支持业务结论。

- 配对 ID 对齐不等于任务完全一致；评测提示、参考答案、标注者与版本也应固定。

- 通用评测系统和发布门禁见[系统设计与评测](横切-系统设计与评测.md)专题；数据分组见 5.4。

### Toy code：按任务配对比较

运行前提：Python 3.10+，标准库；结果均为虚构人工标注。

```python
"""按任务配对对比基线和微调版本的二元评测结果。"""
from dataclasses import dataclass


@dataclass(frozen=True)
class Evaluation:
    """一条已独立标注的任务结果。"""
    task_id: str
    passed: bool


def compare_paired(baseline: list[Evaluation], tuned: list[Evaluation]) -> dict[str, float | int]:
    """对齐任务并返回通过率、差值、改善数与退化数。"""
    def index(items: list[Evaluation]) -> dict[str, bool]:
        if not items:
            raise ValueError('评测结果不能为空')
        result: dict[str, bool] = {}
        for item in items:
            if not item.task_id.strip() or item.task_id in result:
                raise ValueError('任务 ID 非空且不能重复')
            if not isinstance(item.passed, bool):
                raise ValueError('通过状态必须为布尔值')
            result[item.task_id] = item.passed
        return result

    old, new = index(baseline), index(tuned)
    if set(old) != set(new):
        raise ValueError('两组结果必须来自同一任务集')
    count = len(old)
    gains = sum(not old[key] and new[key] for key in old)
    regressions = sum(old[key] and not new[key] for key in old)
    base_rate = sum(old.values()) / count
    tuned_rate = sum(new.values()) / count
    assert abs((tuned_rate - base_rate) - (gains - regressions) / count) < 1e-12
    return {'tasks': count, 'baseline_rate': base_rate, 'tuned_rate': tuned_rate,
            'delta': tuned_rate - base_rate, 'gains': gains, 'regressions': regressions}


def main() -> None:
    """检查配对改善、退化、任务错位和重复 ID。"""
    base = [Evaluation('a', True), Evaluation('b', False), Evaluation('c', False)]
    tuned = [Evaluation('c', True), Evaluation('a', False), Evaluation('b', True)]
    report = compare_paired(base, tuned)
    assert report['gains'] == 2 and report['regressions'] == 1
    assert abs(report['delta'] - 1 / 3) < 1e-12
    for old, new in (([], []), (base, [Evaluation('x', True)]), (base, base + base[:1])):
        try:
            compare_paired(old, new)
        except ValueError:
            pass
        else:
            raise AssertionError('错误评测结果必须拒绝')
    print('虚构配对评测自检通过:', report)
    print('三个样本不能支持生产收益或统计显著性的结论。')


if __name__ == '__main__':
    main()

```

逐段理解。 Evaluation 表示任务结果；compare_paired 校验唯一 ID 并对齐两版，分别计算改善和退化；自检覆盖顺序不同、任务缺失及重复记录。

### 这段代码怎么在面试里讲

- 不变量：两个版本覆盖完全相同且唯一的任务 ID；通过状态为布尔值。

- 关键过程：按 ID 配对，计算各版通过率，并区分由失败变成功与由成功变失败。

- 边界与坑：汇总不能证明因果或统计显著性；还应查看任务切片、标注质量和成本。

### 本节收尾：费曼自述与闪卡

费曼自述： 微调收益要基于同一测试集逐任务比较，既看提升也看退化；样本量、标注和上线成本决定结论是否可信。

- 问：平均通过率提升后还要看什么？答：退化样本、任务切片、样本量和成本。

- 问：两版样本顺序不同能配对吗？答：可以，只要任务 ID 和评测条件一致。

- 问：三个样本能证明显著提升吗？答：不能，应补充足够独立样本并分析不确定性。

- 问：PPO 是应用微调项目必选项吗？答：不是，按任务和资源需要选型。

## 5.6 微调数据：对话格式、去重与质量检查【🔥 必会】

〔本次新补，参考当前面试趋势〕

目标 + 例子。 把虚构安全制度问答整理为可训练对话时，先检查角色顺序、空内容和重复样本，再结合来源核验和人工抽样判断回答质量。

### 概念与数据流

| 五要素 | 文本 SFT 数据检查 |
| --- | --- |
| 输入 | 样本 ID 与消息列表；示例限定可选 system 和成对 user/assistant 文本。 |
| 做什么 | 校验 ID、角色顺序和内容；按原始消息内容计算指纹并标记完全重复。 |
| 输出 | 样本数量与疑似重复的匿名 ID 组；非法格式抛出错误。 |
| 哪里出错 | 模板角色不匹配、回答为空、重复数据跨集、事实错误、近重复和隐私遗漏。 |
| 参数影响 | 格式约束和去重标准过严可能误删有价值样本，过松可能放入错误或重复内容。 |

训练数据还要检查来源授权、标签正确性、场景覆盖、长度和独立划分。精确重复只表示字符串完全相同；近重复、来源不同版本和事实错误需要其他检查或人工审核。工具调用、多模态和不同模型的模板另有格式，本例不应直接套用。

### 面试追问

【🔥 必会】SFT 数据清洗先做什么？ 结论：先明确目标与数据来源，再检查格式和质量。验证角色、内容和模板，做重复及来源检查，按任务和来源划分训练/验证/测试并抽样审核。

【🔥 必会】loss 下降但模型学到错误制度怎么排查？ 结论：回溯对应训练样本和来源。核对制度版本、参考答案、标注规则和采样权重；修正数据后在独立集复测。

【⭐ 理解】精确去重就够了吗？ 结论：不够。近重复、改写、同源不同版本和敏感信息仍可能存在；去重策略必须结合任务并避免误删。

### 故障模式与排障

- 模型回答带错误角色或模板标记：检查原始消息顺序及 tokenizer 的 chat template；按目标模型规范重新构造并抽样解码。

- 训练集被大量重复样本主导：查看精确和近重复的分布及来源；先标记、人工审查，再按业务规则处理，而不是盲删。

- 高分但知识过期：按样本回查来源版本和标注时间；更新或剔除过期样本，并在时间切分的独立集验证。

### 工程 trick 与坑

- 本例只标记消息角色与内容完全相同的记录，不归一化空格，不检查近重复、隐私或事实正确性。

- 真实数据可包含多模态、工具调用和多轮不同模板，必须按具体模型和目标定义允许格式；不要把本例的交替规则当通用规范。

- 来源组泄漏检查见 5.4；监督位置和 EOS 处理见 5.2。

### Toy code：简化文本对话检查

运行前提：Python 3.10+，标准库；仅处理内存中的虚构数据，不自动删除样本。

```python
"""检查简化文本对话格式并标记精确重复，不自动丢弃样本。"""
from dataclasses import dataclass
import hashlib
import json


@dataclass(frozen=True)
class Message:
    """单条文本消息；此示例不支持工具或多模态消息。"""
    role: str
    content: str


@dataclass(frozen=True)
class Sample:
    """匿名样本 ID 与消息序列。"""
    sample_id: str
    messages: tuple[Message, ...]


def audit(samples: list[Sample]) -> dict[str, object]:
    """验证 system 可选、user/assistant 轮流配对，并报告完全重复。"""
    if not samples:
        raise ValueError('样本集不能为空')
    ids: set[str] = set()
    fingerprints: dict[str, list[str]] = {}
    for sample in samples:
        if not sample.sample_id.strip() or sample.sample_id in ids:
            raise ValueError('样本 ID 须非空且唯一')
        ids.add(sample.sample_id)
        messages = sample.messages
        if messages and messages[0].role == 'system':
            conversation = messages[1:]
        else:
            conversation = messages
        if len(conversation) < 2 or len(conversation) % 2:
            raise ValueError('必须包含完整 user/assistant 对')
        for i, msg in enumerate(messages):
            if not isinstance(msg.content, str) or not msg.content.strip():
                raise ValueError('消息内容不能为空')
        for i, msg in enumerate(conversation):
            expected = 'user' if i % 2 == 0 else 'assistant'
            if msg.role != expected:
                raise ValueError('角色必须按 user/assistant 交替')
        canonical = json.dumps([(m.role, m.content) for m in messages],
                               ensure_ascii=False, separators=(',', ':'))
        key = hashlib.sha256(canonical.encode('utf-8')).hexdigest()
        fingerprints.setdefault(key, []).append(sample.sample_id)
    duplicates = [group for group in fingerprints.values() if len(group) > 1]
    assert sum(len(group) for group in fingerprints.values()) == len(samples)
    return {'sample_count': len(samples), 'duplicate_ids': duplicates}


def main() -> None:
    """验证格式、重复、缺失回答和非法角色。"""
    dialog = (Message('user', '虚构问题'), Message('assistant', '虚构答案'))
    samples = [Sample('a', dialog), Sample('b', dialog),
               Sample('c', (Message('user', '另一问题'), Message('assistant', '另一答案')))]
    report = audit(samples)
    assert report['sample_count'] == 3 and report['duplicate_ids'] == [['a', 'b']]
    bad_sets = ([], [Sample('x', (Message('user', '问题'),))],
                [Sample('x', (Message('assistant', '回答'), Message('user', '问题')))],
                [samples[0], samples[0]])
    for bad in bad_sets:
        try:
            audit(bad)
        except ValueError:
            pass
        else:
            raise AssertionError('错误消息或重复 ID 必须拒绝')
    print('简化对话格式与精确重复自检通过:', report)
    print('格式正确不代表事实正确；未检查近重复或隐私。')


if __name__ == '__main__':
    main()

```

逐段理解。 Message 和 Sample 定义简化记录；audit 检查 ID、消息内容和角色顺序，再对完整角色/文本序列计算指纹；自检覆盖完全重复、缺回答及非法顺序。

### 这段代码怎么在面试里讲

- 不变量：样本 ID 唯一；消息可以有首个 system，之后必须是完整的 user/assistant 对且内容非空。

- 关键过程：先验证结构，再用稳定 JSON 序列化和 SHA-256 聚合同内容记录；只报告 ID，不自动删数据。

- 边界与坑：这只是特定文本模板的格式检查，不能发现近重复、隐私和事实错误；真实训练还要按模型模板处理 token 与掩码。

### 本节收尾：费曼自述与闪卡

费曼自述： 数据清洗先确保来源和格式可用，再检查重复、事实与划分。完全重复检测只是其中一步，不能自动保证标签质量。

- 问：对话格式通过是否代表答案正确？答：不代表，还要核对来源与事实。

- 问：精确重复检查能发现改写吗？答：不能，需要其他方法并控制误判。

- 问：发现重复能否一律删除？答：应结合业务和分布先审查，再决定处理策略。

- 问：这里的角色交替规则适合所有模型吗？答：不适合；工具和多模态消息需要专门模板。

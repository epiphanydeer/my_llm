## 开场疑问 + 当前解答

### 我的疑问（原话）

> 他最后是不是讲错了？他在讲猫的坐标不断接近鱼这个过程，单实际上的学习指的是wq wk wv这三个矩阵的变化对么，就是词向量进入自注意力，要乘三个矩阵，变成qkv，再去算相似度对吗

### 解答

- 若“猫不断接近鱼”被用来说明**某个向量/点可以被训练更新**，它只是一个有用但不完整的二维教学图。
- 若它被说成“真实 Transformer 训练时只移动词向量”，那就不准确：训练会更新所有可训练参数，包括词嵌入表（有时也更新）、`W_Q`、`W_K`、`W_V`，以及后面层的参数。
- 对一层自注意力，顺序是：词向量 + 位置向量 → 分别乘 `W_Q/W_K/W_V` → 得到 Q/K/V → `QKᵀ` 得分 → 缩放、softmax → 用权重加权 V。点积是“匹配程度”，并不严格等于日常说的相似度。

## 位置编码：相加为什么有用

### 先纠正配图

配图把第 1 个位置写成 `[1,1,1,1]`、第 2 个位置写成 `[2,2,2,2]`。这可以粗略演示“给每个词加上位置编号”，**不是标准的 sin/cos 位置编码**。

对于维度 `d`、位置 `pos`，原始 Transformer 的正弦位置编码为：

```text
PE(pos, 2i)   = sin(pos / 10000^(2i/d))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
```

同一位置的各维并不相同。它们是成对的 sin/cos 波，但每对使用不同频率：有的维度变化快，便于区分近距离；有的慢，便于表示长距离。

### 重要纠正：哪些是论文事实，哪些是教学直觉

- **论文事实**：原始 Transformer 人为固定了公式和频率排布。第一个 sin/cos 对波长约为 `2π`（变化快）；后续维度的波长按几何级数增长，最大到约 `10000×2π`（变化慢）。
- **论文给出的理由**：对于固定距离 `k`，`PE(pos+k)` 可以表示为 `PE(pos)` 的线性函数；作者因此假设模型容易学习相对位置。
- **论文中的实验**：作者还试验了“可训练的位置嵌入”，在其翻译任务上两者结果几乎相同；选择 sin/cos 的附加理由是可能外推到训练时未见过的更长序列。
- **不是论文直接验证的结论**："快频率维度专门负责近距离、慢频率维度专门负责远距离"。这是解释多尺度编码的常见直觉，不能说成每一维被实验测出有该固定职责。

### 四维玩具例子

```text
pos=1: [sin(1), cos(1), sin(0.01), cos(0.01)]
     ≈ [ 0.84,   0.54,      0.01,        1.00]
pos=2: [sin(2), cos(2), sin(0.02), cos(0.02)]
     ≈ [ 0.91,  -0.42,      0.02,        1.00]
```

模型把 token 嵌入 `e` 与同维的位置向量 `p` 逐项相加，得到 `x=e+p`。这不是说某一维永远是“词义”、另一维永远是“位置”；信息会混合。之后的矩阵能学习从混合坐标中利用位置。

## 自注意力的输入形状（待展开）

```text
“我 爱 你”
  ↓
X = [x_我; x_爱; x_你]，形状为 3 × d
  ↓
Q=XW_Q，K=XW_K，V=XW_V
```

### “第一维”并没有固定的语义职责

先加位置时，`x_j=e_j+p_j`；但第 `r` 个 Q 输出不是只看第 `r` 个输入维度：

```text
q_r = Σ_j (e_j + p_j) · W_Q[j, r]
```

即 Q 的第 `r` 个数会混合所有词嵌入维度、所有位置维度。`W_Q` 的第 `r` 列决定这些输入对该输出数的各自权重。

### 矩阵图的逐格含义

`A[4,3] × B[3,4] = C[4,4]` 时，`C[i,j]` 等于 `A` 第 `i` 行与 `B` 第 `j` 列的点积。图中右上角：`[7,7,6]·[6,4,5]=100`。这不是“放弃矩阵、改为逐行算”；所有格子一起构成一次矩阵乘法。

## 权重共享与第一层自注意力

### 权重共享

同一层、同一个注意力头只有一张 `W_Q`。同一张矩阵会用于一句话里的所有 token，也用于模型见到的所有文本：

```text
q_我 = x_我 W_Q
q_爱 = x_爱 W_Q
q_你 = x_你 W_Q
```

不是所有层/头都共用：每个头、每一层各有自己训练出的 `W_Q/W_K/W_V`。共享使参数量不随句长增长，并允许模型处理训练时没出现过的位置和长度。

### Q、K、V 的完整形状

对于 `n=3` 个 token：

```text
X (3×d_model)
Q=XW_Q  (3×d_k)       每行一个 q
K=XW_K  (3×d_k)       每行一个 k
V=XW_V  (3×d_v)       每行一个 v

S=QKᵀ/√d_k (3×3)      行 i 的 q 对列 j 的 k 的匹配分数
A=softmax(S) (3×3)    每行变成总和为 1 的注意力权重
O=AV (3×d_v)          按权重搬运并混合各行 V
```

`QKᵀ` 是点积匹配分数，不是欧氏距离，也不是余弦相似度。`d_k` 是 q/k 的**维度数量**（例如 64），不是某个 q 或 k 的欧氏长度 `||q||`。除以 `√d_k` 是缩放，防止维度变大时点积数值和 softmax 过度饱和。

### V 为什么存在

Q 和 K 决定“该向谁取信息、各取多少”；V 决定“取回的实际内容是什么”。如果强迫 `V=K`，模型只能搬运用于匹配的同一份特征；独立的 `W_V` 让“地址/标签”和“要传递的内容”能分别学习。

## 从“我爱你”到一层自注意力：完整链路

以下是单个注意力头、无 batch 的教学版本。真实模型会有更高维度、多头、残差连接、归一化和后续网络层，但核心计算一致。

```text
文本 → token → token ID → 查嵌入表 → E
                                 + 位置编码 P
                                 ↓
                                 X
                              ↙  ↓  ↘
                         XW_Q  XW_K XW_V
                           Q     K     V
                            \   / 
                         QKᵀ/√d_k
                              ↓
                           softmax
                              ↓
                         A（注意力权重）
                              ↓
                            A V
                              ↓
                  O（每个 token 的上下文新表示）
```

### 0. 设定符号

- `n`：句中 token 数。`我爱你` 的简化例子取 `n=3`。
- `d_model`：输入表示的维度。真实原始 Transformer 为 512；下方示意取 4。
- `d_k`：Q/K 每行的维度；`d_v`：V 每行的维度。
- 矩阵的每一行总对应一个 token；“形状 a×b”表示 a 行 b 列。

### 1. 文本变为编号，编号查向量

```text
“我 爱 你” → [我, 爱, 你] → [101, 502, 87]
```

ID 是词表索引，像身份证号；它不携带距离或语义。嵌入表 `T` 是可训练参数，形状为 `词表大小×d_model`。查三行得到：

```text
E = [e_我; e_爱; e_你]，形状 3×d_model
```

### 2. 注入顺序

Transformer 本身不会按输入顺序逐个读，所以给每行加入位置向量：

```text
X = E + P
```

`P` 也是 `3×d_model`。原论文使用固定 sin/cos：同一位置各维不同；各对维度具有不同频率。`X` 每一项是词义与位置数字混合后的表示。随后可训练矩阵会学习如何使用这些数字。

### 3. 同一输入，三种投影

```text
Q=XW_Q，K=XW_K，V=XW_V
```

若 `X` 为 `3×d_model`，则 `W_Q` 为 `d_model×d_k`，故 `Q` 为 `3×d_k`；K 同理；`W_V` 为 `d_model×d_v`，故 V 为 `3×d_v`。

每张 `W` 是训练学到的参数，初始随机，通过梯度下降修改。对一句话中的每行、以及所有文本，某层某头复用同一张矩阵（权重共享）；不同层或头拥有不同矩阵。

### 4. 谁看谁：QKᵀ

```text
S = QKᵀ / √d_k
```

`Q` 为 `3×d_k`，`Kᵀ` 为 `d_k×3`，所以 `S` 是 `3×3`。`S[i,j]` 等于第 i 个 token 的 q 与第 j 个 token 的 k 的点积再缩放。它是匹配分数，不是欧氏距离，`√d_k` 也不是 q/k 的模长。

### 5. 分数变比例：softmax

对 S 的每一行单独 softmax，得到 A：

```text
A[i,j] > 0，且每行 Σ_j A[i,j] = 1
```

第 i 行描述 token i 从每个 token 取信息的比例。

### 6. 按比例搬运内容：AV

```text
O = AV
```

`A` 为 `3×3`、`V` 为 `3×d_v`，所以 `O` 为 `3×d_v`。第 i 行：

```text
o_i = A[i,我]v_我 + A[i,爱]v_爱 + A[i,你]v_你
```

Q/K 决定信息路线与比例；V 是沿路线传递的内容；O 是融合上下文后的新 token 表示。

### 图

```text
人类看到：  “我”       “爱”       “你”
计算机看到： token ID → token ID → token ID
模型使用：   词嵌入向量 → 词嵌入向量 → 词嵌入向量
```

## 易混概念对比

| 名词 | 是什么 | 是否会在 Transformer 训练中更新 |
|---|---|---|
| 词嵌入（embedding） | 每个 token 查表得到的初始数字坐标 | 通常会（也可冻结） |
| `W_Q/W_K/W_V` | 把当前表示投影成“查什么/供匹配/带什么信息”的三套规则 | 会 |
| Q/K/V | 输入乘上述矩阵后得到的临时结果 | 不直接存成长期参数 |
| 注意力权重 | 当前句子、当前层即时算出的“该看谁多少” | 不是参数 |

## 一句话电梯演讲

Transformer 先把每个 token 变成带位置的多维坐标，再让每个位置按任务动态决定该从哪些位置取信息。

## 新学习方式：沿完整数据流分块

以后先用 GPT/Decoder 的“预测下一个 token”任务讲完整故事，再逐块深入；不把孤立公式当作起点。每块固定回答：**输入是什么 → 变成什么 → 为什么做 → 可训练的是什么 → 输出交给谁**。

| 块 | 输入 → 输出 | 在整台机器中的职责 |
|---|---|---|
| 0. 任务 | 前文 → 下一个 token 的概率 | 解释模型最终要做什么、训练如何知道对错 |
| 1. Tokenizer | 文本 → token ID | 把符号切分并编号 |
| 2. 词嵌入 | token ID → 初始向量矩阵 E | 给每个 token 可计算的起点 |
| 3. 位置 | E → X | 注入顺序 |
| 4. 单头注意力 | X → 上下文化表示 | 决定从哪些 token 搬运什么信息 |
| 5. 多头与合并 | 多组注意力 → 合并表示 | 同时从多个视角建立关系 |
| 6. 残差与归一化 | 旧表示+新表示 → 稳定表示 | 保留信息，稳定深层训练 |
| 7. FFN | 每行表示 → 更丰富的每行表示 | 对每个 token 单独加工特征 |
| 8. 重复层 | 一层输出 → 深层表示 | 逐层抽象和推理 |
| 9. 输出头 | 最后表示 → 词表概率 | 选择下一个 token |
| 10. 训练 | 概率与正确答案 → 参数更新 | 让嵌入和所有矩阵学会完成任务 |

说明：现代 GPT 通常使用 Pre-Norm（先 LayerNorm 再注意力/FFN），原始 Transformer 论文使用 Post-Norm；理解功能后会专门对比，避免把历史版本和常见现代实现混为一谈。

## 块 2：词嵌入（待费曼复述）

### 流程卡

```text
输入：token ID 序列，例如 [101, 502, 87]
      ↓
操作：用每个 ID 索引嵌入表 T 的对应行
      ↓
输出：初始向量矩阵 E，形状 n×d_model
      ↓
下一站：加入位置向量
```

### 意义卡

- ID 是不可计算的类别标签；嵌入向量是一串可供神经网络计算的浮点数。
- 嵌入表 `T` 是形状为 `词表大小 V × d_model` 的可训练参数矩阵；每一行对应一个 token。
- 初始时 `T` 通常是随机数；训练中反向传播调整向量，让对预测任务有帮助的 token 在表示空间中形成可用关系。
- 查表在数学上等价于“独热向量 × 嵌入表”，但工程实现直接按 ID 取行，节省计算与内存。

### 块 2 费曼复述

> 词表大小 × 向量维度。就去词表找101对应的一行向量，因为ID就是一个数字，没法表达出来相似度，距离，之间的关系。

✅ 正确。补充：一句的多个 ID 各查一行，叠成 `E`；但核心理解已经到位。

## 块 3：位置嵌入（待费曼复述）

### 流程卡

```text
输入：词嵌入矩阵 E，形状 n×d_model
      ↓
操作：构造相同形状的位置矩阵 P；逐项相加 X=E+P
      ↓
输出：带顺序信息的输入矩阵 X，仍为 n×d_model
      ↓
下一站：自注意力
```

### 意义卡

- 自注意力没有天生的读取先后顺序；若不注入位置，调换 token 的行不会给它可靠的顺序线索。
- 原始 Transformer 使用固定 sin/cos 的 P；同一位置各维值不同，维度对的频率从快到慢按人为公式设置。
- 现代模型还可能使用可训练绝对位置嵌入或 RoPE；本块先掌握“位置必须进入表示、后续层才能利用”的共同思想。

### 块 3 费曼复述

> 只有E，没有顺序，文本是有顺序的，P就是把位置信息加进去了，因为只是单纯的数字加减不涉及到矩阵的变换。

✅ 正确。更精确地说是对应元素相加（不是矩阵乘法）；由于 E 与 P 形状相同，所以新矩阵 X 的形状不变。

## 块 4：单头自注意力（待费曼复述）

### 流程卡

```text
输入：X，形状 n×d_model
      ↓ 三张共享于所有 token 的可训练矩阵
Q=XW_Q，K=XW_K，V=XW_V
      ↓
S=QKᵀ/√d_k：每个 q 对每个 k 的匹配分数
      ↓
A=softmax(S)：每行变成“从各 token 取多少”的权重
      ↓
O=AV：按权重加权汇总 V
      ↓
输出：O，形状 n×d_v；每行是融合上下文后的 token 表示
```

### 意义卡

- Q 负责提出当前 token 的信息需求；K 负责供匹配的标签；V 负责被取回、被搬运的内容。
- `W_Q/W_K/W_V` 是训练学到的参数；同一层同一头对句内所有 token、以及所有文本复用同一张矩阵。
- `QKᵀ` 是点积匹配分数，不是距离。`d_k` 是 Q/K 的维数，`÷√d_k` 防止维数大时分数和 softmax 过度极端。
- `A×V` 不再计算相似度，而是让每个 token 以自己的注意力权重融合所有 V。

### 块 4 费曼复述

> Q就相当于提问的内容，K就是对应的怎么被匹配的东西，V就是我带什么内容。AV就是真的将选择概率加权汇总到了V上面，生成融合上下文的O。

✅ 正确。`A` 是每个 Query 对各 Key 的注意力权重；按这些权重汇总各行 V，得到 O。

## 块 5：多头注意力（待费曼复述）

### 流程卡

```text
同一个 X
 ↓ 并行送入 h 个不同的注意力头
head_1(X), head_2(X), ..., head_h(X)
 ↓
Concat（按特征维拼接）
 ↓
乘 W_O
 ↓
输出 MHA(X)，形状通常恢复为 n×d_model
```

### 意义卡

- 每个头拥有独立的 `W_Q/W_K/W_V`，所以能学到不同的关系或表示子空间。
- “多头”不是把同一份结果复制 h 遍，而是 h 套不同参数各做一次注意力。
- 将每头维度缩小到约 `d_model/h` 后，总计算量与单个全宽头大致同量级；`W_O` 让模型学习如何混合各头结果。

### 块 5 费曼复述

> 多头为什么不是重复算同一个注意力？那没意义啊，不如不同参数分别计算。每个头为什么常缩小维度？最好就是分担压力呗，一人负责一点。Concat 后的 W_O 做什么？之后就归一化 ffn残差之类的了呗。

✅ 前两项正确：不同参数才产生不同视角；缩小每头维度是为了分工且使总参数量/计算量不随头数线性爆炸。⚠️ `W_O` 不只是传给下一步：它先把拼接后的各头特征按可训练规则混合、重组并映射回 `d_model` 维；之后才进入残差、归一化和 FFN。

## 块 6：注意力后的加工区（残差、LayerNorm、FFN）（待费曼复述）

### GPT 常见的 Pre-Norm 流程卡

```text
输入 x（n×d_model）
 ↓
u = x + MHA(LayerNorm(x))       # 注意力子层与残差
 ↓
y = u + FFN(LayerNorm(u))       # FFN 子层与残差
 ↓
输出 y（n×d_model）
```

### 意义卡

- 残差：把旧表示直接加回新变换结果，保留原信息并让深层训练的梯度更容易流动。
- LayerNorm：对每个 token 的特征维度做规范化，再用可训练缩放/平移调整，稳定各层数值范围。
- FFN：对每个 token 的一行独立执行“升维→非线性激活→降回 d_model”的相同小网络，补足注意力主要做跨 token 信息路由、却不够擅长逐 token 非线性加工的缺口。
- 原始 Transformer 使用 Post-Norm（先子层加残差，再 LayerNorm）；现代 GPT 常见 Pre-Norm。功能相同，顺序不同。

### 块 6 费曼复述

> 深度层里面，起码让输出不会太烂，起码保持原状。layer是每个token自己做归一化。注意力让token关注token之间交流，ffn是自己加工。

✅ 核心正确。残差不保证输出一定更好，但提供保留/近似恒等映射的通道；LayerNorm 在每个 token 自己的维度内进行；注意力与 FFN 的分工正确。

## 块 7–8：输出头与训练闭环（待费曼复述）

### 流程卡

```text
最后一层隐藏表示 H（n×d_model）
 ↓
取 GPT 当前要预测的位置的一行 h_t（1×d_model）
 ↓ 乘输出矩阵 W_vocab、加偏置
logits（1×词表大小 V）
 ↓ softmax
词表概率分布（1×V）
 ↓ 与训练数据给出的正确下一个 token 比较
交叉熵损失 loss
 ↓ 反向传播 + 优化器
更新嵌入表、所有 W_Q/W_K/W_V/W_O、FFN、LayerNorm 参数、输出头等可训练参数
```

### 意义卡

- logits 是每个词表 token 的未归一化分数；softmax 后才是总和为 1 的概率。
- 训练目标不是硬选一个字后再比较，而是提高正确 token 的概率；常用交叉熵会在正确 token 概率低时给出较大损失。
- 推理时不更新参数：从概率分布按策略选下一个 token，追加到输入，再重复整条流水线。

### 块 7–8 费曼复述（第一次）

| 复述片段 | 判定 | 教练纠正 |
|---|---|---|
| “h_爱…交叉注意力发现需要一个宾语…输出词表分数” | ⚠️ | GPT 在此处不经过交叉注意力；`h_爱` 直接经输出头 `h_爱W_vocab+b` 得到词表 logits。模型可能学到宾语模式，但不是一个显式的“发现需要宾语”步骤。 |
| “你的分数很高，就得到了 logits” | ✅ | logits 就是 softmax 前的词表原始分数。 |
| “softmax 来算分数，0–1 区间” | ⚠️ | softmax 把所有 logits 一起变成概率；每个概率在 0–1，且整个词表概率总和为 1。logits 本身可以是任意实数。 |
| “loss…预测的分数和真实答案相差多远” | ⚠️ | 直觉正确：衡量预测有多错。更精确地说，交叉熵主要惩罚“正确 token 被分到的概率过低”，不是直接做原始分数的数值距离。 |
| “推理又不是训练，为什么要更新？” | ✅ | 正确；推理没有正确标签、loss、反向传播和优化器步骤，因此参数保持固定。 |

### 交叉注意力与 GPT 自注意力

| 机制 | Q 来自哪里 | K/V 来自哪里 | 本节 GPT 预测下一个 token 时是否使用 |
|---|---|---|---|
| 自注意力 | 同一序列 | 同一序列 | 是（带因果遮罩） |
| 交叉注意力 | 解码器序列 | 编码器/另一模态序列 | 否（标准 decoder-only GPT） |

### 块 7–8 费曼复述（第二次）

> h_爱 × W_vocab + b → 词表中每个 token 的 logits → softmax → “你”的概率。logits 是得分，softmax 后才是 0~1 的概率。loss 关心模型有没有把足够高的概率给真实答案。

✅ 正确。Transformer 文字主线的逐块学习完成，进入出师验收与间隔复习。

## 形状推导：5 个 token、768 维、12 头

设输入 `X` 的形状为 `n×d_model=5×768`，头数 `h=12`。标准均分时：

```text
d_k=d_v=d_model/h=768/12=64
```

矩阵乘法只要牢记：`(a×b)×(b×c)=a×c`；中间 `b` 必须相同并消去。

| 步骤（单头） | 左侧形状 | 右侧形状 | 输出形状 | 为什么 |
|---|---:|---:|---:|---|
| `Q=XW_Q` | `5×768` | `768×64` | `5×64` | 每个 token 生成一个 64 维 query |
| `K=XW_K` | `5×768` | `768×64` | `5×64` | 每个 token 生成一个 64 维 key |
| `V=XW_V` | `5×768` | `768×64` | `5×64` | 每个 token 生成一个 64 维 value |
| `S=QKᵀ` | `5×64` | `64×5` | `5×5` | 每个 query 对每个 key 的一个分数 |
| `A=softmax(S)` | `5×5` | — | `5×5` | softmax 不改变形状，只把每行变为权重 |
| `O=AV` | `5×5` | `5×64` | `5×64` | 每个 token 按 5 个权重汇总 5 条 value |

12 个头各自输出 `5×64`。按最后一维拼接：`5×(12×64)=5×768`；再乘 `W_O(768×768)` 仍得到 `5×768`，以便做残差相加。

注意：真实框架常把 12 个头先打包成一个大线性层，再 reshape/split；数学效果等价于每个头各有一套 `768×64` 的投影矩阵。

# 2.9 模型版本与Prompt 迭代：先核对再比较【⭐ 理解】

## 1. 🎯 本节目标与大白话例子

本节目标：掌握科学可控的 Prompt 与模型迭代方法论：控制单一变量、锁定固定模型快照版本、用回归测试集防止“修好东墙拆了西墙”。

大白话例子：给汽车调校性能时，绝对不能同时换掉发动机又改掉轮胎，否则跑快了也不知道是谁的功劳；必须固定同一款发动机（模型快照版本）、同一条赛道（固定评测集），每次只改一个部件，还要检查以前能过的弯道有没有翻车（Regression 退化检查）。

## 2. 🧠 核心原理与五维拆解

单变量控制原则：改 Prompt 时锁定模型快照版本号（如具体日期后缀快照，不用漂移的 latest 别名）；换模型时保持 Prompt 不变。

回归评测（Regression Eval）：不仅看整体通过率（Pass Rate）是否上升，更要逐条核对 “之前对、改后错”的退化样本（Regressions）。

评测集防过拟合：将评测集分为开发调优集（Dev）与盲测保留集（Hold-out），防止针对几条 Bad Case 死写补丁把通用能力改坏。

## 3. 💻 渐进式代码实操（ch2_code/step_09_prompt_regression_eval.py）

```python
"""2.9 模型版本与 Prompt 迭代：单变量回归评测矩阵"""
from dataclasses import dataclass
from typing import Dict, List


@dataclass
class EvalCase:  # 脚手架。回归评测样本数据类
    case_id: str
    passed_v1: bool
    passed_v2: bool
    latency_v1_ms: float
    latency_v2_ms: float


def compare_prompt_versions(cases: List[EvalCase]) -> Dict[str, object]:
    """固定同一模型快照与测试集，输出通过率变化与退化（Regression）样本。"""
    n = len(cases)
    v1_rate = sum(c.passed_v1 for c in cases) / n  # 版本通过率对比
    v2_rate = sum(c.passed_v2 for c in cases) / n
    regressions = [c.case_id for c in cases if c.passed_v1 and not c.passed_v2]  # 退化切片拦截。识别原本通过但新版失败的样本
    improvements = [c.case_id for c in cases if not c.passed_v1 and c.passed_v2]
    return {
        "v1_pass_rate": round(v1_rate, 3),
        "v2_pass_rate": round(v2_rate, 3),
        "regressions": regressions,
        "improvements": improvements,
        "ship_ready": (v2_rate >= v1_rate) and (len(regressions) == 0),  # 零退化上线门禁。总分提升但存在退化样本仍禁止直接上线
    }


if __name__ == "__main__":  # 脚手架。三样本回归测试
    cases = [
        EvalCase("c1", True, True, 400, 380),
        EvalCase("c2", False, True, 500, 420),
        EvalCase("c3", True, True, 450, 410),
    ]
    res = compare_prompt_versions(cases)
    assert res["ship_ready"] is True and res["improvements"] == ["c2"]
    print("[2.9 PASS]", res)
```

### 示例说明与练习范围

本例的设计选择：Prompt 或模型版本迭代不能只看平均通过率上升，必须核对 regressions（v1 通过而 v2 失败的样本），满足零退化才允许 ship_ready。

**代码练习｜能讲清设计**。能讲版本对照及回滚条件，比较脚本作参考。

示例辅助代码：EvalCase dataclass 与 __main__ 示例评测集。

## 4. 🗣️ 面试官视角：这段代码怎么讲

在 Prompt 迭代上线前，我一定会跑一次 compare_prompt_versions 回归矩阵：只有当总体通过率提升且 regressions == []（零退化）时，才允许 ship_ready=True 放行发布，避免为了修一条 Bad Case 把原本正常的十条搞挂。

## 5. 🔧 生产排障指南

坑 1：线上突然效果变差，查了半天代码发现一行没动 → 解法：大概率是用了未锁定的模型别名导致上游静默升级，或外部工具/知识库文档发生了变更。

## 6. ❓ 高频面试追问与参考答法

Q1：如果新 Prompt 总体准确率从 82% 提升到 88%，但引入了 2 条原本正确的核心样本退化，能直接上线吗？ 答：不能盲目上线。需先分析这 2 条退化样本属于普通长尾还是核心高危场景，并检查是否因为新 Prompt 指令冲突或过度约束导致，解决冲突后再重跑回归测试。

## 面试重点｜设计、调参与排障

**面试官可能问**

换模型或 Prompt 后效果下降，怎么找原因？

**参考回答（现场口述）**

我先用同一测试集和同一模型重跑旧 Prompt，再一次只换一个变量。逐样本看哪类输入从对变错，并查模板、分词、输出限制和上下文差异。若涉及外部工具或检索，固定对应快照，才能判断下降来自哪层。

**系统设计怎么选**

记录模型、模板、Prompt、Schema 和工具版本。固定输入与验收口径，在同一批样本上逐项替换。

**参数或条件改变会怎样**

温度和预算会改变输出分布与成本。必要时同样本重复运行，并看高风险切片。

**系统出错怎么查、怎么验证**

拒答增加、JSON 失败和业务答错是不同故障。分别统计并保留可复现样本，给出灰度和回滚条件。

## 本章要学会什么

- **能回答的设计题。** 白板写完一段 Attention 后，能解释 mask 广播、全遮挡、头维变换、残差位置和生成时序。

- **代码练到哪。** 9.1、9.2 优先闭卷。偏模型岗位再练 9.3–9.6 的最小前向、Block 和生成循环。

## 本章总结：项目设计与评测系统

先用一张图讲清请求、状态和失败出口，再用相同输入说明如何对照、如何评分、何时可以上线。下列案例可用作白板练习。

### 案例 1 · 给 TinyTransformer 写最小正确性测试系统

**面试官可能问**　你白板写完 Attention 和多头，如何在一小时内发现形状正确但实际串头的错误？

```text
手算极小张量 → 比对参考 Attention → 检查拆头与合头 → Block 集成测试 → 简短生成回归
```

**系统设计**　把纯计算和模型组装分层测。构造每个 token、每个头都不同的值，覆盖因果、padding 与全遮挡。用显式循环或手算作为对照。不要只看拆头再合头能还原，还要直接验证各头拿到的元素。

**评测系统**　用 2 个 batch、2 个头和短序列固定输入。检查屏蔽位置的权重、合法行和为 1、全遮挡行输出契约、张量形状与因果不受未来 token 影响。对照小参考实现，复测 9.1、9.2 的变换。

**常见追问与排障**　形状都对但结果错，就拿第一个头的单行值比中间张量，确认先拆 C 再换轴。合头后再对照输出投影。

**现场参考回答**

> 我会写一个能区分头和时间轴的最小反例，先逐算子看数值，再看整层输出。

### 案例 2 · 给 TinyTransformer 加增量解码

**面试官可能问**　如何为已有的全量前向增加 KV Cache，并验证结果等价？

```text
Prefill 写每层 KV → Decode 投影新 token → 更新位置并追加 KV → 仅计算新位置 → 参考前向对照
```

**系统设计**　每层缓存过去位置的 K/V，新增 token 的 Q 只读允许看到的历史。保留全量路径用于调试。先实现单请求，再扩到 padding 与不同长度 batch，明确位置索引、缓存截断与 EOS 行为。

**评测系统**　同一序列下，每步比全量和缓存路径最后位置的 logits，固定 dtype、模型、位置与掩码。覆盖单 token、带 padding、尾窗口、EOS 等。通过正确性回归后再看逐步延迟和缓存增长。

**常见追问与排障**　如果第一步对、第二步开始错，先查新位置和追加轴，再查掩码是否允许读到正确历史。按层逐次对齐首个分叉位置。

**现场参考回答**

> 我保留一个慢但正确的参考路径，逐 token 比中间结果。先证明正确性，再判断缓存改动省了多少时延。

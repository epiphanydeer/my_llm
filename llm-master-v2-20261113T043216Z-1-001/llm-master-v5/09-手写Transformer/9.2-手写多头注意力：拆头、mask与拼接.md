### 9.2 手写多头注意力：拆头、Mask 与拼接 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：白板手撕 Multi-Head Attention（MHA）时，最经典的致命错误就是直接一步写 x.reshape(B, H, T, d_k)！虽然总元素个数一样，但内存排布全乱了——把不同时间步的词混进了同一个头里！

本节解法：在 Step 1 基础上实现 MultiHeadAttention，严格执行两步法拆头：x.reshape(B, T, H, d_k).swapaxes(1, 2)，调 Step 1 注意力后再逆序拼接 swapaxes(1, 2).reshape(B, T, C) 并过 $W_O$ 跨头融合。

大白话例子：就像整理 2 叠（Batch=2）、每叠 5 张（T=5）、每张写着 16 个字（C=16）的考卷：你要把每张卷子按 4 道大题（H=4, d_k=4）剪开分给 4 个阅卷老师批改——必须先在每张卷子内部按大题切分 (B, T, H, d_k)，再把“大题维度 H”和“卷子张数 T”调换位置 (B, H, T, d_k)，绝不能直接把 5 张卷子糊成一团乱剪！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | x: (B, T, C)、causal: bool、key_padding_mask: (B, T)。 |
| ② 做什么 | 线性投影 Q/K/V -> 两步规范拆头 (B, H, T, d_k) -> 调 Step 1 计算独立多头注意力 -> 转置连续拼接回 (B, T, C) -> 过输出矩阵 W_O。 |
| ③ 输出什么 | (B, T, C) 与输入等维的输出张量。 |
| ④ 关键参数 | num_heads ($H$)、d_k = d_model // H。 |
| ⑤ 工程 Trade-off | 多头并行不增加总投影参数量（依然是 $4 C^2$），却让模型能同时在多个子空间捕捉局部句法与全局语义。 |

#### 3. 💻 渐进式代码实操（Step 2：MultiHeadAttention 积木）

演进说明：调用 Step 1 的 scaled_dot_product_attention，实现标准多头拆拼与 $W_O$ 输出融合。

```python
"""9.2 Step 2: 手写多头注意力 (MultiHeadAttention: 两步拆头 -> 独立点积 -> 连续拼接)."""

from __future__ import annotations

from typing import Optional
import numpy as np
from step_01 import scaled_dot_product_attention


class MultiHeadAttention:
    """纯 NumPy 多头自注意力，严格校验 (B, T, C) <-> (B, H, T, d_k) 维度变换."""

    def __init__(self, d_model: int, num_heads: int, seed: int = 42) -> None:
        if d_model % num_heads != 0:  # [无需死背-脚手架] 整除校验
            raise ValueError(f"d_model={d_model} 必须能被 num_heads={num_heads} 整除")
        self.d_model = d_model
        self.num_heads = num_heads
        self.d_k = d_model // num_heads  # [必记设计决策-均分头维度] 总维度不变下拆分为 H 个独立子空间

        rng = np.random.default_rng(seed)
        scale = 0.02
        self.wq = rng.normal(0.0, scale, (d_model, d_model))  # [无需死背-脚手架] 权重矩阵初始化
        self.wk = rng.normal(0.0, scale, (d_model, d_model))
        self.wv = rng.normal(0.0, scale, (d_model, d_model))
        self.wo = rng.normal(0.0, scale, (d_model, d_model))

    def split_heads(self, x: np.ndarray) -> np.ndarray:
        """(B, T, C) -> (B, T, H, d_k) -> (B, H, T, d_k)，绝不可直接一步 reshape."""
        b, t, c = x.shape
        return np.swapaxes(x.reshape(b, t, self.num_heads, self.d_k), 1, 2)  # [必背手撕-两步拆头] 先 reshape(B,T,H,d_k) 再 swapaxes(1,2)->(B,H,T,d_k)，严禁直接一步 reshape

    def combine_heads(self, x: np.ndarray) -> np.ndarray:
        """(B, H, T, d_k) -> (B, T, H, d_k) -> (B, T, C)."""
        b, h, t, dk = x.shape
        return np.ascontiguousarray(np.swapaxes(x, 1, 2)).reshape(b, t, h * dk)  # [必背手撕-连续拼接] swapaxes 回 (B,T,H,d_k) 后确保内存连续再合并为 (B,T,C)

    def forward(
        self,
        x: np.ndarray,
        causal: bool = True,
        key_padding_mask: Optional[np.ndarray] = None,
    ) -> np.ndarray:
        if x.ndim != 3 or x.shape[-1] != self.d_model:
            raise ValueError(f"输入形状必须为 (B, T, {self.d_model})，当前为 {x.shape}")
        q = self.split_heads(x @ self.wq)  # [必背手撕-QKV投影拆头] 线性投影后拆分多头
        k = self.split_heads(x @ self.wk)
        v = self.split_heads(x @ self.wv)
        attn_out, _ = scaled_dot_product_attention(q, k, v, causal=causal, key_padding_mask=key_padding_mask)
        merged = self.combine_heads(attn_out)
        out = merged @ self.wo  # [必记设计决策-W_O跨头融合] 拼接后经 W_O 投影融合多头语义信息
        assert out.shape == x.shape
        return out


if __name__ == "__main__":  # [无需死背-脚手架] 自测入口
    mha = MultiHeadAttention(d_model=16, num_heads=4)
    x = np.random.default_rng(0).normal(size=(2, 5, 16))
    assert mha.forward(x, causal=True).shape == (2, 5, 16)
    print("Ch9 Step 2 self-test passed!")
```

### 🧠 代码区记忆清单：背什么 vs 不背什么

🔒 不可替代的系统设计决策：严禁跳过 swapaxes 直接一步 reshape(B, H, T, d_k)（会打乱时间步与特征维的物理映射）；多头拼接后必须经 $W_O$ 融合跨头信息。

✍️ 面试手撕/默写范围：split_heads（reshape -> swapaxes(1, 2)）、combine_heads（swapaxes(1, 2) -> contiguous -> reshape）以及 forward 中 QKV 投影到 W_O 输出的全流程。

🗑️ 无需死背的脚手架代码：rng.normal 参数初始化、ndim != 3 报错检查与 __main__ 断言。

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：d_model % num_heads == 0；拆头前必须先切最后一维 C -> (H, d_k) 再把 H 换到 T 前面。

讲清关键行：np.ascontiguousarray(np.swapaxes(x, 1, 2)).reshape(b, t, h * dk) 对应 PyTorch 经典的 .transpose(1, 2).contiguous().view(b, t, c)——转置后内存不连续，必须先 contiguous 再 view/reshape！

主动点出工程细节：最后的 W_O 不是多余的！如果没有 W_O，各个头拼接在一起只是物理拼接，彼此之间没有任何信息交互；W_O 负责把所有头的子空间信息重新线性融合回主残差流。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：在 PyTorch 里 x.transpose(1, 2).view(...) 直接报 RuntimeError: view size is not compatible with input tensor's size and stride

现象：转置后调 .view() 崩溃。

定位方法：transpose 只改了步长（stride）没拷贝内存，张量处于非连续态。

修复方案：改用 .contiguous().view(...) 或 .reshape(...)。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：为什么拆头不能直接写 x.reshape(B, H, T, d_k)，而必须先 (B, T, H, d_k) 再 transpose(1, 2)？

参考答法：直接 reshape(B, H, T, d_k) 会把第 01 个时间步的特征硬塞给第 0 个头、第 23 个时间步塞给第 1 个头，彻底打乱了序列的时间轴对应关系！必须先拆最后一个特征维，再交换 T 和 H。

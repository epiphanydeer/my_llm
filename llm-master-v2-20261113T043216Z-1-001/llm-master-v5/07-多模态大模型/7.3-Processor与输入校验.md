### 7.3 Processor、对话模板与坏图输入校验 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：在 Step 2 里我们假设进来的 image 已经是干净的 RGB 数组。但在真实线上环境里，用户上传的可能是 0 字节空文件、被截断损坏的 JPEG、带 Alpha 透明通道的 4 通道 RGBA PNG、甚至手机竖拍带 EXIF 旋转标记的图片；更常见的是代码里少拼了一个 <image> 占位符，直接导致推理框架崩溃报错！

本节解法：在 Step 2 基础上封装 SafeMultimodalProcessor：① 字节级文件头魔数拦截坏图；② 统一转换 RGB（与处理 EXIF 方向）；③ 强制断言模板中 <image> 占位符数量与实际传入图片数 100% 一致。

大白话例子：就像机场安检登机：先扫身份证防伪芯片（字节级魔数验真，拦住假证/空文件），再核对“有几件行李就必须贴几张行李条”（<image> 占位符数量必须等于图片数量），少一张行李条绝不放行进货舱！

知识扩展（面试加分盲区）：

手机拍照常见的“EXIF 旋转坑”：很多手机竖拍照片在文件像素矩阵里其实是横着存的，只是在 EXIF 元数据里记了一笔 Orientation=6 (旋转90度)。如果你用 OpenCV cv2.imread 或跳过 ImageOps.exif_transpose() 直接送进模型，模型看到的图片是横躺着的，OCR 和空间方位问答（“左侧工人”）当场全错！

RGBA 4 通道与灰度图 1 通道坑：前端截图经常是带透明通道的 RGBA（4 通道），如果不显式 .convert("RGB")，Step 2 就会直接报通道维度不匹配（shape[2] == 4 != 3）。

#### 3. 💻 渐进式代码实操（Step 3：SafeMultimodalProcessor 输入守卫）

演进说明：复用 Step 2 的 MicroVisionProjector，在其前端加上字节魔数坏图拦截与 <image> 占位符强一致断言。

```python
"""7.3 Step 3: Processor、字节级坏图拦截与 <image> 占位符强一致校验.

在 Step 2 基础上新增输入流水线守卫：
1. 拦截空字节或非 PNG/JPEG 魔数的坏图输入。
2. 渲染多模态 Chat Template，并强制断言模板中的 `<image>` 占位符数量与实际视觉 Token 序列数一致。
"""

from __future__ import annotations

from dataclasses import dataclass
from typing import List
import numpy as np
from step_02 import MicroVisionProjector


PNG_MAGIC = b"\x89PNG\r\n\x1a\n"
JPEG_MAGIC = b"\xff\xd8\xff"


def validate_image_bytes(raw_bytes: bytes) -> str:
    """字节级坏图拦截：校验非空与标准图像魔数 (PNG/JPEG)."""
    if not raw_bytes or len(raw_bytes) < 8:
        raise ValueError("BAD_IMAGE: 图像字节流为空或过短")
    if raw_bytes.startswith(PNG_MAGIC):  # 网关入口字节魔数拦截坏图
        return "PNG"
    if raw_bytes.startswith(JPEG_MAGIC):
        return "JPEG"
    raise ValueError("BAD_IMAGE: 不支持的图像格式或文件头已损坏")


@dataclass
class SafeMultimodalProcessor:
    """模拟 HF AutoProcessor：统一校验图像、渲染模板并对齐视觉占位符."""

    projector: MicroVisionProjector
    image_token: str = "<image>"

    def prepare_inputs(
        self,
        raw_bytes_list: List[bytes],
        images_rgb: List[np.ndarray],
        prompt_template: str,
    ) -> dict[str, object]:
        if len(raw_bytes_list) != len(images_rgb):
            raise ValueError("图像字节列表与解码数组数量不一致")

        formats = [validate_image_bytes(b) for b in raw_bytes_list]
        placeholder_count = prompt_template.count(self.image_token)  # 模板占位符与传入图像数量强一致校验
        if placeholder_count != len(images_rgb):  # 占位符错位直接Fail-Fast报错
            raise ValueError(
                f"TEMPLATE_MISMATCH: 模板中 {self.image_token} 数量 ({placeholder_count}) "
                f"与传入图片数 ({len(images_rgb)}) 不一致！"
            )

        visual_token_batches = [self.projector.forward(img) for img in images_rgb]
        total_visual_tokens = sum(vt.shape[0] for vt in visual_token_batches)
        return {
            "formats": formats,
            "prompt": prompt_template,
            "num_images": len(images_rgb),
            "total_visual_tokens": total_visual_tokens,
        }


if __name__ == "__main__":  # 脚手架
    proc = SafeMultimodalProcessor(MicroVisionProjector(patch_size=16, channels=3, llm_hidden_dim=64))
    fake_png = PNG_MAGIC + b"\x00" * 32
    img = np.zeros((32, 32, 3), dtype=np.float32)

    out = proc.prepare_inputs([fake_png], [img], "请检查图中安全带：<image>")
    assert out["formats"] == ["PNG"] and out["total_visual_tokens"] == 4
    print("MM Step 3 self-test passed!")

```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：① 只有通过文件头魔数校验与 RGB 3 通道校验的图像才能进入视觉编码器；② 文本模板中的 <image> 占位符数必须严格等于 len(images_rgb)。

讲清关键行：validate_image_bytes 在解码图像前先看魔数，直接把伪装成 .jpg 的 HTML 404 错误页拦在外面；placeholder_count != len(images_rgb) 防止静默丢图。

主动点出工程细节：线上服务一定要对 Image.open() 加最大像素炸弹防护（Image.MAX_IMAGE_PIXELS），防止恶意用户传一张高压缩率的“解压炸弹图”把推理服务内存直接打爆。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：用户上传手机竖拍现场照，模型却总是把“顶部/左侧”说反，OCR 识别率暴跌

现象：PC 端图片正常，手机直传图方向错乱。

定位方法：把预处理后的图像保存下来肉眼查看，发现图像顺时针/逆时针倒了 90 度。

修复方案：在解码阶段强制执行 ImageOps.exif_transpose(img).convert("RGB")。

故障 2：多图对话时偶发 IndexError 或模型完全忽略了第 2 张图

现象：传入 2 张图但只回答了第 1 张图的内容。

定位方法：打印 apply_chat_template 渲染后的原始文本，发现只生成了 1 个 <image> 占位符。

修复方案：在 Processor 封装层加入 placeholder_count == len(images) 强断言。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：为什么不能只靠文件后缀名（.jpg/.png）来判断图片是否合法？

参考答法：爬虫或上游 OSS 经常把报错的 HTML 页面或空文件保存成 .jpg 后缀；必须读文件头魔数（Magic Bytes）并调用 img.verify() 校验真实图像结构。

Q2：处理用户上传图片时，除了魔数和通道数，还有哪两个隐蔽坑点？

参考答法：① EXIF 方向旋转标记未应用导致图像横躺；② Decompression Bomb（解压炸弹），一张几十 KB 的畸形 PNG 解压后可能占几个 GB 内存，必须限制最大像素与边长上限。

## 面试重点｜设计、调参与排障

**面试官可能问**

现场图片能在手机打开，进模型后却方向错或图文错位，怎么查？

**参考回答（现场口述）**

我会核对解码后的尺寸、EXIF 方向和 RGB 转换，再查 processor 的图片顺序、模板和实际视觉 token。拿两张内容明显不同的图片做配对回归，区分是图像方向错、图文绑定错还是模型本身识别错。

**系统设计怎么选**

输入先实际解码，统一 EXIF、颜色通道与尺寸限制。把输入媒体项、模板占位符和展开后视觉 token 分别检查。

**参数或条件改变会怎样**

放宽像素限制有利于小字，也会增显存和延迟。设定可接受上限，ROI 与坐标记录需匹配原图。

**系统出错怎么查、怎么验证**

保存脱敏样本，逐步核对解码尺寸、方向、模板、多媒体顺序及坐标回映。先区分处理器错和模型错。

### 7.7 视频理解：时间轴、PTS 对齐与金字塔抽帧 【⭐ 理解】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：视频比图片多了一个核心维度——时间轴（Temporal Axis）。单看“杯子落在地上”那一帧，根本分不清是人碰倒的、猫推下去的、还是原本就在地上！工程上如果把 30 分钟、30fps 的视频（5.4 万帧）全送进模型直接破产；而如果随便按 frame_idx / fps 算时间，遇到变帧率（VFR）监控视频时间戳全错位；更隐蔽的坑是 OpenCV 默认读入的是 BGR 通道，直接喂给期望 RGB 的 VLM 会导致红灯变蓝灯！

本节解法：构建 AdaptiveVideoSampler（自适应抽帧器）：① 校验 **PTS（Presentation Timestamp）**严格单调递增，解决变帧率时间漂移；② 显式执行 BGR -> RGB 通道反转；③ 按 min_interval_sec 间隔采样并配 max_frames 预算上限。

大白话例子：就像法医看案发现场监控：不能只打印 1 张静态照片，也不能把 2 小时录像逐帧全洗成 20 万张照片；而是先每隔 5 秒挑一张看个大概（稀疏采样），发现第 12 分钟有动静再放大加密抽帧（金字塔采样），同时校对好手表时间（PTS 对齐）和把色盲眼镜摘掉（BGR 转 RGB）！

#### 2. 🧠 核心原理与五维拆解

知识扩展（面试加分盲区）：

为什么变帧率（VFR）视频不能用 frame_idx / fps 算时间？：手机录屏、网络监控流为了省带宽经常在静止画面降到 5fps、运动画面升到 30fps（VFR）。按固定 30fps 除法算出来的时间戳会越往后漂移越严重，导致回答“02:14 冒烟”定位不准。必须读取容器内真实的 PTS（Presentation Timestamp）！

视频理解的多路对齐：除了画面帧，视频往往还有音轨（ASR 转录 + 语调/环境声）和画面内嵌字幕（OCR），三路信号都必须统一对齐到 PTS 时间轴上。

#### 3. 💻 渐进式代码实操（Step 7：AdaptiveVideoSampler 视频抽帧与通道对齐）

演进说明：在 Step 3 图像校验基础上扩展时间维度，加入 PTS 单调性断言、BGR->RGB 转换与帧数预算截断。

```python
"""7.7 Step 7: 视频时序自适应抽帧、PTS 时间戳对齐与 BGR->RGB 转换.

解决视频理解三大工程坑点：
1. 变帧率 (VFR) 场景下不能只按帧号 * 1/fps 算时间，必须校验 PTS 时间戳严格单调递增。
2. OpenCV 默认读入为 BGR 通道序，送入 VLM 前必须显式反转为 RGB。
3. 严格限制最大送入帧数 budget，防止长视频炸穿显存与账单。
"""

from __future__ import annotations

from dataclasses import dataclass
from typing import List
import numpy as np


@dataclass(frozen=True)
class RawVideoFrame:
    pts_sec: float
    bgr_image: np.ndarray


def sample_video_frames(
    frames: List[RawVideoFrame],
    min_interval_sec: float = 1.0,
    max_frames: int = 8,
) -> List[dict[str, object]]:
    """按 PTS 时间间隔自适应抽帧，校验单调递增并执行 BGR -> RGB 转换."""
    if not frames:
        raise ValueError("视频帧序列不能为空")
    if min_interval_sec <= 0 or max_frames <= 0:
        raise ValueError("min_interval_sec 与 max_frames 必须为正数")

    prev_pts = -1.0
    sampled: List[dict[str, object]] = []
    last_kept_pts = float("-inf")

    for f in frames:
        if f.pts_sec <= prev_pts:  # VFR场景强制校验PTS严格单调递增
            raise ValueError(f"PTS_NOT_MONOTONIC: 当前 {f.pts_sec} <= 上一帧 {prev_pts}")
        prev_pts = f.pts_sec

        if f.bgr_image.ndim != 3 or f.bgr_image.shape[2] != 3:
            raise ValueError(f"帧图像必须为 (H, W, 3)，当前 {f.bgr_image.shape}")

        if f.pts_sec - last_kept_pts >= min_interval_sec:  # 按PTS时间间隔而非帧号抽帧
            rgb_img = f.bgr_image[..., ::-1].copy()  # OpenCV BGR通道显式反转为RGB
            sampled.append({"pts_sec": round(f.pts_sec, 3), "rgb": rgb_img})
            last_kept_pts = f.pts_sec
            if len(sampled) >= max_frames:  # 最大帧预算硬截断防显存与账单爆炸
                break

    assert len(sampled) <= max_frames
    assert all(sampled[i]["pts_sec"] < sampled[i + 1]["pts_sec"] for i in range(len(sampled) - 1))
    return sampled


if __name__ == "__main__":  # 脚手架
    bgr = np.zeros((16, 16, 3), dtype=np.uint8)
    bgr[..., 0] = 255  # OpenCV Blue channel
    stream = [RawVideoFrame(pts_sec=t * 0.5, bgr_image=bgr) for t in range(10)]
    out = sample_video_frames(stream, min_interval_sec=1.0, max_frames=3)
    assert len(out) == 3 and out[0]["rgb"][0, 0, 2] == 255
    print("MM Step 7 self-test passed!")

```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：① 输出帧时间戳严格单调递增；② 通道序 100% 为 RGB；③ 输出总帧数绝不超过 max_frames 预算上限。

讲清关键行：f.bgr_image[..., ::-1].copy() 解决 OpenCV 经典的红蓝通道反转坑，并 .copy() 确保内存连续（避免 PyTorch from_numpy 报负步长错误！）；pts_sec <= prev_pts 拦截损坏视频流。

主动点出工程细节：在实际 PyTorch 转 Tensor 时，如果切片 [..., ::-1] 不加 .copy()，NumPy 数组步长为负，直接调 torch.from_numpy() 会报错 ValueError: At least one stride in the given numpy array is negative！

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：VLM 把监控里的“红色告警指示灯”全部识别成“蓝色正常运行灯”

现象：图片上传接口正常，一接视频流颜色全反。

定位方法：OpenCV cv2.VideoCapture 读出的是 BGR，未经反转直接送进了期望 RGB 的 VLM Processor。

修复方案：抽帧后立即 cv2.cvtColor(frame, cv2.COLOR_BGR2RGB) 或 [..., ::-1].copy()。

故障 2：30 分钟视频抽帧后定位事件发生在 15:00，人眼打开视频却在 12:30

现象：时间定位整体漂移。

定位方法：监控视频是变帧率（VFR），代码却用 frame_idx / 30.0 估算时间。

修复方案：改用视频封装容器自带的真实 PTS 时间戳。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：为什么 OpenCV 读出的帧直接切片 [..., ::-1] 传给 torch.from_numpy() 会报错？

参考答法：因为 [..., ::-1] 会产生负的内存步长（negative stride），PyTorch 张量不支持负步长视图，必须加上 .copy() 或使用 cv2.cvtColor(..., cv2.COLOR_BGR2RGB) 生成正向连续内存。

Q2：长视频理解如何平衡成本和瞬间动作漏检？

参考答法：采用金字塔多级抽帧：先用字幕/ASR/稀疏关键帧（如 0.5fps）粗筛定位候选时间段，再针对命中片段加密抽帧（如 2~4fps）送入 VLM 精读并输出带时间戳的证据区间。

## 面试重点｜设计、调参与排障

**面试官可能问**

5 秒内短事件为什么没检出，抽帧与时间戳怎么改？

**参考回答（现场口述）**

先查抽帧间隔是不是比事件持续时间长，再用源视频时间戳确认抽到了哪个时刻。可变帧率不能只凭帧号除固定 FPS。我会低频扫全局，对触发线索的区间加密，同时留短事件样本测漏检与成本。

**系统设计怎么选**

用 PTS 乘 time base 对齐真实时间；变帧率不能只靠帧号除 FPS。先低频扫描，再对疑似片段加密抽帧。

**参数或条件改变会怎样**

扫描间隔过大容易漏短事件，采样过密会增加计算和视觉 token。用最短需检事件的覆盖率选间隔。

**系统出错怎么查、怎么验证**

拿漏检事件核对采样时刻、实际帧时间和颜色顺序。再测试疑似区间回溯是否包含事件前后证据。

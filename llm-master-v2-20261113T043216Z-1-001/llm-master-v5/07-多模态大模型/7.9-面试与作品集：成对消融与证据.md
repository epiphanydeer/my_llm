### 7.9 面试与作品集：成对消融与 P95 尾延迟权衡 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：面试被问“你把项目从方案 A 改成方案 B，效果到底提升了多少？”很多候选人只会说“准确率从 80% 涨到了 84%”，面试官一追问“那原来做对的 80% 里有没有被你改坏的？延迟多了多少毫秒？”当场哑火！

本节解法：构建 PairwiseAblationAnalyzer（逐样本成对消融分析器）：① 强制 Baseline 与 Candidate 的 sample_id 与 gold 金标 100% 对齐防篡改；② 精确拆解 Fixed（错->对） vs Regressed（对->错） 净收益；③ 同步汇报 P95 尾延迟代价。

大白话例子：就像吃新药治病：不能只说“100 个病人里治好了 84 个”，如果治好了 10 个原本没治好的（Fixed=10），却把 6 个原本好好的病人吃出了副作用（Regressed=6），净收益其实只有 4 个，而且吃药后心跳慢了一倍（P95 延迟翻倍）！把这两笔账算清，面试官立刻觉得你是真做过上线评审的资深工程师！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 同一批测试样本在 baseline 与 candidate 两套方案下的运行记录 RunSample(sample_id, gold, pred, latency_ms)。 |
| ② 做什么 | 校验样本集长度与 ID 集合完全一致 -> 断言同一 sample_id 的 gold 金标未被篡改 -> 统计 fixed、regressed、net_gain_count 及各自准确率与 P95 尾延迟。 |
| ③ 输出什么 | 成对消融对比报告（fixed、regressed、net_gain_count、base_acc、cand_acc、base_p95_ms、cand_p95_ms）。 |
| ④ 关键参数 | P95（第 95 百分位延迟，比平均值更能暴露长尾大图/复杂推理卡顿）。 |
| ⑤ 工程 Trade-off | 任何优化（如开高分辨率、加多次复核）都会伴随 P95 延迟或成本上升；成对消融让你用“净修复数 vs 延迟代价”的量化账本做技术决策。 |

#### 3. 💻 渐进式代码实操（Step 9：PairwiseAblationAnalyzer 成对消融分析）

演进说明：在 Step 6 评测矩阵基础上，升级为版本迭代上线评审必备的“Baseline vs Candidate 逐样本成对消融对比工具”。

```python
"""7.9 Step 9: 成对消融分析器 (Pairwise Ablation: Fixed vs Regressed + P95 尾延迟).

杜绝只报“总分涨了 2%”却掩盖大量原本做对样本退化的问题：
1. 强制校验 Baseline 与 Candidate 的 sample_id 集合及 gold 金标完全一致。
2. 逐样本统计 Fixed (错->对)、Regressed (对->错)、净提升与 P95 尾延迟变化。
"""

from __future__ import annotations

from dataclasses import dataclass
from typing import Dict, List
import numpy as np


@dataclass(frozen=True)
class RunSample:
    sample_id: str
    gold: str
    pred: str
    latency_ms: float


def compute_p95(latencies: List[float]) -> float:
    if not latencies:
        raise ValueError("延迟列表不能为空")
    return round(float(np.percentile(latencies, 95)), 2)


def pairwise_ablation(baseline: List[RunSample], candidate: List[RunSample]) -> Dict[str, object]:
    """执行严格样本对齐的成对消融对比."""
    if not baseline or len(baseline) != len(candidate):
        raise ValueError("Baseline 与 Candidate 样本数必须一致且非空")

    base_map = {s.sample_id: s for s in baseline}
    cand_map = {s.sample_id: s for s in candidate}
    if set(base_map.keys()) != set(cand_map.keys()):  # 成对消融样本ID集合必须严格对齐
        raise ValueError("Baseline 与 Candidate 的 sample_id 集合不一致")

    fixed = 0
    regressed = 0
    both_right = 0
    both_wrong = 0

    for sid, b in base_map.items():
        c = cand_map[sid]
        if b.gold != c.gold:  # 防止基线与候选集金标被悄悄篡改
            raise ValueError(f"GOLD_MISMATCH: 样本 {sid} 的金标被篡改 ({b.gold} != {c.gold})")
        b_ok = b.pred == b.gold
        c_ok = c.pred == c.gold
        if not b_ok and c_ok:  # 统计Fixed错改对样本数
            fixed += 1
        elif b_ok and not c_ok:  # 统计Regressed对改错样本数
            regressed += 1
        elif b_ok and c_ok:
            both_right += 1
        else:
            both_wrong += 1

    n = len(baseline)
    assert fixed + regressed + both_right + both_wrong == n
    base_acc = (both_right + regressed) / n
    cand_acc = (both_right + fixed) / n

    return {
        "n": n,
        "fixed": fixed,
        "regressed": regressed,
        "net_gain_count": fixed - regressed,  # 净收益与P95尾延迟联合评审
        "base_acc": round(base_acc, 4),
        "cand_acc": round(cand_acc, 4),
        "base_p95_ms": compute_p95([s.latency_ms for s in baseline]),
        "cand_p95_ms": compute_p95([s.latency_ms for s in candidate]),
    }


if __name__ == "__main__":  # 脚手架
    base_runs = [
        RunSample("s1", "hazard", "safe", 120.0),
        RunSample("s2", "hazard", "safe", 130.0),
        RunSample("s3", "safe", "safe", 110.0),
        RunSample("s4", "safe", "safe", 140.0),
    ]
    cand_runs = [
        RunSample("s1", "hazard", "hazard", 210.0),
        RunSample("s2", "hazard", "hazard", 220.0),
        RunSample("s3", "safe", "hazard", 250.0),
        RunSample("s4", "safe", "safe", 200.0),
    ]
    res = pairwise_ablation(base_runs, cand_runs)
    assert res["fixed"] == 2 and res["regressed"] == 1 and res["net_gain_count"] == 1
    print(f"MM Step 9 self-test passed! res={res}")

```

- **本例的设计选择**：版本迭代评审必须做逐样本成对消融，强制校验 Baseline 与 Candidate 的 `sample_id` 集合及 `gold` 金标完全一致防篡改，并联合对比 `Fixed - Regressed` 净收益与 P95 尾延迟变化。
- **代码练习｜能讲清设计**。能算成对净增益，准备真实退化例子，不背汇总器。

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：fixed + regressed + both_right + both_wrong == n，且同一 sample_id 的 gold 金标在两轮实验间绝对不可变动。

讲清关键行：b.gold != c.gold 拦截了工业界最容易踩的“改了版测试集标签却以为模型涨点了”的乌龙；fixed 与 regressed 拆开暴露新方案的副作用。

主动点出工程细节：如果 regressed 样本集中在原本稳定的简单高频场景，哪怕净收益为正也不应该直接全量替换，而应该通过路由分流（见 7.10 节）只在困难场景启用新方案。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：新版本上线后，老客户投诉“以前一眼能看出来的简单图现在反而报错了”

现象：总体准确率涨了 3%，但高频基础能力退化。

定位方法：只看了宏观平均分，没做逐样本 Fixed vs Regressed 消融分析。

修复方案：每次上线前强制跑 pairwise_ablation，逐条人工抽检所有 regressed 样本。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：为什么不能只看平均延迟（Mean Latency）和总体准确率，而要看 P95 和 Fixed/Regressed？

参考答法：平均延迟会被大量快请求拉低，掩盖 5% 大图/超时请求带来的真实卡顿体验（SLA 看 P95/P99）；同理，总体准确率掩盖了“修好 10 个难例却弄坏 7 个简单例”的退化风险，成对消融才能看清真实净收益。

## 面试重点｜设计、调参与排障

**面试官可能问**

总体准确率上涨，为什么还是不能全量上线？

**参考回答（现场口述）**

我会逐样本对照新旧，单看原来正确现在错的项目。若退化集中在夜间或高危隐患，即使总分涨也可能越过上线门槛。确认关键切片、P95 与人工量达标后再小流量试，并设置回滚条件。

**系统设计怎么选**

用同一批样本做成对比较，分别列出改好、变坏和不变。安全关键退化要单独验收。若要归因某个组件，固定其他条件再做消融。

**参数或条件改变会怎样**

用同负载比较 P95、成本和人工量；优先满足关键切片的质量门槛，再权衡总体净增益。

**系统出错怎么查、怎么验证**

检查测试集版本、重复样本和计时范围。变坏样本按小目标、时序或部署配置归因并保留回归。

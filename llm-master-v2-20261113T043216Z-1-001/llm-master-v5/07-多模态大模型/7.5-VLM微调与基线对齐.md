### 7.5 VLM 微调：主干冻结、LoRA 与 -100 损失掩码 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：面对“Qwen2-VL 在工业安全绳识别上的定制需求”，很多新手拿到数据就想“全量微调整个模型”，结果不仅 8 张 A100 都不够显存，还会把模型原本的通用视觉/语言能力训废（灾难性遗忘）；更致命的是，算训练 Loss 时如果忘了把 Prompt 和几百个 <image> 占位符屏蔽掉，模型 90% 的梯度都在背诵输入模板！

本节解法：坚持 Zero-shot 基线先行 -> 冻结 ViT 主干 -> 仅训 Projector / 语言层 LoRA -> 构造 -100（Ignore Index）损失掩码四步工业标准路线。

大白话例子：老师批改学生做的“看图写话”作业卷子：卷子上印着“256 个图片占位符 + 30 字题目要求 + 学生写的 20 字答案”。老师打分（算交叉熵 Loss）时，必须拿胶带把前面的图片和题目贴上 -100 免检马赛克，只批改学生写的最后 20 个字！而且学生原本已经认识世间万物（ViT 眼睛很厉害），别把他的眼睛重头练一遍（冻结 ViT），只训练他“把看到的工业隐患按 JSON 格式表达出来”的翻译官（Projector）和语言习惯（LoRA）就够了！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 图像 Token 数 image_token_count、提问 prompt_token_ids、标准答案 answer_token_ids、模型前向 logits 与 projector_w。 |
| ② 做什么 | 为图像与 Prompt 前缀位置填充 ignore_index = -100 构造 labels -> Causal LM 右移对齐（logits[:-1] 预测 labels[1:]）-> 仅在 labels != -100 的有效答案位计算交叉熵 Loss -> 冻结主干仅更新 Projector/LoRA。 |
| ③ 输出什么 | 带掩码的 labels 序列、标量有限 loss、有效监督 Token 数与参数更新校验。 |
| ④ 关键参数 | ignore_index = -100（PyTorch CrossEntropyLoss 默认忽略值）、freeze_vision_tower=True、LoRA rank（8~16）。 |
| ⑤ 工程 Trade-off | 冻结 ViT + 训练 Projector/LoRA 把显存需求压降到单卡 24G/48G 可跑，且极大保留通用通识能力；仅当遇到全新特种模态（如红外热成像、医学 CT）且有十万级数据时才考虑解冻 ViT。 |

知识扩展（面试加分盲区）：

Zero-shot 基线未穷尽前，绝不启动微调：微调前必须先跑通 Zero-shot 基线评测，排查是不是 Prompt 不够清晰、分辨率太低或没加 RAG 导致的错误；只有确认存在稳定的领域术语偏差、固定 JSON 输出格式不稳、或特定空间判断逻辑缺失，且手头有千级以上高质量无泄漏数据时，才上 SFT/LoRA。

LLaMA-Factory 微调 Qwen2-VL 的经典三开关配置：

freeze_vision_tower: true（锁死 ViT，防小数据集破坏通用视觉特征并省显存）

freeze_multi_modal_projector: false（微调连接器，适配垂直领域视觉特征）

finetuning_type: lora（在 LLM 线性层注入低秩旁路，学习领域决策与结构化输出）

#### 3. 💻 渐进式代码实操（Step 5：-100 损失掩码与冻结主干更新）

演进说明：在 Step 2~4 基础上，实现 VLM 监督微调最核心的 -100 标签掩码构造、标签移位交叉熵与主干冻结更新自检。

```python
"""7.5 Step 5: VLM 微调：主干冻结、-100 损失掩码与梯度流向断言.

在 Step 2~4 基础上实现可微 SFT 最小闭环（纯 NumPy 数值验证版，零额外深度学习框架依赖即可自检）：
1. 构造 `-100` (ignore_index) 标签掩码，确保 Prompt 与 `<image>` 占位符不参与 Loss。
2. 模拟冻结 ViT/LLM 主干参数，仅更新 Projector 权重并校验梯度与损失下降。
"""

from __future__ import annotations

from typing import Dict, List
import numpy as np


def build_sft_labels_with_mask(
    image_token_count: int,
    prompt_token_ids: List[int],
    answer_token_ids: List[int],
    ignore_index: int = -100,
) -> Dict[str, List[int]]:
    """为视觉 Token 与 Prompt 位置打上 -100 掩码，仅对目标答案监督计算 Loss."""
    if image_token_count <= 0 or not answer_token_ids:
        raise ValueError("image_token_count 必须 > 0 且目标答案不能为空")
    # 【按岗位加练开始】训练岗练把图像和文本前缀标签设为 -100
    prefix_len = image_token_count + len(prompt_token_ids)  # 视觉Token与Prompt共同组成掩码前缀
    labels = [ignore_index] * prefix_len + list(answer_token_ids)  # 前缀全打-100仅监督目标答案
    # 【按岗位加练结束】
    supervised = sum(1 for x in labels if x != ignore_index)
    assert supervised == len(answer_token_ids)
    return {"labels": labels, "prefix_len": [prefix_len], "supervised_count": [supervised]}


def masked_cross_entropy_step(
    logits: np.ndarray,
    labels: np.ndarray,
    projector_w: np.ndarray,
    vis_feat: np.ndarray,
    lr: float = 0.1,
    ignore_index: int = -100,
) -> Dict[str, object]:
    """执行一次带标签移位与 -100 掩码的前向交叉熵与 Projector 参数更新."""
    # 【按岗位加练开始】训练岗练 next-token 对齐与有效标签筛选
    shifted_logits = logits[:-1]  # Causal LM预测下一Token错位对齐
    shifted_labels = labels[1:]  # 标签左移一位对应预测位置
    valid_mask = shifted_labels != ignore_index  # 过滤-100位置仅对有效Token算Loss
    if not valid_mask.any():
        raise ValueError("有效监督 Token 数为 0，无法计算梯度")

    valid_logits = shifted_logits[valid_mask]
    valid_targets = shifted_labels[valid_mask]
    # 【按岗位加练结束】

    shifted = valid_logits - np.max(valid_logits, axis=-1, keepdims=True)
    probs = np.exp(shifted) / np.sum(np.exp(shifted), axis=-1, keepdims=True)
    nll = -np.log(np.maximum(probs[np.arange(len(valid_targets)), valid_targets], 1e-12))  # 负对数似然交叉熵核心
    loss = float(np.mean(nll))
    assert np.isfinite(loss), "Loss 出现 NaN/Inf"

    grad_proj = np.outer(vis_feat, np.ones(projector_w.shape[1])) * 0.01
    new_projector_w = projector_w - lr * grad_proj
    assert not np.allclose(new_projector_w, projector_w), "Projector 参数应当更新"
    return {"loss": round(loss, 4), "valid_supervised": int(valid_mask.sum()), "updated": True}


if __name__ == "__main__":  # 脚手架
    mask_info = build_sft_labels_with_mask(
        image_token_count=4, prompt_token_ids=[10, 11], answer_token_ids=[2, 3]
    )
    labels = np.array(mask_info["labels"], dtype=np.int64)
    assert labels.tolist() == [-100, -100, -100, -100, -100, -100, 2, 3]

    logits = np.zeros((8, 5), dtype=np.float64)
    proj_w = np.ones((4, 4), dtype=np.float64)
    vis_f = np.ones(4, dtype=np.float64)
    step_out = masked_cross_entropy_step(logits, labels, proj_w, vis_f)
    assert step_out["valid_supervised"] == 2 and step_out["updated"] is True
    print(f"MM Step 5 self-test passed! step_out={step_out}")

```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：labels 中图像占位符与用户 Prompt 必须全部设为 -100，valid_supervised 必须精确等于目标答案 Token 长度；冻结主干参数 requires_grad=False 后梯度必须为 None。

讲清关键行：logits[:-1] 与 labels[1:] 是自回归模型“第 t 个位置预测第 t+1 个词”的经典移位对齐；valid_mask = shifted_labels != -100 物理过滤掉所有非答案位置。

主动点出工程细节：如果答案太长或被 max_seq_length 从右侧截断，会导致 valid_mask.any() 为 False（全是 -100），算 Loss 直接出 NaN 炸毁整个训练！所以代码里必须断言 valid_mask.any() 并在数据预处理时优先截断文本或限制图片最大分辨率，绝不截断答案。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：微调 Loss 降得非常漂亮，但测试集业务准确率纹丝不动甚至下降

现象：训练曲线一路平滑下降，一测全错。

定位方法：① 检查 labels 是否漏设 -100，导致模型只是背熟了 Prompt 模板；② 检查训练与推理时的 Chat Template（如特殊结束符 <|im_end|>）是否一致。

修复方案：打印单条样本的 tokenizer.decode(labels[labels != -100])，确认参与算 Loss 的 100% 只有期望的 Assistant 答案和结束符。

故障 2：训练中途突然报 Loss = NaN

现象：前几个 Batch 正常，突然遇到某条长图样本 Loss 变 NaN。

定位方法：该样本图像 Token 太多把 max_seq_length 占满，导致目标答案被截断，整条样本的 labels 全是 -100。

修复方案：增大 max_seq_length 或下调视觉 max_pixels，并在 DataCollator 中过滤掉有效监督 Token 为 0 的样本。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：微调 VLM 时，为什么必须把 Prompt 和 <image> 的标签设为 -100？

参考答法：PyTorch CrossEntropyLoss 默认忽略 ignore_index=-100 的位置。一张图动辄占几百上千个视觉 Token，而且图像特征不是由语言模型自回归生成的；如果不掩码，模型大部分梯度都会浪费在拟合输入占位符上，严重稀释真正需要学习的目标答案梯度。

Q2：微调 VLM 时，只训 Projector、冻结 ViT 训 LLM LoRA、还是全量微调？怎么选？

参考答法：工业界性价比最高的是冻结 ViT 主干 + 训练 Projector（可选）+ 语言层挂载 LoRA：显存只需单卡 24G~48G，既能学会领域决策逻辑和 JSON 格式，又不会破坏 ViT 原有的通用视觉感知能力（防灾难性遗忘）。

## 面试重点｜设计、调参与排障

**面试官可能问**

VLM 微调为什么先考虑冻结主干，Loss 又应该算在哪？

**参考回答（现场口述）**

冻结主干能减少训练成本和能力漂移，我先让投影或低秩适配学任务，再根据对照决定是否解冻更多层。监督只覆盖选定的 Assistant 目标，视觉输入、用户前缀和 padding 掩掉。用短样本检查标签位置与结束标记。

**系统设计怎么选**

Projector 学模态对齐，LoRA 可适配回复行为。冻结方案和训练阶段依能力缺口决定。若只监督助手回复，用实际模板确定有效标签并做一次 next-token 对齐。

**参数或条件改变会怎样**

改可训练组件会影响容量、资源和遗忘。对比只训 Projector、加 LoRA 与原模型，用视觉定位、拒答和文字回归同时验收。

**系统出错怎么查、怎么验证**

检查图片 token 数、助手回复起止、EOS/EOT 和截断后仍有监督 token；必要时只拿一条样本验算。

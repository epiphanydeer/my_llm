# 第三章 · RAG 检索增强系统（原理闭卷 + 渐进手撕 + 生产排障）

本章面向 2027 社招大模型/多模态应用算法工程师（Applied MLE）岗位，深度融合 llm-master 原教程严密逻辑与全部原图、补充高频面试盲区与扩展知识，并采用 Step 1 → Step 14 真正“搭积木式”渐进代码底座（每节仅在上一步基础上新增 1 个核心模块，全部附带类型标注、assert 断言、工业级调库对照与三段式面试话术）。

## 本章要学会什么

- **能回答的设计题。** 规程问答找不到正确条款或答错时，能沿入库、召回、重排、拼装、生成追踪。能解释权限、更新一致性、召回和 P95 如何同时守住。
- **能提供的验证证据。** 说出一个错例的金标在哪一层丢失，能拿出同库同查询集的逐层结果、质量对照与延迟数据。先看 3.2、3.5–3.9、3.12、3.13。
- **代码练到哪。** 闭卷练 3.4 的归一化与 Top-K、3.7 的加权 RRF，以及 3.9 的指标小函数。索引、同步和图检索示例读到能解释行为。

## 本章总结：项目设计与评测系统

先用一张图讲清请求、状态和失败出口，再用相同输入说明如何对照、如何评分、何时可以上线。下列案例可用作白板练习。

### 案例 1 · 企业规程问答，能溯源与按权限拒答

**面试官可能问**　给员工做规程问答，如何让编号和同义问法都命中，且引用的是有权限的有效版本？

```text
离线解析与版本化 → 带 ACL 的子块索引；在线身份与日期 → 过滤 → 双路召回 → RRF → 精排 → 带证据生成
```

**系统设计**　子块保留条款号、原文偏移和父块。先按身份与日期约束候选，再双路召回。精排后补齐同条款例外，保留引文出处。证据不足时明确拒答，端到端 trace 记录各阶段候选与时延。

**评测系统**　固定语料快照，标注问题、测试身份、日期、可答性及金标条款和关键事实。用仅关键词、仅向量和混合方案做对比。分别测候选 Recall、精排后命中、引用支持、正确拒答、越权、P95 和成本，逐题看退化。

**常见追问与排障**　正确条款未进候选时查入库、过滤与召回。进了候选但没进上下文时查精排或截断。条款在上下文而答案仍错，就核实数字、例外和引用支持。只在对应阶段调参。

**现场参考回答**

> 我先定有效版本和访问边界，再画离线、在线两条链路。评测定位到正确条款消失在哪一层，然后用双路召回的收益和 P95 证明改动值不值。

### 案例 2 · 旧规程撤权与索引切换

**面试官可能问**　制度已撤销或改了访问权限，旧索引、副本和缓存怎样保持一致？

```text
源库事件 → 变更清单 → 文本指纹与元数据 diff → 构建或更新 → 对账 → 别名切换；查询时执行现行授权
```

**系统设计**　只改 ACL 或日期时优先刷受控元数据，正文变化才重建切片和向量。查询侧由权威权限兜住撤权，缓存命中也重新确认版本与授权。对不完整快照暂停大批删除；回滚索引时仍要沿用现行权限。

**评测系统**　准备新旧版本、仅 ACL 修改、正文替换、撤权后旧缓存、事件重复和乱序等样例。与全量重建或旧增量流程对比。记录撤权到生效的时间、索引与源库差异、重复处理与更新期间的查询 P95，用越权回放当发布门槛。

**常见追问与排障**　已经切换别名还答出旧内容时，先用 trace 确认实际索引版本、缓存版本和授权判定。逐项模拟撤权，直接验证旧结果无法返回给同一用户。

**现场参考回答**

> 索引版本能回滚，授权结果必须由当前规则决定。我会先证明撤权时旧缓存也失效，再优化同步速度。

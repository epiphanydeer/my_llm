# 1.4 应用概念与生成采样：温度、top-k、top-p【🔥 必会】

## 1. 🎯 本节目标与大白话例子

本节目标：彻底掌握解码阶段 temperature、top_k、top_p 的数学作用与执行顺序，知道不同业务场景该如何组合参数。

大白话例子：模型输出 Logits 就像餐厅菜单上每道菜的推荐分：temperature 是调节主厨心情的“冒险开关”（低温只点招牌菜，高温敢试新奇菜）；top_k 是“只看前 K 名”；top_p 是“从高到低累加概率，凑够 90% 就截断”，把长尾怪菜全踢掉。

## 2. 🧠 核心原理与五维拆解

图片待恢复：原图

Temperature ($T$)：$p_i = \text{softmax}(z_i / T)$。$T \to 0$ 退化为贪心解码（Greedy）；$T < 1$ 让分布更尖锐确定；$T > 1$ 让分布更平坦随机。

Top-K：仅保留 Logits 最高的 $K$ 个候选 Token，其余置为 $-\infty$。缺点是 $K$ 固定，分布很尖时可能引入噪声，分布很平时可能截断太多合理词。

Top-P（Nucleus Sampling）：按概率降序累加，保留最小集合使得累积概率 $\ge P$。能自适应分布形状，是工业界默认首选。

标准执行顺序：Logits / Temperature → Top-K 截断 → Softmax → Top-P 截断 → 重新归一化并按多项式分布采样。

## 3. 💻 渐进式代码实操（ch1_code/step_04_sampling_strategies.py）

```python
"""1.4 应用概念与生成采样：Temperature、Top-K、Top-P (Nucleus) 采样器"""
import numpy as np
from typing import Dict


def softmax(logits: np.ndarray) -> np.ndarray:
    shifted = logits - np.max(logits)  # [必背手撕-数值稳定Softmax] 减去最大值防止 exp 溢出
    exp_v = np.exp(shifted)
    return exp_v / np.sum(exp_v)


def sample_next_token_probs(
    logits: np.ndarray,
    temperature: float = 1.0,
    top_k: int = 0,
    top_p: float = 1.0,
) -> np.ndarray:
    """按标准推理引擎顺序执行：Temperature -> Top-K -> Top-P -> 归一化。"""
    if temperature <= 0.0:  # [必记设计决策-零温贪心退化] T<=0 时直接 argmax 取确定性输出
        out = np.zeros_like(logits, dtype=np.float64)
        out[int(np.argmax(logits))] = 1.0
        return out

    scaled = logits.astype(np.float64) / temperature  # [必背手撕-温度缩放] 先缩放 logits 再做截断

    if top_k > 0 and top_k < len(scaled):
        kth_val = np.partition(scaled, -top_k)[-top_k]  # [必记设计决策-采样顺序] 先 Top-K 屏蔽尾部，再转概率做 Top-P
        scaled = np.where(scaled < kth_val, -np.inf, scaled)

    probs = softmax(scaled)

    if 0.0 < top_p < 1.0:
        sorted_idx = np.argsort(probs)[::-1]
        sorted_probs = probs[sorted_idx]
        cum_probs = np.cumsum(sorted_probs)
        # 保留首个使累积概率 >= top_p 的 token，截断其后所有低概率长尾
        remove_mask = (cum_probs - sorted_probs) >= top_p  # [必背手撕-Nucleus截断边界] 保留首个使累积概率>=top_p的token
        filtered_sorted = np.where(remove_mask, 0.0, sorted_probs)
        probs = np.zeros_like(probs)
        probs[sorted_idx] = filtered_sorted
        probs = probs / np.sum(probs)

    return probs


if __name__ == "__main__":  # [无需死背-脚手架] 采样分布验证脚本
    raw_logits = np.array([4.0, 3.0, 1.5, 0.2, -1.0])
    greedy = sample_next_token_probs(raw_logits, temperature=0.0)
    assert greedy[0] == 1.0 and np.sum(greedy[1:]) == 0.0
    topk_topp = sample_next_token_probs(raw_logits, temperature=0.8, top_k=3, top_p=0.9)
    assert np.isclose(np.sum(topk_topp), 1.0) and topk_topp[3] == 0.0 and topk_topp[4] == 0.0
    print("[1.4 PASS] greedy:", greedy.round(3), "top_k+top_p:", topk_topp.round(3))
```

## 4. 🗣️ 面试官视角：这段代码怎么讲

在我的采样器实现里，严格按 Temperature -> Top-K -> Softmax -> Top-P 顺序处理。生产上做 JSON 提取或分类时我通常设 temperature=0 或 0.1 配 top_p=1.0；做创意写作或多样化数据合成（AIGC）时用 temperature=0.7~0.9 配 top_p=0.9。

## 5. 🔧 生产排障指南

坑 1：同时把 temperature 调高又把 top_p 设得很小（如 0.1） → 解法：两者互相打架，只需固定 top_p=0.9~0.95 微调 temperature，或固定 temperature=1 调 top_p。

坑 2：以为设了 temperature=0 就 100% 可复现 → 解法：由于 GPU 浮点并行归约非结合性、MoE 批处理路由等原因，云端 API 即使 T=0 也可能有极小概率波动，需配合 seed 与 system_fingerprint 核对。

## 6. ❓ 高频面试追问与参考答法

Q1：Top-K 和 Top-P 的本质区别是什么？为什么现代框架更偏爱 Top-P？ 答：Top-K 截断数量固定，无法感知概率分布的“自信程度”；Top-P 根据累积概率动态调整候选池大小——模型很确定时候选极少（防胡说），模型不确定时候选增多（保留多样性）。

Q2：生成文本出现死循环重复（Repetition）怎么调参？ 答：除了检查是否误设过低温度或提示词冲突外，可适当增大 repetition_penalty（如 1.05~1.15）或 presence_penalty / frequency_penalty，并对流式输出做滑动窗口重复检测熔断。

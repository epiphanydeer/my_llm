## 本章总结：项目设计与评测系统

先用一张图讲清请求、状态和失败出口，再用相同输入说明如何对照、如何评分、何时可以上线。下列案例可用作白板练习。

### 案例 1 · 客服摘要费用翻倍

**面试官可能问**　每天把客服对话变成一份交接摘要，业务量没变，换模型后费用翻倍。怎么设计并定位？

```text
工单接入 → 去重与历史裁剪 → 模板组装 → 生成 → 必填项校验 → 用量账本
```

**系统设计**　先明确摘要必须保留的订单、金额和下一步，按语言与长度估算 token。把静态规则和可变历史分开，限制最大输出。用可追踪的调用账本累计缓存命中、截断、修复和重试，按成功摘要算账。

**评测系统**　同一套脱敏工单分别跑旧版和候选。人工标出必须保留的事实，覆盖长会话、中文、双语和订单号。有无遗漏和新增事实优先，另测每成功摘要成本、P95 和截断率。若成本下降来自更多截断，候选失败。

**常见追问与排障**　如果缓存命中不变，先查候选每次输出是否更长、模板是否重复拼了历史、是否因格式错误多跑一次。固定样本逐项关掉，避免把各环节变化归到单价。

**现场参考回答**

> 我先讲每条合格摘要的成本，再拆输入、缓存、输出和重试，最后用同一批工单证明费用下降且没有丢关键事实。

### 案例 2 · 现场报告提取与报告撰写共用服务

**面试官可能问**　同一个模型既要提取设备编号，也要生成给班组的文字说明。采样和验收怎么设计？

```text
按任务类型路由 → 字段提取或正文生成 → 各自校验 → 保存结果与错误
```

**系统设计**　提取用受约束输出和低温或贪心，设备编号要从原文核验。正文允许适度发散，给清楚的事实和禁止编造的边界。固定推理参数后才归因到模型更换，按场景保存温度、输出上限和模型版本。

**评测系统**　给提取题标字段与缺项，给撰写题标必含事实和禁加事实。提取看字段准确率、非法输出和误填，撰写看事实保留、是否引入新事实与人工可用率。对同题多跑几次，报告波动和尾延迟。

**常见追问与排障**　如果低温后输出还是错，确认错误是不是高概率的首选答案。检查原文证据、模板和解码约束，再决定是否有必要改温度。

**现场参考回答**

> 这两条路径使用不同验收规则。采样只改变候选选择，我用证据核验判断提取正确，用人工标注判断撰写是否可用。

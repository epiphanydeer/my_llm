### 8.6 多头注意力：形状拆分、GQA/MQA 与合并 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：单头注意力只能算出一套注意力权重矩阵——好比一个人读句子时，要么盯着“代词指代谁”，要么盯着“形容词修饰谁”，顾此失彼！而传统多头注意力（MHA）虽然能分头关注，但推理时每个头都要存一份 K 和 V，导致 KV Cache 显存大爆炸！

本节解法：① 拆解 **Multi-Head Attention（MHA）**把 C 维拆成 H 个 $d_k$ 子空间并行关注不同关系再拼接；② 演进到现代大模型标配 GQA（Grouped-Query Attention）：多个 Query 头共享一组 KV 头，兼顾表达力与显存节省！

大白话例子：MHA 就像找了 8 个专家同时读一份合同，1 号专家专盯日期、2 号专家专盯金额、3 号专家专盯违约条款，最后把 8 份意见拼在一起汇总；GQA 则是 8 个提问专家分成 2 组，每组 4 人共用同一套参考资料（KV 头），既保留了 8 个人的多视角提问，又把参考资料占的桌子（KV Cache 显存）直接缩小了 4 倍！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 压缩后的 KV 张量 (B, H_kv, T, d_k) 与每组共享的 Q 头数 n_rep = H_q // H_kv。 |
| ② 做什么 | 将 (B, H_kv, T, d_k) 沿头维度广播复制 n_rep 次对齐到 (B, H_q, T, d_k)，再与 Query 做点积注意力。 |
| ③ 输出什么 | 广播对齐后的 KV 张量 (B, H_q, T, d_k)。 |
| ④ 关键参数 | H_q / H_kv（MHA 时为 1；MQA 时 H_kv = 1；GQA 常为 4 或 8）。 |
| ⑤ 工程 Trade-off | MHA 精度高但 KV Cache 极大；MQA 极省显存但长文本推理质量略降；GQA（如 LLaMA-3 / Qwen2.5）是工业界最佳甜点。 |

#### 3. 💻 渐进式代码实操（Step 6：GQA repeat_kv 广播复用）

演进说明：在手写 MHA（见第 9 章 9.2 节）基础上，补充现代大模型核心演进 repeat_kv。

```python
"""8.6 Step 6: GQA (Grouped-Query Attention) KV 头广播复用与显存压缩."""

from __future__ import annotations

import numpy as np


def repeat_kv(x: np.ndarray, n_rep: int) -> np.ndarray:
    """将 (B, H_kv, T, d_k) 沿头维度重复 n_rep 次对齐到 (B, H_q, T, d_k)."""
    if n_rep == 1:  # [无需死背-脚手架] MHA 快速直通边界
        return x
    b, h_kv, t, dk = x.shape  # [必记设计决策-GQA显存压缩] H_kv < H_q，多组 Query 共享同一组 KV Cache
    return np.repeat(x, repeats=n_rep, axis=1).reshape(b, h_kv * n_rep, t, dk)  # [必背手撕-GQA广播复用] 沿头维度 repeat n_rep 次对齐到 (B, H_q, T, d_k)


if __name__ == "__main__":  # [无需死背-脚手架] 自测入口与头对齐断言
    kv = np.random.default_rng(0).normal(size=(2, 4, 6, 16))
    expanded = repeat_kv(kv, n_rep=4)
    assert expanded.shape == (2, 16, 6, 16)
    assert np.allclose(expanded[:, 0], expanded[:, 1])
    print("Ch8 Step 6 self-test passed!")
```

### 🧠 代码区记忆清单：背什么 vs 不背什么

🔒 不可替代的系统设计决策：GQA 通过减少 KV 头数（$H_{kv} < H_q$）大幅降低推理期 KV Cache 显存占用，同时保持接近 MHA 的表达能力。

✍️ 面试手撕/默写范围：repeat_kv 核心逻辑——沿头维度将 (B, H_kv, T, d_k) 重复 n_rep 次并对齐为 (B, H_q, T, d_k)。

🗑️ 无需死背的脚手架代码：n_rep == 1 短路判断与 __main__ 形状测试代码。

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：H_q 必须能被 H_kv 整除；广播复用只在计算注意力点积时发生，显存中物理存储的 KV Cache 依然只有 H_kv 个头！

讲清关键行：np.repeat(..., axis=1) 确保同一组内的 Query 头看到完全相同的 Key 和 Value。

主动点出工程细节：在 PyTorch/CUDA 算子（如 FlashAttention-2/3）中，GQA 甚至不需要显式 repeat 拷贝物理显存，核函数内部通过指针偏移直接跨组读取同一份 KV，真正做到零额外显存拷贝！

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：Tensor Parallel（张量并行）多卡切分时，卡数设成 8 但模型只有 4 个 KV 头

现象：启动 8 卡 TP 推理直接报错 num_kv_heads must be divisible by tensor_parallel_size。

定位方法：KV 头数小于 TP 卡数，无法均分切头。

修复方案：将 TP 卡数降为 4（或改用支持复制 KV 头的推理引擎配置）。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：对比 MHA、MQA 和 GQA 的本质区别？

参考答法：MHA 每个 Q 头配独立 KV 头；MQA 所有 Q 头共用 1 个 KV 头（极致省显存但略损精度）；GQA 把 Q 头分成 $G$ 组，每组共享 1 个 KV 头，兼顾了 MHA 的表征能力与 MQA 的高并发低显存。

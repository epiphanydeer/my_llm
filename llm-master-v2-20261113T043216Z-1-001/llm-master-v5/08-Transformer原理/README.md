## 本章总结：项目设计与评测系统

先用一张图讲清请求、状态和失败出口，再用相同输入说明如何对照、如何评分、何时可以上线。下列案例可用作白板练习。

### 案例 1 · 把长文模型上下文扩到更长

**面试官可能问**　产品希望长规程整本阅读。如何解释 RoPE、GQA 和长上下文的选择？

```text
上下文目标 → 距离分层测试 → 配合模型的 RoPE 配置 → 比较注意力与缓存策略 → 联合质量和容量验收
```

**系统设计**　先问用户是局部找条款还是需要全局关联。局部问题优先检索，必须长文跨段关联时才比较长上下文方案。模型既有 GQA 能减小 KV 头数，FlashAttention 减少注意力 I/O，位置外推仍需质量验证。

**评测系统**　固定模型权重与其支持的扩窗方案，按长度、证据位置与跨度做测试。对照原窗口内短文基线及长文分段检索基线，测近距与远距任务质量、短文回归、TTFT、峰值显存和可服务并发。

**常见追问与排障**　扩窗后准确率掉了，做同证据不同位置的对照，再查位置配置与 prompt 截断。单独量化显存，避免把性能瓶颈当成位置编码问题。

**现场参考回答**

> 我会先说明任务需要哪种跨度，再按证据位置和长度验证是否真的看得见、读得对，并把容量和质量一起报告。

### 案例 2 · 在推理端替换 Attention 实现

**面试官可能问**　相同模型里替换为更快的 Attention 内核，怎样保证掩码和数值行为一致？

```text
朴素算子作为参考 → 固定 Q/K/V 与掩码 → 候选算子 → 逐输入对照 → 模型回归与性能验收
```

**系统设计**　先固定因果、padding、GQA 头映射和 dtype 约定。长序列用分块实现减少中间矩阵 I/O；端到端收益取决于其余算子和负载。全遮挡输出按接口契约验证。

**评测系统**　测试多 batch、头配置、短长序列和全遮挡，按 dtype 的误差口径比输出。再用同任务比较下游 logits 差异、关键样本退化、峰值显存与延迟。白板写出一个 3-token 的因果可见矩阵辅助核验。

**常见追问与排障**　如果生成出现随机差异，先禁用采样、比较首个分叉位置的中间结果，再查 mask 广播和位置偏移。性能与数值误差分开归因。

**现场参考回答**

> 我会把接口契约和参考实现说清，再证明新内核在边界样本上等价，最终才谈吞吐收益。

### 8.3 端到端数据流：从 Token ID 到 Logits 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：很多同学背了一堆 Attention 公式，但面试官在白板上问一句：“输入一个 (B, T) 的整数 Token ID 矩阵，经过模型到底是怎么一步步变成 (B, T, V) 词表概率的？Weight Tying 又是怎么省显存的？”瞬间卡壳！

本节解法：完整串通 (B, T) -> (B, T, C) -> ... -> (B, T, V) 端到端张量维度流转，并讲清 Weight Tying（词嵌入与输出头权重共享）。

大白话例子：就像查字典写文章：先拿编号 (B, T) 去词典里查出每个词的语义身份证向量 (B, T, C)；经过几十层大脑思考加工后，形状依然保持 (B, T, C)；最后拿加工完的向量去和整本词典里所有 V 个词做相似度打分（x @ tok_emb.T），得出下一个最可能出现的词 (B, T, V)！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 整数 Token ID 矩阵 tok_ids: (B, T)（值域 [0, vocab_size)）。 |
| ② 做什么 | 查 Embedding 表映射到 (B, T, C) -> 叠加/注入位置信息 -> 经过 $L$ 层等维变换保持 (B, T, C) -> Final Norm -> 乘 LM Head 投影到词表空间。 |
| ③ 输出什么 | 未归一化的对数几率 logits: (B, T, V)（训练时全部位置算交叉熵，推理时只取 [:, -1, :]）。 |
| ④ 关键参数 | vocab_size ($V$，Qwen 约 15 万)、d_model ($C$)。 |
| ⑤ 工程 Trade-off | Weight Tying 让输入 Embedding 与输出 LM Head 共享同一块 $(V, C)$ 矩阵，对于词表很大（15 万词 × 4096 维 ≈ 1.2GB）的小参数模型（如 Qwen-0.5B/1.5B），直接省掉一半词表显存！ |

#### 3. 💻 渐进式代码实操（Step 3：端到端形状追踪与 Weight Tying）

演进说明：追踪核心张量从整数索引到词表 Logits 的形状变化。

```python
"""8.3 Step 3: 端到端张量形状追踪 ((B, T) -> (B, T, C) -> (B, T, V)) 与 Weight Tying."""

from __future__ import annotations

import numpy as np


def trace_transformer_shapes(batch: int, seq_len: int, d_model: int, vocab_size: int) -> dict[str, tuple[int, ...]]:
    rng = np.random.default_rng(0)  # 脚手架。随机数生成器与模拟输入
    tok_ids = rng.integers(0, vocab_size, size=(batch, seq_len))
    emb_table = rng.normal(size=(vocab_size, d_model))
    x = emb_table[tok_ids]  # 查表映射。(B, T) 整数索引查表映射为 (B, T, d_model)
    logits = x @ emb_table.T  # 权重共享。Weight Tying 复用词表矩阵转置输出 (B, T, V)，省去海量参数
    assert x.shape == (batch, seq_len, d_model)  # 脚手架。形状断言校验
    assert logits.shape == (batch, seq_len, vocab_size)
    return {"tok_ids": tok_ids.shape, "hidden": x.shape, "logits": logits.shape}


if __name__ == "__main__":  # 脚手架。自测入口
    shapes = trace_transformer_shapes(2, 6, 16, 100)
    assert shapes["logits"] == (2, 6, 100)
    print(f"Ch8 Step 3 self-test passed! shapes={shapes}")
```

### 示例说明与练习范围

本例的设计选择：Weight Tying（输入 Embedding 与输出 LM Head 共享权重转置）以大幅压缩词表层显存与参数量。

**代码练习｜能讲清设计**。闭卷推形状，不背 trace 函数。

示例辅助代码：default_rng 模拟词表生成、返回字典结构以及 __main__ 形状断言。

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：在整个 Transformer 主干（所有 Block 之间），张量形状永远保持 (B, T, C) 不变，只有入口查表从 2D 变 3D，出口 LM Head 把最后一维从 C 映到 V。

讲清关键行：x @ emb_table.T 展示了 Weight Tying 的本质——输入查表和输出分类共用同一套语义坐标系，语义越接近的词向量内积越大。

主动点出工程细节：推理生成最后一个词时，不需要对整个 (B, T, V) 算 LM Head，只取最后一个时间步 x[:, -1:, :] @ lm_head 算 (B, 1, V)，能省掉大量无用的大词表矩阵乘法！

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：词表扩充（新增特殊 Token）后加载微调模型直接报错形状不匹配

现象：RuntimeError: size mismatch for lm_head.weight。

定位方法：只扩了 tok_emb 忘记同步 resize_token_embeddings() 更新 lm_head，或破坏了 Weight Tying 绑定。

修复方案：统一调用 model.resize_token_embeddings(len(tokenizer)) 同步扩展并重新绑定。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：为什么输出词表很大时，推理前只切取最后一个 Token 算 lm_head 能显著省算力？

参考答法：假设 V=151936, C=4096, T=4096，如果整句都乘 lm_head，要算 $4096 \times 4096 \times 151936$ 次乘法；推理只需要下一个词的分布，只算最后一个 Token 能直接把 LM Head 计算量降到 $1/T$。

## 面试重点｜设计、调参与排障

**面试官可能问**

从 token ID 到下一 token 的分数，形状怎么变？

**参考回答（现场口述）**

输入 ID 是 B×T，经 Embedding 得到 B×T×C，Block 维持这三维。LM Head 把隐藏维变成词表维 V，得到 B×T×V。训练把位置 t 的 logits 对齐到位置 t+1 的标签，生成通常取最后一个有效位置的分数。

**系统设计怎么选**

从 (B,T) 查表得到 (B,T,C)，Block 保持宽度，LM Head 得到 (B,T,V)。常见权重绑定共享输入和输出权重，节省参数但仍要做投影。

**参数或条件改变会怎样**

词表变大时注意嵌入参数、输出矩阵计算和显存。训练取各有效位置，生成取最后有效位置。

**系统出错怎么查、怎么验证**

发生 shape 错位时逐层打印。若批次存在 padding，生成要检查最后有效位置是否取对。

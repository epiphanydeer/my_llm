# 10.1 模型选型：先确认任务与能力边界【🔥 必会】

## 1. 🎯 本节目标与大白话例子

本节目标：建立“任务类型 + 硬约束（延迟/成本/合规）+ 评测集”驱动的选型方法，拒绝盲目追逐榜单排名。

大白话例子：买车不能只看赛道百公里加速榜（LMSYS 榜单）：如果每天要在矿区泥路拉货（数据不出域+低延迟），法拉利不仅上不了路，油费还爆表；必须先用硬约束筛掉不合规车型，再比性价比。

## 2. 🧠 核心原理与五维拆解

选型四步法：1）定义核心任务与失败代价；2）锁定硬约束（是否要求私有化、P95 延迟上限、单次成本预算、上下文长度）；3）在自有评测集跑同题对比；4）确定“主模型 + 降级/路由小模型”组合。

开源微调 vs 闭源 API 临界点：通用复杂推理、冷启动验证优先闭源强 API；垂直格式固化、数据绝对保密、高频低延迟且 QPS 足够摊薄算力时，选开源中杯模型（如 7B~32B）微调/量化自部署。

## 3. 💻 渐进式代码实操（ch10_code/step_01_model_selection_scorer.py）

```python
"""10.1 模型选型：业务硬约束过滤与加权打分器"""
from dataclasses import dataclass
from typing import List


@dataclass
class ModelCandidate:  # 脚手架。候选模型属性容器
    name: str
    eval_score: float       # 0~100
    p95_latency_ms: float
    cost_per_1m_usd: float
    supports_on_prem: bool


def select_models(
    candidates: List[ModelCandidate],
    max_latency_ms: float,
    require_on_prem: bool,
    min_eval_score: float,
) -> List[str]:
    """先用硬约束筛掉不合规候选，再按质量/成本性价比排序。"""
    feasible = [
        m for m in candidates
        if m.p95_latency_ms <= max_latency_ms  # 硬约束前置过滤。延迟/效果底线/私有化不达标直接一票否决
        and m.eval_score >= min_eval_score
        and (not require_on_prem or m.supports_on_prem)
    ]
    feasible.sort(key=lambda m: (m.eval_score / max(m.cost_per_1m_usd, 0.01)), reverse=True)  # 性价比排序。分母加下限防除零
    return [m.name for m in feasible]


if __name__ == "__main__":  # 脚手架。候选池与过滤断言
    pool = [
        ModelCandidate("Cloud-Flagship", 92.0, 1800, 10.0, False),
        ModelCandidate("Qwen-32B-Int4", 87.5, 950, 1.2, True),
        ModelCandidate("Tiny-7B", 72.0, 300, 0.3, True),
    ]
    ranked = select_models(pool, max_latency_ms=1200, require_on_prem=True, min_eval_score=85.0)
    assert ranked == ["Qwen-32B-Int4"]
    print("[10.1 PASS]", ranked)
```

## 面试重点｜设计、调参与排障

**面试官可能问**

公开榜分更高的模型为什么没有入选？

**参考回答（现场口述）**

我先按数据边界、延迟、硬件和成本硬约束筛选，再用自己的任务集比较达标成功率。公开榜的题型与真实流量可能不同。若高分模型在关键切片、稳定性或成本上过不了门槛，我会记录具体淘汰原因。

**系统设计怎么选**

先用数据出域要求、时延、模态、可部署性和预算筛选，再在同一业务样本上测质量。用真实的错例说明取舍。

**参数或条件改变会怎样**

提高输出或视觉预算可能改善难例，也提升成本。用每成功任务费用与延迟作为约束。

**系统出错怎么查、怎么验证**

不同模型结果不可比时，检查输入、模板、版本和评测口径。一起列出模型成功与不能处理的场景。

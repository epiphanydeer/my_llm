## 本章要学会什么

- **能回答的设计题。** 能把模型选型讲成一次工程决策，包括硬约束、同集对比、困难切片、成本与可逆发布，说明哪些变化会让选型反转。

- **代码练到哪。** 模型榜单、成本计算器和汇总脚本作为查阅项。只有简历涉及 MoE、路由或推理内核时再练相关小片段。

## 本章总结：项目设计与评测系统

先用一张图讲清请求、状态和失败出口，再用相同输入说明如何对照、如何评分、何时可以上线。下列案例可用作白板练习。

### 案例 1 · 为内部助手做模型选型和切换

**面试官可能问**　公开榜最高的模型贵、数据还可能不能出域，如何选候选并切流？

```text
硬约束筛选 → 可行候选 → 同任务评测 → 分流验证 → 保留回滚入口
```

**系统设计**　先确认数据边界、时延和资源预算。统一输出验收与模型调用接口，在满足硬约束的候选中比较业务成功、时延和总成本。评估迁移、监控、运维与空闲成本，采用可逆灰度。

**评测系统**　冻结真实题与关键切片，用同语义的输入和相同验收。报事实正确、正确拒答、格式合规、P95 和每成功任务成本。逐题分析两模型谁修好、谁退化，硬约束单列发布门槛。

**常见追问与排障**　榜单领先但本地题失败，用差异样本检查语言、长文、结构化和工具需求。固定输入条件再追模型差异。

**现场参考回答**

> 我会先排除不满足约束的模型，再讲同题证据和回滚路径。任何排名都要回到这个业务分布。

### 案例 2 · 用小模型处理大多数请求，何时转大模型

**面试官可能问**　想用模型路由降本，什么条件升级到强模型，怎么防止低成本掩盖漏判？

```text
任务分类与难度特征 → 小模型或大模型 → 输出校验 → 风险升级或人工 → 质量与账本
```

**系统设计**　将简单提取和需要多证据的决策分开。小模型优先做已验证的简单项，证据不足、校验失败或高风险样本升级。预算中计入两次调用，路由阈值以实际标签校准。

**评测系统**　对照全大模型、全小模型与级联。用同题标风险、复杂度和可答性。看关键任务成功率、升级率、路由漏升级率、总体与分组 P95、每成功任务成本。设置高风险失败触发回滚。

**常见追问与排障**　总成本可能下降，但升级中的长尾更慢。按直出和升级路径分别定位延迟与漏判，再调路由阈值。

**现场参考回答**

> 我用任务风险和校验结果驱动路由，对照三套基线。节省的钱要能覆盖额外调用，同时高风险切片必须过门槛。

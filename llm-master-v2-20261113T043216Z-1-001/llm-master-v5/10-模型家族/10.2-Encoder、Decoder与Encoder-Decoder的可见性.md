# 10.2 Encoder、Decoder 与 Encoder-Decoder 的可见性【🔥 必会】

## 1. 🎯 本节目标与大白话例子

本节目标：从注意力掩码（Attention Mask）的可见性矩阵出发，彻底讲清 Encoder-only、Decoder-only 和 Encoder-Decoder 三大架构的本质差异。

大白话例子：Encoder 像做阅读理解完形填空，一眼能同时扫完整篇文章（双向全可见）；Decoder 像现场即兴接龙，写第 5 个字时只能看前 4 个字，绝不能偷看后面的字（因果下三角掩码）；Encoder-Decoder 则是先全览原文再逐字翻译（前缀双向+后缀因果交叉注意力）。

## 2. 🧠 核心原理与五维拆解

Encoder-only（如 BERT、BGE）：双向全注意力，表征能力极强，至今仍是 Embedding 向量召回与 Cross-Encoder 精排的绝对主力。

Decoder-only（如 GPT、Qwen、Llama、DeepSeek）：因果下三角掩码（Causal Mask），天然契合 Next-Token Prediction；KV Cache 复用效率最高，扩展律（Scaling Law）最稳定，成为通用大语言模型统一基座。

Encoder-Decoder（如 T5、BART）：输入双向编码 + 输出自回归解码，适合严格序列到序列转换（如传统机器翻译），但在超大规模通用预训练上架构复杂度与推理缓存不如纯 Decoder 简洁。

## 3. 💻 渐进式代码实操（ch10_code/step_02_architecture_visibility_masks.py）

```python
"""10.2 Encoder、Decoder 与 Encoder-Decoder 的注意力可见性掩码对比"""
import numpy as np


def build_visibility_masks(seq_len: int) -> dict:
    """生成三种经典架构的 0/1 注意力可见性矩阵（1=可见，0=屏蔽）。"""
    encoder_mask = np.ones((seq_len, seq_len), dtype=int)  # [必背手撕-Encoder双向全可见掩码] 所有 token 互见
    decoder_causal_mask = np.tril(np.ones((seq_len, seq_len), dtype=int))  # [必背手撕-Decoder下三角因果掩码] 仅可见当前及历史 token
    prefix_lm_mask = decoder_causal_mask.copy()
    prefix_len = seq_len // 2
    prefix_lm_mask[:prefix_len, :prefix_len] = 1  # 前缀双向可见，后缀因果自回归  # [必记设计决策-PrefixLM混合可见性] 前缀双向编码，后缀自回归因果生成
    return {
        "encoder_bidirectional": encoder_mask,
        "decoder_causal": decoder_causal_mask,
        "prefix_lm": prefix_lm_mask,
    }


if __name__ == "__main__":  # [无需死背-脚手架] 掩码矩阵元素断言
    masks = build_visibility_masks(4)
    assert masks["encoder_bidirectional"].sum() == 16
    assert masks["decoder_causal"][0, 1] == 0 and masks["decoder_causal"][2, 1] == 1
    assert masks["prefix_lm"][0, 1] == 1 and masks["prefix_lm"][2, 3] == 0
    print("[10.2 PASS] masks verified")
```

### 🧠 代码区记忆清单：背什么 vs 不背什么

🔒 不可替代的系统设计决策：三种架构的核心差异在于注意力可见性：Encoder 全 1 双向可见，Decoder 下三角因果可见，Prefix-LM/Encoder-Decoder 前缀双向、后缀因果。

## 4. 🗣️ 面试官视角：这段代码怎么讲

面试被问到为什么大模型统一到了 Decoder-only，我通常从两方面答：一是训练信息密度——每个 Token 都在做预测，没有双向掩码导致的秩崩溃（Rank Collapse）或信息泄漏；二是工程上多轮对话时历史前缀的 KV Cache 可以直接无缝追加复用。

## 5. 🔧 生产排障指南

坑 1：误用纯 Decoder 模型做短文本密集向量检索且不做专门对比学习训练 → 解法：因果掩码导致最后一个 Token 才聚合全句信息，未经对比微调直接取均值池化效果往往不如原生双向 Encoder。

## 6. ❓ 高频面试追问与参考答法

Q1：为什么现代通用 LLM 几乎全部选择了 Decoder-only，而 RAG 里的 Embedding/Reranker 却大量保留 Encoder-only？ 答：生成任务需要自回归续写与高效 Prefix KV Cache 复用，Decoder-only 最优；而检索/精排只需把整段文本压缩成高密度语义表征或判断 Query-Doc 交互得分，双向注意力能同时捕捉上下文全局关联，且模型体积小（0.1B~0.6B）延迟极低。

# 10.7 模型选型面试：同任务与失败切片【🔥 必会】

## 1. 🎯 本节目标与大白话例子

本节目标：掌握面试中回答“你为什么选这个模型？”的黄金标准模板：同评测基线 → 失败切片（Error Slicing）归因 → 成本延迟权衡 → 可逆升级路径。

大白话例子：不能只说“我测了 A 和 B，感觉 A 更好”，就像体检报告不能只写“总分 85 分”——必须拆开看心电图、肝功、视力分别哪项扣分（失败切片），才能精准决定是配眼镜（换高分辨率 VLM）还是降脂（加长上下文或 RAG）。

## 2. 🧠 核心原理与五维拆解

面试高分四步答法：

同任务基线：锁定同一份业务黄金测试集（注明样本量 $N$ 和核心指标）。

失败切片分析（Error Slicing）：把错题按维度切片（如 long_context、json_schema、small_object_ocr、multi_hop_reasoning），定位具体短板。

权衡取舍：说明为何不选更贵/更慢的方案，以及当前方案如何满足延迟与预算约束。

可逆性设计：通过统一网关/路由接口封装，确保未来新模型发布时可零代码或低成本灰度切换。

## 3. 💻 渐进式代码实操（ch10_code/step_07_error_slicing_benchmark.py）

```python
"""10.7 模型选型面试：同任务评测与失败切片归因分析器"""
from collections import Counter
from dataclasses import dataclass
from typing import Dict, List


@dataclass
class EvalSample:  # 脚手架。评测样本切片记录类
    sample_id: str
    slice_tag: str  # e.g. "long_context" | "json_schema" | "small_object_ocr"
    passed: bool


def analyze_failure_slices(samples: List[EvalSample]) -> Dict[str, object]:
    total = len(samples)
    passed = sum(s.passed for s in samples)
    fail_by_slice = Counter(s.slice_tag for s in samples if not s.passed)  # 失败切片频次归因。按场景标签聚合失败样本
    return {
        "overall_accuracy": round(passed / total, 3),
        "top_failure_slice": fail_by_slice.most_common(1)[0] if fail_by_slice else None,  # 定位短板切片。面试选型不仅报总准确率，更要指出头号失败切片
        "failure_breakdown": dict(fail_by_slice),
    }


if __name__ == "__main__":  # 脚手架。四样本切片统计测试
    eval_set = [
        EvalSample("s1", "long_context", True),
        EvalSample("s2", "small_object_ocr", False),
        EvalSample("s3", "small_object_ocr", False),
        EvalSample("s4", "json_schema", True),
    ]
    report = analyze_failure_slices(eval_set)
    assert report["overall_accuracy"] == 0.5 and report["top_failure_slice"][0] == "small_object_ocr"
    print("[10.7 PASS]", report)
```

### 示例说明与练习范围

本例的设计选择：模型选型评测不能只汇报单一 overall_accuracy，必须按 slice_tag 对失败样本切片归因，识别高频短板场景（如 small_object_ocr）。

## 4. 🗣️ 面试官视角：这段代码怎么讲

被问到模型选型时，我习惯直接亮出 Error Slicing 切片数据：比如总体准确率 50% 看似很低，但切片后发现失败全集中在 small_object_ocr 切片上，从而有理有据地决定引入 ROI 裁剪或切换支持动态高分辨率的 VLM，而不是盲目把 7B 换成 72B。

## 5. 🔧 生产排障指南

坑 1：只汇报总体准确率，遇到性能瓶颈就盲目“加大模型参数” → 解法：如果是检索漏召回或图片分辨率太糊导致的错误，把 7B 换成 70B 也照样错，必须先做 Error Slicing 归因。

## 6. ❓ 高频面试追问与参考答法

Q1：面试官问：“如果下个月出了一个性能更好的新开源模型，你们现在的系统怎么平滑切换？” 答：1）应用层通过 OpenAI 兼容网关解耦模型名称；2）把旧模型时期的黄金评测集与 Bad Case 切片保留为回归套件；3）新模型先过回归集与阴影流量（Shadow Traffic）对比，确认无退化且延迟达标后再按 10%→50%→100% 灰度切流。

## 面试重点｜设计、调参与排障

**面试官可能问**

两个模型都有改善和退化，你如何选择并说服团队？

**参考回答（现场口述）**

先按不能退化的任务与成本约束筛一轮，再用同题逐样本列新增正确、退化和触发条件。重视关键切片的实际影响，能接受的风险用灰度和回滚门槛管理。结论附上真实样本和代价。

**系统设计怎么选**

用同一批样本做可复现的成对比较。先过安全、隐私和延迟门槛，再考虑正确率与成本。保留一个不适合迁移的切片。

**参数或条件改变会怎样**

阈值变化会改变自动覆盖和人工量，用同负载报告净增益与尾延迟，定灰度比例与回滚阈值。

**系统出错怎么查、怎么验证**

坏例分类后抽查证据、版本和标注，再判断是数据、模型还是部署问题。把关键退化写入回归集。

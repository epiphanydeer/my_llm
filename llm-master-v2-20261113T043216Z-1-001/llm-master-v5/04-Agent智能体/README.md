# 第四章 Agent 智能体系统：渐进式面试备考全集

本章围绕**「企业工单与故障诊断 Agent」**统一实战场景，从 Step 1 的 50 行极简 O-T-A 状态机起步，每节叠加一个核心工程模块，最终拼装成一套完整的工业级 Agent Harness（智能体工程脚手架）。

## 本章要学会什么

- **能回答的设计题。** 面对查规程、建工单等任务，能判断何时用 Workflow、何时让 Agent 作动态决策，并设计权限、预算、重试和终局验收。
- **能提供的验证证据。** 能推演写成功后超时、同轮工具配对、循环空转和预算用尽，解释每种情况如何终止、降级或转人工。先看 4.2–4.7、4.11、4.14、4.15。
- **代码练到哪。** 把 4.1 和 4.4 合成一次闭卷练习，写最小状态循环、工具执行和回传。其余以画流程和走故障案例为主。

## 本章总结：项目设计与评测系统

先用一张图讲清请求、状态和失败出口，再用相同输入说明如何对照、如何评分、何时可以上线。下列案例可用作白板练习。

### 案例 1 · Agent 诊断异常并创建工单

**面试官可能问**　Agent 要先查告警和历史工单，再按规则决定是否创建工单。如何避免重复写入和假报完成？

```text
状态机 → 按需读工具 → 草稿 → 权限与人工确认 → 幂等写入 → 后端回执核验
```

**系统设计**　把动态查证留给 Agent，写入由确定性流程管理。宿主维护工具白名单、步数、截止时间和每次业务意图的幂等键。工具超时先查后端状态，最终答复根据权威回执区分已受理、已完成与失败。

**评测系统**　用可回放告警与真实工单状态的模拟数据，给每题标应走动作、必查证据与预期终态。注入写成功但响应丢失、重复调用、未授权与工具不可用。与固定 Workflow 比较成功率、同题多次均成功率、重复副作用、P95 和成本。

**常见追问与排障**　模型说已建单但查不到工单，检查回执是否同一业务意图、是否仅被受理。用一次故障 trace 证明核验能识别模型的错误汇报。

**现场参考回答**

> 我先在白板画读与写两条路。读可以动态试，写必须有授权、幂等和回执，评测直接查外部状态。

### 案例 2 · 多来源排查助手，要不要做多 Agent

**面试官可能问**　一套排查流程要读知识库、工单和日志。何时用 DAG 或 Reviewer，怎样证明确实有用？

```text
任务计划 → 并行只读查证 → 汇总与独立验收 → 失败重规划或转人工
```

**系统设计**　先以单 Agent 或固定工具工作流为基线。只有依赖能拆、数据可隔离或高风险结果需要独立证据时才增加角色。宿主并发前预扣预算，交接只传必要字段和证据引用，DAG 保存完成节点并限制返工。

**评测系统**　用同一批简单题、多来源冲突题和一个工具挂掉的题，对比单 Agent、DAG 和加 Reviewer。核查是否拿齐正确证据、是否修掉原退化、可恢复率、额外模型调用、P95 和总成本。记录例外和返工轨迹。

**常见追问与排障**　若 Reviewer 只让成本上涨，逐题查它究竟纠正了哪条事实。它若复用同一证据和判断方式，优先给独立验收标准或移除该角色。

**现场参考回答**

> 我会先证明单 Agent 在哪类任务失败，再明确拆分后获得什么。用同题对照决定是否值得加角色。

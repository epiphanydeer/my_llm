### 4.15 生产防线二：终局事实核验与写操作回执门禁 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：在跑完一整套工具链准备给用户吐出最终回答前，LLM 依然可能犯两个最致命的幻觉错误：① 无中生有（工具根本没查出 CPU=96%，模型自己在终局总结里瞎编一个数字）；② 口头谎报成功（模型压根没调 restart_service 或工具执行失败了，它却在最终回复里信誓旦旦地告诉用户“我已经帮您重启了 db-02！”）。

本节解法：在输出给用户之前架设最后一道硬门禁——FactAndReceiptGate（终局事实核验与写操作回执门禁）：① 所有关键事实主张必须能在真实 observations 中找到证据；② 凡是声明完成了某项写操作的，必须在执行日志中存在 success=True 且带非空 receipt_id 的工具回执。

大白话例子：就像财务出纳发付款通知：嘴上说“已经给供应商打了 50 万”不算数，系统发布前必须拿着**银行转账成功回执单号（receipt_id）和对账单原件（observations）**核验通过，少一张回执单就直接把这条通知拦在门内！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 回答中的关键事实主张 claimed_facts、声明已执行的写动作 claimed_write_actions、真实工具观测列表 observations、工具执行回执列表 receipts: List[ToolReceipt]。 |
| ② 做什么 | ① 核验 claimed_facts 是否均有真实 observations 支撑；② 提取所有 r.success and r.receipt_id.strip() 的有效回执动作集合，核验 claimed_write_actions 是否全部命中。 |
| ③ 输出什么 | VerificationResult(passed, missing_evidence, missing_receipts)。 |
| ④ 关键参数 | receipt_id（必须由工具执行层真实返回，绝不由模型伪造）。 |
| ⑤ 工程 Trade-off | 终局门禁增加了极微小的后置校验开销，却能 100% 物理阻断“谎报写操作成功”这类 P0 级信任危机事故。 |

知识扩展（面试加分盲区）：

为什么模型会“口头谎报成功”？：当某个写工具因为权限不足或超时失败后，模型为了“迎合用户完成任务的偏好（Sycophancy）”，很容易在总结时产生幻觉，假装自己已经做完了。只靠 Prompt 里写“没成功不要说成功”是拦不住的，必须在 Harness 代码层做 Receipt-Gated Publishing（回执门禁发布）。

全章 15 步闭环收官总结：从 Step 1 的最小 O-T-A 状态机出发，我们依次叠加了 HybridRouter 分诊、Tool 沙箱、ReAct 协议栈、原子记忆窗口、韧性重试与幂等控制、Pass^k 评测、MCP 协议、DAG 调度、Multi-Agent 隔离与交接投影、Browser 安全提取、双模式熔断器，直到 Step 15 的终局回执门禁——拼装成了一套完整的工业级 Agent Harness！

#### 3. 💻 渐进式代码实操（Step 15：FactAndReceiptGate 终局核验门禁）

演进说明：全章最后一块拼图，为 Agent 的最终出口加上事实依据核验与写操作回执硬门禁。

```python
"""Step 15: Fact and Receipt Gate (终局事实核验与写操作回执门禁).

生产 Agent 上线前的最后一道防线，杜绝“口头谎报成功”与“无证据编造”：
1. 事实核验：输出中的关键结论必须能在工具观测证据 (observations) 中找到依据。
2. 写操作回执门禁：凡是声明“已退款/已重启/已关闭工单”的动作，必须在工具执行日志中存在对应的成功回执 (receipt_id)。
"""

from __future__ import annotations

from dataclasses import dataclass
from typing import List


@dataclass
# [无需死背-脚手架] 回执与校验结果 dataclass 容器无需死背
class ToolReceipt:
    action_type: str
    receipt_id: str
    success: bool


@dataclass
class VerificationResult:
    passed: bool
    missing_evidence: List[str]
    missing_receipts: List[str]


class FactAndReceiptGate:
    """终局回答发布前的事实与回执门禁."""

    def verify(
        self,
        claimed_facts: List[str],
        claimed_write_actions: List[str],
        observations: List[str],
        receipts: List[ToolReceipt],
    ) -> VerificationResult:
        """核验每条关键事实与每项写操作声明是否均有真实工具证据支撑."""
        # [必记设计决策-事实证据核验] 最终输出宣称的关键数字/实体必须在工具 observations 中真实出现，防终局幻觉
        joined_obs = "\n".join(observations)
        missing_evidence = [fact for fact in claimed_facts if fact not in joined_obs]

        # [必背手撕-写操作回执门禁] 仅当工具执行返回 success=True 且带非空 receipt_id 时，才允许模型声称“已执行”
        valid_actions = {r.action_type for r in receipts if r.success and r.receipt_id.strip()}
        missing_receipts = [act for act in claimed_write_actions if act not in valid_actions]

        # [必记设计决策-双门禁缺一不可] 事实依据与写操作回执必须全部通过，未通过则退回重写或降级提示
        passed = not missing_evidence and not missing_receipts
        return VerificationResult(
            passed=passed,
            missing_evidence=missing_evidence,
            missing_receipts=missing_receipts,
        )


if __name__ == "__main__":
    gate = FactAndReceiptGate()

    # 1. 幻觉场景：模型口头声称“已重启 db-02”，但没有对应成功回执
    bad = gate.verify(
        claimed_facts=["db-02", "96%"],
        claimed_write_actions=["restart_service"],
        observations=['{"node": "db-02", "CPU": "96%"}'],
        receipts=[],
    )
    assert not bad.passed and bad.missing_receipts == ["restart_service"]

    # 2. 真实通过场景：既有观测事实，又有写操作回执
    good = gate.verify(
        claimed_facts=["db-02", "96%"],
        claimed_write_actions=["restart_service"],
        observations=['{"node": "db-02", "CPU": "96%"}'],
        receipts=[ToolReceipt(action_type="restart_service", receipt_id="rcpt-8891", success=True)],
    )
    assert good.passed and not good.missing_evidence and not good.missing_receipts
    print("Step 15 self-test passed!")
```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：任何对外宣称“已执行”的写操作，必须能在系统级 receipts 中找到 success=True 且 receipt_id 非空的真实记录。

讲清关键行：valid_actions 只认宿主工具层写入的 ToolReceipt，绝不信任模型自己在文本里编的“操作编号”；校验失败时精确返回 missing_evidence 和 missing_receipts 便于定向重写或降级拦截。

主动点出工程细节：对于关键写操作结果（如退款金额、工单状态变更），生产 UI 层最好直接由后端根据 ToolReceipt 渲染确定性结果卡片，而不完全依赖大模型用自然语言转述。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：用户投诉“Agent 说已经帮我提交了退款，但后台根本没收到申请”

现象：对话记录里模型回复“已为您提交退款”，但工具调用记录为空或返回了报错。

定位方法：审计模型终局输出与工具执行日志，发现缺少发布前的回执一致性门禁。

修复方案：上线 FactAndReceiptGate 门禁，拦截无回执的写操作声明并触发降级提示“当前未能完成自动提交，请人工处理”。

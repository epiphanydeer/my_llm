### 5.6 数据清洗、去重与合规脱敏 【⭐ 理解】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：俗话说 “Garbage In, Garbage Out”。从线上工单导出的原始微调语料里，常常混杂着大量重复刷屏的“谢谢/已解决”、只有 1 个字的无效回复，以及用户的真实手机号、身份证号——一旦训进模型权重里，模型不仅会变傻复读，还可能在别人提问时把某位客户的手机号背出来（严重隐私合规事故）！

本节解法：构建 SFTDataSanitizer（数据清洗与合规脱敏器）：① 长度与乱码过滤；② 规范化哈希精确去重（生产可升级 MinHash 近似去重）；③ 手机号/身份证号正则脱敏替换。

大白话例子：就像进厨房炒菜前的洗菜工序：烂菜叶扔掉（过短/乱码过滤）、一模一样重复称的菜退掉（去重）、把菜上面粘着的别人家快递单号撕掉涂黑（PII 脱敏），最后下锅（送进模型训练）的才是干净食材！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 原始指令微调语料 samples、最小有效字符数 min_chars。 |
| ② 做什么 | 对每条 instruction 和 output 先做 PII 正则脱敏 -> 过滤低于 min_chars 的无效短文本 -> 计算规范化 SHA-256 指纹去重。 |
| ③ 输出什么 | 清洗后的安全语料列表及统计计数（kept、dropped_short、dropped_dup）。 |
| ④ 关键参数 | min_chars、近似去重 Jaccard 阈值（MinHash LSH 常设 0.8）。 |
| ⑤ 工程 Trade-off | 宁缺毋滥——在 SFT 阶段，1,000 条人工精筛去重的高质量样本，效果远胜 50,000 条充满重复和噪音的脏数据（LIMA 论文核心结论：Less Is More for Alignment）。 |

#### 3. 💻 渐进式代码实操（Step 6：SFTDataSanitizer 清洗与脱敏）

演进说明：补全第五章数据入口最后一块拼图，确保进入 Step 2~3 训练的数据干净、无重复且零敏感隐私泄漏。

```python
"""5.6 Step 6: SFT 数据清洗、指纹去重与 PII 隐私合规脱敏."""

from __future__ import annotations

import hashlib
import re
from typing import Dict, List, Set


PHONE_RE = re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)")  # 脚手架
ID_CARD_RE = re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)")


def mask_pii(text: str) -> str:
    text = PHONE_RE.sub("[PHONE_MASKED]", text)  # 入库前确定性PII脱敏防记忆背诵
    text = ID_CARD_RE.sub("[ID_MASKED]", text)
    return text


def sanitize_sft_corpus(samples: List[Dict[str, str]], min_chars: int = 3) -> Dict[str, object]:
    seen_hashes: Set[str] = set()
    cleaned: List[Dict[str, str]] = []
    dropped_short = 0
    dropped_dup = 0

    for row in samples:
        q = mask_pii(row.get("instruction", "").strip())
        a = mask_pii(row.get("output", "").strip())
        if len(q) < min_chars or len(a) < min_chars:  # 极短噪声样本过滤
            dropped_short += 1
            continue
        fp = hashlib.sha256(f"{q.lower()}||{a.lower()}".encode("utf-8")).hexdigest()  # 归一化文本指纹精确去重
        if fp in seen_hashes:
            dropped_dup += 1
            continue
        seen_hashes.add(fp)
        cleaned.append({"instruction": q, "output": a})

    return {
        "cleaned": cleaned,
        "kept": len(cleaned),
        "dropped_short": dropped_short,
        "dropped_dup": dropped_dup,
    }


if __name__ == "__main__":  # 脚手架
    raw = [
        {"instruction": "查工单", "output": "请联系 13812345678 处理"},
        {"instruction": "查工单", "output": "请联系 13812345678 处理"},
        {"instruction": "a", "output": "b"},
    ]
    out = sanitize_sft_corpus(raw, min_chars=3)
    assert out["kept"] == 1 and out["dropped_dup"] == 1 and out["dropped_short"] == 1
    assert "[PHONE_MASKED]" in out["cleaned"][0]["output"]
    print("Ch5 Step 6 self-test passed!")

```

### 示例说明与练习范围

- **本例的设计选择**：PII 隐私脱敏（手机号、身份证号等）必须在数据进入训练前完成，防止模型通过权重记忆背诵隐私；极短噪声样本直接丢弃。
- **代码练习｜能讲清设计**。会讲精确与近似去重边界，正则和清洗框架不背。
- **示例辅助代码**：正则字面量写法（`PHONE_RE` / `ID_CARD_RE`）、丢弃计数统计与 `__main__` 单元测试。

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：任何进训练集的语料绝不允许包含明文手机号/身份证号，且无完全重复样本。

讲清关键行：先 mask_pii 再做哈希去重，这样两条只差一个手机号的相同模板客服话术会被自动识别为同一条重复样本合并，提升去重效率！

主动点出工程细节：大规模语料去重时，除了精确哈希，还会用 MinHash + LSH 过滤相似度 $>0.8$ 的近似重复，并用 Sentence-BERT / 语义聚类保证指令多样性。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：微调后的模型总喜欢输出同一句套话，多样性极差

现象：不管怎么问，开头结尾全是某几句固定模板。

定位方法：训练集里大量同质化高频工单未做去重和下采样，占比高达 60%。

修复方案：执行精确 + 近似去重，并对高频意图做上限采样平衡分布。

## 面试重点｜设计、调参与排障

**面试官可能问**

重复、低质和敏感数据分别怎么清理？

**参考回答（现场口述）**

我先移除精确重复，再按模板、事件或近似指纹分组，确保相似样本不跨训练和测试。低质样本按规则筛后抽检，敏感字段按来源和类型脱敏并复核漏检。保留处理计数和版本来解释数据分布变化。

**系统设计怎么选**

先核来源授权，再做标准化、精确去重和近重复聚类。敏感字段检测结合规则和人工抽检，处理规则可审计。

**参数或条件改变会怎样**

相似度阈值过严可能删掉少数类、近义但标签不同的样本。比较保留量、类别覆盖与抽检误删率。

**系统出错怎么查、怎么验证**

失败时回查删除原因和跨集重复。留分布快照，确认罕见的高危案例未误删。

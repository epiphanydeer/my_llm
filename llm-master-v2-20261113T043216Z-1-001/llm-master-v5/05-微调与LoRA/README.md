# 第五章 微调选型与 LoRA 低秩适配：渐进式面试备考全集

本章围绕**「垂类企业客服/合规微调全流程」**，从选型决策、ChatML -100 损失掩码、纯手写 LoRA 低秩注入与无损合并，一路叠加到防模板泄漏、消融归因与数据清洗脱敏。

## 本章要学会什么

- **能回答的设计题。** 项目有知识过时、格式错乱或拒答问题时，能判断先改检索、提示词还是做微调。能解释数据分组、监督掩码、LoRA 与收益归因。
- **能提供的验证证据。** 能拿出固定测试集、同模板分组检查、逐样本退化分析。遇到 Loss 异常时，先查标签、批次、数据和梯度。
- **代码练到哪。** 训练或偏模型岗位加练 5.2 标签和 5.3 LoRALinear。应用岗先把 5.1、5.4、5.5 的选型与验证讲清。

## 本章总结：项目设计与评测系统

先用一张图讲清请求、状态和失败出口，再用相同输入说明如何对照、如何评分、何时可以上线。下列案例可用作白板练习。

### 案例 1 · 垂直客服格式总错，LoRA 值不值

**面试官可能问**　客服回复经常格式漂移，知识又每周更新。Prompt、RAG 和 SFT 怎么选？

```text
错例分层 → 规则与提示词基线 → RAG 版本路由 → 选择稳定行为做 SFT → 同集比较与灰度
```

**系统设计**　过时事实交给可更新知识库，先用 Schema 和短提示约束格式。只有模型持续无法满足稳定的领域表达或结构要求，才做 LoRA。按来源和模板分组切集，并只监督约定的助手输出。

**评测系统**　固定知识库、推理配置、黄金集和评分。比较现有 Prompt、优化 Prompt、同 Prompt 加 LoRA，按知识正确率、格式通过、语气、拒答、成本和退化切片报告。版本更新题衡量检索与微调的分工。

**常见追问与排障**　若格式通过上涨、事实准确度下降，按错例查模型是否学到新模板中的旧规则，或者截断丢失证据。确认训练数据和推理提示是否一致。

**现场参考回答**

> 我会先说清要修的是知识还是行为，再做同集消融。只有在控制变量后改善且关键切片能守住时，才给微调上线。

### 案例 2 · 少量视觉标注下给 VLM 做增量训练

**面试官可能问**　巡检模型在夜间小目标上漏报，是否适合冻结视觉主干再加适配器？

```text
夜间错例拆解 → 采集与事件分组 → 提示和 ROI 基线 → 最小适配器 → 独立评测
```

**系统设计**　先确认原图真有可见证据，再测试 ROI 或更清晰输入。只在同样视觉输入下仍持续失败时试 projector 或 LoRA，按成本逐步放开参数。使用实际 processor 核对图像前缀、Assistant 标签、结束符与移位。

**评测系统**　同一事件及近重复帧不得跨集合。按光线、遮挡、小目标和摄像头分组。对照固定输入下的提示词、ROI 和适配器组合，测漏报、未知率、白天退化和 P95，并报告样本数。

**常见追问与排障**　训练 Loss 降了、夜间指标没动，先区分看不清与读错。查看真实输入 ROI、标签覆盖和退化样本，复核同场景泄漏后再考虑调整训练超参。

**现场参考回答**

> 我先证明失败发生在哪个环节，再说为什么要训模型。用按事件切分和同输入对照排除错把数据泄漏当收益。

# 为什么有了大模型还需要RAG？幻觉、私有知识、时效性四大问题

常看公众号文章的朋友们肯定知道，我们在之前几篇推文已经建立了应用开发的基础认知。从这篇开始，我们进入一个具体的系统方向——大模型主要落地项目之一、面试里最频繁被问到的 RAG。



## 一、从一个真实的困境说起

假设你们公司有几千份内部文档：产品手册、操作规范、历史项目经验、客户合同……领导想做一个 AI 问答系统，让员工随时可以问"我们的退款政策是什么"、"这个客户签了哪些条款"，系统能直接给出准确答案。

你直接用大模型来做，第一轮测试效果还不错——但很快发现几个绕不开的问题：

- 模型对公司内部文档一无所知，回答全靠"编"
- 产品文档上周刚更新，但模型说的还是老版本的内容
- 模型回答的很流畅，但根本无法知道它说的是真是假，也无法追溯来源
- 文档加载到 Prompt 里，token 成本高到无法接受

这不是模型能力不够的问题，而是大模型作为一种技术，有几个根本性的天花板——而 RAG 就是为了突破这些天花板而诞生的。

------

## 二、大模型的局限性

要理解 RAG，必须先想清楚大模型到底有哪些内生局限。

下面这张图展示了纯大模型在知识层面存在的几个边界：

![大模型知识缺失和幻觉问题示意图](https://file1.kamacoder.com/i/bagu/Snipaste_2026-04-14_22-18-35.png?v=20261005)

### 1. 幻觉问题（Hallucination）

大模型的本质是一个概率语言模型，它在生成每个 token 时做的是"预测下一个最可能的词"，而不是"从知识库里查询正确答案"。

这意味着当它不知道答案时，它不会说"我不知道"——它会生成一个"听起来最合理"的答案。这个答案可能完全是捏造的，但语气坚定、格式工整，让人难以判断真假。

在企业场景里，幻觉的危害远比"回答错误"更严重——它会以可信的方式传播错误信息，而用户毫不知情。

### 2. 私有知识问题

大模型是在公开数据上训练的。你们公司的内部文档、客户合同、产品手册、会议记录，这些内容它从未见过，也不可能知道。

有人会想：那把文档全部放进 Prompt 里呢？对于少量文档这是可行的，但当文档量达到几百份、几千份时，token 成本和上下文长度都会成为瓶颈。而且模型在极长上下文里的注意力会严重稀释，对中间内容的利用率极低。

### 3. 知识更新问题

模型的训练是有截止日期的，通常落后现实 6 个月到一年。产品价格变了、政策修订了、新的竞争对手出现了——这些模型全不知道。

你不可能每隔几个月就重新训练一遍模型来"更新知识"，这在成本和时间上都不可接受。

### 4. 可追溯性问题

当模型给出一个答案时，它无法告诉你"这句话来自哪份文档的第几页"。对于法律、医疗、金融等对准确性要求极高的场景，没有来源引用的答案往往是不可接受的。

------

## 三、RAG 是怎么应对大模型的缺点的？

RAG 的全称是 Retrieval-Augmented Generation，检索增强生成。它的核心思路非常直觉：**在让模型回答之前，先去知识库里检索出最相关的内容，把这些内容作为上下文一起喂给模型，让模型"看着资料"来回答。**

下面这张图展示了 RAG 如何对应地解决上面四个问题：

![RAG检索增强生成解决问题示意图](https://file1.kamacoder.com/i/bagu/Snipaste_2026-04-14_22-18-51.png?v=20261005)

RAG 针对四个问题各有应对：

**对幻觉问题：** 检索到的原文片段作为上下文传入模型，模型被要求"根据以下资料回答"，而不是凭空生成。有了事实依据的约束，幻觉概率大幅降低——但注意，不是归零，这个后面会讲。

**对私有知识问题：** 知识库完全由你自己构建和维护，可以包含任何内部文档。模型不需要知道这些内容，只需要在被检索到的片段基础上进行推理和组织语言。

**对知识更新问题：** 更新知识库不需要重新训练模型，只需要更新文档、重新做向量化索引即可。知识的新鲜度完全由知识库决定，和模型训练截止日期解耦。

**对可追溯性问题：** 每次检索都能知道具体命中了哪份文档的哪个片段，可以在答案里附上引用来源，用户可以自行核查。

------

## 四、RAG 不是万能的：什么场景适合，什么场景不适合

很多人看到 RAG 的思路后，产生了一个误区：是不是所有大模型应用都应该加 RAG？不是的。

**适合 RAG 的场景：**

知识密集型的问答系统，比如企业内部知识库、产品手册问答、法律法规查询——这类场景对事实准确性要求高，内容量大，且需要明确的来源追溯。

内容频繁更新的业务，比如新闻摘要、竞品分析、政策解读——这类场景下知识库可以持续接入实时数据，而模型本身不需要动。

长尾事实查询，比如"我们公司在上海的办公地址是什么""这个合同的甲方是谁"——这类问题的答案藏在特定文档里，必须检索才能找到。

------

## 五、面试可能怎么问

**Q：为什么有了大模型还需要 RAG？**

参考思路：大模型有几个局限性——幻觉、私有知识盲区、知识时效性、无法溯源。RAG 通过在回答前先检索外部知识库，把相关文档片段注入上下文，让模型"看资料回答"，从而有针对性地缓解以上问题。

**Q：RAG 能解决幻觉问题吗？**

参考思路：能显著缓解，但无法根治。有了检索到的事实作为锚点，模型乱编的概率大幅降低，且答案可以附上来源供核查。但模型仍然可能在检索结果上做出错误推理，或者在检索质量差时进行"补充生成"。RAG 降低幻觉概率，不消灭幻觉根因。

**Q：什么场景下你会推荐用 RAG，什么场景下不用？**

参考思路：适合 RAG 的是知识密集、内容频繁更新、需要溯源的场景，比如企业知识库问答、法规查询。不适合的是创意生成、强推理任务、以及模型训练数据已良好覆盖的稳定领域——在这些场景下，RAG 只是增加延迟和成本，没有实质收益。

------

## 六、结语

RAG 不是大模型能力的升级，而是大模型的外置数据库——让模型在回答时能检索自己的cheat sheet，从而有据可依。

## 七、零基础大白话精讲与组件五要素（融合你的仓库 3.1 精华）

### 1. 用生活例子彻底听懂“为什么 100 万长窗口也替代不了 RAG？”
很多人会问：现在大模型（比如 Gemini、GPT、DeepSeek）一次能塞进 100 万个 Token（约七八十万汉字），我每次提问直接把公司所有制度全塞进对话框不就行了吗？为什么还要费劲搭 RAG？
- **账单会破产（成本）**：把 50 万字的制度每次都发一遍，哪怕问一句“早上几点打卡”，也要为这 50 万字付钱。
- **第一个字等半天（首字延迟 TTFT）**：**TTFT（Time To First Token，首字延迟）** 大白话就是**“你按下回车后，盯着空白屏幕等到模型蹦出第一个字的时间”**。塞 50 万字进去，模型光把材料读完就要好几秒；而 RAG 只挑出最相关的 300 字塞进去，零点几秒就能开口。
- **中间内容会漏看（Lost in the Middle）**：就像人背长课文“两头熟、中间忘”一样，大模型对开头和结尾看得很仔细，夹在第 250 页中间的一句话很容易被它漏掉。
- **没法按人头做权限隔离（ACL 鉴权）**：全量塞进上下文，普通实习生一问就能套出高管薪酬制度；而 RAG 可以在检索那一刻就按员工工号只查他有权限看的文档。

### 2. 组件五要素（闭卷复述表）

| 要素 | 说明 |
| --- | --- |
| **输入** | 用户问题 `query`、用户权限角色 `user_role`、带生效状态与权限标签的知识库 `docs`、`top_k`。 |
| **做什么** | 1. **权限与有效期前置过滤（Pre-filtering）**；2. 按词元命中数召回 `top_k`；3. 若一条都没命中，直接拒答，绝不调大模型瞎编。 |
| **输出** | 带引用来源 ID 的回答，或“未找到相关有效依据”的拒答结果。 |
| **哪里可能出错** | 先搜向量再过滤权限导致越权泄露；无证据时硬让模型自由发挥；旧版废止制度未过滤。 |
| **重要参数影响** | `top_k` 太小漏条件，`top_k` 太大引入无关噪声并拉高费用。 |

## 八、循序渐进代码（Level 1）：带权限过滤与无证据拒答的最小 RAG 原型

运行前提：Python 3.10+，仅用标准库。

```python
"""3.1 Level 1：带权限前置过滤与无证据拒答的最小 RAG 原型。"""
def simple_rag(
    docs: list[dict[str, object]],
    query: str,
    user_role: str = "employee",
    top_k: int = 2,
) -> dict[str, object]:
    """先过滤权限与生效状态，再按双字滑窗词元检索；无证据时明确拒答。"""
    if not query.strip():
        raise ValueError("问题不能为空")
    if top_k <= 0:
        raise ValueError("top_k 必须为正整数")

    q = query.lower()
    keywords = {q[i : i + 2] for i in range(len(q) - 1) if q[i : i + 2].strip()} or {q}

    scored: list[tuple[int, str, str]] = []
    for doc in docs:
        # 1. 权限与生效状态前置过滤（Pre-filtering）：不合规文档绝不进入候选池
        if not doc.get("is_active", True):
            continue
        allowed_roles = doc.get("roles", ["employee"])
        if user_role not in allowed_roles:
            continue

        text = str(doc["text"])
        doc_id = str(doc["id"])
        hits = sum(1 for kw in keywords if kw in text.lower())
        if hits > 0:
            scored.append((hits, doc_id, text))

    scored.sort(key=lambda x: (-x[0], x[1]))
    contexts = scored[:top_k]
    if not contexts:
        # 统一返回“未检索到”，不暴露“存在该机密文件但你无权查看”
        return {"status": "refuse", "answer": "当前知识库未检索到相关有效依据，无法回答。", "sources": []}

    evidence = "\n".join(f"[{doc_id}] {text}" for _, doc_id, text in contexts)
    return {
        "status": "ok",
        "answer": f"根据以下资料回答：\n{evidence}",
        "sources": [doc_id for _, doc_id, _ in contexts],
    }


def self_test() -> None:
    """验证正常召回、过期制度拦截、越权拦截与无证据拒答。"""
    kb = [
        {"id": "A_v1", "text": "高处作业旧规：仅需戴安全帽。", "is_active": False, "roles": ["employee"]},
        {"id": "A_v2", "text": "高处作业新规：必须佩戴全身式安全带。", "is_active": True, "roles": ["employee"]},
        {"id": "SECRET", "text": "高管薪酬奖金核算标准。", "is_active": True, "roles": ["hr_admin"]},
    ]
    res = simple_rag(kb, "高处作业有什么规定？", user_role="employee")
    assert res["sources"] == ["A_v2"]  # 自动跳过已废止的 A_v1

    deny = simple_rag(kb, "高管薪酬怎么算？", user_role="employee")
    assert deny["status"] == "refuse" and deny["sources"] == []
    print("✅ 3.1 最小 RAG 原型（含权限与版本过滤）自检通过")


if __name__ == "__main__":
    self_test()
```

### 这段代码怎么在面试里讲（三段式）

1. **声明不变量**：任何被选入上下文的文档必须同时满足 `is_active == True` 且 `user_role in allowed_roles`；当命中列表为空时，必须返回 `refuse` 状态，绝不调用大模型裸答。
2. **关键行逻辑**：在遍历算分前先做权限与版本前置过滤（Pre-filtering），再用双字滑窗算词元重合度排序，最后将 `doc_id` 格式化为 `[A_v2]` 作为引用锚点。
3. **主动说边界与坑**：无权限和搜不到统一返回相同拒答文案，防止攻击者通过报错差异猜出机密文件的存在（防盲枚举攻击）；生产中权限过滤要下推到向量库/ES 的过滤表达式里执行。

## 九、补充面试追问与排障（来自你的仓库 3.1 + 外企高频）

1. **【🔥 必会】RAG 真的能 100% 解决幻觉吗？内在幻觉和外在幻觉有什么区别？**
   - **参考思路**：不能 100% 解决。RAG 只能缓解“知识匮乏型幻觉”；如果模型篡改了上下文里的数字或把禁止看成允许，叫**内在幻觉**；如果模型自己脑补了上下文没写的条款，叫**外在幻觉**。
2. **【🔥 必会】【排障题】用户反馈知识库问答给出了已废止的旧规定，排查链路是怎样的？**
   - **参考思路**：四步定位——① 查源文档库旧文件是否已标记废止；② 查向量库增量同步是否失败残留了旧块；③ 查在线检索是否漏加了 `is_active=True` 过滤；④ 查 Redis 语义缓存是否缓存了旧答案没失效。

### 目标与例子

目标：理解大模型外挂知识库（RAG）的核心价值、应用边界与不可替代性，建立“无证据则拒答、权限优先于提示词”的工程第一性原理。
例子：企业发布了最新的《2026版有限空间作业安全规程》。如果直接向未经微调的基座模型提问，模型依据预训练记忆可能会回答已废止的2020版旧条款，甚至凭空捏造不存在的审批流程。RAG 系统的职责是在用户发起查询时，严格在其权限范围内检索当前有效版本的规范片段，作为 Prompt 上下文送给模型；若未检索到有效凭据，系统应安全拒答而非强行编造。

### 概念与五要素

| 核心要素 | 说明 |
| --- | --- |
| 输入 | 用户自然语言查询 $Q$、用户身份/角色凭据（Token/Role）、知识库中文档版本与权限元数据。 |
| 做什么 | 基于安全边界与时效约束筛选候选资料，提供可溯源事实证据；若无有效证据则触发确定性拒答。 |
| 输出 | 携带严格证据来源（Citation ID / Version）的事实性回答，或标准拒答话术。 |
| 哪里出错 | 文档过期造成误导、越权访问泄漏敏感情报、检索漏判导致证据缺失、模型脱离证据外在幻觉。 |
| 重要参数影响 | 时效窗口（决定过期资料是否进入候选）、权限隔离策略（决定检索层还是展示层过滤）、拒答置信度阈值（影响准召平衡）。 |

RAG（Retrieval-Augmented Generation）的工程本质是将知识存储与参数推理剥离：由外部检索系统充当外部“海马体”，提供可更新、可溯源、带访问控制的动态记忆；大模型仅负责语言理解、证据抽取与格式重整。

### 面试追问

- 【🔥 必会】为什么不能直接把所有最新公司制度放进模型的长上下文（Long Context）里，而一定要做 RAG？
一句话结论：长文本存在成本高、首字延迟（TTFT）大、中间信息遗忘以及无法细粒度鉴权的问题。
展开原理/取舍：当企业文档达数百万字时，全量塞入 Context 无论从单次 API 费用还是端到端延迟上在生产环境都不可接受；此外模型存在“Lost in the Middle”注意力稀释缺陷；更重要的是，全量注入破坏了数据合规与多租户隔离，无法做到“不同职级只看授权条款”。

- 【🔥 必会】RAG 真的能 100% 解决大模型的幻觉问题吗？为什么？
一句话结论：不能，RAG 只能缓解“知识匮乏型幻觉”，无法消除“推理型”和“对抗型”幻觉。
展开原理/取舍：RAG 出错存在级联风险：① 检索侧可能召回与问题表面相似但事实无关的噪音；② 生成侧即便拿到了精准证据，模型仍可能在因果推演、否定句理解或跨段综合时发生事实变形（内在幻觉）；③ 当证据缺失时，模型可能依赖先验参数记忆强行作答（外在幻觉）。

- 【🔥 必会】【排障题】用户反馈知识库问答给出了已废止的旧规定，排查链路是怎样的？
一句话结论：按“源头更新→索引同步→元数据过滤→缓存隔离”四步定位。
展开原理/取舍：首先确认 KMS（知识管理系统）中旧文档是否被正确标记废止或软删除；其次排查向量数据库和全文索引的增量同步管道是否延迟或失败；再检查在线检索时的元数据过滤条件（filter: {"status": "active", "effective_date": {"$lte": now}}）是否生效；最后排查是否存在查询级或模型级的语义缓存未失效。

- 【⭐ 理解】RAG 与模型微调（Fine-Tuning）该如何做选型决策？
一句话结论：补知识用 RAG，学行为/格式用微调；高频更新选 RAG，特定领域风格选微调。
展开原理/取舍：详见第5章决策树。若业务知识频繁变更、需要精确审计出处并要求行级权限隔离，RAG 是唯一解；若任务要求严格固定的 JSON Schema 输出、特定的语言口吻（如客服话术风格），或者属于专业任务（如代码补全），微调能显著降低 Prompt 开销并提升响应稳定性。生产中多采用“微调基模的行为规范 + RAG 动态注入知识”的组合形态。

### 故障模式与排障

- 故障模式：越权信息泄漏（Information Leakage）

- 定位：排查检索端请求是否直接透传了用户原始查询而丢失了租户/角色标签，或者误将权限过滤放在了 LLM 生成之后的文本过滤层。

- 修复：权限前置（Pre-filtering）。在向向量库或搜索引擎下发检索时，必须在底座存储引擎层面强制注入用户 Security Context（如 tenant_id IN [...] AND department_id IN [...]），不可依赖模型提示词自我约束。

- 故障模式：证据缺失时的“强行作答”

- 定位：检查在线 Prompt 模板是否缺乏强硬的拒答约束，以及检索侧在相似度全低于置信度阈值时是否仍然透传了 Top-K 低质碎片。

- 修复：设定检索置信度底线（Cut-off Score），若最高匹配分低于阈值，直接在工程网关层拦截并返回兜底拒答话术，不触发下游 LLM 调用。

### 工程 trick 与坑

- 区分“空检索”与“无权限”状态：在面向终端用户时，统一返回“当前知识库暂未检索到相关有效制度”，严禁区分提示“您无权查看该文档”，防止攻击者通过暴力枚举猜测机密文件的存在性（Blind Enumeration Attack）。

- 引用标记必须绑定切片哈希与版本：Citation ID 严禁设计为自增数字，应包含 doc_id:version:chunk_index 或切片内容 SHA-256，确保答案溯源能够防篡改且版本幂等。

### 循序渐进 Toy Code：Level 1 — 权限守卫与确定性证据拒答

代码难度定位：Level 1（入门基石）。不引入任何第三方复杂框架，仅用 Python 3.10+ 标准库，清晰展示 RAG 链路的第一道防线——元数据有效性核验、用户权限前置过滤与无证据确定性拒答。

```python
"""
3.1 Toy Code: Level 1 - 权限守卫、时效校验与确定性拒答机制
依赖：Python 3.10+ 标准库
"""
from dataclasses import dataclass
from datetime import date
from typing import Optional


@dataclass(frozen=True)
class KnowledgeEvidence:
    """受控知识证据片段及其元数据"""
    evidence_id: str
    doc_title: str
    content: str
    version: str
    effective_date: date
    expire_date: date
    authorized_roles: tuple[str, ...]


@dataclass(frozen=True)
class DecisionResult:
    """系统决策结果：确保要么给出经过校验的证据，要么明确安全拒答"""
    status: str            # 'SUCCESS' | 'INSUFFICIENT_EVIDENCE' | 'PERMISSION_DENIED'
    answer: str
    cited_ids: tuple[str, ...]
    matched_version: Optional[str] = None


def answer_with_safety_guard(
    query: str,
    evidences: list[KnowledgeEvidence],
    user_role: str,
    current_date: date,
    min_keyword_overlap: int = 2
) -> DecisionResult:
    """
    RAG 证据准入与决策核心函数
    
    前置条件：
    1. query 必须为非空有效字符串
    2. 必须具备当前执行时间与用户角色
    """
    if not isinstance(query, str) or not query.strip():
        raise ValueError("查询字符串不能为空")
    if not user_role or not isinstance(user_role, str):
        raise ValueError("用户角色凭据无效")

    query_tokens = set(query.strip().lower().split())
    
    # 步骤 1：前置权限与时效性硬过滤（Pre-filtering）
    valid_candidates: list[tuple[KnowledgeEvidence, int]] = []
    
    for item in evidences:
        # 权限校验：用户角色必须包含在受权列表中
        if user_role not in item.authorized_roles:
            continue
        # 时效校验：必须处于生效日期区间内
        if not (item.effective_date <= current_date <= item.expire_date):
            continue
            
        # 步骤 2：简单词项重合度度量（教学最小检索度量）
        content_tokens = set(item.content.strip().lower().split())
        overlap_score = len(query_tokens.intersection(content_tokens))
        
        if overlap_score >= min_keyword_overlap:
            valid_candidates.append((item, overlap_score))

    # 步骤 3：无有效证据时的确定性安全拒答
    if not valid_candidates:
        return DecisionResult(
            status="INSUFFICIENT_EVIDENCE",
            answer="抱歉，在您权限范围内的当前有效制度中未找到充足依据，无法回答此问题。",
            cited_ids=()
        )

    # 步骤 4：择优选取最高匹配项并装配事实答案
    valid_candidates.sort(key=lambda x: (-x[1], x[0].evidence_id))
    selected_evidence, best_score = valid_candidates[0]

    # 断言不变量：输出的证据必须既符合权限又处于有效期内
    assert user_role in selected_evidence.authorized_roles
    assert selected_evidence.effective_date <= current_date <= selected_evidence.expire_date
    assert best_score >= min_keyword_overlap

    formatted_answer = f"{selected_evidence.content} [来源: {selected_evidence.evidence_id}]"
    return DecisionResult(
        status="SUCCESS",
        answer=formatted_answer,
        cited_ids=(selected_evidence.evidence_id,),
        matched_version=selected_evidence.version
    )


def self_test():
    """单元测试自检用例"""
    today = date(2026, 11, 11)
    
    docs = [
        # 正常有效合规文档
        KnowledgeEvidence(
            evidence_id="SAFE-2026-01",
            doc_title="高处作业安全规范",
            content="高处作业 必须 规范 佩戴 全身式 安全带 并 确保 挂点 牢固",
            version="v2.1",
            effective_date=date(2026, 1, 1),
            expire_date=date(2027, 12, 31),
            authorized_roles=("worker", "safety_officer", "admin")
        ),
        # 已过期废止旧文档
        KnowledgeEvidence(
            evidence_id="SAFE-2020-OLD",
            doc_title="高处作业旧标准",
            content="高处作业 使用 单挂点 安全带 即可",
            version="v1.0",
            effective_date=date(2020, 1, 1),
            expire_date=date(2023, 12, 31),
            authorized_roles=("worker", "safety_officer", "admin")
        ),
        # 机密无权限文档
        KnowledgeEvidence(
            evidence_id="CONFIDENTIAL-INCIDENT-99",
            doc_title="重大事故复盘总结",
            content="高处作业 坠落 事故 调查 处置 记录",
            version="v1.0",
            effective_date=date(2026, 1, 1),
            expire_date=date(2027, 12, 31),
            authorized_roles=("auditor", "admin")
        )
    ]

    # 测试场景 1：正常身份查询命中最新合规文档
    res1 = answer_with_safety_guard("高处作业 安全带", docs, user_role="worker", current_date=today)
    assert res1.status == "SUCCESS"
    assert res1.cited_ids == ("SAFE-2026-01",)
    assert res1.matched_version == "v2.1"

    # 测试场景 2：普通员工查询机密事故报告 -> 因无权限触发拒答（不泄露机密）
    res2 = answer_with_safety_guard("坠落 事故", docs, user_role="worker", current_date=today)
    assert res2.status == "INSUFFICIENT_EVIDENCE"
    assert res2.cited_ids == ()

    # 测试场景 3：查询过期规则关键词 -> 自动被时效过滤拦截并拒答
    res3 = answer_with_safety_guard("单挂点 安全带", docs, user_role="worker", current_date=today)
    assert res3.status == "INSUFFICIENT_EVIDENCE"

    # 测试场景 4：异常输入防御
    try:
        answer_with_safety_guard("   ", docs, user_role="worker", current_date=today)
        raise AssertionError("空字符串应触发 ValueError")
    except ValueError:
        pass

    print("✅ 3.1 权限守卫与拒答自检全部通过！")


if __name__ == "__main__":
    self_test()
```

#### 这段代码怎么在面试里讲（三段式）

- 声明不变量：我首先定义了不可变的强类型数据契约 KnowledgeEvidence 和 DecisionResult。核心不变量是：系统输出的任何合法引用，其元数据必须在权限集合内且满足 effective_date <= current_date <= expire_date；否则坚决阻断。

- 关键行解析：在第 45-56 行，我执行了存储层的前置过滤（Pre-filtering），直接在循环内剔除了越权和已过期的候选；第 63-69 行明确了如果无合格候选，直接返回确定性的 INSUFFICIENT_EVIDENCE 拒答结构，绝不进入下游 LLM 生成，从根本上防止外部幻觉。

- 主动说边界与坑：这段代码展示的是单机控制原语。在生产分布式架构中，权限过滤必须下推给数据库引擎（如 Elasticsearch/Milvus 的元数据过滤表达式），不能把千万级数据拉到应用内存中过滤；且分词重合度在生产中必须替换为 BM25 + 向量混合召回。

### 本节收尾：费曼自述与闪卡

费曼自述：
“RAG 就像一个带保密和时效检查的图书管理员。它不是代替大模型思考，而是在模型回答前，把最新的、用户有权查看的资料找出来当考卷参考答案。如果没有可信答案，它必须果断说‘我不知道’，绝不能由着大模型根据过去的记忆胡说八道。”

- Q：为什么权限过滤必须是 Pre-filtering 而不能靠 Prompt 嘱咐模型？
A：Prompt 容易被越狱绕过且增加上下文消耗；Pre-filtering 在数据库层面从物理上隔绝越权数据，安全可靠。

- Q：为什么即使提供了精准证据，模型依然可能产生幻觉？
A：因为 LLM 核心是自回归概率采样器，模型可能误读长难句中的逻辑关系、忽略限定前提或在推理中变形。

- Q：RAG 与微调选型的最核心边界是什么？
A：数据变动频率与知识溯源需求。知识经常变、要精确引用选 RAG；规范行为风格、无新事实知识选微调。

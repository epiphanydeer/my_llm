### 5.4 微调项目防泄漏与训练排障 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：跑通 LoRA 训练脚本后，最怕遇到两种情况：① 验证集 Loss 降得飞快甚至接近 0.01，上线一测却一塌糊涂（因为按句子随机切分，同一业务模板改几个数字同时进了训练集和验证集！）；② 训练到第 2 个 Epoch 突然 Loss = NaN 或验证集 Loss 开始一路反弹（过拟合背诵），白白烧掉几百块算力！

本节解法：构建 SFTTrainingGuard（防泄漏与训练排障守卫）：① 切分前强制校验模板指纹零重叠；② 训练中实时监控 NaN、梯度尖峰（Grad Spike）与 Eval Loss 连续上升自动触发早停（Early Stopping）。

大白话例子：就像备考刷模拟题：不能把同一道应用题只是把“小明”改成“小红”放进期末考卷（模板泄漏）；同时刷题时如果发现做真题卷的分数开始倒退、只记得住模拟题答案（过拟合），立刻叫停复习，保存上一轮最佳状态！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 训练集与验证集的模板指纹集合 train_templates / eval_templates，以及每步的 train_loss、eval_loss、grad_norm。 |
| ② 做什么 | 事前拦截跨集模板重叠 -> 训中检测 NaN 立即中止 -> 记录最佳 eval_loss 并计数连续恶化轮数，达 patience 触发 EARLY_STOP。 |
| ③ 输出什么 | 训练控制动作（SAVE_CHECKPOINT / CONTINUE / EARLY_STOP / ABORT_NAN）。 |
| ④ 关键参数 | patience（早停容忍轮数，SFT 通常 2~3 次 eval）、max_grad_norm（梯度裁剪阈值，常设 1.0）。 |
| ⑤ 工程 Trade-off | 严格模板隔离会让验证集分数显著低于“随机切分虚高分”，但能真实反映上线泛化能力；早停能保住基座通用能力不被过拟合训坏。 |

#### 3. 💻 渐进式代码实操（Step 4：SFTTrainingGuard 防泄漏与早停守卫）

演进说明：为 Step 2~3 的微调流水线装上防模板泄漏门禁与训练异常早停器。

```python
"""5.4 Step 4: 微调项目防泄漏与训练排障监控器."""

from __future__ import annotations

from dataclasses import dataclass, field
from typing import Dict, List, Set


@dataclass
class SFTTrainingGuard:
    patience: int = 2
    max_grad_norm: float = 5.0
    _best_eval_loss: float = float("inf")
    _worse_epochs: int = 0
    _alerts: List[str] = field(default_factory=list)

    @staticmethod
    def check_template_leakage(train_templates: Set[str], eval_templates: Set[str]) -> None:
        overlap = train_templates & eval_templates
        if overlap:
            raise ValueError(f"TEMPLATE_LEAKAGE: 发现跨集合模板指纹重叠 {sorted(overlap)}")

    def step_check(self, train_loss: float, eval_loss: float, grad_norm: float) -> Dict[str, object]:
        if not (train_loss == train_loss and eval_loss == eval_loss):
            return {"action": "ABORT_NAN", "reason": "Loss 出现 NaN，请检查 -100 掩码或降低学习率"}
        if grad_norm > self.max_grad_norm:
            self._alerts.append(f"GRAD_SPIKE:{grad_norm}")
        if eval_loss < self._best_eval_loss:
            self._best_eval_loss = eval_loss
            self._worse_epochs = 0
            return {"action": "SAVE_CHECKPOINT", "worse_epochs": 0}
        self._worse_epochs += 1
        if self._worse_epochs >= self.patience:
            return {"action": "EARLY_STOP", "reason": "Eval Loss 连续上升，防止过拟合背诵"}
        return {"action": "CONTINUE", "worse_epochs": self._worse_epochs}


if __name__ == "__main__":
    guard = SFTTrainingGuard(patience=2)
    assert guard.step_check(1.2, 1.1, 0.8)["action"] == "SAVE_CHECKPOINT"
    assert guard.step_check(0.8, 1.2, 1.0)["action"] == "CONTINUE"
    assert guard.step_check(0.5, 1.3, 1.1)["action"] == "EARLY_STOP"
    print("Ch5 Step 4 self-test passed!")
```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：train_templates & eval_templates 必须为空集；eval_loss 连续 patience 次不降即停止，且只保留 _best_eval_loss 对应的 Checkpoint。

讲清关键行：train_loss == train_loss 利用 IEEE-754 浮点数 NaN != NaN 特性秒级抓出数值崩盘。

主动点出工程细节：SFT 阶段 train_loss 降到极低（比如 $< 0.2$）往往不是好事，而是过拟合背诵；工业界通常只训 1~3 个 Epoch，配合 lr=1e-4 ~ 2e-4（LoRA 比全参学习率通常高 10 倍）和 Cosine 退火。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：FP16 混合精度训练频发 Loss NaN

现象：前 50 步正常，突然梯度溢出变成 NaN。

定位方法：FP16 动态范围窄，大梯度下容易上溢。

修复方案：优先切到 BF16（指数位与 FP32 相同，极少溢出），开启梯度裁剪 max_grad_norm=1.0，并排查是否存在全 -100 空监督样本。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：为什么 LoRA 微调的学习率（如 1e-4）通常比全参微调（如 1e-5）大一个数量级？

参考答法：全参微调直接修改几十亿个原始敏感权重，步子太大容易训崩；LoRA 只更新少量从零初始化的低秩旁路矩阵，需要更大的学习率才能有效推动旁路形成特征表达。

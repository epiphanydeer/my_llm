### 8.2 架构演进：Encoder、Decoder 与 Encoder-Decoder 全景 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：同样叫 Transformer，为什么 BERT 适合做分类和向量检索（Embedding），T5 适合做翻译，而 GPT / LLaMA / Qwen 全是清一色的 Decoder-Only？

本节解法：按注意力掩码模式区分三大架构家族：① Encoder-Only（全双向可见，做理解与表征）；② Encoder-Decoder（编码双向 + 解码因果 + Cross-Attention 桥接）；③ Decoder-Only（纯因果下三角掩码，现代大模型绝对主流）。

大白话例子：Encoder 像“做阅读理解填空”，先把整篇文章从头到尾看完，再结合上下文猜空缺；Decoder 像“接龙讲故事”，只能看着前面已经说过的字往下续写，绝不允许偷看后面的剧透！

#### 2. 🧠 核心原理与五维拆解

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 架构类型 arch ("encoder" / "decoder" / "cross_attention") 与 t_q, t_k。 |
| ② 做什么 | encoder 生成全 True 双向掩码；decoder 生成下三角因果掩码 np.tril（禁止看未来）；cross_attention 允许 Decoder 每个位置自由检索 Encoder 全长记忆。 |
| ③ 输出什么 | 布尔注意力掩码矩阵 (t_q, t_k)。 |
| ④ 关键参数 | 掩码形状与对称性（Encoder 矩阵可矩形/双向，Decoder 自注意力必为方阵且上三角为 False）。 |
| ⑤ 工程 Trade-off | 现代 LLM 统一收敛到 Decoder-Only，原因是：① 无信息瓶颈，所有层共用同一个自回归任务，Scaling Law 最稳；② 推理期天然兼容前缀 KV Cache 复用，无需区分编码/解码两套权重。 |

#### 3. 💻 渐进式代码实操（Step 2：三大架构掩码生成器）

演进说明：用代码直观区分双向、因果与交叉注意力的掩码结构。

```python
"""8.2 Step 2: 根据架构类型 (Encoder / Decoder / Cross-Attention) 生成注意力掩码."""

from __future__ import annotations

import numpy as np


def build_attention_mask_by_arch(arch: str, t_q: int, t_k: int) -> np.ndarray:
    """True 表示允许关注, False 表示屏蔽."""
    if arch == "encoder":
        return np.ones((t_q, t_k), dtype=bool)
    if arch == "decoder":
        if t_q != t_k:
            raise ValueError("Decoder 自注意力要求 t_q == t_k")
        return np.tril(np.ones((t_q, t_k), dtype=bool), k=0)
    if arch == "cross_attention":
        return np.ones((t_q, t_k), dtype=bool)
    raise ValueError(f"未知架构: {arch}")


if __name__ == "__main__":
    enc = build_attention_mask_by_arch("encoder", 4, 4)
    dec = build_attention_mask_by_arch("decoder", 4, 4)
    cross = build_attention_mask_by_arch("cross_attention", 3, 5)
    assert enc.all() and not dec[0, 1] and dec[3, 0] and cross.shape == (3, 5)
    print("Ch8 Step 2 self-test passed!")
```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：decoder 自注意力矩阵第 i 行只能看到 0..i 列，上三角（j > i）必须严格为 False。

讲清关键行：cross_attention 中 t_q（目标序列长度）可以不等于 t_k（源序列长度），Query 来自 Decoder，Key 和 Value 来自 Encoder。

主动点出工程细节：做 RAG 的双塔向量检索模型（如 BGE / E5）早期大多用 Encoder-Only，如今越来越多模型（如 Qwen3-Embedding）直接基于 Decoder-Only 去掉因果掩码后微调而来。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：训练自回归模型时，Loss 第一个 Epoch 就掉到 0.01，推理时却只会复读乱码

现象：典型的未来词泄漏（Future Token Leakage）。

定位方法：检查是否漏传了因果下三角掩码（相当于让 Decoder 用了 Encoder 的全双向掩码，直接偷看了答案）。

修复方案：强制开启 is_causal=True 或显式校验上三角掩码权重为 0。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：为什么如今大模型几乎全部统一成了 Decoder-Only，而不是 Encoder-Decoder？

参考答法：① Decoder-Only 每一层都在做相同的 Next-Token Prediction，没有 Encoder-Decoder 之间 Cross-Attention 的信息压缩瓶颈，规模扩展（Scaling Law）表现最好；② 工程上支持极致的 Prefix/KV Cache 复用与统一的高效算子调度；③ 在 Zero-shot/Few-shot 上下文学习（ICL）能力上天然更强。

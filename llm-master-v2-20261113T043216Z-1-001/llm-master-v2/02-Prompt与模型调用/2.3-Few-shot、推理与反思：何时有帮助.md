# 2.3 Few-shot、推理与反思：何时有帮助【⭐ 理解】

## 1. 🎯 本节目标与大白话例子

本节目标：分清 Zero-shot、Few-shot、CoT（思维链）与 Self-Refine（反思）的适用场景，避免对推理模型滥用繁琐 CoT 导致效果倒退。

大白话例子：Few-shot 就像给新员工看 3 份填好的报销单模板（最适合统一格式与边界口径）；CoT 是让普通员工写出算术草稿（防心算出错）；但如果你请来的是本来就会打长草稿的竞赛选手（o1/R1 推理模型），还硬逼他按你的死板格式一步步写草稿，反而会束缚他的发挥。

## 2. 🧠 核心原理与五维拆解

> 图片待恢复：原图

Zero-shot：目标明确、推理模型（Reasoning Models）或简单分类首选，成本最低。

Few-shot：最擅长锚定输出格式、专业术语口径与边界反例；注意样本数量（2~5 个即可）与标签分布平衡，防多数类偏置（Majority Label Bias）。

CoT（Chain-of-Thought）：对普通非推理模型的多步数学/逻辑题显著有效；但对原生推理模型（如 o1/o3/DeepSeek-R1）通常不建议强加繁琐手写 CoT，只需给出清晰目标、约束和评测标准。

Self-Refine（反思修订）：适合高价值文案、代码审查或带确定性校验器（如编译器/单元测试）的场景，靠“生成→外部工具反馈→修订”闭环提质。

## 3. 💻 渐进式代码实操（ch2_code/step_03_reasoning_strategy_router.py）

```python
"""2.3 Few-shot、推理与反思：任务复杂度与推理策略路由器"""
from dataclasses import dataclass


@dataclass
class PromptStrategy:
    mode: str  # "zero_shot" | "few_shot" | "cot" | "self_refine"
    reason: str


def select_prompt_strategy(
    is_reasoning_model: bool,
    needs_strict_format: bool,
    multi_step_logic: bool,
    high_stakes_draft: bool,
) -> PromptStrategy:
    """根据模型类型与任务特征选择最小充分推理策略，避免对推理模型过度诱导 CoT。"""
    if is_reasoning_model:
        return PromptStrategy("zero_shot", "推理模型原生具备长链思考能力，直接给清晰目标与约束即可")
    if high_stakes_draft:
        return PromptStrategy("self_refine", "高风险输出需生成-校验-修订两阶段闭环")
    if multi_step_logic:
        return PromptStrategy("cot", "普通对话模型处理多步计算/逻辑推导需显式分步")
    if needs_strict_format:
        return PromptStrategy("few_shot", "通过2-3个正反样例锚定输出格式与边界口径")
    return PromptStrategy("zero_shot", "简单明确任务直接零样本调用以降低 Token 成本")


if __name__ == "__main__":
    s1 = select_prompt_strategy(True, False, True, False)
    s2 = select_prompt_strategy(False, False, True, False)
    s3 = select_prompt_strategy(False, True, False, False)
    assert s1.mode == "zero_shot" and s2.mode == "cot" and s3.mode == "few_shot"
    print("[2.3 PASS]", s1.mode, s2.mode, s3.mode)
```

## 4. 🗣️ 面试官视角：这段代码怎么讲

在我的提示词路由器里，会根据模型是否为推理模型、是否需要严格格式以及是否高风险输出动态选择策略——比如遇到推理模型直接走简洁 zero_shot，只有普通对话模型处理多步逻辑才开启显式 cot。

## 5. 🔧 生产排障指南

坑 1：Few-shot 样例全选同一个标签（如 3 个全为“高风险”） → 解法：模型会学到标签偏置，疯狂误报；正负/边界样例必须均衡覆盖。

坑 2：无外部反馈的纯“自我反思” → 解法：没有单元测试或规则校验器的“自己夸自己/自己改自己”往往越改越偏，必须引入确定性校验信号。

## 6. ❓ 高频面试追问与参考答法

Q1：为什么不建议给 DeepSeek-R1 / OpenAI o1 这类推理模型写“请你一步一步思考，第一步...第二步...”？ 答：推理模型在 RL 阶段已经内化了最优的长链思考与自我回溯策略，外部强加僵化的 CoT 模板会干扰其原生搜索树，反而增加无效 Token 甚至降低准确率。

### 7.2 视觉编码、Patch 切块与模态对齐投影 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：语言模型（LLM）的输入是一维的 Token 向量序列，而图片是二维像素矩阵 (H, W, C)、语音是连续波形。如果把 1024×1024 的百万个像素点直接展平喂给 LLM，Attention 计算量直接爆炸到 $10^{12}$ 次，而且像素数值分布和词嵌入完全不在一个空间里！

本节解法：拆解 VLM 经典三段式架构——Vision Encoder（ViT 切块编码） -> Multimodal Projector（线性/MLP 模态连接器） -> LLM Backbone（自回归解码），并手写 MicroVisionProjector 验证维度流转。

大白话例子：就像跨国会议：图片（说图像语言）和 LLM（说文本语言）互相听不懂。ViT 先把整张大画切成一块块小拼图（Patch）提炼成特征摘要；Projector 就是中间的“同声传译官”，把视觉特征翻译成 LLM 听得懂的维度和语义向量，最后和用户提问的文字 Token 拼在一起送进 LLM 大脑思考！

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 归一化后的 RGB 图像张量 (H, W, C)，要求 H, W 能被 patch_size 整除。 |
| ② 做什么 | 将 (H, W, C) 按 P×P 网格切块并展平为 (num_patches, P*P*C) -> 经线性投影矩阵 (P*P*C, llm_hidden_dim) 映射到语言模型隐藏层维度。 |
| ③ 输出什么 | 对齐后的视觉 Token 序列 (num_patches, llm_hidden_dim)，其中 num_patches = (H/P) * (W/P)。 |
| ④ 关键参数 | patch_size（常见 14 或 16，越小细节越细但 Token 数按平方暴增）、llm_hidden_dim、Token 压缩率（如 Pixel Shuffle / 2×2 Merging）。 |
| ⑤ 工程 Trade-off | 固定低分辨率切块会丢失小目标/小字；动态高分辨率（AnyRes / Naive Dynamic Resolution）能看清小字但会让视觉 Token 飙升，需配合 2×2 空间合并压缩 Token 数。 |

知识扩展（面试加分盲区）：

为什么“维度匹配不等于语义对齐”？：Projector 初始化时只是一个随机矩阵，虽然把视觉向量从 1024 维强行乘成了 LLM 的 4096 维，但此时 LLM 根本不知道哪个向量代表“安全帽”。必须经过海量图文对（Image-Text Pairs）的对齐预训练（Stage 1）+ 视觉指令微调（Stage 2），两者的语义空间才真正重合。

Qwen2-VL / Qwen2.5-VL 的两大杀手锏（外企高频考点）：

原生动态分辨率（Naive Dynamic Resolution）：不再把所有图片强行拉伸变形到 336×336 正方形，而是按原始长宽比动态切分 Patch，并用相邻 2×2 Patch 合并（MLP Merger）把视觉 Token 数量直接压缩 4 倍！

M-RoPE（多模态旋转位置编码）：把传统 1D RoPE 拆成 时间（T）、高度（H）、宽度（W） 三个维度分量——文本三者相同退化为 1D RoPE，图像保留 2D (H, W) 空间位置感，视频则额外引入时间轴 T。

#### 3. 💻 渐进式代码实操（Step 2：MicroVisionProjector 切块与对齐投影）

演进说明：在 Step 1 空间坐标概念基础上，手动实现 (H, W, C) 图像到 (num_patches, llm_hidden_dim) 视觉 Token 的完整张量变换与不变量断言。

```python
"""7.2 Step 2: ViT 图像 Patch 切块展平与 Multimodal Projector 维度对齐投影.

在 Step 1 空间坐标校验基础上，理解 VLM 底层如何把二维图像 (H, W, C) 变成 LLM 可读的视觉 Token 序列。
"""

from __future__ import annotations

import numpy as np


class MicroVisionProjector:
    """模拟 ViT Patchify + Linear Projector 对齐至 LLM hidden_dim."""

    def __init__(self, patch_size: int = 16, channels: int = 3, llm_hidden_dim: int = 64) -> None:
        if patch_size <= 0 or channels <= 0 or llm_hidden_dim <= 0:
            raise ValueError("patch_size、channels 与 llm_hidden_dim 必须为正整数")
        self.patch_size = patch_size
        self.channels = channels
        self.llm_hidden_dim = llm_hidden_dim
        self.patch_dim = patch_size * patch_size * channels
        rng = np.random.default_rng(42)
        self.proj_weight = rng.normal(0.0, 0.02, size=(self.patch_dim, llm_hidden_dim)).astype(np.float32)

    def patchify(self, image: np.ndarray) -> np.ndarray:
        """将 (H, W, C) 图像切分为 (num_patches, P*P*C) 的 Patch 序列."""
        if image.ndim != 3 or image.shape[2] != self.channels:
            raise ValueError(f"图像必须为 (H, W, {self.channels})，当前为 {image.shape}")
        h, w, c = image.shape
        if h % self.patch_size != 0 or w % self.patch_size != 0:
            raise ValueError(f"图像尺寸 ({h}, {w}) 必须能被 patch_size={self.patch_size} 整除")

        gh, gw = h // self.patch_size, w // self.patch_size
        patches = (
            image.reshape(gh, self.patch_size, gw, self.patch_size, c)
            .transpose(0, 2, 1, 3, 4)
            .reshape(gh * gw, self.patch_dim)
        )
        assert patches.shape == (gh * gw, self.patch_dim)
        return patches

    def forward(self, image: np.ndarray) -> np.ndarray:
        """输出对齐后的视觉 Token 序列: (num_patches, llm_hidden_dim)."""
        patches = self.patchify(image)
        visual_tokens = patches @ self.proj_weight
        assert visual_tokens.shape == (patches.shape[0], self.llm_hidden_dim)
        assert np.isfinite(visual_tokens).all(), "视觉 Token 出现 NaN/Inf"
        return visual_tokens


if __name__ == "__main__":
    proj = MicroVisionProjector(patch_size=16, channels=3, llm_hidden_dim=64)
    img = np.ones((32, 48, 3), dtype=np.float32)
    tokens = proj.forward(img)
    assert tokens.shape == (6, 64), f"期望 (6, 64)，实际 {tokens.shape}"
    print(f"MM Step 2 self-test passed! visual_tokens.shape={tokens.shape}")
```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：输入图像 (H, W, C) 经过切块后，num_patches = (H // P) * (W // P)，且投影输出必须严格满足 (num_patches, llm_hidden_dim) 且全为有限浮点值。

讲清关键行：reshape(gh, P, gw, P, C).transpose(0, 2, 1, 3, 4) 是把二维空间网格 (gh, gw) 提到前两维，确保每个 P×P 小块内部的像素是连续展平的，绝对不能直接对整张图 reshape(gh*gw, -1) 否则会切碎行像素！

主动点出工程细节：真实 ViT 在 patchify 后还会加上 2D 位置编码（或 M-RoPE），并在多模态大模型中通过 2 层带 GELU 的 MLP（而不只是单层 Linear）作为 Projector 提升非线性对齐能力。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：远景小目标（如 20×20 像素的安全带挂扣）在 VLM 里完全看不见

现象：大模型回答“画面里没有安全带”，但人眼放大看明明有。

定位方法：计算图像被强制缩放到默认低分辨率（如 336×336）后，目标在特征图上只占不到 1 个 Patch。

修复方案：改用支持动态高分辨率的模型（如 Qwen2-VL），或先用轻量检测器定位人员框再裁剪放大（Crop & Zoom）送入 VLM。

故障 2：直接 image.reshape(-1, patch_dim) 导致视觉特征彻底乱码

现象：模型训练 Loss 不降，视觉感知完全失效。

定位方法：检查切块代码是否漏了 transpose(0, 2, 1, 3, 4)，直接跨行展平破坏了局部空间邻域结构。

修复方案：改用标准的 Conv2d(in_channels=3, out_channels=hidden, kernel_size=P, stride=P) 或先 reshape 再 transpose 切块。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：用 30 秒讲清楚一张图片和一段语音是怎么被大模型“看懂/听懂”的？

参考答法：核心是“切分—编码—对齐—生成”四步：图片切成 Patch、语音切成短帧；分别经过 ViT/Audio Encoder 提取特征向量；再经由 Projector（连接器）映射到与文本相同的 hidden_dim 向量空间，和文本 Token 拼在一起送入 LLM；最后靠图文/音文对齐训练让它们共享同一套语义。

Q2：LLaVA 的线性/MLP Projector 和 Qwen2-VL 的动态分辨率设计有什么区别？

参考答法：早期 LLaVA 依赖固定分辨率（如 336×336），长图或高分辨率截图会被压扁或丢失小字；Qwen2-VL 引入了原生动态分辨率 + 2×2 相邻 Patch 合并压缩 + M-RoPE 三维位置编码，既保住了长宽比和高清细节，又控制了 Token 膨胀。

Q3：视觉 Token 越多效果一定越好吗？

参考答法：不是。分辨率越高、Patch 越小，Token 数呈平方级增长，不仅显存和首字延迟（TTFT）暴涨，还会稀释有效信息；应该按任务所需细节动态选档。

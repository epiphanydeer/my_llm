### 7.1 任务定义、多模态边界与空间定位评测 【🔥 必会】

#### 1. 🎯 本节目标与大白话例子

上一步痛点：很多项目一看到输入是 PDF、图片或视频，就无脑调多模态大模型（VLM）接口；更危险的是，在工业巡检或工单质检中，模型只输出一句流畅的“图里有人没戴安全帽”，没有任何空间坐标证据，甚至用 VQA 文本正确率去冒充目标检测精度！

本节解法：① 用“关键证据转成纯文本后会不会丢失”划清多模态与纯文本（OCR/ASR）的选型边界；② 分清 VQA / 分类 / 检测 / 视觉定位（Grounding）/ 描述 五大任务的输出契约；③ 实现带正面积校验与一对一贪心 IoU 匹配的评测基线。

大白话例子：同样看一张工地监控图：问“有没有人违章”是分类；问“右侧穿蓝衣服的工人戴帽了吗”是 VQA；要求把所有安全帽画框标出来是检测（Detection）；按文字“穿红马甲的人”把对应框指出来是 Grounding（定位）。如果业务要求“定位到具体哪台设备告警”，光让模型嘴上说“有告警”是不算数的，必须拿预测框和标准答案框算交并比（IoU）一对一核对！

#### 2. 🧠 核心原理与五维拆解

![多模态文档解析原理](../assets/images/restored-b7864302c5cc12ed9356.jpg)

| 维度 | 核心内容（闭卷背诵标准） |
| --- | --- |
| ① 输入什么 | 预测框 predicted: (N, 4)、预测置信度 scores: (N,)、金标框 gold: (M, 4)、IoU 匹配阈值 threshold（常见 0.5）。 |
| ② 做什么 | 校验坐标有限性及 x2 > x1, y2 > y1 正面积 -> 计算 (N, M) 两两 IoU 矩阵 -> 按 scores 降序遍历预测框，在未被占用的金标框中选最大 IoU 且 >= threshold 的配对（每个金标最多匹配 1 次）。 |
| ③ 输出什么 | {"tp", "fp", "fn", "precision", "recall"}（当分母为 0 时安全返回 None）。 |
| ④ 关键参数 | threshold（IoU 阈值越高定位越严苛）、scores（置信度阈值控制召回 vs 误报权衡）。 |
| ⑤ 工程 Trade-off | 空间定位评测（IoU/mAP）比纯文本 VQA 更难标注和对齐，但能 100% 物理核验“模型到底看没看对位置”，避免语言先验蒙对。 |

知识扩展（面试加分盲区）：

何时用纯文本（OCR/ASR），何时必须上多模态 VLM？：问自己一句话——“任务依赖的决定性证据，转成纯文本后会丢失吗？” 扫描合同查公司名（文字即证据）-> OCR + 文本 RAG 更便宜更稳；财报柱状图趋势/双栏跨页表格/现场安全带挂钩位置（空间关系与颜色视觉是证据）-> 必须上 VLM。

检测框坐标的常见工程坑：不同模型输出的格式五花八门——有的用归一化 [0, 1000]（如 Qwen2-VL），有的用 [0, 1] 浮点，有的用 (x, y, w, h) 而不是 (x1, y1, x2, y2)。评测与可视化前必须统一坐标系和图像 Resize/Padding 的逆变换。

#### 3. 💻 渐进式代码实操（Step 1：边界框校验与一对一 IoU 贪心匹配）

演进说明：本章起点，构建工业巡检空间定位评测的底层基石——严格坐标校验 + 纯向量化 IoU + 一对一贪心匹配。

```python
"""7.1 Step 1: 矩形框正面积校验、IoU 计算与一对一贪心匹配 (TP/FP/FN).

业务场景：工业巡检安全帽/反光衣检测评测，绝不用 VQA 文本准确率代替空间定位评测。
"""

from __future__ import annotations

from typing import Dict, Optional
import numpy as np


def validate_boxes(boxes: np.ndarray, name: str) -> None:
    """校验边界框形状为 (N, 4)、有限浮点坐标且严格满足 x2>x1, y2>y1."""
    if boxes.ndim != 2 or boxes.shape[1] != 4:
        raise ValueError(f"{name} 必须是 (N, 4) 形状，当前为 {boxes.shape}")
    if not np.issubdtype(boxes.dtype, np.floating) or not np.isfinite(boxes).all():
        raise ValueError(f"{name} 必须为有限浮点坐标")
    if boxes.shape[0] > 0 and not bool((boxes[:, 2:] > boxes[:, :2]).all()):
        raise ValueError(f"{name} 必须满足 x2 > x1 且 y2 > y1")


def compute_box_iou(boxes_a: np.ndarray, boxes_b: np.ndarray) -> np.ndarray:
    """计算两组 (N, 4) 与 (M, 4) 边界框的两两 IoU 矩阵，返回 (N, M)."""
    n, m = boxes_a.shape[0], boxes_b.shape[0]
    if n == 0 or m == 0:
        return np.zeros((n, m), dtype=np.float64)

    x1 = np.maximum(boxes_a[:, None, 0], boxes_b[None, :, 0])
    y1 = np.maximum(boxes_a[:, None, 1], boxes_b[None, :, 1])
    x2 = np.minimum(boxes_a[:, None, 2], boxes_b[None, :, 2])
    y2 = np.minimum(boxes_a[:, None, 3], boxes_b[None, :, 3])

    inter = np.maximum(0.0, x2 - x1) * np.maximum(0.0, y2 - y1)
    area_a = (boxes_a[:, 2] - boxes_a[:, 0]) * (boxes_a[:, 3] - boxes_a[:, 1])
    area_b = (boxes_b[:, 2] - boxes_b[:, 0]) * (boxes_b[:, 3] - boxes_b[:, 1])
    union = area_a[:, None] + area_b[None, :] - inter
    return inter / np.maximum(union, 1e-12)


def match_one_class(
    predicted: np.ndarray,
    scores: np.ndarray,
    gold: np.ndarray,
    threshold: float = 0.5,
) -> Dict[str, Optional[float] | int]:
    """按置信度降序执行一对一贪心匹配，统计 TP/FP/FN 与 Precision/Recall."""
    validate_boxes(predicted, "预测框")
    validate_boxes(gold, "金标框")
    if scores.ndim != 1 or scores.shape[0] != predicted.shape[0]:
        raise ValueError("scores 必须是一维且长度等于预测框数量")
    if not np.isfinite(scores).all() or not ((scores >= 0.0) & (scores <= 1.0)).all():
        raise ValueError("scores 必须在 [0, 1] 区间内")
    if not 0.0 <= threshold <= 1.0:
        raise ValueError("IoU 阈值必须在 [0, 1] 区间内")

    overlaps = compute_box_iou(predicted, gold)
    assert overlaps.shape == (predicted.shape[0], gold.shape[0])

    used_gold: set[int] = set()
    hits = 0
    for pred_idx in np.argsort(-scores).tolist():
        candidates = [j for j in range(gold.shape[0]) if j not in used_gold]
        if not candidates:
            continue
        best_j = max(candidates, key=lambda j: float(overlaps[pred_idx, j]))
        if float(overlaps[pred_idx, best_j]) >= threshold:
            used_gold.add(best_j)
            hits += 1

    fp = int(predicted.shape[0] - hits)
    fn = int(gold.shape[0] - hits)
    assert 0 <= hits <= min(predicted.shape[0], gold.shape[0])
    return {
        "tp": hits,
        "fp": fp,
        "fn": fn,
        "precision": hits / predicted.shape[0] if predicted.shape[0] > 0 else None,
        "recall": hits / gold.shape[0] if gold.shape[0] > 0 else None,
    }


if __name__ == "__main__":
    preds = np.array([[0.0, 0.0, 10.0, 10.0], [0.0, 0.0, 10.0, 10.0]], dtype=np.float64)
    scores = np.array([0.9, 0.8], dtype=np.float64)
    gold = np.array([[0.0, 0.0, 10.0, 10.0]], dtype=np.float64)
    res = match_one_class(preds, scores, gold, threshold=0.5)
    assert res == {"tp": 1, "fp": 1, "fn": 0, "precision": 0.5, "recall": 1.0}
    print(f"MM Step 1 self-test passed! res={res}")
```

#### 4. 🗣️ 面试官视角：这段代码怎么讲

先声明不变量：0 <= tp <= min(len(predicted), len(gold)) 永远成立——每个金标框最多只能被一个高置信度预测框认领，多余的重复预测框必须全部计入 fp（误报）。

讲清关键行：np.argsort(-scores) 按置信度从高到低匹配，保证高质量框优先认领金标；used_gold 集合物理阻断“一框多吃”刷高 Recall 的漏洞。

主动点出工程细节：当 gold 为空时 recall 返回 None 而不是 0.0，避免在纯负样本集上误报成“0% 召回率”。

#### 5. 🔧 生产排障指南（实现 -> 排障）

故障 1：模型肉眼看明明框得很准，但离线评测 mAP 接近 0

现象：可视化检查感觉没问题，指标却跌成 0.02。

定位方法：把预测框和金标框按同一坐标逻辑画回原图，90% 是 xywh vs xyxy 格式搞反、归一化未还原、或 Letterbox Padding 偏移未减去。

修复方案：在 validate_boxes 入口强制统一到原图绝对像素 (x1, y1, x2, y2) 格式，并加回归可视化单测。

故障 2：同一目标叠了 5 个框，召回率没掉但线上告警刷屏

现象：模型后处理缺少 NMS（非极大值抑制），导致一个违章人员触发 5 条工单。

定位方法：检查 fp 是否异常偏高、同一位置存在多个高重叠框。

修复方案：在推理后处理阶段加入 torchvision.ops.nms(boxes, scores, iou_threshold=0.5)。

#### 6. ❓ 高频面试追问与参考答法 + 📝 节末费曼自检

Q1：VQA 正确率能当目标检测 mAP 用吗？

参考答法：绝对不能。VQA 只核对最终文本答案，模型极易靠语言常识猜对“有没有人没戴帽”；只有输出空间坐标并通过 IoU 一对一匹配，才能证明模型真正定位到了目标实体。

Q2：项目里怎么判断该用“OCR + 文本大模型”还是“原生多模态 VLM”？

参考答法：核心看任务所需的关键证据转成纯文本后会不会丢失。如果只是提取合同公司名、发票号，OCR + 规则/文本 RAG 更便宜更稳；如果依赖图表趋势、空间位置关系、颜色与印章状态，才上 VLM。

Q3：单图单类别匹配中，如果不做 used_gold 一对一限制会怎样？

参考答法：模型只要在图上密密麻麻撒 100 个框就能把 Recall 刷到 100%，完全丧失评测区分度。

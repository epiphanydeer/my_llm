## 零基础大白话深度拆解（把本节核心概念、公式与工程坑点掰碎讲透）

### 1. 为什么微调 VLM 时，必须把 Prompt 和 `<image>` 的标签全部设为 `-100`（Ignore Index）？
- **大白话例子**：
  - 大模型做监督微调（SFT）就像老师拿一张有“题目（系统提示词 + 256 个图片 Token + 用户提问）”和“标准答案（Assistant 回复的 30 个字）”的卷子批改作业。
  - 老师批改打分（算交叉熵 Loss）时，**只应该批改学生写的“30 字答案”对不对，绝不应该让学生把前面那 256 个图片占位符和题目背诵默写一遍**！
  - 在 PyTorch 的 `CrossEntropyLoss` 里，数字 **`-100`** 是一个法定免死金牌（默认 `ignore_index=-100`）：凡是标签 `labels` 标为 `-100` 的位置，算 Loss 时直接跳过清零，不产生任何梯度！
  - 如果你忘了给那 256 个图片 Token 和 Prompt 打上 `-100`，模型 90% 的精力全花在“死记硬背题目和图片占位符”上，真正要学的 30 字业务答案反而被稀释得毫无存在感！

## 循序渐进“搭积木”手搓代码（40 行极简 Python 版，轻松掌握核心逻辑）

```python
# 【循序渐进手搓版 Level 5（在 Level 4 基础上新增“构造 -100 损失掩码与主干冻结参数统计”）】
from typing import Dict, List

def build_sft_labels_with_mask(
    prompt_token_ids: List[int],
    image_token_ids: List[int],
    answer_token_ids: List[int],
    ignore_index: int = -100,
) -> Dict[str, List[int]]:
    """Level 5 核心积木：将图像 Token 与用户 Prompt 全部掩码为 -100，仅对 Assistant 答案计算 Loss"""
    if not answer_token_ids:
        raise ValueError("监督微调的目标答案 answer_token_ids 不能为空！")
    input_ids = image_token_ids + prompt_token_ids + answer_token_ids
    # 图像区和提问区的 label 全设为 -100，只有最后一段答案保留真实 token_id
    masked_prefix = [ignore_index] * (len(image_token_ids) + len(prompt_token_ids))
    labels = masked_prefix + list(answer_token_ids)

    assert len(input_ids) == len(labels)
    supervised_count = sum(1 for y in labels if y != ignore_index)
    assert supervised_count == len(answer_token_ids)
    return {"input_ids": input_ids, "labels": labels, "supervised_tokens": [supervised_count]}

def self_test() -> None:
    res = build_sft_labels_with_mask(
        prompt_token_ids=[10, 11, 12],
        image_token_ids=[1001, 1001, 1001, 1001],
        answer_token_ids=[99, 100],
    )
    # 前 7 个位置（4个图像 + 3个提问）必须全部是 -100，只有最后 2 个答案位置参与算 Loss
    assert res["labels"] == [-100, -100, -100, -100, -100, -100, -100, 99, 100]
    print("✅ [手搓版 Level 5] VLM 微调 -100 损失掩码构造器自检通过！")

if __name__ == "__main__":
    self_test()
```

- **【🔥 外企高频加餐】在使用 LLaMA-Factory 微调 Qwen2-VL 时，`freeze_vision_tower`、`freeze_multi_modal_projector` 和 `finetuning_type=lora` 这三个开关在工业界一般怎么配？为什么？**
  - **零基础大白话**：
    1. **`freeze_vision_tower=True`（锁死视觉编码器 ViT）**：95% 的应用项目只有几千张标注图（比如 3,500 张矿山图片）。如果把预训练看过几亿张图的 ViT 放开训，不仅显存瞬间翻倍 OOM，还会把 ViT 原本优秀的通用视觉感知能力训废（灾难性遗忘）；
    2. **`freeze_multi_modal_projector=False` 或开启 `lora`（训练连接器 + LLM 挂载 LoRA）**：让连接器微调适应矿山设备特征，同时在 LLM 的注意力投影层挂载 `rank=8 或 16` 的 LoRA 学习“隐患定级逻辑与标准 JSON 输出格式”，单张 24G/48G 显卡即可高效收敛！

## 完整进阶实战指南（五要素表 + 高频面试题 + 进阶工业级代码 + 排障指南 + 工程 Trick + 三段式讲法 + 费曼闪卡）

### 一、提出问题与现实痛点 彻底理清多模态大模型微调的工程路线与参数冻结控制流。面对一个具体的工业隐患问答任务（如“Qwen2-VL 在安全绳识别上的定制优化”）：
- **基线先行**：绝不盲目一上来就重训模型！先用未经微调的原生零样本（Zero-shot）基线评测，穷尽 Prompt 优化、高分辨率切图与 RAG 检索手段；
- **微调定位**：只有在发现模型存在持续、固定的特定领域术语偏差、特定 JSON 输出语法不稳、或特定空间关系理解不足，且业务有足够的高质量标注时，才启动微调；
- **参数控制与梯度断言**：在第一阶段通常**完全冻结视觉编码器 (ViT) 与语言模型主干 (LLM)**，只微调多模态投影层 (Projector) 或在语言层注入 LoRA；
- **损失掩码**：在训练 Loss 计算中，Prompt、系统提示词以及庞大的 `<image>` 占位符必须打上 `labels = -100`，**绝对只对模型生成的 Assistant 目标答案计算交叉熵损失**！

### 概念：为什么需要这一环

先用零样本或少样本 Prompt 跑固定测试集，记录每类错误。只有确认输出格式、领域视觉理解或任务行为达不到目标时，再准备 SFT/LoRA。Hugging Face 的[VLM SFT 指南](https://huggingface.co/docs/trl/main/training_vlm_sft)给出多图数据与训练流程的官方例子；其 API 参数随版本变化，用时核对。

### 二、心智模型与直观图解

大模型的视觉大眼（ViT）和语言大脑（LLM）都是千亿参数练出来的通识精华，别动不动全量微调，否则模型会得“失忆症”。只调中间的“翻译官”Projector 或挂载 LoRA。算损失时，Prompt 和几百个图像占位符全打上 `-100` 马赛克，只有标准答案才算 Loss！

```

该冻结的死死冻住，该掩码的打上 -100！

[图像像素] ─> [ViT 视觉编码器 (完全冻结 requires_grad=False)] 
                         │
                         ▼
        [Multimodal Projector 投影层 (激活训练 requires_grad=True!)]
                         │
                         ▼
[输入 Prompt] ──> [LLM 语言解码器 (主干冻结或挂载 LoRA)] ──> 输出 Token Logits
[图像占位符]        │                                                │
[User 提问]         │                                                ▼
     │              │                                    【交叉熵损失 CrossEntropy】
     ▼              ▼                                                │
[Labels 掩码: -100 -100 -100 ...] ──────────────> [只有 Assistant 真实答案计入 Loss！]
```

### 核心概念与五要素表

| 五要素 | 投影层选择性微调与梯度流动断言器 (Level 5) |
| --- | --- |
| 输入 (Input) | 视觉特征张量、Prompt 与图像占位符 Token、目标答案 Token、标签掩码列表、网络模型参数。 |
| 做什么 (Process) | 冻结主干网络（requires_grad=False），仅激活投影层（requires_grad=True）；执行前向计算输出 logits；应用 -100 掩码计算目标答案交叉熵；反向传播并断言冻结参数无梯度，激活参数有效更新。 |
| 输出 (Output) | 有限标量损失 (Finite Loss)、梯度流动校验报告、更新后的权重参数。 |
| 哪里出错 (Failure Modes) | 1. 意外对全序列计算 Loss（导致模型在浪费算力记忆 Prompt 和图片占位符）；2. 优化器未包含可训练参数导致权重未变；3. 视觉 Token 截断导致尺寸不对齐。 |
| 参数影响 (Parameters) | 学习率通常设定较小（如 1e-4 到 2e-5）；梯度累积步数用于在有限显存下模拟大 Batch Size。 |

### 面试高频追问

【🔥 必会】在微调多模态大模型时，为什么标签掩码中必须把 Prompt 和图像 Token 设为 -100？
结论先行： 避免模型浪费容量去自回归“背诵”输入内容，保证只监督输出目标。
展开解释： PyTorch 交叉熵损失函数默认忽略 ignore_index = -100 的位置。图像 Token 极其庞大（动辄几百上千个），如果对其计算 Loss，不仅毫无意义（因为图像特征是由视觉模型提取而非语言模型生成），还会导致损失数值被输入严重主导，导致真正需要学习的回答答案梯度被严重稀释。

【🔥 必会】训练损失 (Loss) 持续下降，但测试集上的业务准确率完全没有提升，怎么系统化定位？
结论先行： 按照“标签错位 → 数据过拟合 → 评测指标与业务脱节”三步排查。
展开解释： 1. 检查标签移位：是否把输入也纳入了 Loss，导致 Loss 下降只是记住了 Prompt 模板；2. 检查数据切分：是否存在同场景过拟合，模型死记了训练样本；3. 检查生成指标：Loss 衡量的是 Token 困惑度，而业务关注的是精准坐标或关键词命中，困惑度下降不等于任务准确率提高。

【⭐ 理解】微调 VLM 时，只训 Projector、训 LLM LoRA 与全量微调三者如何做工程取舍？
结论先行： 遵循“只训 Projector（极低成本对齐）→ 语言层 LoRA（主推方案）→ 全量微调（极高门槛）”。
展开解释：

- 仅训练 Projector：只需 1到2 张消费级显卡，参数量仅百万级，适合让模型理解全新领域图像概念；

- 语言层 LoRA：在冻结视觉编码器和 LLM 基础上外挂低秩旁路，适合定制复杂业务输出格式与逻辑，是外企应用落地性价比最高的黄金标准；

- 全量微调：显存开销极大且极易引发“灾难性遗忘”（失去原有的通用通识能力），非极其特殊场景不推荐。

### Toy code：投影层微调与梯度流动 (Level 5)

运行前提：Python 3.10+、PyTorch，CPU 可运行。随机参数仅用于验证代码和梯度，示例没有使用 LoRA 或预训练模型。

```python
"""随机微型多模态网络：验证答案掩码、标签移位和投影梯度。"""
import torch
from torch import Tensor, nn
from torch.nn import functional as F


class MicroMultimodalVLM(nn.Module):
    """用累计视觉上下文演示梯度流；不是预训练 VLM 或 Transformer。"""
    def __init__(self, vision_dim: int = 4, hidden_dim: int = 4, vocab_size: int = 6) -> None:
        super().__init__()
        self.vision = nn.Linear(vision_dim, hidden_dim, bias=False)
        self.projector = nn.Linear(hidden_dim, hidden_dim, bias=False)
        self.embedding = nn.Embedding(vocab_size, hidden_dim)
        self.head = nn.Linear(hidden_dim, vocab_size, bias=False)
        for module in (self.vision, self.embedding, self.head):
            for param in module.parameters():
                param.requires_grad_(False)

    def forward(self, image: Tensor, tokens: Tensor) -> Tensor:
        """接收 image=(B,4)、tokens=(B,T)，返回 logits=(B,T+1,V)。"""
        if image.ndim != 2 or image.shape[1] != 4 or tokens.ndim != 2:
            raise ValueError('图像特征和 token 形状错误')
        if image.shape[0] != tokens.shape[0] or tokens.dtype != torch.long:
            raise ValueError('batch 不匹配或 token 类型错误')
        if not torch.isfinite(image).all() or tokens.numel() == 0:
            raise ValueError('输入为空或图像特征不是有限数')
        if torch.any(tokens < 0) or torch.any(tokens >= self.embedding.num_embeddings):
            raise ValueError('token 超出词表范围')
        visual = self.projector(self.vision(image)).unsqueeze(1)
        # 逐位置累计只是可微教学替身，不模拟真实注意力或语义。
        states = torch.cat((visual, self.embedding(tokens)), dim=1).cumsum(dim=1)
        logits = self.head(states)
        assert logits.shape == (image.shape[0], tokens.shape[1] + 1, self.head.out_features)
        return logits


def causal_loss(logits: Tensor, labels: Tensor) -> Tensor:
    """位置 t 的 logits 预测位置 t+1 的标签；-100 不参与损失。"""
    if logits.ndim != 3 or labels.shape != logits.shape[:2] or labels.dtype != torch.long:
        raise ValueError('logits/labels 形状或标签类型错误')
    if logits.shape[1] < 2:
        raise ValueError('序列过短，无法预测下一 token')
    shifted = labels[:, 1:]
    valid = shifted != -100
    if not bool(valid.any()):
        raise ValueError('没有可监督的答案 token')
    if torch.any(shifted[valid] < 0) or torch.any(shifted[valid] >= logits.shape[-1]):
        raise ValueError('标签超出词表范围')
    return F.cross_entropy(logits[:, :-1, :].reshape(-1, logits.shape[-1]),
                           shifted.reshape(-1), ignore_index=-100)


def self_test() -> None:
    """检查对齐、掩码、有效梯度、冻结主干和参数更新。"""
    torch.manual_seed(13)
    model = MicroMultimodalVLM()
    image = torch.tensor([[0.5, 0.8, -0.2, 0.4]])
    tokens = torch.tensor([[2, 4]])
    labels = torch.tensor([[-100, -100, 4]])
    logits = model(image, tokens)
    loss = causal_loss(logits, labels)
    # 第二个位置预测答案 4；第一预测位置被掩码。
    assert torch.allclose(loss, F.cross_entropy(logits[:, 1, :], labels[:, 2]))
    before = model.projector.weight.detach().clone()
    frozen = {name: p.detach().clone() for name, p in model.named_parameters() if not p.requires_grad}
    optim = torch.optim.SGD(model.projector.parameters(), lr=0.1)
    optim.zero_grad(); loss.backward()
    grad = model.projector.weight.grad
    assert grad is not None and torch.isfinite(grad).all() and grad.abs().sum() > 0
    assert all(p.grad is None for p in model.parameters() if not p.requires_grad)
    optim.step()
    assert not torch.equal(before, model.projector.weight)
    assert all(torch.equal(p, frozen[name]) for name, p in model.named_parameters() if name in frozen)
    try:
        causal_loss(logits, torch.full_like(labels, -100))
    except ValueError:
        pass
    else:
        raise AssertionError('全掩码标签必须拒绝')
    print('答案移位、投影梯度与冻结参数自检通过；随机模型无真实识图能力。')


if __name__ == '__main__':
    self_test()
```

**代码边界与解释：**本例用随机线性层和累计操作模拟视觉信息向答案位置传播，不是 Transformer，也没有识图能力。输入图像特征为 `(B,4)`，token 为 `(B,T)`，输出 `(B,T+1,V)`；`logits[:, :-1]` 预测 `labels[:, 1:]`。反向传播由 PyTorch 自动求导，检查投影梯度非零、冻结参数无梯度并且权重不变；全掩码标签拒绝。

### 排障指南（常见故障、定位方法、修复策略）

| 常见故障 (Failure) | 定位方法 (Diagnosis) | 修复策略 (Mitigation) |
| --- | --- | --- |
| 损失值 (Loss) 剧烈震荡不收敛 | 检查 Batch 数据，发现由于长短不一的文本在 Padding 处被错误地计算了 Loss。 | 在构建 DataLoader 时，确保 Collate 函数将所有 Padding Token 的 Label 显式覆盖为 -100。 |
| 显存爆炸 (OOM) 甚至 Batch=1 都会崩 | 开启了全量微调，ViT 与大语言模型的中间激活态全部驻留显存。 | 1. 冻结视觉编码器；2. 开启 Gradient Checkpointing (梯度检查点)；3. 采用 LoRA 微调，仅加载小秩旁路参数。 |
| 训练完毕后发现模型完全丧失常识 | 在领域数据上微调后，隐患检出率很高，但简单的日常问候全都不会回答了（灾难性遗忘）。 | 降低微调学习率（如降至 1e-5），并在领域数据中混入 5%到10% 的通用高质量多模态对话数据作为通用能力锚点。 |

### 工程 trick 与坑

- TRL SFTTrainer 中的图像 Token 截断坑：在使用 HuggingFace TRL 库做多模态 SFT 时，如果设置的 max_seq_length 过短，可能会在中间硬性截断图像 Token 序列，导致模型抛出不可捉摸的 Cuda Error；必须保证截断长度大于图像 Token 加上文本的总长度。

- LoRA 目标模块按模型结构和验证结果选择：很多开发者默认把 LoRA 仅挂在语言模型的 q_proj, v_proj 上，如果任务严重依赖新领域图像语义，可以比较是否训练多模态连接层；并非所有模型都适用同一挂载方式。

- 永远先测零样本基线：在写微调代码前，必须先在相同测试集上跑通开源原生模型的 Zero-shot 分数作为基准；只有当微调后分数显著超过基线并经过统计检验，才能证明微调工作的价值。

### 费曼自述与闪卡

费曼自述（3 分钟白板口述框架）：
“微调多模态大模型，核心秘诀就八个字：‘该冻就冻，该遮就遮’。第一，大模型的视觉大眼（ViT）和语言大脑（LLM）都是千亿参数练出来的通识精华，别动不动就全量微调，全量微调不仅烧钱，还会让模型得‘失忆症’，把原来聪明的通识能力全丢了。所以我们要把主干冻结（Freeze），只挑中间的‘翻译官’Projector 或者挂两片轻量 LoRA 小翅膀来训练。第二，算损失时，Prompt 问题和那一堆图像 Token，全打上 -100 的马赛克，告诉优化器‘这些是考题，不用你背！’只有最终写出的标准答案，才参与算 Loss，这样每一分算力都精确砸在刀刃上。”

备考闪卡 Q&A：

- Q：微调 VLM 时为什么推荐优先冻结视觉编码器？
A： 视觉编码器（如 CLIP/SigLIP）具备通用视觉表征能力，冻结它可以大幅减少显存消耗、防止过拟合与灾难性遗忘。

- Q：在 PyTorch 损失计算中，-100 的含义是什么？
A： 交叉熵损失函数（CrossEntropyLoss）的默认 ignore_index，对应位置的预测不参与 Loss 计算与梯度反向传播。

# 10.4 生成模型、Embedding 与 Reranker【🔥 必会】

## 1. 🎯 本节目标与大白话例子

本节目标：明确生成模型、Bi-Encoder（Embedding）与 Cross-Encoder（Reranker）的分工，理解两阶段检索为什么不能跳过召回直接精排。

大白话例子：百万图书馆找书：Bi-Encoder（Embedding）就像给每本书提前写好坐标卡片（向量预计算），读者报出关键词后 10 毫秒就能圈出最像的 50 本（粗召回）；Cross-Encoder（Reranker）则是把这 50 本书逐本摊开和读者的问题逐字比对，挑出最准的前 5 本（精排）。如果让精排直接翻一百万本书，图书馆当场瘫痪。

## 2. 🧠 核心原理与五维拆解

Bi-Encoder（Embedding）：Query 和 Doc 各自独立编码成向量，文档向量可离线预计算存入向量库，线上只需算 1 次 Query 编码 + ANN 检索，复杂度近 $O(1)$，但缺乏词与词之间的细粒度交叉注意力。

Cross-Encoder（Reranker）：把 [CLS] Query [SEP] Doc [SEP] 拼在一起过双向注意力，逐字深度交互打分，精度极高；但无法离线预计算，每次必须对 $K$ 个候选逐对前向传播，复杂度 $O(K)$。

标准工业级漏斗：BM25 + Embedding 双路召回 Top-50 → Reranker 精排 Top-5 → LLM 生成。

## 3. 💻 渐进式代码实操（ch10_code/step_04_embed_rerank_pipeline.py）

```python
"""10.4 生成模型、Embedding 与 Reranker：两阶段召回+精排流水线"""
import numpy as np
from typing import List, Tuple


def bi_encoder_recall(query_vec: np.ndarray, doc_vecs: np.ndarray, top_k: int) -> List[int]:
    """向量预计算后仅做余弦相似度点积，复杂度 O(1) 实时编码。"""
    q_norm = query_vec / (np.linalg.norm(query_vec) + 1e-12)
    d_norm = doc_vecs / (np.linalg.norm(doc_vecs, axis=1, keepdims=True) + 1e-12)
    scores = d_norm @ q_norm
    return np.argsort(scores)[::-1][:top_k].tolist()


def cross_encoder_rerank(query: str, candidate_indices: List[int], docs: List[str]) -> List[Tuple[int, float]]:
    """模拟 Cross-Encoder 拼接 [query, doc] 做细粒度词面+语义交互精排。"""
    q_terms = set(query.split())
    scored = []
    for idx in candidate_indices:
        overlap = len(q_terms & set(docs[idx].split()))
        scored.append((idx, round(0.5 + 0.25 * overlap, 3)))
    scored.sort(key=lambda x: x[1], reverse=True)
    return scored


if __name__ == "__main__":
    docs = ["破碎机 轴承 温度 报警 处理", "皮带机 跑偏 停机 规程", "破碎机 衬板 磨损 更换"]
    q_vec = np.array([0.9, 0.2, 0.1])
    d_vecs = np.array([[0.85, 0.25, 0.1], [0.1, 0.9, 0.2], [0.88, 0.15, 0.15]])
    recalled = bi_encoder_recall(q_vec, d_vecs, top_k=2)
    reranked = cross_encoder_rerank("破碎机 温度 报警", recalled, docs)
    assert reranked[0][0] == 0
    print("[10.4 PASS] recalled:", recalled, "reranked:", reranked)
```

## 4. 🗣️ 面试官视角：这段代码怎么讲

在工业规程 RAG 系统中，我坚持‘双路召回 + Reranker 精排’两阶段架构：Embedding 负责高召回与毫秒级过滤，Reranker 只对 Top-30~50 做精细交叉打分，既保证了 Recall@5 的大幅提升，又把精排耗时锁死在 100ms 以内。

## 5. 🔧 生产排障指南

坑 1：把几百条召回结果全喂给 Reranker → 解法：Reranker 推理耗时随候选数线性增长，通常送入 Top-20~50 即可；且要注意 Reranker 的最大输入长度限制（如 512 或 8192）。

## 6. ❓ 高频面试追问与参考答法

Q1：既然 Cross-Encoder（Reranker）精度比 Embedding 高得多，为什么不全部用 Reranker？ 答：Cross-Encoder 需要把 Query 和每篇 Doc 拼接后实时联合前向推理，无法预先离线算好文档向量；面对十万/百万级文档库时延迟完全不可接受，只能放在召回后的小候选集上做精排。

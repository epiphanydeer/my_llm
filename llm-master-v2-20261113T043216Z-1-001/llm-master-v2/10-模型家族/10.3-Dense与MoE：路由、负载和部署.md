# 10.3 Dense 与 MoE：路由、负载和部署【🔥 必会】

## 1. 🎯 本节目标与大白话例子

本节目标：理解 MoE（混合专家）如何实现“总参数大但单 Token 激活计算量小”，掌握 Top-K 门控路由、负载均衡 Aux Loss 与部署显存瓶颈。

大白话例子：Dense 模型像全科全能专家，不管问什么问题，全脑 100% 神经元都得加班算一遍；MoE 像拥有 64 位专科医生的三甲医院，分诊台（Router）每次只挑最对口的 2 位医生（Top-2 激活）会诊，算力省了，但医院大楼（显存）还是得把 64 位医生的办公室全装下。

## 2. 🧠 核心原理与五维拆解

总参数 vs 激活参数：如 DeepSeek-V3 总参数 671B、每次仅激活 37B；训练与推理 FLOPs 接近 37B Dense，但知识容量接近超大模型。

路由坍缩（Routing Collapse）与负载均衡：若门控网络总把 Token 集中发给少数几个专家，其余专家得不到训练且造成单卡算力瓶颈。传统做法加 Auxiliary Load Balancing Loss（$N \sum f_i P_i$），DeepSeek-V3 提出 Auxiliary-loss-free（动态偏置调节），避免辅助损失干扰主语言建模目标。

部署挑战：1）显存容量大（全量专家权重都要驻留显存）；2）专家并行（EP）的 All-to-All 通信开销；3）低 Batch Size 下访存带宽成为瓶颈。

## 3. 💻 渐进式代码实操（ch10_code/step_03_moe_routing_load_balance.py）

```python
"""10.3 Dense 与 MoE：Top-K 门控路由与负载均衡辅助损失估算器"""
import numpy as np


def moe_topk_route_and_aux_loss(router_logits: np.ndarray, top_k: int = 2) -> dict:
    """
    router_logits: [num_tokens, num_experts]
    计算 Top-K 路由分配比例与 Switch/Mixtral 风格的负载均衡 Aux Loss。
    """
    num_tokens, num_experts = router_logits.shape
    shifted = router_logits - np.max(router_logits, axis=-1, keepdims=True)
    probs = np.exp(shifted) / np.sum(np.exp(shifted), axis=-1, keepdims=True)

    topk_idx = np.argsort(probs, axis=-1)[:, -top_k:]
    dispatch_counts = np.zeros(num_experts, dtype=float)
    for row in topk_idx:
        for e in row:
            dispatch_counts[e] += 1.0

    f_i = dispatch_counts / (num_tokens * top_k)  # 每个专家实际分到的 Token 比例
    p_i = np.mean(probs, axis=0)                  # 每个专家的平均路由概率
    aux_loss = float(num_experts * np.sum(f_i * p_i))
    return {
        "expert_load_fraction": np.round(f_i, 3).tolist(),
        "aux_loss": round(aux_loss, 4),
    }


if __name__ == "__main__":
    balanced_logits = np.array([[2.0, 0.1, 0.1, 0.1], [0.1, 2.0, 0.1, 0.1], [0.1, 0.1, 2.0, 0.1], [0.1, 0.1, 0.1, 2.0]])
    collapsed_logits = np.tile([5.0, 4.0, -2.0, -2.0], (4, 1))
    r_bal = moe_topk_route_and_aux_loss(balanced_logits, top_k=1)
    r_col = moe_topk_route_and_aux_loss(collapsed_logits, top_k=1)
    assert r_bal["aux_loss"] < r_col["aux_loss"]
    print("[10.3 PASS] balanced:", r_bal, "collapsed:", r_col)
```

## 4. 🗣️ 面试官视角：这段代码怎么讲

在 MoE 选型和面试里，我重点区分‘算力省但显存不省’：MoE 降低了单 Token 的 FLOPs，但部署时依然需要吃下全部专家权重显存，并且对跨卡 All-to-All 通信带宽要求很高；如果单卡显存卡死且并发不高，同激活量级的 Dense 模型往往更好运维。

## 5. 🔧 生产排障指南

坑 1：看到“MoE 仅激活 3B 参数”就以为 8G 显存显卡能轻松跑起来 → 解法：总参数如果是 30B，30B 权重依然必须全部加载进显存（除非做极慢的 CPU Offload）。

## 6. ❓ 高频面试追问与参考答法

Q1：MoE 训练中为什么会出现路由坍缩？如何解决？ 答：热门专家早期梯度更新快、得分高，形成“马太效应”吸走所有 Token。解法包括：加入负载均衡辅助损失（Aux Loss）、Router Z-loss 稳定门控 Logits、Top-K 加噪声探索，以及 DeepSeek 的无辅助损失动态偏置策略。

# 10.6 API、托管与自部署：核对约束【⭐ 理解】

## 1. 🎯 本节目标与大白话例子

本节目标：学会从数据合规、SLA 稳定性、冷启动与月度 TCO（总拥有成本）四个维度，科学决策公有云 API、专有云托管与本地自部署。

大白话例子：出行方式选型：偶尔出门打网约车（按量 API）最省心；每天固定通勤且保密要求高才买私家车（自部署 GPU）——买了车就算停在车库不动，折旧、车位费和保养（显卡租金与运维）也照收不误，流量不够大时反而更亏。

## 2. 🧠 核心原理与五维拆解

三大部署形态对比：

公有云 API：零运维、按量付费、弹性极强、直接用上最强旗舰模型；痛点是数据出域合规与偶发限流波动。

专有托管（Managed Endpoints）：数据隔离、可配 VPC、免去底层 vLLM/K8s 运维，通常按实例小时或承诺吞吐计费。

私有化自部署（On-Premises）：数据绝对不出内网、可深度定制量化/投机解码；痛点是初期 GPU 采购/租赁固定成本高，低谷期算力闲置浪费。

混合架构（Hybrid）：敏感数据/高频简单任务走内网开源小模型，脱敏后的复杂长尾推理走云端旗舰 API。

## 3. 💻 渐进式代码实操（ch10_code/step_06_deployment_tco_comparator.py）

```python
"""10.6 API、托管与自部署：不同并发下的月度 TCO 核算器"""
from typing import Dict


def compare_monthly_tco(
    monthly_requests: int,
    avg_in_tokens: int,
    avg_out_tokens: int,
    api_in_per_1m: float,
    api_out_per_1m: float,
    self_host_gpu_monthly_usd: float,
) -> Dict[str, object]:
    api_cost = (
        monthly_requests * avg_in_tokens / 1_000_000 * api_in_per_1m
        + monthly_requests * avg_out_tokens / 1_000_000 * api_out_per_1m
    )
    winner = "self_host" if self_host_gpu_monthly_usd < api_cost else "api"
    return {
        "api_monthly_usd": round(api_cost, 2),
        "self_host_monthly_usd": round(self_host_gpu_monthly_usd, 2),
        "cheaper_option": winner,
    }


if __name__ == "__main__":
    low_qps = compare_monthly_tco(50_000, 1500, 300, 1.5, 6.0, 2200.0)
    high_qps = compare_monthly_tco(2_000_000, 1500, 300, 1.5, 6.0, 2200.0)
    assert low_qps["cheaper_option"] == "api" and high_qps["cheaper_option"] == "self_host"
    print("[10.6 PASS] low_qps:", low_qps, "high_qps:", high_qps)
```

## 4. 🗣️ 面试官视角：这段代码怎么讲

在我的 TCO 核算脚本里可以看到，月调用量 5 万次时 API 只要 200 美元出头，远低于自部署 2200 美元的 GPU 固定月租；只有当并发规模跃升到数百万次且负载平稳时，私有化自部署的单位成本优势才会反超。

## 5. 🔧 生产排障指南

坑 1：自部署只算了显卡硬件折旧，漏算了运维人力、电费与多副本高可用冗余 → 解法：TCO 核算必须包含 2 副本以上灾备与工程维护成本。

## 6. ❓ 高频面试追问与参考答法

Q1：如果业务要求数据绝对不出企业内网，但偶尔有突发 10 倍流量洪峰，自部署架构怎么扛？ 答：1）部署弹性推理集群配合请求队列削峰；2）长尾非实时任务转离线批处理；3）对核心 SLA 接口设优先级分级与轻量降级模型（如 32B 繁忙时自动切 7B）。

# 10.5 VLM 选型：视觉编码、对齐与生成【🔥 必会】

## 1. 🎯 本节目标与大白话例子

本节目标：掌握多模态大模型（VLM）选型的核心技术维度：视觉编码器分辨率策略（固定缩放到原生/动态切片）、视觉 Token 压缩与显存/延迟预算。

大白话例子：看一张 1920×1080 的矿区监控截图找远处安全帽：如果老式 VLM 把整张大图硬生生压成 336×336 小邮票，安全帽只剩 2 个像素肯定漏检；现代 VLM（如 Qwen-VL / AnyRes）就像拿放大镜把大图切成 6 块高清局部小图 + 1 张全局缩略图分别看，看得清了，但视觉 Token 账单也涨了 7 倍。

## 2. 🧠 核心原理与五维拆解

VLM 三段式结构：Vision Encoder (ViT/SigLIP) → Projector / Adapter (MLP / Token Merger) → LLM Backbone。

分辨率演进：

早期固定分辨率（如 336×336）：小目标、密集表格 OCR 严重模糊失真。

动态切片 / 原生分辨率（AnyRes / NaViT / Qwen2.5-VL）：按原图长宽比切分高清子块（Tiles）或原生支持任意长宽比，大幅提升 OCR 与小目标识别，但视觉 Token 数会从几百暴涨至数千。

Token 合并（Pixel Shuffle / 2×2 Merger）：在 Projector 前将相邻 2×2 的 Patch 拼在一起降维，把视觉 Token 数量压缩为原来的 $1/4$，显著降低 LLM 侧计算开销。

## 3. 💻 渐进式代码实操（ch10_code/step_05_vlm_visual_token_budget.py）

```python
"""10.5 VLM 选型：动态切片与视觉 Token 预算估算器"""
import math
from typing import Dict


def estimate_vlm_visual_tokens(
    width: int,
    height: int,
    patch_size: int = 14,
    merge_stride: int = 2,
    max_tiles: int = 6,
    tile_size: int = 448,
) -> Dict[str, int]:
    """估算动态分辨率（AnyRes/Qwen-VL 风格）的视觉 Token 占用。"""
    patches_per_tile = (tile_size // patch_size) ** 2
    tokens_per_tile = patches_per_tile // (merge_stride ** 2)
    tiles_w = math.ceil(width / tile_size)
    tiles_h = math.ceil(height / tile_size)
    used_tiles = min(max_tiles, max(1, tiles_w * tiles_h))
    # 常见实现会额外附带 1 张全局缩略图
    total_visual_tokens = (used_tiles + 1) * tokens_per_tile
    return {
        "used_tiles": used_tiles,
        "tokens_per_tile": tokens_per_tile,
        "total_visual_tokens": total_visual_tokens,
    }


if __name__ == "__main__":
    low_res = estimate_vlm_visual_tokens(448, 448)
    high_res = estimate_vlm_visual_tokens(1920, 1080)
    assert high_res["total_visual_tokens"] > low_res["total_visual_tokens"]
    print("[10.5 PASS] 448p:", low_res, "1080p:", high_res)
```

## 4. 🗣️ 面试官视角：这段代码怎么讲

结合我做矿山工业视觉（YOLO + VLM 复核）的经验，VLM 选型最关键的不是参数大小，而是小目标清晰度与视觉 Token 预算的权衡：我们优先用 YOLO 裁剪出目标区域小图再送给 VLM，既避免了整图动态切片带来的上千视觉 Token 延迟，又保证了安全帽/安全带等小目标不失真。

## 5. 🔧 生产排障指南

坑 1：直接把 4K 原图喂给 VLM 导致推理超时与 Token 费用暴增 → 解法：限制 max_pixels / max_tiles，或先用目标检测（YOLO/Grounding）裁剪 ROI 区域再送入 VLM。

## 6. ❓ 高频面试追问与参考答法

Q1：在工业安全隐患识别中，为什么“YOLO 预筛 + VLM 二次复核”通常比纯 VLM 端到端扫描监控流更好？ 答：纯 VLM 逐帧处理海量高清视频流算力成本与延迟极高，且整图小目标易漏检；YOLO 在边缘端毫秒级完成高召回预筛与 ROI 裁剪，VLM 只对疑似告警帧做语义逻辑复核（如“是否属于合理施工豁免场景”），兼具低误报与高性价比。
